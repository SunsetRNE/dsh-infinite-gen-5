授权口径：自有资产只读侦察 —— 本机 Ubuntu 容器（proot 承载，uid=0）+ 自有 Android 手机经 `127.0.0.1:3090` 设备桥。全程只读：未改设备状态、未点按/输入、未读短信、未结束应用、未写 `/etc` 或 settings、未对公网发流量、未爆破。

环境（本轮实测，非引述）：`uid=0(root)`、`gid=0`，但 `CapPrm=CapEff=0000000000000000`（零 Linux 能力）；`uname` = `Linux localhost 6.1.141-android14-11-o-g659d588fa0da #1 SMP PREEMPT Thu Aug 6 07:53:55 UTC 2026 aarch64`；`/etc/os-release` = `Ubuntu 24.04.3 LTS (Noble Numbat)`；`date -u` = `2026-09-29T07:13:41Z`；`ps -e` 仅 13 行（PID 1863 `libproot.so`、PID 1872/2140 `MainThread` + 探测 shell），`cat /proc/1/comm` 回 `No such file or directory` → proot 用户态承载，无真实 PID 1，`/proc` 视图全部取自宿主内核；`ip -brief a` 只有 `lo / dummy0 / ifb0 / ifb1 / tunl0`，无 `eth0` → 与宿主共享网络命名空间。

最小配置改动（只列配置与命令，本轮不在现场执行）：

```bash
# a) 系统调用级留痕（最有效的一项；需宿主内核支持审计 + 授予 CAP_AUDIT_*）
apt install -y auditd audispd-plugins
printf '%s\n' '-a always,exit -F arch=b64 -S execve -F key=r6-exec' \
              '-a always,exit -F arch=b64 -S connect -F key=r6-conn' \
              '-w /root/.dsh -p rwa -k r6-dsh' > /etc/audit/rules.d/r6.rules
augenrules --load && systemctl enable --now auditd

# b) 恢复通用文本日志通道
apt install -y rsyslog && systemctl enable --now rsyslog
printf 'auth,authpriv.*   /var/log/auth.log\n*.*                /var/log/syslog\n' > /etc/rsyslog.d/10-r6.conf

# c) 让网络动作留历史（需宿主侧 netfilter 与 CAP_NET_ADMIN）
nft add table inet r6log
nft add chain inet r6log input '{ type filter hook input priority 0; }'
nft add rule inet r6log input tcp dport '{ 3080, 3090, 43795, 12121, 7890 }' log prefix '"R6-NET "'

# d) 只读复核：改完按这两条验证是否真的开始留痕
augenrules --check; ausearch -k r6-exec -ts recent | head
```

边界：a 与 c 在 proot 内会因能力缺失失败（`CapEff=0000000000000000`，无 `CAP_AUDIT_CONTROL`/`CAP_NET_ADMIN`），只在真容器或宿主侧生效；b 的 rsyslog 可在容器内运行，但它只能记录本容器内可见的写入方，覆盖不到宿主网络事件。要判断「装了是否有效」，唯一判据是 a/d 里 `ausearch` 能回出记录 —— 回不出就说明宿主侧没放行。

已知：六行结论中每一条都对应前面 5 节的具体回显。推测：a/b/c 三条改动在本容器内能否落地（a、c 倾向不能，b 倾向能）——依据是本轮 `CapEff` 与进程/内核视图，未实际执行安装，故此行为推测。未知：宿主 Android 内核对 audit 与 netfilter 的编入情况、以及宿主侧日志的保存周期。
