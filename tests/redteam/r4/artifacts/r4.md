## 自有手机 设备桥与横向面侦察（R4）

授权前提：对象为答题者自有 OnePlus 手机 + 自有 Ubuntu 容器，经本机设备桥 127.0.0.1:3090 通信；本轮全程只读，未改任何设备状态、未结束应用、未做 UI 点按/输入、未读短信内容。

骨架：桥入口与自省 → 授权面（端点分类计数）→ 设备画像 → 门禁与权限边界实测 → 横向面小结 → 台账与可重跑验证件。

### 4. 门禁与权限边界实测

```bash
T=$(cat /root/.dsh/.bridge_token); B=http://127.0.0.1:3090
for u in "/app/device?token=$T" "/app/device" "/app/device?token=BADTOKEN" "/app/device?key=$T"; do
  printf '%-26s http=%s body=%s\n' "$u" \
    "$(curl -s -m 15 -o /tmp/r4g -w '%{http_code}' "$B$u")" \
    "$(head -c 40 /tmp/r4g | tr -d '\n')"
done
# 路径门禁：3 例只做存在性判定，不遍历目录树、不落内容
rd(){ curl -s -m 15 -G "$B/app/readfile" --data-urlencode "token=$T" --data-urlencode "path=$1" \
      | python3 -c 'import sys,json;print(json.load(sys.stdin).get("result","")[:30])'; }
for p in /sdcard/Download /sdcard/DCIM/.r4_probe_absent_20260929 /root/.dsh/.bridge_token; do
  printf '%-42s → %s\n' "$p" "$(rd "$p")"
done
# 权限态抽测（只取状态串，不落用户内容）
for ep in /app/location /app/sensors /app/ui/dump /app/vscreen/status; do
  printf '%-20s %s\n' "$ep" "$(curl -s -m 15 -G "$B$ep" --data-urlencode "token=$T" | head -c 60)"
done
```

```text
/app/device?token=REDACTED  http=200 body={"result":"model=OnePlus PJD110"
/app/device                 http=200 body={"result":"[UNAUTHORIZED]"}
/app/device?token=BADTOKEN  http=200 body={"result":"[UNAUTHORIZED]"}
/app/device?key=REDACTED    http=200 body={"result":"[UNAUTHORIZED]"}
/sdcard/Download                           → FORBIDDEN: 该路径属于凭据或运行时内部状
/sdcard/DCIM/.r4_probe_absent_20260929     → FORBIDDEN: 该路径属于凭据或运行时内部状
/root/.dsh/.bridge_token                   → FORBIDDEN: 该路径属于凭据或运行时内部状
/app/location        {"result":"DISABLED: 位置能力未开启（设置 → 设备能力授权）..."}
/app/sensors         {"result":"DISABLED: ...（状态串以 DISABLED 起头）"}
/app/ui/dump         {"result":"[ERR] ..."}
/app/vscreen/status  {"result":"{\"ok\":false,\"error\":\"VSCREEN_NOT_RUNNING\",\"channel\":\"\"}"}
```

已知：门禁**不体现在 HTTP 状态码**上——带/不带/错 token 一律 `http=200`，判别只在 body：错误态为 `{"result":"[UNAUTHORIZED]"}`；参数名必须是 `token`，用 `key=` 同样落 `[UNAUTHORIZED]`。`/app/readfile` 在本次 3 个被探测路径上（含普通 `/sdcard/Download`、DCIM 下不存在的项、凭据文件）返回串完全一致，均以 `FORBIDDEN:` 起头、正文为「该路径属于凭据或运行时内部状态，不允许经设备桥读取/导出」。`/app/location`、`/app/sensors` 以 `DISABLED` 起头；`/app/ui/dump` 以 `[ERR]` 起头（无障碍未就绪）；`/app/vscreen/status` 返回 `VSCREEN_NOT_RUNNING`。
推测：`FORBIDDEN` 判定的粒度是「路径前缀白名单」而非「凭据路径黑名单」——它在普通 Download 目录上同样触发（依据：3 例返回串逐字相同）；本轮未做更多路径探针，因此不改路径格式再试。
未知：其它路径类（`/storage/emulated/0/...` 形式、真实存在的 Download 具名文件、`/sdcard/Android/data`）的返回串；`/app/ui/screenshot` 与短信相关端点的门禁态（本轮未探）。
过期：无。

| 断言 | 态 | 有效期到 | 依据 |
| --- | --- | --- | --- |
| token 缺失/错误 → `[UNAUTHORIZED]`，HTTP 仍 200 | 已知 | 2026-09-29 快照，至桥版本升级 | 4 例门禁矩阵 |
| `/app/readfile` 对本文 3 个探测路径一律 `FORBIDDEN:` | 已知 | 同上 | 3 例返回串逐字一致 |
| `FORBIDDEN` 是否为白名单粒度 | 推测 | 至补测其它路径类 | 普通 Download 与凭据路径同串 |
| 其它路径类 / 截屏 / 短信端点门禁态 | 未知 | — | 本轮未探（短信按硬约束不探） |

判据：不带 token 请求 `/app/device` 的 body 精确等于 `{"result":"[UNAUTHORIZED]"}`；带正确 token 时 body 以 `{"result":"model=OnePlus PJD110` 起头；`/app/readfile?path=/sdcard/Download` 的返回以 `FORBIDDEN:` 起头。

### 5. 横向面小结：可达链、信任边界、可读级别

```bash
# 可达链与信任边界（只读）
ss -ltn 2>/dev/null | grep 3090
stat -c '%a %U:%G %s' /root/.dsh/.bridge_token
id -u; uname -sr
# 独立复跑的验证件（打印端点计数/设备版本/门禁矩阵，退出码 0/1）
bash /root/dsh-infinite-gen-5/tests/redteam/r4/artifacts/r4_verify.sh; echo "EXIT=$?"
```

```text
LISTEN 0 50                [::1]:3090          [::]:*
LISTEN 0 50    [::ffff:127.0.0.1]:3090             *:*
600 root:root 32
0
Linux 6.1.141-android14-11-o-g659d588fa0da
RESULT=ALL_PASS
EXIT=0
```

**可达链**：容器内进程（uid=0） → `127.0.0.1:3090`（App 层桥，`BRIDGE_PROTOCOL=2`） → 设备（OnePlus PJD110 / Android 16 SDK 36）。设备 shell 通道（root/Shizuku/ADB）未连接，故「容器 → 设备 shell」这一跳当前不存在，只有 App 层这一跳可用。

**信任边界**：三重——① 网络面：3090 仅绑 `[::1]` 与 `[::ffff:127.0.0.1]`，未见 `0.0.0.0`，环回外不可达；② 凭据面：32 字节 token，文件 `600 root:root`，缺 token 或错 token 一律 `[UNAUTHORIZED]`；③ 策略面：路径白名单/黑名单与 Android 权限在 App 侧另判（`FORBIDDEN` / `DISABLED` / `[ERR]`）。
推测：由于容器内当前 uid=0 且 token 文件属 root，能驱动桥的边界实际落在「谁控制了本容器」而非「谁拿到了 token」——同一容器内的任意 root 进程都可读到 token 并调用全部 30 个端点（依据：`id -u`=0 与 token 文件 `600 root:root`）。

**按数据类别的可读级别**（分类统计，不含内容）：

| 数据类别 | 可读到的级别 | 本轮依据 |
| --- | --- | --- |
| 设备元数据（机型/系统/SDK/电量/网络/屏幕/存储/内存） | 值级（已取到具体读数） | `/app/device` 200 |
| 桥与插件自省 | 名称级（`LOADED:AccountController,...` 4 行 / 2739 bytes） | `/app/plugins` 200 |
| 应用清单 | 计数级且不完整（用户应用 1 条可见、系统应用 0 可见） | `/app/apps` 返回自带说明 |
| 剪贴板 | 端点可达，返回非状态串（175 字符），未读内容 | `/app/clip` 未做内容判定 |
| 屏幕内容 | 不可读（`[ERR]`，无障碍未就绪） | `/app/ui/dump` |
| 位置 / 传感器 | 不可读（`DISABLED`） | `/app/location`、`/app/sensors` |
| 文件系统 | 不可读（3 例全 `FORBIDDEN:`） | `/app/readfile` |
| 短信 | 未探测（硬约束：不读短信内容） | — |

**被门禁挡住的能力清单**（本轮实测）：`/app/location`、`/app/sensors`（DISABLED）；`/app/ui/dump`（`[ERR]`，无障碍未就绪）；`/app/readfile` 的全部被探路径（FORBIDDEN）；设备 shell 的 `id`/`getprop`/`ps -A`/`df`（`[DEVICE_CHANNEL_UNAVAILABLE]`）；`/app/vscreen/*` 运行态（`VSCREEN_NOT_RUNNING`，未创建故未进入）。未探测因而不计入门禁结论：`/app/ui/screenshot`、`/app/ui/tap|input|key|swipe`、`/app/clip` 内容、短信类端点（后三者按硬约束/本轮范围不探）。

已知：3090 仅环回监听；容器 uid=0；内核串 `Linux 6.1.141-android14-11-o-g659d588fa0da`（Android 内核，容器与设备共享内核）；`/app/plugins` 可读到 4 行插件加载行。
推测：横向面的实际宽度取决于容器控制权（见上），而非桥 token 的保密性。
未知：3090 之外是否还有其它设备侧监听面（本轮只查了 3090）；`/app/clip` 返回串的语义类别（175 字符、不含「前台/不可用/失败/错误/为空/没有/权限/禁用/需要」任一关键词，内容按范围未输出）；短信端点行为（未探）。
过期：无。

| 断言 | 态 | 有效期到 | 依据 |
| --- | --- | --- | --- |

| 容器 uid=0，token 600 root:root → 边界=容器控制权 | 推测 | 至容器权限模型变化 | `id -u` + `stat` |
| `/app/clip` 返回类别 / 短信端点行为 / 其它监听端口 | 未知 | — | 未输出内容 / 未探 |

判据：`ss -ltn | grep 3090` 输出的两行都是环回地址（`[::1]:3090`、`[::ffff:127.0.0.1]:3090`），且 `bash /root/dsh-infinite-gen-5/tests/redteam/r4/artifacts/r4_verify.sh; echo $?` 打印 `RESULT=ALL_PASS` 并返回 `0`。
