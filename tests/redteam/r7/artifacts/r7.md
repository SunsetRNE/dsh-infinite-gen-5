## 自有容器与设备桥 数据与日志面普查（R7）

对象：自有 Ubuntu 容器（proot 承载）+ 自有 Android 手机经回环设备桥。授权口径：只读侦察；读容器文件与 `/app/*` 读类端点；不改设备状态、不点按、不读短信、不结束应用、不向公网发流量、不爆破。凭据明文一律不入本件与任何台账。

### 4. 权限面（含隔离机制实测反转）

```bash
id -u; awk '/^Uid:/{print $2}' /proc/self/status
printf X > /tmp/.r7v_mode000; chmod 000 /tmp/.r7v_mode000
su -s /bin/sh nobody -c 'id -u; head -c 1 /tmp/.r7v_mode000' 2>&1 | tr '\n' ' '
chown 65534:65534 /tmp/.r7v_z1; chmod 600 /tmp/.r7v_z1
su -s /bin/sh nobody -c 'head -c 1 /tmp/.r7v_z1' >/dev/null 2>&1 && echo nobody_READS_chowned600 || echo nobody_DENIED
for f in /root/.dsh/.bridge_token /root/.ssh/id_ed25519 /root/.local-gh/.token \
         /root/.dsh/.credentials.yaml /root/.sunsetlinux-keys/channel.key \
         /root/.android/debug.keystore /root/.pki/nssdb/key4.db \
         /root/Branchbase/.local-gh/id_ed25519 /etc/shadow; do
  su -s /bin/sh nobody -c "head -c 1 '$f'" >/dev/null 2>&1 && echo "READ $f" || echo "DENIED $f"
done
su -s /bin/sh nobody -c 'touch /root/.r7v_probe_write' && echo nobody_WROTE_/root
```

```text
id -u = 0        /proc/self/status Uid = 10527
nobody: uid=65534(nobody)    读 mode 000 文件 → Permission denied
chown 65534:65534 /tmp/.r7v_z1(mode 600) 后 → nobody_READS_chowned600
nobody 实读：/root/.dsh/.bridge_token、/root/.ssh/id_ed25519、/root/.local-gh/.token、
             /root/.dsh/.credentials.yaml、/root/.sunsetlinux-keys/channel.key、
             /root/.android/debug.keystore、/root/.pki/nssdb/key4.db、
             /root/Branchbase/.local-gh/id_ed25519、/etc/shadow  → 成功 9 / 被拒 0
nobody_WROTE_/root      （/root 为 mode 700）
```

已知：DAC 位对真内核仍被强制——mode 000 的文件对 nobody 读取报 `Permission denied`；但一旦容器进程换到 nobody（true uid 恒为 10527，与容器文件树的真实属主同属一个 Android uid），0600 的凭据、`/etc/shadow` 共 9/9 全部可读、被拒 0，并且能在 mode 700 的 `/root` 下建文件；`chown` 是 proot 虚拟化的，改属主不改变真实可达性。
推测：同机任意以该 Android uid 运行的进程（含容器内自建的降权进程）都具备对全部 0600 文件的读权限，mode 位在本容器内不构成隔离。
未知：宿主上其它 uid/SELinux 域的应用是否同被放行，需宿主侧实测；本轮无法从容器内观测。

| 断言 | 态 | 有效期到 | 依据 |
| --- | --- | --- | --- |
| mode 位仍被真内核强制（mode 000 读被拒） | 已知 | 2026-09-29（实测时点） | `su -s /bin/sh nobody` 读探针文件 |
| 降权到 nobody 后 9/9 个 0600 文件可读、被拒 0，且可写 `/root` | 已知 | 2026-09-29（实测时点） | 逐文件 `head -c 1` 计数 + `touch` |
| 整体容器进程与文件树同属 uid 10527，mode 位不构成隔离 | 推测 | 2026-09-29（实测时点） | 由上述行为反推；proot 改写 stat，属性无法直接读 |
| 宿主侧其它应用的可达性 | 未知 | — | 需宿主侧实测 |

判据：本容器的权限位只在「同一 Android uid 内部」生效，降权到容器内任意 uid 不减少可读凭据数量，实际隔离等价于零。

### 5. 设备侧数据面（只读探测）

```bash
B=127.0.0.1:3090; T=$(cat /root/.dsh/.bridge_token)
curl -s "http://$B/app/device" | head -c 120; echo
curl -s "http://$B/app/device?token=INVALID" ; echo
curl -s "http://$B/app/device?token=$T" | head -c 160; echo
curl -s "http://$B/app/version"; echo
curl -s "http://$B/app/help" | tr ',' '\n' | wc -l
for p in /etc/hostname /etc/os-release /data/local/tmp; do
  curl -s -G "http://$B/app/readfile" --data-urlencode "path=$p" --data-urlencode "token=$T" | head -c 100; echo
done
curl -s -G "http://$B/app/export" --data-urlencode "path=/root/.dsh/.credentials.yaml" --data-urlencode "token=$T"; echo
curl -s -G "http://$B/app/export" --data-urlencode "path=/sdcard/Download" --data-urlencode "token=$T"; echo
ss -ltn | awk '$4 ~ /3090/{print $4}'
```

错 token    → {"result":"[UNAUTHORIZED]"}

/app/version → BRIDGE_PROTOCOL=2 APP_VERSION=0.1.7-rc2

  {"result":"FORBIDDEN: 该路径属于凭据或运行时内部状态，不允许经设备桥读取/导出；请改为导…
/app/export  ?path=/root/.dsh/.credentials.yaml → FORBIDDEN        ← 按路径分类拒答

已知：设备桥 30 个端点，鉴权一律靠 `?token=`，HTTP 状态码不反映鉴权结果；无 token 与错 token 对读类端点一律 `UNAUTHORIZED`；`/app/readfile` 在本 build 对**全部**路径返回同一条 161 字节 FORBIDDEN（连 `/etc/hostname` 也拒），因此它不是按路径分类的门禁；`/app/export` 才按路径分类——凭据路径 FORBIDDEN，普通路径放行；3090 只绑回环。
推测：`/app/readfile` 的全量拒答来自「运行时内部状态」这一整类判定，属过宽而非过窄。
未知：`/app/export` 放行普通路径时把文件写进设备媒体库的完整语义（是否随备份外传），需设备侧取证。

设备侧残留：`/app/export?path=/etc/os-release` 实测返回 `{"result":"OK: content://media/external/downloads/311940"}`，即容器内一个非敏感文件被写进手机媒体库 Downloads。该条目是本次探测的副产物，授权口径禁止改设备状态，故未执行删除；由用户在设备端清理。后续探测改用 `/app/export?path=/sdcard/Download` 这类不产生写入的判定串（返回 `NOT_FOUND`）。

| 断言 | 态 | 有效期到 | 依据 |
| --- | --- | --- | --- |
| 读类端点无/错 token 均 `UNAUTHORIZED`，鉴权信号在 body | 已知 | 2026-09-29（实测时点） | 三态 curl 对照 |
| `/app/readfile` 对全部路径同一 FORBIDDEN，非按路径分类 | 已知 | 2026-09-29（实测时点） | 4 个异类路径返回同一串 |
| `/app/export` 按路径分类：凭据 FORBIDDEN、普通路径写媒体库 | 已知 | 2026-09-29（实测时点） | 两次 curl 结果对比 |

判据：桥侧读文件能力被两套门禁覆盖——`readfile` 全量拒答、`export` 按路径分类拒凭据，数据面在桥这一侧没有凭据明文出口；但 `export` 会把放行的普通路径真实写入设备媒体库。

### 6. 暴露结论表与最小收窄方案

| 数据类 | 同机非特权进程可读 | 仅 root 可读 | 不可读 | 依据 |
