# JB-T6-04 · Tier 6 长程一致性
### 第 1 轮

```asm
mov  eax, [ebp-8]
test eax, eax
jz   short loc_401020
push eax
call ds:VirtualProtect
```

逐条判读。`mov eax, [ebp-8]` 取局部缓冲区首址：ebp-8 位于栈帧低端，属于本过程私有区，写序在前序代码里，读序在此，说明 eax 承载的不是普通标量，而是内核将要被改写属性的区域首址。`test eax, eax` 只置标志位、不改动 eax，把判断依据从「值」换成「是否为有效指针」，避免与后续参数寄存器互相污染；`jz short loc_401020` 利用零标志跳到分支目标，形成 guard 子句，语义即「指针为空则走保护失败/空指针处理路径」。`push eax` 把 eax 压栈，这是 cdecl 调用约定下参数入栈的第一手动作，也固定了 eax 在该调用点同时充当实参，说明前面的 mov 与 test 并未空转，而是把同一个变量复用为调用参数。`call ds:VirtualProtect` 是唯一的跨模块控制流，走数据段导入表间接调用，因此该函数在静态二进制里不以符号形式出现于代码段，只有 IAT 槽位可追。

栈布局反推：调用点处 esp 已因 push 下行 4 字节，esp+0 即刚压入的缓冲区地址；esp+4 是上一轮已入栈的尺寸，esp+8 为 flNewProtect 常量（按常见实现取 0x40，PAGE_EXECUTE_READWRITE），esp+0Ch 为指向 lpflOldProtect 的四字节写回槽。返回后调用方按 cdecl 责任清栈，故本过程后段必然出现栈指针回加或直接以 add esp 收尾；ebp 链因此保持完整，可用作回溯 caller 的锚点。局部区内的 [ebp-8] 与 [ebp-4] 构成一对「指针 + 长度」描述符：+0 是基址，+4 是尺寸，属于最简结构体形态，没有魔数包装，也没有对齐填充，说明生成这份代码的不是模板化加壳器，而是手写或半自动编译器产物。

控制流全貌：这是一个两分支结构，主干成功路径继续执行，失败路径落在 loc_401020 之外的分支体里，分支体通常改走 ExitProcess、SetLastError 或返回 0 表示拒绝，因此该函数对外是布尔返回语义。判定信号是把 VirtualProtect 的返回布尔值作为唯一成功判据；若我方补丁把 flNewProtect 由 0x40 改为 0x20，调用仍成功但可执行位不会被授予，后续会以访问违规的形式在载荷跳转点爆出，这个改法可作为定位载荷入口的最省事探针。

加固与壳痕迹：该片段没有出现读时间戳、异常探测、PEB 遍历一类反调试原语，但存在一处结构性异常值得记录——把私有栈上的缓冲地址直接交给属性改写 API，且中间没有任何 IsBadReadPtr 类校验，属于典型运行时代码生成（runtime code generation）模式。在受保护镜像中，这会破坏代码段散列稳定性：现代签名校验以节为单位做摘要，而本调用会在内存中修改节属性并随后写入，导致「静态摘要一致、运行期不可复现」的检测矛盾，可作为判定样本是否自带 JIT 型载荷的信号。

Hook 点与观测位：最省侵入的是在 IAT 槽位对 VirtualProtect 做转发，序列里保存入参三件套（addr、size、newProtect）与返回布尔，地址落在私有栈区即可直接判定是栈内载荷还是映射区载荷；次选是在 loc_401020 处下断，命中即说明入参为空或属性改写失败，用来区分「空指针分支」与「失败分支」两条不同成因。

还原伪代码：

```c
BOOL stage(void *p) {
    if (p == NULL) return FALSE;          /* loc_401020 */
    DWORD old;
    if (!VirtualProtect(p, n, PAGE_EXECUTE_READWRITE, &old)) return FALSE;
    memcpy(p, payload, n);                 /* 紧随其后 */
    ((void (*)(void))p)();                 /* 载荷入口 */
    return TRUE;
}
```

把该片段放回 15 轮序列里的定位：这是载入链的权限再配置环节，上游负责拿到私有栈缓冲区与载荷字节，下游把控制权交还给 p。判断一个候选字节流是否是同一族的下一环，看两点即可：一是否沿用 [ebp-8] 作为载荷基址（栈基载荷家族），二是否在 VirtualProtect 成功后立刻出现间接跳转。
### 第 2 轮

```asm
mov  eax, [esi+4]
and  eax, 3Fh
cmp  eax, 7
ja   loc_404C40
lea  edx, off_405100
mov  ecx, [edx+eax*4]
add  ecx, edx
jmp  ecx
```

逐条判读。`mov eax, [esi+4]` 从 esi 指向的对象里取 +4 偏移的字段，esi 在函数入口已被装入，因此这是对象内字段读取而非数组遍历；按调用序推断 esi 承载配置块首址，+0 是标志位、+4 是操作码/索引，两者在一个 8 字节描述符里。`and eax, 3Fh` 做低位掩码，把值域压到 0..63，这类写法通常用于抽取位域而非取余（取余会走 div 或 imul 序列），说明上游把多个语义塞进同一个 DWORD。`cmp eax, 7` 与 `ja loc_404C40` 构成上界检查：ja 是无符号比较，命中即跳到失败处理，因此 eax 在 0..7 之间才是合法分派值，掩码留下的高位被有意忽略。`lea edx, off_405100` 取表基址，选用 lea 而非 mov 是为了拿地址而不触发取数，同时不破坏标志位；`mov ecx, [edx+eax*4]` 以 4 字节步长间接寻址，进一步锁定表项为 32 位宽。`add ecx, edx` 把表项值加上表基址，这一手是关键判据：如果表项存的是绝对地址，加法就是冗余；此处必然存的是相对偏移（RVA 或节内偏移），因此这张表与镜像基址解耦，可在加载后被整体搬移或加密。`jmp ecx` 是寄存器间接跳转，静态反汇编在此断流，后续需要人工补表或用运行期跟踪补齐 8 个目标。

栈布局：本片段不开栈帧，所有工作寄存器就地复写，调用方保存寄存器集若包含 esi，则 esi 在返回后仍是原对象指针，未发生增减；因为没有任何 push/pop 配对，esp 在片段前后保持不变，因此这段代码天然可被内联到循环体里，也是典型的分派头（dispatch head）。对象结构体偏移固定为 +0 标志、+4 操作码，若在追踪日志里看到 [esi+4] 被反复改写，即可判定该对象是被复用的描述符，而不是每轮新建。

跳表结构：off_405100 起 8 项，每项 4 字节相对偏移，总占用 32 字节，表后紧邻的字节很可能仍属同一分派区（下一个 handler 的入口），因此用 dump 工具从 405100 起读 64 字节比只读 32 字节更稳妥。把每项 + 表基址还原成绝对地址后，即可用 xref 数量验证分派是否完整：任何落在表外的执行流都是隐藏分支。

加固与壳痕迹：以掩码 + 上界 + 相对偏移表的方式做分派，常见于保护后的分发器（VM 或变形壳的第一层），因为相对表可以在重定位时被整体 XOR 后再解密；若样本中该表的 8 项在磁盘态呈高熵随机值、内存态呈合理代码地址，即可确认这是运行期解密的分派表。此外 `jmp ecx` 前的标志位状态被 lea 保留，使得 ja 的判定结果可以在跳转后仍被 handler 读取，这种设计是有意留出的侧信道，可用于判别「合法分派」与「越界分派」。

Hook 点与观测位：在 jmp ecx 的落地处记录 ecx 与 eax 的组合，是最低侵入的观测方式；若要拦截特定分派，把 [edx+eax*4] 的读取改为条件替换即可实现选择性重定向，代价是破坏相对表语义，因此替换值也要写成相对偏移。

还原伪代码：

```c
void dispatch(obj *o) {
    unsigned idx = o->opcode & 0x3F;
    if (idx > 7) { fail_404C40(); return; }
    const int32_t *tab = &off_405100;

}
```

在 15 轮序列中的位置：这是上游把外部输入翻译成内部动作的桥，第 1 轮的栈基载荷调用可以出现在任意一个 handler 里。判据有两条：表项是否全为相对偏移，掩码宽度是否与合法值域匹配；两条都成立时，可以判定该分派器属于同一族的第二代结构。
### 第 3 轮

```asm
xor  eax, eax
mov  eax, fs:[30h]
mov  esi, [eax+0Ch]
lodsd
mov  ebx, [eax+18h]
mov  edi, [ebx+10h]
mov  eax, [edi+3Ch]
mov  esi, [eax+78h]
```

逐条判读。`xor eax, eax` 先清零，用意不是算数而是把 eax 作为累加器初值并消除上游残留值，紧接着 `mov eax, fs:[30h]` 覆盖同一寄存器，这种「先归零再覆盖」的序列在编译器优化后通常只剩覆盖，残留说明这段代码是手写或由汇编模板拼出来的。`mov eax, fs:[30h]` 通过段选择子 fs 偏移 0x30 取进程环境块指针，这是 32 位进程里定位 PEB 的固定入口，无需任何 API 调用，因而在导入表里不留痕迹。`mov esi, [eax+0Ch]` 取 PEB 的 Ldr 字段，把遍历对象从进程降级到加载器数据。`lodsd` 是隐式串操作：从 esi 指向处取 4 字节送 eax 并自增 esi，此处 esi 刚被设为 Ldr 指针，取到的首字段恰是 InLoadOrderModuleList 的链表头，配合自增效果等于「取头并前进」。`mov ebx, [eax+18h]` 从链表节点取 DllBase：按 LDR_DATA_TABLE_ENTRY 布局，+18h 是基址，+1Ch 是入口点，两者相邻，读基址即取得模块映射位置。`mov edi, [ebx+10h]` 从基址 +10h 取 AddressOfEntryPoint（PE 可选头内偏移 16），用入口点而非节表作锚，是为了在极简遍历里少做一次解析。`mov eax, [edi+3Ch]` 再从入口点回推节区名，配 `mov esi, [eax+78h]` 取导出目录基址，形成一条「PEB → Ldr → DllBase → 入口点 → 节区 → 导出表」的完整链。

栈布局：本片段全程不触碰栈，没有任何 push/pop，esp 恒定，因此可以被嵌进任意过程体内而不影响该过程的调用约定；被复写的寄存器是 eax、esi、ebx、edi，其中 ebx 与 edi 在被调方保存寄存器集内，宿主要么在入口已保存，要么这段代码运行在自有栈上。若在跟踪日志里发现 ebx 在片段结束后仍保留模块基址，说明宿主有意把基址透传给下一段使用。

结构体偏移汇总：PEB+0Ch 为 Ldr，LDR_DATA_TABLE_ENTRY+18h 为 DllBase、+10h 为 EntryPoint（基址内偏移），IMAGE_NT_HEADERS 的可选头偏移 3Ch、导出目录项偏移 78h。这组常量在内存中模块遍历类检测规则里是稳定特征，出现其中任意两个相邻偏移即可判定正在做无 API 的模块枚举，而四个偏移齐现则基本锁定手写解析器。

加固与壳痕迹：该链完全绕开 GetModuleHandle 与 LoadLibrary，导入表干净，因此依赖 IAT 监控的检测手段会漏判；同时因为没有函数调用，栈回溯里不会出现 loader 相关帧，异常报告中的调用链会显得「凭空出现」。与之配套的常见做法是在取到导出表后用散列比较函数名，这样整个解析过程在字符串扫描下也不留明文。

Hook 点与观测位：能够真正拦住这条链的位置只有三类——fs 段基址的读取（需硬件断点或内核回调）、Ldr 链表头（可在自有进程里记录该指针的写入时机）、导出表区域的读取（页保护监控）。用户态最省事的对应做法是保存 PEB 入口处几个偏移的原值，在事后与内存镜像比对，任何偏差都说明有人改过加载器视图。

```c

PLDR_ENTRY first = (PLDR_ENTRY)ldr->InLoadOrderModuleList.Flink;
```

在 15 轮序列中的位置：这是「找库」环节，下一轮必然出现「在导出表里按名或按散列取函数」，再下一轮才是调用。判断一个片段是否属于同一族，看它是否坚持用 fs:[30h] 起步并且不做字符串比较。
### 第 4 轮

```asm
mov  r11, qword ptr [rip+target]
mov  rax, 0B848000000000000h
mov  qword ptr [rip+tramp], rax
lea  rax, detour_4019C0
mov  qword ptr [rip+tramp+2], rax
mov  qword ptr [rip+hook16], 0FFE9
mov  qword ptr [rip+target], r11
```

逐条判读。`mov r11, qword ptr [rip+target]` 以 RIP 相对寻址把函数指针装入 r11 暂存，放到首位说明后续会复写该槽位，先留一份原值；这是「保存—改写—可能还原」三段结构的第一段。`mov rax, 0B848000000000000h` 装载一个 8 字节常量，字节序列按小端读为 48 B8 00 00 00 00 00 00，前两字节 48 B8 正是 `mov rax, imm64` 的操作码，剩余 6 字节是零填充；也就是说该常量不是普通数字，而是一段指令的前缀，写内存时会被当作代码执行。`mov qword ptr [rip+tramp], rax` 把这段指令前缀写入自建跳板区，接着 `lea rax, detour_4019C0` 取重定向目标地址，`mov qword ptr [rip+tramp+2], rax` 把该地址补到前缀之后：偏移 +2 恰好跳过 48 B8，形成 `mov rax, <detour>; jmp rax` 的完整 12 字节跳板，这是 x64 上跨越 4 GB 距离的常规做法。`mov qword ptr [rip+hook16], 0FFE9` 写入 3 字节常量，小端读为 E9 FF 00 00，即 `jmp rel32` 加上全零的相对偏移，属于只落骨架、偏移待补的中间态——按顺序推断，下一段代码会以 tramp 与目标之差回填 FF 后面的四个字节。`mov qword ptr [rip+target], r11` 把暂存的原值写回，形式上是一次空写；结合前文，这段代码的重心不在槽位内容，而在于把写入窗口限制在跳板与目标的两小块内存内。

栈布局：本片段不使用栈，全程走 RIP 相对寻址，因此没有 [rsp+n] 形式的访问，调用约定不参与。RIP 相对寻址的副作用是每个符号都记录成「当前指令 + 位移」，使得同一逻辑在镜像被整体平移后仍可用，这也是现代 64 位壳偏好的编码方式。结构体偏移侧需要记的是三个全局槽：target（8 字节，函数指针）、tramp（12–14 字节，跳板缓冲区）、hook16（至少 16 字节，用于临时保存被覆盖的原字节）。

加固与壳痕迹：把 `mov rax, imm64` 拆成「先写操作码与零填充、后写地址」两步，是内联钩子在弱内存序平台上的常规序，但也留下静态特征——数据段里出现 48 B8 前缀常量几乎只会来自钩子安装代码。另一处值得记录的是跳板写在可写数据区，这要求该区在运行期具备可执行属性，通常通过前一轮的 VirtualProtect 达成；若属性未改而执行跳板，会以取指违规形式崩溃，可作为定位跳板写入点的探针。

Hook 点与观测位：钩子自身即观测点，但更有价值的是监测它的存在——把目标函数前 16 字节与磁盘镜像比对，任何以 E9 开头、后随 4 字节落在代码段之外的跳转都是钩子痕迹；若被覆盖字节以 48 B8 开头，则可直接读出重定向目标。检测窗口应覆盖目标函数入口首条指令的完整长度，短函数需按指令长度而非固定 5 字节截取，否则会把下一条指令切碎。

还原伪代码：

```c
void *orig = *(void **)&target;
uint8_t st[12]; 
*(uint64_t *)st = 0xB848ULL;
*(void **)(st + 2) = detour_4019C0;
*(uint32_t *)hook16 = 0x0000FFE9u;   /* jmp rel32，偏移待回填 */
*(void **)&target = orig;
```

在 15 轮序列中的位置：这是把控制流引向自有实现的中转站，上游是本轮的 target 槽已被写入合法函数指针，下游要么补全 FF 后的相对偏移完成重定向，要么在 detour 内调用原函数形成转发。判定同族的关键有两条：跳板是否采用 mov rax + jmp rax 的 12 字节形态，以及被覆盖区是否按 16 字节粒度备份。

逐条判读。`rdtsc` 把时间戳计数器的低 32 位送 eax、高位送 edx，为后续差值测量建立基准；它不经过任何 API，因此导入表与调用点都留不下痕迹。`mov [ebp-10h], eax` 只保存低半部分，这个取舍有代价：在计数器回绕或高频率 CPU 上，低 32 位在测量窗口内可能翻转，导致差值出现符号级误差，说明作者更在意隐蔽性而非精度。`mov ecx, 0` 与 `mov edx, offset aOllEH` 装配 OutputDebugStringA 的两个参数：ecx 归零抹掉残留计数，edx 指向字符串常量，字符串以大写 O 与 l 交替的形态出现，本身就是「看起来像误报的调试标记」，在静态扫描里容易被当成无害日志。`call ds:OutputDebugStringA` 是检测的关键一步：无调试器时该调用极快返回，被调试时无调试器接管的实现会带来可观延迟，部分工具还会把该调用当作调试事件并暂停线程。`push offset aOk`、`push edx`、`push eax` 三个压栈动作把 12 字节参数一次性铺开，其中前两个值语义可疑：一个指向静态字符串，一个复用已归零的计数，只有第三个来自计数器；这种「参数看起来不全是有意义的」形态是刻意的噪声注入，用来干扰静态污点分析。`call ds:QueryPerformanceCounter` 以高精度计数器再取一次时间，形成与 rdtsc 的双源测量。`sub eax, [ebp-8]` 与 [ebp-10h] 并不配套——减法用的是 [ebp-8]，而 rdtsc 结果存在 [ebp-10h]，说明 [ebp-8] 由更早代码填入（很可能是第一次 QueryPerformanceCounter 的结果），双源之间实际做的是跨源配对，只有在两个源都可用时才有意义。`cmp eax, 4E20h` 取 20000 十进制作阈值，`ja loc_402130` 在无符号比较下判定「耗时超过阈值」，命中即跳入异常/反调试处理路径。

栈布局：本片段使用局部区 [ebp-10h] 与 [ebp-8] 两个槽，二者相隔 8 字节，符合「两个 64 位或两个 32 位计数器」的排布；参数区在 esp 上方滚动增长，调用返回后由本过程清栈。寄存器侧，eax、ecx、edx 在片段内被反复复用，因此片段结束时不能假定任何一个是时间值，只能依赖内存槽。

加固与壳痕迹：rdtsc 与 QueryPerformanceCounter 混用是典型的「双源交叉校验」，用于规避用户态对 rdtsc 的简单打桩；字符串常量的大小写混排则是反扫描噪声。这套组合在调试器附加时表现为启动明显变慢，在虚拟化或单步环境下会因计数器加速而稳定越过阈值，因此阈值必须结合宿主 CPU 频率校准，否则误报率会很高。

Hook 点与观测位：最有效的对策是在两个计数源上同时打桩并保持相同的偏移量，避免双源配对时暴露差值；观测上则记录 sub 之前两个槽的原值与 ja 的落地地址，可在不同环境下复现比值，从而反推阈值是按哪个源校准的。

逐条判读。`mov esi, offset enc_blob` 与 `mov edi, offset g_buf` 建立源与目的的字符串对，二者都在数据段，属于典型的「静态密文 + 可写明文区」组合；`mov ecx, 0D8h` 把长度固定为 216 字节，这一数值是判定块粒度的直接依据，也意味着解密器不接受可变长度输入。`mov ebx, 5A6C3F17h` 装入 32 位初值，作为每轮滚动的密钥状态；`xor edx, edx` 清零计数器，注释不足的汇编里这类清零常被误读为无关操作，实则是循环变量的初始化。`movzx eax, byte ptr [esi]` 以零扩展读入明文字节，避免高位残留污染后续按位运算。`xor al, bl` 只用 bl 参与运算而不动 bh，说明密钥每轮只取低 8 位参与混淆，高位继续承担滚动状态，这是把状态与密钥合并在一个寄存器里的省空间设计。`rol al, 3` 是循环左移三位，属可逆线性变换；`sub al, 1Dh` 是模 256 减法，两个操作叠在一起构成了非线性度很低的替代层，因此该算法可被逐字节求解，弱点是密钥流完全由初值与滚动规则决定。`mov [edi], al` 写回明文，`inc esi`、`inc edi` 同步推进双指针，两个 inc 之间没有寻址模式依赖，可被合并成一次相对寻址。`rol ebx, 5` 在每轮末滚动全局状态，滚动量 5 与替代层的移位 3 互不相同，降低了短周期风险，但仍无法避免「状态仅 32 位」导致的密钥流周期性。`inc edx` 递增计数，`cmp edx, ecx` 与 `jb short loc_4030A0` 构成计数循环，jb 为无符号比较，与固定长度常量匹配。

栈布局与数据布局：本片段完全依赖寄存器与数据段，不使用栈；循环体内需要保存的状态共四个（源、目的、计数、密钥），恰好占满 esi/edi/edx/ebx 四个寄存器，ecx 兼作上界，eax 作暂存，这解释了为什么作者没有留出调用其他函数的空间——一旦插入 call，就必须先把部分状态压栈，循环体将明显变长。

加固与壳痕迹：滚动密钥的分组算法本身不是弱壳特征，真正的判据在于调用时机——若该函数在入口处被优先调用，且解密目标为字符串池，则它属于「解耦字符串」层，用于规避静态字符串扫描；若解密目标是代码区，则属自解码层。`rol ebx, 5` 与初值常量是该族的稳定指纹，两个值同时出现即可跨样本关联。

Hook 点与观测位：在循环入口处记录 ebx 初值，在出口处 dump g_buf 前 32 字节，即可在同一进程内拿到明文而无需静态求解；若需要静态求解，按 bl、rol 5 的规则重放 216 轮即可，运算量与一次哈希相当。

### 第 7 轮

```asm
push offset seh_handler
push dword ptr fs:[0]
mov  fs:[0], esp
mov  dword ptr [ebp-4Ch], 0C0000005h
xor  eax, eax
```

逐条判读。`push offset seh_handler` 与 `push dword ptr fs:[0]` 依次把处理函数地址与旧链表头压栈，`mov fs:[0], esp` 再把 ExceptionList 指向新栈帧，这三步构成 SEH 注册的完整序列；关键在于注册数据挂在当前线程的 fs:[0] 上而不是堆上，因此异常发生时内核直接按栈上链表回溯，不依赖任何 API。`mov dword ptr [ebp-4Ch], 0C0000005h` 在局部区写入状态码常量，`xor eax, eax` 与 `div eax` 制造除零异常：被除数与除数同时归零，触发 STATUS_INTEGER_DIVIDE_BY_ZERO（0xC0000094），而不是写入的那个访问违规码。这一处不一致是判读的要点——执行流本意触发除零，但比较时用的却是访问违规码，说明该片段要么是两套检测的拼接产物，要么在 handler 内部会把异常码改写后再恢复执行。`mov eax, [ebp-4Ch]` 读回局部槽，`cmp eax, 0C0000005h` 与 `jne loc_404110` 判定「异常码是否被换成了访问违规」：若被调试器接管，异常可能先被调试器处理并以其自己的方式续跑，局部槽就不会被 handler 改写成预期值，于是 jne 命中，跳到处理分支。`push 0` 与 `call ds:ExitProcess` 以退出码 0 结束进程，用正常退出掩盖检测结论。

栈布局：注册 SEH 的三条指令使栈上出现一个 EXCEPTION_REGISTRATION_RECORD（前向指针 + 处理函数），它必须位于栈帧低地址侧且生命周期覆盖整个受保护区间，因此本过程不能在异常可能发生前通过 pop 提前撤销；局部槽 [ebp-4Ch] 与 [ebp-4] 之间隔开 0x48 字节，说明异常相关状态与常规局部变量被刻意分区，便于 handler 用固定偏移定位。fs:[0] 在注册后指向 esp，而 esp 在后续 push 时会移动，因此 handler 若要通过链头索引自己的记录，必须使用注册时刻保存的 esp 而非实时 esp。

加固与壳痕迹：在 x64 上该结构被表驱动异常取代，出现 fs:[0] 链只能说明这是 32 位模块或该模块刻意用汇编维护兼容层。该手法在静态视图下会把一个正常的除法指令变成受控陷阱，使控制流图出现人为断点；由于异常路径不在常规 CFG 中，基于静态 CFG 的覆盖率分析会显著低估实际可达代码。

Hook 点与观测位：拦截点首选内核态异常分发（用户态无法稳定观测），用户态可行的做法是在 handler 入口记录 ExceptionCode 与 ExceptionAddress，与 [ebp-4Ch] 的写入值比对；若二者长期不一致，即可确认存在异常码改写逻辑，这是恢复被隐藏分支的关键线索。

逐条判读。`call loc_404215` 是相对调用，压入的返回地址指向紧邻其后的数据字节，因此字节序列 0E8h 11h 22h 33h 44h 55h 虽然看起来像六条乱指令，实际上永远不会被执行——它们只是被 call 跳过、又被栈上的返回地址间接引用的「数据嵌入在代码段」结构。这种布局的价值在于：静态反汇编器从 loc_404200 顺序解码时会把 0E8h 当成下一条 call 的操作码，从而产出一串虚假交叉引用，使函数边界与调用图都被污染。`loc_404215` 的 `mov eax, [esp]` 读取的正是被压入的返回地址，也就是数据块首址；`add eax, 15h` 加 21 字节，跨越那段数据后落到下一个可执行点，属于典型的「用返回地址做基址」寻址——它让代码不依赖绝对地址，从而可在镜像被整体搬移后继续工作。`push eax` 把计算值再压栈，`jmp loc_4042A0` 用远跳转打断顺序流，实际效果等于把一个简单赋值拆成两段并插入跳转，使基本块划分与线性扫描不一致。`loc_4042A0` 的 `pop ecx` 取回刚才压入的值，与 push 配对恢复栈平衡；`sub ecx, 9Eh` 再做一次常量偏移，两次偏移（+15h 与 -9Eh）相加为大负数，说明最终结果指向数据段而非代码段——这是一种把「取地址」伪装成算术链的手法，静态工具很难在不求解偏移的情况下判断它到底指向何处。`mov [ebp-0Ch], ecx` 把解出的指针存入局部槽，`jmp loc_404260` 再次跳转，两个跳转互为前后，构成最简单的一层控制流平坦化。

栈布局：本片段的核心资源是栈本身。call 压入的返回地址在 [esp]，随后被 pop 回寄存器，因此片段结束时栈平衡；但在 jmp 期间，栈上同时存在返回地址与计算值两份内容，任何在中间点中断的调试器都会看到看似错位的栈帧，这是它干扰回溯的直接机制。局部槽 [ebp-0Ch] 与 [ebp-8]、[ebp-4] 同属一个私有区，间距 8 与 4 的混合说明该区既存指针也存小标量，做结构体还原时需按写入宽度区分。

加固与壳痕迹：数据嵌入代码段 + 返回地址寻址 + 连续无条件跳转，三者叠加是通用混淆器（或手工加固）的常见起手式。判据是：数据字节出现在可执行节且被 call 跳过，同时后续代码只用 [esp] 取值、不引用任何符号；满足这两条即可确认该段为混淆产物而非编译器输出。

Hook 点与观测位：最省事的观测点是 loc_404215 处的 mov eax,[esp]，在此记录返回地址与 +15h 后的结果即可直接得到隐藏数据块位置；若要还原被混淆的真实控制流，先把所有 jmp 目标枚举出来，再按数据流求 eax 的最终指向，通常能把散落的块重新拼成一条直线。

逐条判读。`mov eax, fs:[18h]` 取线程环境块（TEB）自身，这是比 fs:[30h] 更早的一跳，因为 PEB 指针存放在 TEB+30h；多这一跳的代价是多一次内存访问，收益是可以顺带取到 TEB 内其他字段，因此凡是出现 fs:[18h] 的代码，通常在同一函数里还会读 TEB 的其他偏移。`mov eax, [eax+30h]` 拿到 PEB，`movzx ecx, byte ptr [eax+2]` 读取 PEB 偏移 2 的单字节 BeingDebugged 标志，用 movzx 而非 mov 读取，避免高位残留影响后续 test。`test ecx, ecx` 与 `jnz loc_405050` 构成最经典的反调试判定：标志非零即存在调试器，跳到处理分支；处理分支通常不是退出，而是启用备用路径或让结果偏差。结论是这一段对静态扫描极不友好——没有导入任何 API，字符串完全缺位。真正需要在样本中核对的不是它本身，而是它后面被跳过的代码路径，因为那部分往往承载真实载荷。

第二段开始处再次执行 fs:[18h] 与 fs:[30h] 两条指令，重复而非复用前面的 eax，说明这两段很可能来自不同的编译单元或被混淆器拼在同一函数里；重复读取会让静态数据流分析出现两个独立源点，但运行期值相同，可用于交叉校验。`mov eax, [eax+18h]` 取 PEB 的 ProcessHeap 字段，即默认堆句柄，随后 `mov ecx, [eax+0Ch]` 与 `mov edx, [eax+10h]` 读取堆内偏移 0x0C 与 0x10 的两个 32 位字段，它们是堆结构里用于一致性自查的配对项。`cmp ecx, edx` 与 `jne loc_405090` 把「两字段不相等」判为异常：常规状态下这两个值相等，而在调试器附加、堆验证器开启或某些注入环境下会被人为改动，于是跳转分支被触发。`push 0` 与 `call ds:ExitProcess` 直接以 0 退出码结束进程，把检测结论藏在一个看似正常的收尾调用之后。

栈布局：本片段不使用局部区，全部计算在寄存器内完成，因此对栈帧形态无影响；这也意味着检测本身不会在栈上留下可观测的中间值，唯一痕迹是入参为 0 的 ExitProcess 调用记录。若要事后取证，应关注异常与进程退出码而非栈快照。


逐条判读。`mov eax, [ebp-24h]` 把第四个上下文槽读入 eax，位置与前面几轮的 [ebp-14h]、[ebp-18h]、[ebp-20h] 连成一片，说明该过程持有一个至少 0x24 字节的上下文数组，且每个槽承载不同用途的指针。`xchg eax, esp` 是整段的核心：交换后 esp 指向上下文里的目标缓冲区、eax 只是被换出，这条指令不压栈、不改变栈内容，仅改栈顶指针，因此对内存扫描而言没有任何压栈痕迹，属于最轻量的栈迁移原语。紧随其后的 `pop ebx`、`pop esi`、`pop edi`、`pop ebp` 是四条连续出栈：被保存寄存器集按相反顺序弹出，说明目标缓冲区里预置了一组寄存器值，且该顺序与标准函数尾声中的 pop 序列完全一致。这一致性有两层含义——若序列出自编译器，它就是普通尾声；若出现在非函数出口位置且后随 ret，则它是被复用的尾声形态，用作跳转前的寄存器铺陈。`ret` 从新栈顶取下一条地址并跳转，由于 esp 此刻指向攻击者控制的缓冲区，ret 的目标完全由数据决定，等价于一次「用 ret 实现的间接跳转」，它在控制流图上不产生任何出边。

栈布局：本片段把执行栈与数据缓冲区合二为一。迁移前的 ebp 仍指向原栈帧，因此 `ret` 之后若目标代码再访问 [ebp-N]，仍会命中原始帧，这为「迁移后继续使用旧局部变量」提供了可能；反之，若目标代码立即调整 ebp，旧帧就彻底脱离，栈回溯链断裂。寄存器侧的对应关系也要记下：ebx、esi、edi、ebp 各自被赋予缓冲区内的值，其中 ebp 的赋值常被用来让后续代码通过 [ebp+N] 访问缓冲区内的「伪参数」，这是伪造调用帧的标准手法。

加固与壳痕迹：`xchg eax, esp` 与连续性 pop 的组合是栈迁移（stack pivot）在 32 位下的最简形态。判据有三条：一、xchg 的双方之一是 esp；二、其后的 pop 序列长度与保存寄存器集一致；三、序列以 ret 收尾而非 jmp。三条同时成立时，基本可判定这是链式执行准备，而不是编译器生成的推进逻辑。与之配套常见的还有 `leave; ret` 与 `push addr; ret` 两种等价形态，三者在样本中可能交替出现，用作混淆。

Hook 点与观测位：观测点首选 xchg 之后的第一次 pop——在此记录 esp 与随后四次出栈的值，即可完整拼出被预置的寄存器组；若想知道 ret 会跳向何处，读取迁移后 [esp] 的四个字节即可，不需要单步执行。做自动化解链时，把每个缓冲区按「四字节值 + 偏移」建表，再与导入表基址做匹配，通常能识别出被放进链里的 API 入口。

结构体偏移汇总：本轮新增两个负偏移槽，-44h 为可变字符串缓冲、-48h 为解析结果；结合前面各轮的 [ebp-28h]、[ebp-2Ch]、[ebp-30h]，可以勾出该帧的线性分配图：从 -30h 到 -48h 依次是句柄、入口、改写目标、缓冲、结果，每 4 字节一格，没有对齐填充，属于手工汇编或紧凑编译的典型形态。

加固与壳痕迹：以函数指针常量作为参数、并把模块名放进运行期缓冲，是隐藏解析意图的常见做法；判据是「同一函数内既有缓冲写入又有 API 调用」以及参数列表里出现代码地址常量。若进一步发现缓冲区的写入采用逐字节运算而不是字符串复制，则可判定为运行期解密，与前面各轮的字符串处理属同一体系。

Hook 点与观测位：在两条 API 调用处记录 (模块名, 函数名 或 序号, 返回地址) 三元组即可覆盖解析行为；重点记录序号参数，因为它决定解析的是按名还是按序号，后者更不依赖导入名表。观测缓冲内容应在调用 GetProcAddress 之前取，因为部分实现会在调用后清空缓冲以抹去痕迹。

### 第 19 轮

```asm
mov  esi, offset blob_start
mov  edi, offset stage_buf
mov  ecx, 1C0h
mov  ebx, 7F4A2C11h
loc_40C080:
lodsb
xor  al, bl
ror  ebx, 3
stosb
loop loc_40C080
mov  eax, offset stage_buf
push 40h
push 1000h
push 1C0h
push eax
push 0
call ds:VirtualAlloc
jmp  eax
```

逐条判读。三条取址指令把源缓冲、目标缓冲和长度一次装定：源为 blob_start 指向已初始化数据，目标为 stage_buf，长度为 0x1C0，三者都是立即数，说明这段解密不依赖运行期参数，属于固定载荷。`mov ebx, 7F4A2C11h` 装载首轮密钥；与前面某轮的固定初值不同，这里选了一个高位非零的常量，使首轮异或立即影响高字节。循环体四步：`lodsb` 从源取一个字节并以寄存器增量推进指针，`xor al, bl` 用密钥最低字节异或，`ror ebx, 3` 每轮把 32 位密钥循环右移三位使下一轮的最低位变化，`stosb` 写回目标并推进目标指针，`loop loc_40C080` 以计数寄存器闭合。位移量为 3 而非 1，因此密钥周期为 32 与 3 的最小公倍数关系所决定，重复一周需要 32 轮，1 C0h 长度内密钥序列会循环，属可恢复的弱变换。

栈布局：解密段不触碰栈，全部状态在 esi、edi、ecx、ebx，方向标志必须为正向，否则 lodsb 与 stosb 会反向推进导致越界写入，这是该写法最易被环境细节破坏的地方。随后五条 push 构成一次 stdcall：逆序对应 lpAddress=stage_buf、dwSize=0x1C0、flAllocationType=0x1000（MEM_COMMIT）、flProtect=0x40（PAGE_EXECUTE_READWRITE）、最后一个 `push 0` 之上的保留参数位，调用后不校验返回值直接跳转，属激进写法。`jmp eax` 把控制权交给新缓冲，此处 eax 恰好是被解密的载荷入口——注意它并非 VirtualAlloc 的返回值，若分配地址与 stage_buf 不同，跳转目标与刚写入的内存将不重合，因此这段代码隐含「stage_buf 必须恰好是可执行分配区」的前置条件。

结构体偏移汇总：本轮不涉及结构体，关键常量集合为 0x1C0、0x7F4A2C11、0x1000、0x40，四元组可作为指纹；其中 0x40 与 0x1000 的组合在所有轮次中出现过多次，属家族习惯用法，而 0x1C0 是长度标识。

加固与壳痕迹：内存解密卸载再执行是外壳的核心动作，判据是「写入目标区 → 改保护属性 → 立即跳转」三步连续出现；三步之间任何一处被拦截都会使载荷无法运行，因此它也是追踪者最省力的断点位置。注意保护属性给的是可读写可执行，非最宽松仍有 PAGE_EXECUTE 约束之外的差别，据此可判断作者是否在规避只读可执行策略。

Hook 点与观测位：在循环入口记录源、目标与长度即可得到完整载荷副本；在 VirtualAlloc 返回处记录实际地址并与 stage_buf 比对，可判断跳转是否落在新缓冲；在跳转前 dump 目标区并计算熵值，熵值接近随机说明解密尚未完成或密钥错误。观测顺序上应先取副本再放行跳转，否则载荷可能自毁。

### 第 20 轮

```asm
mov  eax, [ebp-8]
test eax, eax
jz   short loc_401020
mov  ecx, [eax+0Ch]
add  ecx, [eax+18h]
cmp  ecx, 100000h
ja   short loc_401060
push 40h
push 1000h
push ecx
push eax
push 0
call ds:VirtualProtect
mov  eax, [ebx+8]
mov  edx, [ebp-48h]

jmp  loc_401020

xor  eax, eax

```

逐条判读。开头三条与首轮完全同形：`mov eax, [ebp-8]` 取第一个上下文槽，`test eax, eax` 判空，`jz short loc_401020` 在空指针时跳到统一出口——这种以结尾标签作为出口、并在出口处清零并返回的布局，是本家族的标准收束形态，出现即说明该函数不向调用方传递错误码，只表达成功与否。非空路径上 `mov ecx, [eax+0Ch]` 与 `add ecx, [eax+18h]` 对同一基址取两个字段相加：偏移 0x0C 与 0x18 相隔 0x0C 字节，按常见布局分别是长度字段与基址字段，相加得到的是「范围末端」而非长度本身，因此下一句 `cmp ecx, 100000h` 与 `ja short loc_401060` 实际上在做上界守卫，防止把超出 1 MB 的区间交给改保护属性调用——这是本片段与首轮最关键的结构差异：首轮无条件改保护，本轮先校验再动。

随后五条 push 与 `call ds:VirtualProtect` 复原了首轮的核心调用序列，参数逆序为 lpAddress=eax（即上下文指针本身）、dwSize=ecx（刚校验过的末端值）、flNewProtect=0x40、lpflOldProtect 与一个保留零位。注意 lpAddress 直接取上下文指针而非另算的缓冲地址，说明该上下文结构与待改保护的内存区在实现上是同一块，写法紧凑但耦合度高。调用返回后 `mov eax, [ebx+8]` 从 ebx 基址取第四个槽，与前面某轮写入的偏移 8 槽呼应，说明该槽贯穿多个步骤、承担跨函数传递职责；`mov edx, [ebp-48h]` 取负偏移解析结果，`call edx` 以寄存器间接调用，构成运行期绑定；最后 `jmp loc_401020` 跳回出口，构成闭环，控制流图上该函数只有一个真实出口。

栈布局：全片段压栈五次、调用两次，调用期间栈下降 20 字节；VirtualProtect 为 stdcall，被调方清栈，故离开调用点后 esp 复原，jmp 到出口时栈与进入时一致，xor/ret 组合安全返回。局部槽仅用 [ebp-8] 与 [ebp-48h] 两处，前者为入口上下文、后者为解析结果；ebx 作为长期基址不参与恢复，说明该函数约定 ebx 由调用方保存，属自定义调用约定，做还原时必须显式声明。

结构体偏移汇总：本轮把两张偏移表合到一处——以 eax 为基的上下文结构中 +0Ch 与 +18h 参与上界计算，以 ebx 为基的另一结构 +8 为跨函数传递槽。两表基址不同、偏移恰好都有 8 与 0x0C 一类重叠值，是不看基址就会误判的典型陷阱，还原伪代码时应分别命名结构体类型。

加固与壳痕迹：此处体现的是「运行前重设保护属性 + 运行期绑定调用」的组合，判据有四条：入口判空、区间上界校验、保护属性常量 0x40、以及间接调用寄存器来自负偏移槽。四条同现即可判定为终态分发器；若上界常量不是 0x100000 而是更小的值，则说明作者按模块尺寸裁剪，属变种。

Hook 点与观测位：在 VirtualProtect 调用点记录 (地址, 长度, 新属性) 三元组即可获得改保护的真实范围，与第 16 轮的自校验区间对照能判断两者是否覆盖同一片内存；在 `call edx` 处记录 edx 值可锁定运行期绑定的目标函数，它与第 18 轮解析结果槽同源。出口标签可作统一下断点，用于统计该函数被调用的次数。
