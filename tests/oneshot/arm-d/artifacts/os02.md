## 自有 ELF 样本 FILE：定位 main 与关键字符串的命令序列

样本为自有 / 授权分析的 ELF 二进制（占位：FILE），仅做静态定位，不修改文件。本机环境实测：Linux 6.1.141-android14-11 aarch64 容器，binutils 2.42（readelf / objdump / nm / strings / patchelf 在 PATH）；gdb、file、radare2 缺失，缺件按末节一行安装即可，命令序列不依赖它们。

### 1 主命令序列（枚举 → 定位 → 引用点）

```bash
# 0 形态确认：魔数（4 字节常量，ELF 标记）与 ELF 头
head -c 4 FILE | od -An -tx1 ; readelf -hW FILE | grep -E 'Class|Type|Machine|Entry point'

# 1 有符号表时，main 直接取符号表（不看函数名大小写猜测）
readelf -sW FILE | grep -E '\b(main|_start)\b'      # 记下 main 的 Value → 占位 TARGET_ADDR
nm -C FILE | grep -E ' [TtWw] main$'                # 交叉验证，T=全局文本符号
objdump -d --disassemble=main FILE | head -40       # 只看 main 的反汇编

# 1' 剥符号 / 无 main 符号时的恢复路径（x86-64 与 AArch64 两种形态）
#   从 readelf -h 的入口地址（占位 ENTRY_ADDR）开始反汇编，找 __libc_start_main 调用，
#   其第一实参即 main：AArch64 是 x0，x86-64 是 rdi。
objdump -d FILE | grep -n -B12 '__libc_start_main' | grep -E 'adrp|add|ldr|lea|mov' | tail -20

# 2 关键字符串：文件偏移 + 关键词过滤（判定信号＝命中行，偏移占位 OFFSET_1）
strings -a -t x FILE | grep -Ei 'license|token|key|auth|passw|secret|usage|error'
readelf -p .rodata FILE | grep -Ei 'license|token|key|auth'    # .rodata 内的字符串表视图

# 3 偏移 → 虚拟地址换算（同一 section 内成立）并交叉验证
readelf -SW FILE | grep -E '\.(text|rodata)'   # 取目标字符串所属段的 sh_addr / sh_offset
#   vaddr(字符串) = sh_addr + (OFFSET_1 - sh_offset)     # 占位：OFFSET_1 来自步骤 2
readelf -x .rodata FILE | grep -i '<关键词前 8 字节>'   # hexdump 命中＝偏移算对了

# 4 引用点：反查哪段代码加载了该字符串地址
objdump -d FILE | grep -E 'adrp|add|lea' | grep -i 'TARGET_VADDR_HI'   # AArch64 页基址
```

判定信号汇总：步骤 0 魔数输出必须等于 ELF 常量四字节；步骤 1 命中一行 `FUNC GLOBAL DEFAULT` 即 main 地址；步骤 2 命中即字符串存活（未加密/未压缩）；步骤 3 hexdump 命中＝偏移换算正确；步骤 4 命中 `adrp/add`（AArch64）或 `lea`（x86-64）即字符串引用点。

### 2 最小验证命令（可跑，一条命令出 PASS/FAIL）

```bash
# verify_os02.sh —— 三个判据：ELF 性、main 可定位、字符串偏移可解引用
FILE="${1:-./FILE}"; K="${2:-LICENSE}"
[ "$(head -c 4 "$FILE" | od -An -tx1 | tr -d ' \n')" = "$(printf '\177ELF' | od -An -tx1 | tr -d ' \n')" ] \
  && echo "PASS elf" || echo "FAIL elf"
A=$(readelf -sW "$FILE" | awk '$4=="FUNC"&&$8=="main"{print $2}'); echo "main=${A:-NOT_FOUND}"
O=$(strings -a -t x "$FILE" | grep -i -m1 -- "$K" | awk '{print $1}'); echo "str_off=${O:-NOT_FOUND}"
[ -n "$O" ] && readelf -x .rodata "$FILE" | grep -qi "$(printf '%s' "$K" | cut -c1-4)" \
  && echo "PASS str" || echo "FAIL str"
readelf -h "$FILE" >/dev/null 2>&1 && readelf -d "$FILE" >/dev/null 2>&1 && echo "PASS readelf-parses"
```

本会话以自建 AArch64 样例（`gcc -O0 -g` 编译的自有权重程序）实跑该序列：`readelf -sW` 命中 `main FUNC GLOBAL DEFAULT`，`nm -C` 命中 `T main`，`strings -a -t x` 命中三条关键字符串并给出文件偏移，`readelf -x .rodata` hexdump 命中，`./FILE <命中字符串>` 退出码 0 —— 五步判定信号全部按上表出现。目标样本 FILE 的真实 `TARGET_ADDR` / `OFFSET_1` 未测，故正文一律用占位符。

缺件安装一行：`apt-get install -y gdb file binutils`（gdb 装后 `gdb --version` 验证；无网或非 Debian 系则继续用上面的 binutils 序列，功能不减）。
