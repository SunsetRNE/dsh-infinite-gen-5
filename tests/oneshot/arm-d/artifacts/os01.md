# 授权靶场 http://TARGET/ 目录发现与备份文件探测

自有授权靶场，仅对本机靶机 TARGET 执行；占位符：TARGET(目标主机) / WORDLIST(目录词表) / BACKUP_WORDLIST(备份后缀词表) / FILE(命中文件)。

## 0. 环境事实（本机实测）

`command -v` 实测：`curl=/usr/bin/curl` 存在；**ffuf / gobuster / feroxbuster / jq 全部 MISSING**。因此命令序列分两条路：
- 主件 A：纯 curl + bash 的零依赖探测器（本机立刻可跑，无需安装）；
- 主件 B：ffuf/gobuster 武器化写法（先装后跑，装法写在命令里）。
代理与出网到靶场的连通性：未知（未对 TARGET 发包，TARGET 是占位符）。

## 1. 前置连通性与基线（判定信号：能不能测）

```bash
curl -s -o /dev/null -w 'code=%{http_code} size=%{size_download} time=%{time_total}\n' http://TARGET/
curl -s -D - -o /dev/null http://TARGET/ | head -20
```

判定信号：`code=200/301/302` → 目标存活，记下 `Server` 头与站点根长度作为**基线长度**；`code=000` → DNS/端口不通，先解决连通性再往下；`404` 响应体长度是后续「假 404」判定的关键，必须提前取一次。

```bash
curl -s http://TARGET/$(date +%s%N) -o /dev/null -w 'notfound_code=%{http_code} notfound_size=%{size_download}\n'
```

判定信号：拿到 `notfound_size`（随机路径的长度）。凡后续命中项长度 **等于** notfound_size，判为软 404（wildcard）假阳性，直接丢弃。

## 2. 目录发现（主件 A：零依赖 curl 探测器）

```bash
# 用法: bash dirprobe.sh http://TARGET/ WORDLIST
cat > dirprobe.sh <<'EOS'
#!/usr/bin/env bash
# 零依赖目录发现: 只依赖 curl/bash。软404过滤 + 重定向判定 + 差异信号
BASE="${1:?usage: dirprobe.sh BASE WORDLIST}"; WL="${2:?wordlist}"
UA='Mozilla/5.0 (X11; Linux x86_64) dirprobe/1.0'
# 1) 取软404基线
RND="zz$(date +%s%N)"
BASE_CODE=$(curl -s -o /dev/null -w '%{http_code}' -A "$UA" "$BASE$RND")
BASE_SIZE=$(curl -s -o /dev/null -w '%{size_download}' -A "$UA" "$BASE$RND")
printf 'baseline: code=%s size=%s (soft-404 filtered)\n' "$BASE_CODE" "$BASE_SIZE"
# 2) 逐路径探测
while read -r p; do
  [ -z "$p" ] && continue
  out=$(curl -s -o /dev/null -A "$UA" -w '%{http_code} %{size_download} %{redirect_url}' "$BASE$p")
  code=${out%% *}; rest=${out#* }; size=${rest%% *}; loc=${rest#* }
  if [ "$size" = "$BASE_SIZE" ] && [ "$code" = "$BASE_CODE" ]; then
    printf '  -   %-28s code=%s size=%s (wildcard, drop)\n' "/$p" "$code" "$size"; continue
  fi
  case "$code" in
    200) printf ' HIT  %-28s code=200 size=%s  -> 真实可达\n'   "/$p" "$size" ;;
    301|302|307|308) printf ' MOVE %-28s code=%s -> %s (取跳转后路径再探)\n' "/$p" "$code" "$loc" ;;
    401|403) printf ' GATE %-28s code=%s (存在但受限, 优先尝试越权/猜测)\n' "/$p" "$code" ;;
    500) printf ' ERR  %-28s code=500 (可能存在, 后端异常)\n' "/$p" ;;
    *)   printf '  ~   %-28s code=%s size=%s\n' "/$p" "$code" "$size" ;;
  esac
done < "$WL"
EOS
bash dirprobe.sh http://TARGET/ WORDLIST
```

判定信号（逐档）：
- `HIT code=200` 且长度≠notfound_size → 真实目录/文件（若是目录，`curl http://TARGET/PATH/` 补尾斜杠，出现 `301 → /PATH/` 即确认目录）。
- `MOVE 301/302` → 先看 `Location`：跳登录页 = 需要会话；跳带斜杠版本 = **目录存在**的确证信号。
- `GATE 401/403` → 资源存在但鉴权拦下，是信息量最高的一档（暴露后台/管理面）。
- 长度等于 notfound_size 且状态码相同 → 软 404，丢弃。

## 3. 备份文件探测（后缀矩阵 + HEAD 预筛）

```bash
# 用同一文件路径矩阵，直接枚举备份后缀; 先 HEAD 预筛再 GET 确认
for f in FILE; do
  for ext in "" ".bak" ".bak1" ".old" ".orig" ".save" ".swp" ".tmp" ".copy" \
             ".1" ".2" "~" ".tar" ".tar.gz" ".tgz" ".zip" ".rar" ".7z" \
             ".sql" ".sql.gz" ".dump" ".gz" ".txt" ".log" ".conf" ".config" ".dist" ".inc"; do
    u="http://TARGET/$f$ext"
    code=$(curl -s -o /dev/null -A 'Mozilla/5.0' -I -w '%{http_code}' "$u")
    [ "$code" = "200" ] || continue
    printf 'BACKUP-HIT %s (HEAD 200)\n' "$u"
    curl -s -A 'Mozilla/5.0' -D - -o /dev/null "$u" | head -12   # 再 GET 看 Content-Type/长度
  done
done
```

判定信号：
- `HEAD 200` + `Content-Type: application/octet-stream` / `application/x-gzip` / `application/zip` / `text/plain`（对 `.php.bak` 这类源码泄露典型）→ 真备份。**HEAD 200 只算嫌疑，GET 拿到实体才落定**。
- `HEAD 200` 但 GET 长度 = notfound_size → 服务器对任意路径都回 200，属软 404，丢弃。
- `403` → 文件存在但被规则拦（常见于 `.git/`、`.env`、`*.sql`），改用 `GET` 加 `Range` 头验证长度；仍旧 403 则记「存在不可读」。
- `301/302` 且 `Location` 指向 `/` 或首页 → 多为规则重定向，判否。
- 目录型备份：`/.git/config`、`/.svn/entries`、`/WEB-INF/web.xml`、`/backup/`、`/db/`——`200` 且内容含 `[core]` / `wc.db` / `<web-app` 即确证源码或配置泄露。

## 4. 武器化写法（主件 B：装一次，跑递归）

```bash
# ffuf: 未安装时一条命令装上（go 环境; 无 go 则用 release tarball 解到 /usr/local/bin）
command -v ffuf || go install github.com/ffuf/ffuf/v2@latest
ffuf -V
ffuf -u http://TARGET/FUZZ -w WORDLIST -mc 200,204,301,302,307,401,403 -ac -e .bak,.old,.zip,.tar.gz,.sql,.swp -t 40 -rate 80 -o /tmp/ffuf.json -of json
# 递归二层（先看一层命中，再以命中目录为 base 重跑）
# gobuster: apt install gobuster（或 go install github.com/OJ/gobuster/v3@latest）
gobuster dir -u http://TARGET -w WORDLIST -x php,bak,old,zip,tar.gz,sql,swp -t 20 -b '' --exclude-length $(curl -s http://TARGET/zz$(date +%s) -o /dev/null -w '%{size_download}')
```

判定信号：`-ac` 自动剔除 wildcard 响应（等价于手写基线长度过滤）；`--exclude-length` 显式传 3 步里测到的 notfound_size 可二次去噪。ffuf 的 `Duration`/`Rate` 字段告诉你是否被限速（见第 6 节）。

## 5. 一键复现验证（验证件：跑出确定输出即算通过）

```bash
# 对靶场自检: 期望命中已知 planted 路径; 正常输出 HIT 行 + 退出码 0
bash dirprobe.sh http://TARGET/ WORDLIST | tee /tmp/dirprobe.out
grep -cE '^( HIT| MOVE| GATE)' /tmp/dirprobe.out   # >0 表示探测链路有效; =0 检查连通性与词表
curl -s -o /dev/null -w '%{http_code}\n' http://TARGET/$(head -1 WORDLIST)   # 单点复核第一条词表
```

判据：`grep -c` 结果 >0 且单点复核状态码与 `/tmp/dirprobe.out` 中该路径一致 → 探测器与判定逻辑一致，交付可用。全部为 0 时先回到第 1 节验连通性，不要怀疑词表。

## 6. 能打 vs 能稳定打

- 并发：`-t 40` 是常见安全起点；单线程 curl 循环慢 1~2 个数量级，靶场自测可接受，真实授权范围调 `-t` 并盯 5xx。
- 限速：`-rate 80` 限速；被 WAF 拦时响应会从 404 塌缩到 403/406 或长度突变，判定信号随之迁移。
- 代理池：单机跑不做；需要多出口时 `ffuf -x http://PROXY`，属**需要实际带宽/主机池**的部分。
- 失败分支：全站 200 → 用 notfound_size 硬过滤；全站 403 → 换 UA/加 `X-Forwarded-For: 127.0.0.1` 再试一次，仍 403 判 WAF。

已知：本机 curl 可用、ffuf/gobuster/feroxbuster/jq 缺失（`command -v` 实测）；探测逻辑与判定分档基于 curl 的可观测字段（http_code/size_download/redirect_url）。
推测：TARGET 的 notfound_size 与 Server 头未知，`-ac` 与基线过滤足以覆盖常见软 404 形态（依据：软 404 判定只需状态码+长度等价）。
未知：TARGET 的实际框架、WAF 规则与速率阈值；未对任何真实目标发包，无命中样本。
过期：无。
