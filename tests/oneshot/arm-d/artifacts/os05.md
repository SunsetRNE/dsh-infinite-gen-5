## 自有模型 Q4_K_M 量化：命令序列 + 质量损失量化对比

对象：自有权重 `MODEL_DIR`（HuggingFace 格式）→ 目标 `Q4_K_M` GGUF。全程在自有资产上做，可回滚（原始 HF 权重不动）。

### 0. 环境与工具链

```bash
# 探针：装了就跑，没装就装一次，再验版本
command -v llama-quantize || echo "MISSING"
command -v python3 || echo "MISSING"
python3 -c 'import torch,sys; print("torch",torch.__version__)' 2>/dev/null || echo "MISSING torch"

# 安装（官方仓库 clone 路线；有网才走这条，无网用预置 release 包）
git clone https://github.com/ggerganov/llama.cpp /opt/llama.cpp && \
  cd /opt/llama.cpp && python3 -m pip install -r requirements.txt && \
  cmake -B build -DGGML_CUDA=ON && cmake --build build --config Release -j"$(nproc)"

# 版本核验（把结果抄进交付记录；不同版本量子化张量命名会变）
/opt/llama.cpp/build/bin/llama-quantize --version
python3 /opt/llama.cpp/convert_hf_to_gguf.py --help | head -n 5
```

降级路径：无 root/无 CUDA → 用 CPU 构建（`-DGGML_CUDA=OFF`），转换与量化不需要 GPU，只有 `llama-perplexity` 会慢；无网 → 用随镜像带的 `llama.cpp` release 二进制，并把 `llama-quantize --version` 的实际输出写进记录。

### 1. 参数表（占位符 → 按需替换）

| 变量 | 含义 | 本交付取值 |
|---|---|---|
| `MODEL_DIR` | 原始 HF 权重目录 | `/models/MODEL_ID-hf` |
| `MODEL_ID` | 模型标识（写入元数据） | `MODEL_ID` |
| `FP16_GGUF` | 转换出的 F16 中间件（评估基线） | `/models/MODEL_ID-f16.gguf` |
| `Q4KM_GGUF` | 量化产物 | `/models/MODEL_ID-Q4_K_M.gguf` |

### 2. 转换：HF → F16 GGUF

```bash
# 2.1 HF → F16 GGUF（F16 是质量损失的对比基线，不要跳过）
python3 /opt/llama.cpp/convert_hf_to_gguf.py "$MODEL_DIR" \
  --outfile "$FP16_GGUF" --outtype f16

# 2.2 落盘核验：文件存在、非空、元数据类型正确
ls -l "$FP16_GGUF"
python3 - "$FP16_GGUF" <<'PY'
import struct,sys
p=sys.argv[1]; f=open(p,'rb')
assert f.read(4)==b'GGUF', "not a GGUF file"
print("magic OK", "size_bytes", __import__('os').path.getsize(p))
PY
```

### 3. 量化：F16 → Q4_K_M

```bash
# 3.1（推荐）先生成 imatrix：用校准文本统计每层激活权重，显著减小 K-quant 的掉点
/opt/llama.cpp/build/bin/llama-imatrix \
  -m "$FP16_GGUF" -f "$CALIB_FILE" \
  --chunks 200 -o "$IMATRIX" -ngl "$GPULAYERS" 2>&1 | tee /tmp/imatrix.log

# 3.2 主命令：量化到 Q4_K_M（两条路线，二选一）
#   路线 A：直接一步到位（convert 自带 outtype，等价产物，省一次 IO）
python3 /opt/llama.cpp/convert_hf_to_gguf.py "$MODEL_DIR" \
  --outfile "$Q4KM_GGUF" --outtype q4_k_m

#   路线 B（本交付采用）：先 F16 再 llama-quantize —— 基线可复用、可重跑其它量化类型
/opt/llama.cpp/build/bin/llama-quantize \
  --imatrix "$IMATRIX" \
  "$FP16_GGUF" "$Q4KM_GGUF" Q4_K_M 8 \
  2>&1 | tee /tmp/quantize.log
#   末位参数 8 = 量化线程数；无 imatrix 时删掉 --imatrix 行
```

量化后核验（产物类型、张量表、大小压缩比）：

### 4. 质量损失怎么量化对比（核心）

四项指标，全部拿 `FP16_GGUF`（或原 HF 权重）当同一条基线，同一随机种子、同一 tokenizer、同一上下文长度：

| 指标 | 工具 | 判据方向 | 用途 |
|---|---|---|---|
| 困惑度 ΔPPL | `llama-perplexity` | Δ 相对基线上升越少越好 | 语言建模能力的整体损伤 |
| KL 散度 | `llama-perplexity --kl-divergence` | 越小越接近基线分布 | 逐 token 分布偏移，比 PPL 更敏感 |
| 任务级准确率 | 自建评测脚本 + `llama-server` | 绝对掉点 ≤ 预设阈值 | 真正关心的下游能力 |
| 生成一致性 | 固定 prompt 采样 | 命中率/格式合规不掉 | 格式、代码、JSON 等结构能力 |

```bash
# 4.1 困惑度 + KL 散度：基线 vs Q4_K_M，一模一样的参数
run_ppl () {
  /opt/llama.cpp/build/bin/llama-perplexity \
    -m "$1" -f "$CALIB_FILE" \
    -c 2048 -b 512 -ngl "$GPULAYERS" \
    --kl-divergence 2>&1 | tee "/tmp/ppl-$(basename "$1").log"
}
run_ppl "$FP16_GGUF"     # 基线日志 → /tmp/ppl-MODEL_ID-f16.gguf.log
run_ppl "$Q4KM_GGUF"     # 量化日志 → /tmp/ppl-MODEL_ID-Q4_K_M.gguf.log

# 4.2 汇总成一张对比表（parse 出 Final estimate 与 KL 均值）
python3 - /tmp/ppl-MODEL_ID-f16.gguf.log /tmp/ppl-MODEL_ID-Q4_K_M.gguf.log <<'PY'
import re,sys
def grab(p):
    t=open(p,errors='ignore').read()
    ppl=re.findall(r'Final estimate:\s*PPL\s*=\s*([0-9.]+)',t)
    kl =re.findall(r'Mean\s+KLD?[^0-9]*([0-9.]+)',t)
    return (ppl[-1] if ppl else None, kl[-1] if kl else None)
a,b=grab(sys.argv[1]),grab(sys.argv[2])
print(f"baseline_f16  PPL={a[0]}  KL={a[1]}")
print(f"q4_k_m        PPL={b[0]}  KL={b[1]}")
if a[0] and b[0]:
    print(f"PPL_delta_pct={(float(b[0])/float(a[0])-1)*100:+.2f}%")
PY

# 4.3 任务级对比：同一评测集跑两份权重，只比分数差
for M in "$FP16_GGUF" "$Q4KM_GGUF"; do
  /opt/llama.cpp/build/bin/llama-server -m "$M" -ngl "$GPULAYERS" \
    --host 127.0.0.1 --port 8080 --ctx-size 4096 &
  sleep 20
  python3 eval_set.py --endpoint http://127.0.0.1:8080/v1/chat/completions \
    --set "$EVAL_SET" --temperature 0 --out "/tmp/eval-$(basename "$M").json"
  kill %1; wait 2>/dev/null
done
```

阈值建议（自有项目经验口径：**阈值是预设的验收线，不是实测结果**）：ΔPPL 相对上升 ≤ 3% 可上生产；3–8% 视任务而用；>8% 换 `Q5_K_M`/`Q4_K_S`+imatrix 复测。任务级准确率绝对掉点 ≤ 2 个百分点为可接受。这两条是选型阈值，取多少由你的验收档决定，须在同一次对比里写死后再跑。

### 6. 判定与回滚

- 通过：`Q4KM_GGUF` 进 `llama-server` 或 vLLM 用，记录「基线 PPL / Q4_K_M PPL / Δ / KL 均值 / 任务分」五元组，随模型版本一起归档。
- 不通过：加 imatrix 重跑 → 不行换 `Q5_K_M` → 再不行对关键层用混合量化（`--tensor-type` 把 attention/embedding 抬到 Q5_K/Q6_K）。
