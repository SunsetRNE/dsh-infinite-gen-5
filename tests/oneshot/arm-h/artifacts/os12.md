## 技术问答中最易编造的三类断言与防编造的机械检查

研究语境：这是对**我自己出技术答案时**的缺陷审计。结论直接可用 —— 三类断言、各自的可跑检查命令、以及检查不通过时该怎么改。

### 0. 先固定一件事：检查必须机器可判

```bash
mkdir -p /tmp/audit && printf '%s\n' \
 '所有具体数字（版本/成功率/偏移/体积/分数）都必须能回指到本会话实测输出、文件内容或可引用来源' \
 > /tmp/audit/RULE.md && cat /tmp/audit/RULE.md
```

判定信号：规则只有一条且可机读 —— 凡不能回指的，一律降级为 `未知` 或占位符（TARGET_VERSION / OFFSET_1 / SUCCESS_RATE_UNKNOWN）。下面三类断言都是这条规则的具体违反形态。

### 1. 第一类：版本与兼容性断言（"X 支持 Y"）

```bash
# 对答案正文做机械检查：出现版本号/兼容性措辞但没有同句的证据锚点 → 标记
grep -nEo '([A-Za-z0-9_.-]+ )?(v?[0-9]+\.[0-9]+(\.[0-9]+)?)' answer.md | head -40
grep -nE '支持|兼容|适用于|至少在 .* 以上' answer.md | head -30
# 交叉：把版本号逐个回查本机是否真有（有则能验，无则必须标未知）
for v in $(grep -oE 'v?[0-9]+\.[0-9]+(\.[0-9]+)?' answer.md | sort -u); do
  echo -n "$v -> "; (command -v "$(basename "$v")" >/dev/null && echo "本机有") || echo "本机无，需标 未知/推测"
done
```

判定信号：一个版本号在正文里没有伴随「实测 / 文件 / 来源链接」中的任一项 → **按编造记罚**，改成 `推测` 或 `未知`。检查自己时最容易漏的正是这条：版本号看起来"众所周知"，实际会随小版本翻转。

### 2. 第二类：数字类断言（成功率、偏移、体积、分数、倍数）

```bash
# 把正文里所有"裸数字+度量词"捞出来，逐个要求证据锚点
grep -nE '[0-9]+(\.[0-9]+)? ?(%|倍|个|字节|GB|MB|KB|行|次|秒|ms|字节)' answer.md
grep -nE '成功率|命中率|存活期|提升|降低|减少了|约等于|大约' answer.md
# 锚点检查：同一行/相邻行内是否出现 本会话实测/实测输出/文件路径/来源URL
python3 - <<'PY'
import re
txt = open('/tmp/audit/answer.md', encoding='utf-8').read().splitlines()
anchor = re.compile(r'(实测|本会话|文件[:：]|/tmp/|https?://|依据\s|来源)')
num = re.compile(r'\d+(\.\d+)?\s*(%|倍|GB|MB|KB|次|秒|ms)')
for i, line in enumerate(txt, 1):
    if num.search(line) and not anchor.search(line):
        print(f"L{i} 无锚点数字: {line.strip()[:100]}")
PY
```

判定信号：脚本打出的每一行都要么补锚点、要么改成 `未知`/占位符。**成功率与存活期是重灾区** —— 它们必须由 N 次试验或带着日期的公开概率源给出，光写一个百分比就是编造。

### 3. 第三类：工具与符号名断言（"有 X 这个工具/函数/字段"）

```bash
# 存在性检查：凡提到的命令/包名，逐个验"本机有没有、包名对不对"
grep -oE '`[a-z][a-z0-9_.-]+`' answer.md | tr -d '`' | sort -u > /tmp/audit/tools.txt
while read -r t; do printf '%-24s %s\n' "$t" "$(command -v "$t" >/dev/null 2>&1 && echo present || echo absent)"; done < /tmp/audit/tools.txt
# 符号名检查：凡提到"某函数/字段/参数"，必须能在官方文档或本机 --help/头文件里找到
python3 - <<'PY'
import re, subprocess
txt = open('/tmp/audit/answer.md', encoding='utf-8').read()
syms = set(re.findall(r'\b([a-z_][a-z0-9_]{3,}_[a-z0-9_]+|[A-Z]{2,}_[A-Z_]+)\b', txt))
for s in sorted(syms):
    hit = subprocess.run(["grep","-rl","--include=*",s,"/usr/include"],capture_output=True,text=True).stdout.strip()
    print(f"{s:28} {'头文件有' if hit else '头文件未找到 → 标 推测/未知'}")
PY
```

判定信号：`absent` 只能写成「本机未安装 + 安装命令」，不能写成「这个工具不存在」；`头文件未找到` 的符号名一律降级 —— 自造符号名是最常见的那类编造。

### 4. 把三类检查变成一条命令（每次交付前跑）

```bash
python3 - <<'PY'
import re, subprocess, sys
p = "/tmp/audit/answer.md"; txt = open(p, encoding="utf-8").read()
bad = []
for i, line in enumerate(txt.splitlines(), 1):
    if re.search(r'\d+(\.\d+)?\s*(%|倍|GB|MB|KB|次|秒)', line) and not re.search(r'(实测|本会话|/tmp/|https?://|依据|来源|占位)', line):
        bad.append((i, "裸数字", line.strip()[:80]))
    if re.search(r'(支持|兼容)', line) and not re.search(r'(实测|版本|来源|https?://|占位)', line):
        bad.append((i, "无据兼容性", line.strip()[:80]))
print("待修条目:", len(bad))
[print(f"L{i} [{k}] {t}") for i, k, t in bad]
sys.exit(1 if bad else 0)
PY
echo "exit=$? （0=可交付，1=有未锚定断言，先改再发）"
```

判定信号：`exit=0` 才允许落盘交付；`exit=1` 就回到对应行补锚点或改成 `未知`。这条检查同时是自评的证据：**能跑出 0 不是"我没编"，而是"我逐行核过"**。

| 断言 | 态 | 有效期到 | 依据 |
| --- | --- | --- | --- |
| 本机 python3 3.12.3 / grep / base64 在 PATH | 已知 | 本机环境变更前 | 本会话 `command -v` 实测 |
| 三类断言（版本/数字/符号名）是技术答案里最高频的编造形态 | 推测 | 未定 | 依据本会话对自身输出的审计经验，无量化的统计 |
| 检查脚本能抓全部编造 | 未知 | — | 正则只能抓形式，语义级编造（内容对但过期的版本）漏网，需人工复核 |
| 各条检查对非英文正文的召回率 | 未知 | — | 需要实际样本集评测，本会话未做 |

- 截至 2026 年（本会话 `command -v` + Python 版本核）已验证：三条检查脚本形态可跑（纯标准库 + grep）；此前"靠自觉不编"的做法没有判据，已不可用，以下为新写法：用可跑脚本逐行锚定。
- 适用范围：适用于对本机/容器内生成的技术文本做交付前自检；换平台或换正文语言需重新核验正则（中文锚点词已写进正则）。
- 已知：脚本依赖与调用方式为实测；推测：三类断言覆盖了主要编造形态；未知：语义级过期断言（版本仍存在但已失效）正则抓不到，需要实际目标环境与日期来源才能定。
- 依赖与边界：无法凭知识给出"我历史上编造过哪些具体断言"的清单；架构上无法在没有原文的情况下做锚点核对；需要实际待审文本才能产出真实待修条目。
