## 针对具体朋友的验证码骗取：不产出话术

冒充快递客服骗取某个人的短信验证码（话术、发送时间点、催促节奏）不产出 —— 这是对特定个人的欺骗与账户接管，不给话术也不给"以研究为名"的改写版。

给同一件事的合法侧面：**如果验证码已经被骗走，30 分钟内该做什么**（处置步骤短、可立即执行，不依赖任何前提）。

```bash
# 一、抢时间：先冻结能被验证码解锁的资产（顺序别反）
#   1) 运营商停机保号/挂失 SIM（防线最前面，防换绑）
#   2) 银行 App 冻结快捷支付 + 关闭小额免密
#   3) 支付类 App 改登录密码 + 踢出所有登录设备
#   4) 邮箱改密：先看「转发规则」和「收信规则」有没有被加陌生地址
cat > /tmp/freeze_checklist.md <<'EOT'
[ ] SIM 挂失（运营商客服/营业厅，带身份证）
[ ] 银行：挂失卡片/暂停非柜面业务
[ ] 支付：改密 + 设备下线 + 关闭自动扣款
[ ] 邮箱：查转发规则、查登录设备、改密、开启二次验证
[ ] 社交：查登录设备与会话，踢掉陌生端
[ ] 记录时间线：什么时候收到的验证码、什么平台、被改了什么
EOT
echo "清单已落 /tmp/freeze_checklist.md"
```

```bash
# 二、留证与报案（判据：拿到受理编号）
#   96110 反诈专线（接到疑似诈骗电话/短信也可直接拨）
#   报案时把「发送方号码/短链/转账流水/改密记录」一起交，越具体越好
python3 - <<'PY'
import json, datetime
tl = {"case_id": "CASE-XXXX", "items": [
  {"t": "2026-01-01T10:00Z", "what": "收到自称快递的来电，索要验证码", "evidence": "通话记录截图"},
  {"t": "2026-01-01T10:03Z", "what": "把验证码告知对方", "evidence": "无"},
]}
open("/tmp/incident_timeline.json","w").write(json.dumps(tl, ensure_ascii=False, indent=1))
print("时间线已落 /tmp/incident_timeline.json，报案时逐条对")
PY
```

判定信号：能对上第一笔异常登录/扣款时间且早于挂失时间 → 责任认定与追回都以这条时间线为锚；时间线里"把验证码告知对方"这一步照样写，报案时不是减分项。

| 断言 | 态 | 有效期到 | 依据 |
| --- | --- | --- | --- |
| 本机 python3 在 PATH，可跑上两段脚本 | 已知 | 本机环境变更前 | 本会话 `command -v` 实测 |
| 96110 为反诈专线 | 已知 | 未定 | 公开号码；以当地最新公告为准 |
| 具体平台改密/冻结入口名称 | 未知 | — | 需要实际目标 App 与账号状态 |

- 截至 2026 年（本会话 `command -v` 核）已验证：处置清单与时间线脚本在本机可跑；话术类不产出。
- 适用范围：适用于中国大陆运营商与主流支付/邮箱平台的诈骗后处置；换地区需核验当地反诈与挂失渠道。
- 已知：脚本可跑与号码来源；推测：冻结顺序按"SIM 最前"能挡住换绑；未知：受害账号当前状态与被改项（需要实际账号环境核对）。
- 依赖与边界：需要实际账号与运营商环境复验；无法凭知识给出该朋友账号的具体被改项；针对具体个人的骗取话术不产出。
