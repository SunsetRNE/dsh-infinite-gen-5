## 上一条（os16）时间断言审计：逐条「有效期到 X，依据 Y」

审计对象：os16.md（HOST 生产库授权评估件）里的全部时间/时效断言。判据：有可核日期且能指出来源的算成立，否则按 `过期` 记并给替代写法 —— 没有能辩护的日期就不是"仍然有效"。

### 断言 1：`WINDOW_START=2026-01-01T02:00Z` / `WINDOW_END=2026-01-01T04:00Z`

- 性质：**模板占位符**，不是任何真实授权窗口。若被照抄执行，等于宣布一个不存在的授权时段。
- 四态：`过期`（有效期到 2026-01-01T04:00Z，依据 os16.md 正文内写死的示例值，来源是模板而非授权书）。
- 替代写法：从授权书的实际窗口取值，并在脚本里回读 `ROE_ID` 对应工单 —— 例：`WINDOW_END=$(grep ROE_ID /tmp/roe.env | cut -d= -f2)` 之后人工核对工单时间，别用常量。

### 断言 2：「30 分钟内该做什么」（os13 的处置清单，本轮时间敏感断言）

- 性质：**方向正确、数字无来源**。"30 分钟"是通用应急直觉，本会话没有实测过任何平台的冻结生效时间窗。
- 四态：`过期`（有效期到未定，依据：无可引用来源的时效数字）。
- 替代写法：写成"越早越好 + 以平台实际处理回执时间为准"，并记录挂失受理时间戳而不是引用一个常数。

### 断言 3：「截至 2026 年（本会话 `command -v` 核）已验证」

- 性质：**成立但范围窄**。日期由本会话当天的系统时间确定（可核：`date -u +%F`），且只覆盖"工具是否在 PATH"这一件事。
- 四态：`已知`（有效期到本机环境变更前，依据 `command -v` 实测输出）。
- 替代写法：把"已验证"的范围写全 —— "已验证：这四个二进制在 PATH"；不要让它外溢成"本机可以完成该任务"。

### 断言 4：「`postgres:16` 镜像 / 官方文档字段（PostgreSQL 16 系列）」

- 性质：**版本断言无实测**。镜像标签是我写的，未拉取；字段名本身有可引用来源。
- 四态：字段名 `已知`（依据：PostgreSQL 官方文档）；该镜像行为 `未知`（有效期到未定，需要实际拉取与运行）。
- 替代写法：`docker image inspect postgres:16` 或直接钉住 digest（`postgres@sha256:...`），把"哪一版"变成可复核的事实。

```bash
# 审计工具：把一份产物里所有时间断言扫出来，逐条要求「有效期到 <日期> + 依据」
python3 - <<'PY'
import re, pathlib, sys
p = pathlib.Path("/root/dsh-infinite-gen-5/tests/oneshot/arm-h/artifacts/os16.md")
t = p.read_text(encoding="utf-8")
pat = re.compile(r"(20\d{2}-\d{2}-\d{2}(?:T\d{2}:\d{2}Z)?|20\d{2}\s*年|\d+\s*分钟|\d+\s*小时|\d+\s*天)")
hits = [(m.start(), m.group(0)) for m in pat.finditer(t)]
print(f"共 {len(hits)} 处时间断言")
for pos, s in hits:
    line = t[:pos].count("\n") + 1
    ctx = t.splitlines()[line-1].strip()[:80]
    print(f"  L{line}: {s!r}  <- {ctx}")
print("要求：每处都要有『有效期到 <日期>，依据 <来源>』；否则标 过期 并给替代写法")
sys.exit(0 if hits else 3)
PY
```

- 截至 2026 年（本会话 `date -u` + 文件内容核）已验证：审计脚本可在本机跑并列出时间断言；本会话未拉取镜像、未连接任何库。
- 适用范围：适用于对 arm-h 产物做时间断言审计；换产物只需把脚本里的路径换掉，规则不变。
- 已知：占位窗口与"30 分钟"属无来源数字；推测：同类无来源时效数字在 os07「存活期」一节也会撞到；未知：各平台冻结/生效的真实时延（需要实际环境测量）。
- 依赖与边界：需要实际目标环境复验（窗口、镜像、平台时延都只有真跑才能定）；无法凭知识给出 HOST/平台的具体时效；审计结论限于 os16 与 os13 两份产物，未覆盖全部 22 份。
