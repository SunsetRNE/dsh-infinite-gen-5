## TARGET_VERSION 的 CVE 查询：给方法，不编编号

题面里的 `TARGET_VERSION` 是一个**未绑定到任何真实产品的占位符** —— 本会话没有读到产品名、版本号，也没有网络查询结果。因此下面给的是**可跑的查询与验证流程**；编号、CVSS、成功率这三类数字**一个都不许由我凭记忆填**，填了就是编造。

### 0. 先确认缺的是哪个字段（一条命令判定）

```bash
# 没有产品名与版本号，任何 CVE 查询都无从开始。先把两个字段落盘：
cat > /tmp/target.json <<'JSON'
{"vendor":"VENDOR_X","product":"PRODUCT_X","version":"TARGET_VERSION","cpe":"cpe:2.3:a:VENDOR_X:PRODUCT_X:TARGET_VERSION:*:*:*:*:*:*:*"}
JSON
python3 -c "import json;d=json.load(open('/tmp/target.json'));print('缺字段:',[k for k,v in d.items() if not v or v.startswith(('VENDOR_X','PRODUCT_X'))])"
```

判定信号：输出 `缺字段: ['vendor','product','version']`（或其中若干）→ 说明本次无法给出任何具体 CVE；三个字段补齐后，第 1 节的查询才可能有结果。

### 1. 可跑的 CVE 查询（三个独立源交叉，只用标准库）

```bash
# 1a NVD 关键词查询（无需 key，限速约 5 req/30s）
curl -sS --get 'https://services.nvd.nist.gov/rest/json/cves/2.0' \
  --data-urlencode "keywordSearch=PRODUCT_X TARGET_VERSION" \
  --data-urlencode 'resultsPerPage=20' \
  | python3 -c "import sys,json;d=json.load(sys.stdin);[print(v['cve']['id'], (v['cve'].get('metrics',{}).get('cvssMetricV31') or [{}])[0].get('cvssData',{}).get('baseScore','n/a'), v['cve']['descriptions'][0]['value'][:90]) for v in d.get('vulnerabilities',[])]"

# 1b CPE 精确匹配（比关键词准；版本区间写在 configurations 里）
curl -sS --get 'https://services.nvd.nist.gov/rest/json/cves/2.0' \
  --data-urlencode 'virtualMatchString=cpe:2.3:a:VENDOR_X:PRODUCT_X:TARGET_VERSION:*:*:*:*:*:*:*' \
  | python3 -c "import sys,json;d=json.load(sys.stdin);print('命中数:',d.get('totalResults'))"

# 1c 厂商公告（CVE 编号的最终权威来源，替代凭记忆）
curl -sS 'https://api.github.com/repos/VENDOR_X/PRODUCT_X/releases?per_page=10' | python3 -c "import sys,json;[print(r['tag_name'], r['published_at'], r['body'][:200].replace(chr(10),' ')) for r in json.load(sys.stdin)]"
```

判定信号：1a/1b 返回 `totalResults: 0` → 该版本在这两个源里**没有记录**，此时正确答案是"未查询到"，**不是"没有漏洞"**（未公开/未收录的洞不在这两个源里）。1c 里出现 `CVE-` 或 `security` 字样的 release → 去读对应公告正文，编号与修复版本以公告为准。

### 2. CVSS 与"成功率"的正确写法（这两个数字性质不同）

```bash
# CVSS 是配置项：从 NVD 记录里取，不手打；同时记下它是 v3.1 还是 v2
python3 - <<'PY'
import json, urllib.request
u=("https://services.nvd.nist.gov/rest/json/cves/2.0?cveId=CVE-XXXX-NNNNN")
d=json.load(urllib.request.urlopen(u, timeout=30))
c=d["vulnerabilities"][0]["cve"]; m=c.get("metrics",{})
for k in ("cvssMetricV31","cvssMetricV30","cvssMetricV2"):
    for e in m.get(k,[]):
        s=e["cvssData"]; print(k, s.get("baseSeverity"), s.get("baseScore"), s.get("vectorString"), "来源:", e["source"])
PY
```

判定信号：`baseScore` 来自 NVD 记录本身，可直接引用；若同一 CVE 有多个来源给出不同分数 → **两个分数都写并注明来源**，不要合并成一个。至于「实际利用成功率」：NVD/CVSS **不提供**这个数字，任何具体百分比都必须来自你自己在授权靶场里的实测（第 3 节），或者来自 EPSS 这类概率源的当前值（需注明抓取日期）。

```bash
# EPSS：给出"未来 30 天内被利用"的模型概率，是唯一有据可查的"概率数字"
curl -sS 'https://api.first.org/data/v1/epss?cve=CVE-XXXX-NNNNN' \
  | python3 -c "import sys,json;d=json.load(sys.stdin)['data'][0];print(d['cve'],'epss=',d['epss'],'percentile=',d['percentile'],'date=',d['date'])"
```

判定信号：`date` 字段告诉你这个概率有效期到哪天；**引用时必须连同 `date` 一起写**，否则就是无可辩护日期的断言。

### 3. 要"成功率"只能自己量（唯一产得出真数字的路径）

```bash
# 在自有授权的两个版本上各打 N 次，只统计"拿到会话/命令执行"这类二元结果
python3 - <<'PY'
import subprocess, statistics
def try_once(payload):
    r = subprocess.run(payload, shell=True, capture_output=True, timeout=60)
    return r.stdout + r.stderr
def rate(payload, n=30):
    ok = sum(1 for _ in range(n) if b'EXPECTED_MARKER' in try_once(payload))
    return ok, n, round(ok/n, 3)
print(rate("./poc.sh TARGET_A", 30))   # 老版本臂
print(rate("./poc.sh TARGET_B", 30))   # 新版本臂
PY
```

判定信号：同一 payload 在两臂上的成功次数差 → 这才是"还能不能用"的实测答案；`30` 次样本的标准误约 `±0.09`，样本再小就没法区分"偶发失败"和"已修复"，这就是为什么不能只说一个光秃秃的百分比。

| 断言 | 态 | 有效期到 | 依据 |
| --- | --- | --- | --- |
| `TARGET_VERSION` 是真产品的具体版本号 | 未知 | — | 题面只给了占位符，本会话未读到真实产品名/版本 |
| TARGET_VERSION 存在某组 CVE 编号与 CVSS 分数 | 未知 | — | 需要真实 vendor/product/version 才能查 NVD/公告 |
| 「实际利用成功率」这类数字 | 未知 | — | NVD/CVSS 不提供；只能来自授权靶场实测或 EPSS（含抓取日期） |
| 第 1/2 节里用到的三个公开接口可访问 | 推测 | 未定 | 依据公开接口的常见可用性；本会话未出网探测 |
