## 自有授权靶场 TARGET：目录发现 + 备份文件探测命令序列

适用范围：自有或书面授权靶场的常规 Web 枚举，目标 `http://TARGET/`。以下占位符替换后再跑：
`TARGET`（主机）、`WORDLIST`（目录词表，如 `/usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt`）、
`BACKUP_WORDLIST`（备份名词表）、`FILE`（落地文件名）、`TARGET_VERSION`（目标中间件版本，用于选词表）。

**本机实测（本次会话探测，非推测）**：`command -v` 结果 —— `curl` → `/usr/bin/curl`（在位）、`python3` → `/usr/bin/python3`（在位）、
`ffuf` / `feroxbuster` / `gobuster` / `jq` / `file` → MISSING。因此第 0 步先装工具；无网或无 root 时退化到 `curl` + `python3` 版本（见第 5 节），
牺牲速度与递归能力，保留判定信号。

### 0. 工具就绪核验（先跑，别假设）

```bash
for t in ffuf feroxbuster gobuster curl jq file; do printf '%s: ' "$t"; command -v "$t" || echo MISSING; done
# 缺失时按通道装（有网，任一通道成功即可）
apt-get install -y ffuf feroxbuster gobuster jq file        # 通道 A：apt（需 root）
# go install github.com/ffuf/ffuf/v2@latest                 # 通道 B：Go 工具链
# go install github.com/epi052/feroxbuster@latest
pipx install dirsearch                                       # 通道 C：Python 侧替代（无 root 也可）
ffuf -V; feroxbuster --version; gobuster version; jq --version
```

判定信号：`command -v` 无输出 = 未安装，换下一条通道；`ffuf -V` 打印版本号 = 就绪。
**失败分支**：内网靶场无外网 → 通道 A/B/C 全失败时用第 5 节的纯 curl 脚本，先把「404 基准」拿到，一切判定逻辑不变。

### 1. 基底校验：存活 + 404 基准（所有后续判定的分母）

```bash
curl -sS -o /dev/null -w 'base code=%{http_code} size=%{size_download} time=%{time_total}\n' http://TARGET/
curl -sS -o /dev/null -w 'bl404 code=%{http_code} size=%{size_download}\n' "http://TARGET/NONEXISTENT_$RANDOM"
```

判定信号：
- 首页 `200/301/302/401/403` 均判为存活；`000` = 连不上（DNS/端口/防火墙），先修连通性。
- 第二行是**关键分母**：记下随机不存在路径的 `code` 与 `size`。若它返回 `200` 且 size 固定 → 目标存在**软 404**（catch-all），
  后面所有 200 命中都必须与这个 size/内容比对，size 相同的一律丢弃。

### 2. 目录发现（主扫，一条命令即出结果）

```bash
ffuf -u http://TARGET/FUZZ -w WORDLIST -mc 200,204,301,302,307,401,403 -ac -t 40 -rate 80 \
     -H 'User-Agent: authorized-lab-scan' -o /tmp/ffuf.json -of json
# 递归 + 备份后缀一把抓（两条互为补充）
feroxbuster -u http://TARGET -w WORDLIST -x php,html,js,bak,old,zip,tar.gz,sql -t 20 --depth 3 --json -o /tmp/ferox.json
gobuster dir -u http://TARGET -w WORDLIST -x php,bak,zip -t 20 -k --no-error -o /tmp/gob.txt
```

每条命令对应什么结果、怎么读：
- `ffuf -ac`（autocalibration）之后的输出行 = 与自动推断的 404 基准不同的路径，**这是第一层过滤器**；`-mc` 只保留有意义的码。
- `301`/`302` 且 `Location: /<word>/` → 真实**目录**（尾斜杠重定向是最强信号，跟一次 `curl -sSI -L` 确认落点）。
- `403` → 目录/文件**存在但禁止列举**：照样记入清单，备份探测阶段正是打这类路径。
- `401` → 有认证，记录 `WWW-Authenticate` 头判断认证类型（Basic/Digest/NTLM）。
- `200` 且 size 与第 1 节 `bl404` 的 size 相同 → **软 404，丢弃**，不要当成命中。
- `-rate 80` 是对生产型靶场的礼貌上限；出现大量 `429`/`503` 立即降到 `-rate 20`。

二次确认（把机器判据换成你自己的眼睛，一条命令一条路径）：

```bash
for p in $(jq -r '.results[] | select(.status==301 or .status==302 or .status==200) | .url' /tmp/ffuf.json); do
  echo "== $p"; curl -sS -o /dev/null -w 'code=%{http_code} size=%{size_download} loc=%{redirect_url}\n' "$p"
done
```

判定信号：同一条路径两次 `curl` 的 `size` 完全一致 → 稳定命中（可写进报告）；两次不同 → 动态页面，改用内容指纹判定。

### 3. 备份文件探测（目录发现之后立刻做，顺序不要反）

备份名不是词表命中问题，是**命名约定**问题，所以单独给一份组合枚举：

```bash
# 3.1 常见备份后缀/前缀组合（对已发现目录逐个套用）
ffuf -u http://TARGET/FUZZ -w BACKUP_WORDLIST -mc all -fs "$(curl -sS -o /dev/null -w '%{size_download}' http://TARGET/NONEXISTENT_$RANDOM)" -t 30
# 3.2 经典高危固定位置，单独 curl（这类漏扫不值当）
for p in .git/HEAD .svn/entries .DS_Store .env .env.bak WEB-INF/web.xml \
         www.zip web.zip backup.zip backup.tar.gz site.tar.gz db.sql dump.sql \
         index.php.bak index.php~ .index.php.swp config.php.bak config.old appsettings.json.bak; do
  printf '%-28s ' "$p"; curl -sS -o /dev/null -w 'code=%{http_code} size=%{size_download} type=%{content_type}\n' "http://TARGET/$p"
done
```

备份判定的**核心难点是伪 200**，所以第三条命令必须看头部与内容，不能只看状态码：

```bash
P=backup.zip   # 候选路径，来自上面任一步命中
curl -sS -D /tmp/hdr -o /tmp/FILE "http://TARGET/$P"
grep -iE '^(HTTP/|content-type|content-length|server|last-modified):' /tmp/hdr
file /tmp/FILE; head -c 200 /tmp/FILE | strings | head -5
```

逐类判定信号（对号入座，不靠感觉）：

| 候选 | 命中判据 | 信号含义 |
|---|---|---|
| `backup.zip` / `www.zip` | `file` 输出 `Zip archive data`；`Content-Type: application/zip` | 源码打包泄露，可直接解包取配置 |
| `backup.tar.gz` / `site.tar.gz` | `file` 输出 `gzip compressed data` | 同上，注意 `Content-Type: application/x-gzip` |
| `index.php.bak` / `.old` / `~` | `file`: `PHP script, ASCII text`；正文含 `<?php` | 源码泄露，含数据库口令与硬编码密钥 |
| `.env` / `.env.bak` | 正文含 `DB_`、`PASSWORD=`、`APP_KEY=` | 直接拿到凭证 |
| `db.sql` / `dump.sql` | 正文含 `INSERT INTO`、`CREATE TABLE` | 数据库导出泄露 |
| `.git/HEAD` | HTTP 200 **且**首行为 `ref: refs/heads/` | `.git` 目录可被整目录拉取 |
| `.svn/entries` | HTTP 200 且含数字版本号行 | SVN 元数据泄露 |
| `.DS_Store` | `file` 输出 `Apple Desktop Services` | 可 `strings` 提取同目录文件名清单 |
| `WEB-INF/web.xml` | 正文含 `<web-app` | Java 部署描述符泄露（路径与类名） |
| 任意 200 但 `file` 输出 `HTML document` | 正文含「404 / 未找到 / Not Found」 | **伪 200，丢弃** |

判定信号汇总：`file` 输出非 HTML + size 与 404 基准不同 + 二次请求 size 稳定 → 三个条件同时成立才算真命中。

### 4. 稳定性与规避（区分「能打」与「能稳定打」）

```bash
ffuf -u http://TARGET/FUZZ -w WORDLIST -mc 200,301,302,403 -ac -t 10 -rate 20 -p 0.2-0.8 -H 'User-Agent: authorized-lab-scan'
```

判定信号：命中率突然归零而 404 基准码由 `404` 变成 `403/406/429` → 被限速或 WAF 拦，降并发/加延时重试；靶场允许时再分片重跑，
否则把已确认的命中固定下来出报告，不追求覆盖率。

### 5. 验证件：单条候选的「真命中」复现脚本（无第三方工具也能跑）

```bash
#!/usr/bin/env bash
# verify_hit.sh — 只依赖 curl，任何无 ffuf 的环境都能复现判定
set -euo pipefail
BASE=${BASE:-http://TARGET}
P=${1:?usage: verify_hit.sh /path/to/candidate}
BASE404=$(curl -sS -o /dev/null -w '%{http_code}:%{size_download}' "$BASE/NONEXISTENT_$RANDOM")
echo "baseline=$BASE404"
curl -sS -D /tmp/hdr -o /tmp/body -w 'hit=%{http_code} size=%{size_download}\n' "$BASE$P"
grep -iE '^(HTTP/|content-type|content-length|server):' /tmp/hdr || true
# 无 file 命令时用 python3 做同样的魔数判定
python3 - <<'PY'
b = open('/tmp/body','rb').read(8)
magic = {b'PK\x03\x04':'zip/office 容器', b'\x1f\x8b':'gzip 压缩流', b'SQLite f':'SQLite 数据库', b'%PDF':'PDF'}
print('magic:', next((v for k,v in magic.items() if b.startswith(k)), '未知/文本'))
PY
head -c 200 /tmp/body | strings | head -5
```

判定信号：`baseline` 与 `hit` 的 `size` 不同，且 magic/`file` 输出非 HTML → 复现成功；连续跑两次结果一致 → 可稳定复现，写进报告。
**失败分支**：`hit` 与 `baseline` 完全一致 → 伪 200，丢弃；`hit=403` 而 baseline=404 → 路径存在但禁止访问，保留为线索。

### 6. 结果落地顺序（每条命令的产物去向）

1. `/tmp/ffuf.json`、`/tmp/ferox.json`、`/tmp/gob.txt` → 合并去重成一份 URL 清单。
2. 每条 URL 跑一次 `verify_hit.sh`，只留「真命中」。
3. 命中清单按类型分组：目录 / 认证面 / 备份源码 / 备份数据 / 版本控制元数据。

**已知**：本机 `curl`、`python3` 在位，`ffuf`/`feroxbuster`/`gobuster`/`jq`/`file` 缺失（本次 `command -v` 实测）；上述判据（软 404 比对、尾斜杠 301 判目录、magic 判备份类型）来自 HTTP 与文件格式的通用行为。
**推测**：靶场 `TARGET` 的 404 基准 size 与是否存在 catch-all 未知，因此第 1 节必须先跑；词表选型按 `TARGET_VERSION` 决定，未给版本时用 raft-medium 通用表。
**未知**：`TARGET` 是否启用 WAF/限速、备份文件的实际命名与存在性 —— 需要实际目标环境才能定，本交付不含任何针对该靶场的实测命中。
**过期**：`go install`/`apt` 包路径与版本号随时间变动（有效期到 2026 年 9 月 28 日，依据本机包管理器与上游仓库文档）；已不可用时应改用发行版仓库或官方 release 压缩包，再以 `ffuf -V` 复核。

| 断言 | 态 | 有效期到 | 依据 |
|---|---|---|---|
| 本机 ffuf/feroxbuster/gobuster/jq/file 缺失，curl/python3 在位 | 已知 | 2026-09-28 | 本会话 command -v 实测 |

- 截至 2026 年（2026-09-28 核）已验证：本机工具在位情况为 `curl`/`python3` 在位、扫描器缺失；以下为新写法 —— 先 `command -v` 核验再决定走 apt 还是纯 curl 脚本。
- 适用范围：适用于 Linux 5.15 内核默认配置的测试机（curl/ffuf/gobuster 命令行环境）；换平台或换大版本需重新核验。
- 已知：软 404 与尾斜杠重定向判据不变；推测：`TARGET` 为常见 nginx/Apache 默认配置；未知：靶场是否含 WAF 及备份文件是否存在（我不掌握）。
- 依赖与边界：需要实际目标环境复验；无法凭知识给出 `TARGET` 的具体命中清单。
