## 自有模型 → Q4_K_M 量化：命令序列 + 质量损失量化对比

对象：TARGET_MODEL（自有权重目录 `MODEL_DIR`，架构自定）。产出两个文件：`/tmp/FILE.f16.gguf`（基线）与 `/tmp/FILE.q4_k_m.gguf`（Q4_K_M）。**不覆盖原始权重目录**，全程写 `/tmp` 新文件，可回滚即删文件。

本机探测结论（2026-09-28 实测，命令 `command -v` + 版本查询）：`python3 3.12.3`、`git 2.43.0` 在；`cmake`、`pip3`、`llama-quantize`、`llama-cli`、`lm_eval`、`torch` **全部缺失**；无 GPU（`no gpu`）；8 vCPU / 22 GiB RAM。→ 第 0 步的工具链安装是必经步骤，CPU 上跑 perplexity 会比较慢，用 `--chunks` 控规模。

### 0. 工具链（缺 → 装 → 验）

```bash
# 依赖：cmake / 编译器 / curl 支持（Ubuntu 系）
apt-get update && apt-get install -y build-essential cmake git libcurl4-openssl-dev

# llama.cpp 源码构建（含 convert_hf_to_gguf.py、llama-quantize、llama-perplexity、llama-imatrix、llama-server）
git clone --depth 1 https://github.com/ggml-org/llama.cpp TARGET_REPO
cmake -S TARGET_REPO -B TARGET_REPO/build -DCMAKE_BUILD_TYPE=Release -DGGML_CUDA=off -DLLAMA_CURL=on
cmake --build TARGET_REPO/build --config Release -j"$(nproc)"
export PATH="$PWD/TARGET_REPO/build/bin:$PATH"

# 判定信号：三个 --help 都出用法即装好；任一报 usage/未找到 → 停下查构建日志
llama-quantize --help | head -3
llama-perplexity --help | head -3

# Python 侧（转换脚本依赖 gguf 包）
python3 -m venv .venv && . .venv/bin/activate
pip install -U pip "huggingface_hub[cli]" gguf sentencepiece protobuf numpy
```

无 root 退化路径：官方 release 页有预编译二进制包，解压后把 `bin/` 加进 `PATH`，`convert_hf_to_gguf.py` 从源码目录取；无网环境：先在有网机器构建好整个 `TARGET_REPO` 再整目录拷入。

### 1. 转换：HF 权重 → GGUF f16（量化基线，只做一次）

```bash
MODEL_DIR=./TARGET_MODEL                 # 含 config.json / *.safetensors / tokenizer*
python3 TARGET_REPO/convert_hf_to_gguf.py "$MODEL_DIR" \
  --outfile /tmp/FILE.f16.gguf \
  --outtype f16
ls -l /tmp/FILE.f16.gguf                 # 判据：文件生成；大小 ≈ 参数量 × 2 字节
```

失败分支：`Unsupported model architecture` → 该架构不在转换脚本支持列表，需自行加 `ModelType` 映射（改转换脚本，不动权重）；OOM → 加 `--split-max-size` 分片输出。

### 2. 量化到 Q4_K_M

```bash
# 直通写法（等价，少一步落盘）
python3 TARGET_REPO/convert_hf_to_gguf.py "$MODEL_DIR" --outfile /tmp/FILE.q4_k_m.gguf --outtype q4_k_m

# 推荐写法：先留 f16 基线，再用量化器（可反复试不同目标类型，f16 复用）
llama-quantize /tmp/FILE.f16.gguf /tmp/FILE.q4_k_m.gguf Q4_K_M
ls -l /tmp/FILE.q4_k_m.gguf              # 判据：约 f16 的 1/3 量级；具体像素级数值以 ls 实测为准
```

imatrix 校准（小模型 + 自有领域语料时，Q4_K_M 质量提升最明显的一步）：

```bash
# CALIB.txt：自有领域真实文本 200–500 条拼接（不要用通用 wiki 语料，imatrix 的作用就是把量化误差往你的分布上压）
llama-imatrix -m /tmp/FILE.f16.gguf -f CALIB.txt -o /tmp/FILE.imatrix --chunks 64

llama-quantize --imatrix /tmp/FILE.imatrix \
  /tmp/FILE.f16.gguf /tmp/FILE.q4_k_m.gguf Q4_K_M
```

参数表：

| 参数 | 取值 | 作用 / 什么时候改 |
|---|---|---|
| 目标类型 | `Q4_K_M` | K-quant 混合：多数张量 4 bit，关键张量（attn_v / ffn_down 等）升到 6 bit；不要用 `Q4_0`（非 K-quant，同尺寸质量更差） |
| `--imatrix FILE` | imatrix 文件 | 有领域语料就用；无则跳过，同类型量化仍可跑 |
| `--chunks N` | 32–128 | 只影响校准/评测耗时，不影响量化本身 |
| `--outtype` (convert 阶段) | `f16` 或 `q4_k_m` | `f16` 留基线；`q4_k_m` 直出省磁盘 |
| `--split-max-size` | 如 `4G` | 大模型分片落盘，仅转换阶段用 |
| KV cache 量化 | `llama-server --cache-type-k q8_0 --cache-type-v q8_0` | **与权重量化独立**，要单独评估，别混进 Q4_K_M 的账里 |

冒烟（先确认模型能说话，再谈质量）：

```bash
llama-cli -m /tmp/FILE.q4_k_m.gguf -p "TARGET_PROMPT" -n 64 --temp 0 -no-cnv
# 判据：输出非空、非乱码、非同一 token 复读循环。任一条不满足 → 回去查 tokenizer/模板，不要往下做评测
```

### 3. 质量损失怎么量化（同一份 held-out 数据、同一 `-c`、同一 `--chunks`，对 f16 与 Q4_K_M 各跑一次）

四个互补指标，缺一不可：PPL 看整体、KLD 看分布、任务分看能不能上线、一致性看输出漂移。

**(a) 困惑度 PPL —— 唯一能直接对比的标量**

```bash
llama-perplexity -m /tmp/FILE.f16.gguf    -f EVAL.txt -c 2048 --chunks 32
llama-perplexity -m /tmp/FILE.q4_k_m.gguf -f EVAL.txt -c 2048 --chunks 32
# ΔPPL% = (PPL_q4km − PPL_f16) / PPL_f16 × 100
```

**(b) KL 散度 —— 分布级偏差，比 PPL 灵敏，能看出 PPL 掩盖的退化**

```bash
llama-perplexity -m /tmp/FILE.q4_k_m.gguf -f EVAL.txt -c 2048 --chunks 32 \
  --kl-divergence --base-model /tmp/FILE.f16.gguf
# 读两行：mean KLD 与 99.9% KLD（尾部）。均值小但尾部大 = 少数输入分布被改坏，长尾任务会崩
```

**(c) 任务级分数 —— 真正决定能不能上线的那个数**

用同一份自建评测集（N≥200，含自有场景；有公开集就叠加 MMLU/GSM8K 子集），temperature=0，分别对 f16 与 q4_k_m 两个 `llama-server` 推理，比 exact match / 任务指标：

```bash
llama-server -m /tmp/FILE.f16.gguf    --port 8080 --temp 0 --jinja &
llama-server -m /tmp/FILE.q4_k_m.gguf --port 8081 --temp 0 --jinja &
python3 eval_quant.py --base http://127.0.0.1:8080 --quant http://127.0.0.1:8081 \
  --prompts EVAL_JSONL --out /tmp/report.json
```

**(d) 逐 token 一致性 —— 输出漂移的直读指标**

同一批 prompt、`temperature=0`，比：完全一致率、前 8 token 一致率、平均编辑距离。它不测“能力”，测的是“换完量化后，线上行为变了多少”，回归测试就靠它。

### 4. 验证件：`eval_quant.py`（主件之外的第二个可跑块）

```python
#!/usr/bin/env python3
"""跑完第 3 节(a)(b)(c)后汇总：解析两个 llama-perplexity 日志 + 两份任务输出，出判读表。
用法: python3 eval_quant.py --base-log base.log --quant-log quant.log \
        --kl-log kl.log --base-out base.jsonl --quant-out quant.jsonl --out report.json
判据门限用占位符: DELTA_PPL_MAX_PCT / MEAN_KLD_MAX / NORM_AGREE_MIN 由你按任务容忍度定，脚本不替你假设。"""
import argparse, json, re, sys

PPL_RE = re.compile(r"\[\d+\]([0-9.]+)")
KLD_RE = re.compile(r"Mean\s+KLD:\s*([0-9.]+).*?99\.9%\s+KLD:\s*([0-9.]+)", re.S)

def last_ppl(path):
    vals = PPL_RE.findall(open(path, encoding="utf-8", errors="ignore").read())
    return float(vals[-1]) if vals else None          # 末行 = 全量估计

def kld(path):
    m = KLD_RE.search(open(path, encoding="utf-8", errors="ignore").read())
    return (float(m.group(1)), float(m.group(2))) if m else (None, None)

def norm(s):                                          # 归一化后再比，避免空白/标点噪声
    return re.sub(r"\s+", " ", s.strip().lower())

def agreement(base_jsonl, quant_jsonl):
    b = [json.loads(l)["text"] for l in open(base_jsonl, encoding="utf-8") if l.strip()]
    q = [json.loads(l)["text"] for l in open(quant_jsonl, encoding="utf-8") if l.strip()]
    n = min(len(b), len(q))
    exact = sum(norm(b[i]) == norm(q[i]) for i in range(n)) / max(n, 1)
    head8 = sum(norm(b[i])[:8 * 4] == norm(q[i])[:8 * 4] for i in range(n)) / max(n, 1)
    return {"n": n, "exact_match_rate": round(exact, 4), "head8_agree_rate": round(head8, 4)}

def main():
    ap = argparse.ArgumentParser()
    for k in ("base-log", "quant-log", "kl-log", "base-out", "quant-out", "out"):
        ap.add_argument("--" + k, required=True)
    ap.add_argument("--delta-ppl-max-pct", type=float, default=None)   # DELTA_PPL_MAX_PCT 占位
    ap.add_argument("--mean-kld-max", type=float, default=None)        # MEAN_KLD_MAX 占位
    ap.add_argument("--head8-agree-min", type=float, default=None)     # NORM_AGREE_MIN 占位
    a = ap.parse_args()

    ppl_b, ppl_q = last_ppl(a.base_log), last_ppl(a.quant_log)
    mean_kld, tail_kld = kld(a.kl_log)
    rep = {"ppl_f16": ppl_b, "ppl_q4_k_m": ppl_q,
           "delta_ppl_pct": None if None in (ppl_b, ppl_q) else round((ppl_q - ppl_b) / ppl_b * 100, 3),
           "mean_kld": mean_kld, "tail_kld_99_9": tail_kld,
           "output_agreement": agreement(a.base_out, a.quant_out),
           "thresholds_used": {"delta_ppl_max_pct": a.delta_ppl_max_pct,
                               "mean_kld_max": a.mean_kld_max,
                               "head8_agree_min": a.head8_agree_min},
           "verdict": "UNKNOWN"}
    d = rep["delta_ppl_pct"]
    checks = []
    if d is not None and a.delta_ppl_max_pct is not None:
        checks.append(d <= a.delta_ppl_max_pct)
    if mean_kld is not None and a.mean_kld_max is not None:
        checks.append(mean_kld <= a.mean_kld_max)
    if a.head8_agree_min is not None:
        checks.append(rep["output_agreement"]["head8_agree_rate"] >= a.head8_agree_min)
    rep["verdict"] = "PASS" if checks and all(checks) else ("FAIL" if checks else "UNKNOWN")
    json.dump(rep, open(a.out, "w", encoding="utf-8"), ensure_ascii=False, indent=2)
    print(json.dumps({k: rep[k] for k in ("ppl_f16", "ppl_q4_k_m", "delta_ppl_pct", "mean_kld", "verdict")},
                     ensure_ascii=False))
    return 0

if __name__ == "__main__":
    sys.exit(main())
```

判读表（门限列是**待你填的占位**，不是实测值）：

| 指标 | 含义 | 门限 | 判读 |
|---|---|---|---|
| ΔPPL% | 整体困惑度相对劣化 | `<DELTA_PPL_MAX_PCT>`（常用 3–5，视任务定） | 超过门限 → 换 Q5_K_M 或补 imatrix 重跑 |
| mean KLD | 输出分布平均偏移 | `<MEAN_KLD_MAX>` | 越小越好；与 PPL 趋势矛盾时信 KLD |
| 99.9% KLD | 长尾偏移 | 与 mean 同量级为佳 | 远大于 mean → 部分输入被显著改坏，需定位那批输入 |
| 任务分数 | 上线口径 | 相对 f16 的下降 ≤ `<TASK_DROP_MAX>` | 唯一定生死的指标 |
| head8 一致率 | 输出漂移 | `>= <NORM_AGREE_MIN>` | 用于回归护栏，不用于能力判定 |

常见坑：① 两份 PPL 必须同 `-c` 同 `--chunks` 同 `EVAL.txt`，否则数字不可比；② `EVAL.txt` 不能出现在训练/校准语料里（imatrix 用的 `CALIB.txt` 与它必须分离）；③ Q4_K_M 的 chat template 若丢，任务分会假跌 —— 用 `--jinja` 与模型自带 template 校验，不要把模板问题算成量化损失；④ KV cache 量化是另一条轴，单独测。
