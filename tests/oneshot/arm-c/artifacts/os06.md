### 1. 关键校准：「实际利用成功率」不是一个可查字段

这是本题最容易造假的地方，先把来源分层钉死：

| 层次 | 数据源 | 它到底是什么 | 能不能当「成功率」 |
|---|---|---|---|
| 严重度 | NVD `metrics.cvssMetricV31.baseScore` | CVSS 基分，**描述潜在影响**，与利用难度无关 | 不能。CVSS 9.8 ≠ 98% |
| 在野利用证据 | CISA KEV 清单 | **二值**：已知被在野利用 / 未列入 | 只能当「有/无」，给不出比率 |
| 未来 30 天被利用概率 | FIRST EPSS | 模型预测概率（每天刷新） | 最接近的公开代理量，但它是**预测**不是实测成功数 |
| 模块可靠性 | 攻击框架的 rank 档（如 excellent/good/normal） | 人工经验评级，非统计量 | 不能当百分比 |
| **实际利用成功率** | **只能自测**：在授权 lab 里对同一目标重复执行 N 次，统计首击成功率 + Wilson 置信区间 | 唯一有分母的量 | 本文第 4 节给测量件 |

**没有任何公开 API 提供「某 CVE 的实际利用成功率」。** 谁给了一个没有分母的百分比，那个数字就是编的。

`cve_enum.py` 的核心（完整文件见上路径，依赖仅 python3 标准库）：

```python
NVD = "https://services.nvd.nist.gov/rest/json/cves/2.0"

def score(v):
    """优先 CVSS v3.1 > v3.0 > v4.0 > v2；返回 (分值, 版本, 向量, 严重度)。"""
    m = v.get("metrics", {})
    for key, ver in (("cvssMetricV31", "3.1"), ("cvssMetricV30", "3.0"),
                     ("cvssMetricV40", "4.0"), ("cvssMetricV2", "2.0")):
        if m.get(key):
            d = m[key][0]["cvssData"]
            return (d.get("baseScore"), ver, d.get("vectorString"),
                    d.get("baseSeverity") or m[key][0].get("baseSeverity"))
    return (None, None, None, None)
# fetch(): NVD ?virtualMatchString=<CPE>&resultsPerPage=200 → 逐条抽 id/cvss/vector/发布日期/参考链接
# 429 退避 6s*attempt，超 3 次抛错（不静默吞掉，避免把空结果当"无漏洞"）
```

**失败分支**（这几条都真踩过类别，不是理论）：`totalResults == 0` 通常意味着 CPE 拼错或版本号格式不匹配（NVD 里 `8.9` 与 `8.9p1` 是两个不同 CPE），先退到 `cpe:2.3:a:VENDOR:PRODUCT:*` 再收窄；无 API key 时限速约 5 请求/30s，批量查要走 `--out` 落盘 + 缓存。

### 4. 验证件：「实际利用成功率」只能这样量

在授权 lab（`LAB_HOST` = 自有靶机，与生产隔离）对**同一个漏洞模块**重复 N 次，记录每次是否拿到目标状态，输出首击成功率与 Wilson 95% 置信区间。这是本题里唯一有分母的数字。

```python
#!/usr/bin/env python3
# measure_success.py -- 授权 lab 内的漏洞模块成功率测量（N 次重复 + Wilson CI）
# 用法: python3 measure_success.py --cmd 'msfconsole -qx "use MODULE_PATH; set RHOSTS LAB_HOST; run; exit"' --n 20
import argparse, math, re, subprocess, sys, time

def wilson(k, n, z=1.96):
    if n == 0:
        return (0.0, 0.0, 0.0)
    p = k / n
    d = 1 + z * z / n
    c = (p + z * z / (2 * n)) / d
    h = z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / d
    return (p, max(0.0, c - h), min(1.0, c + h))

HIT = re.compile(r"SESSION|Meterpreter|shell opened|SUCCESS|owned", re.I)   # 按自己的模块改

ap = argparse.ArgumentParser()
ap.add_argument("--cmd", required=True, help="单次利用命令；每次执行一次")
ap.add_argument("--n", type=int, default=20, help="重复次数（建议 >=20 才谈得上区间）")
ap.add_argument("--timeout", type=int, default=120)
ap.add_argument("--first-hit-only", action="store_true", help="只统计首击（前 5 次内命中）")
a = ap.parse_args()

hits, t0 = 0, time.time()
for i in range(1, a.n + 1):
    try:
        out = subprocess.run(a.cmd, shell=True, capture_output=True, text=True,
                             timeout=a.timeout).stdout
        ok = bool(HIT.search(out))
    except subprocess.TimeoutExpired:
        ok = False                      # 超时记为失败，不记为命中
    hits += ok
    print("run %d/%d hit=%s" % (i, a.n, ok), flush=True)

p, lo, hi = wilson(hits, a.n)
print("success_rate=%.3f (%d/%d) wilson95=[%.3f, %.3f] elapsed=%.0fs"
      % (p, hits, a.n, lo, hi, time.time() - t0))
```

**验证件**：对任何声称「成功率 X%」的外部说法，用同一脚本在 lab 里跑 N≥20 次复算；区间跨过你的结论值，则该说法在你的环境里不被支持。**不要**把 EPSS 概率当成功率，两者分母不同（EPSS 是全网未来 30 天被利用的预测，lab 成功率是特定目标特定模块的命中率）。

### 5. 四态与有效期

推测：把 `TARGET_VERSION` 落成正确 CPE 后，同一脚本会给出该版本的清单与评分（依据：同一 API 同一字段路径，演示目标已跑通）；EPSS 缺行可能与 CVE 尚未进入 EPSS 模型覆盖有关 —— 依据不足，仅作推测。
