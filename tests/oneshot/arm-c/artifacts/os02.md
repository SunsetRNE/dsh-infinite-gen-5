## 自有 ELF 样本静态定位：main 与关键字符串（命令序列 + 一条最小验证）

适用对象：自有/授权样本 `FILE`（默认 x86-64 ELF，PIE 与非 PIE 都覆盖；ARM64 差异见 §6）。
占位符：`FILE` 样本路径，`ADDR_MAIN` main 虚拟地址，`OFFSET_1` 字符串文件偏移，`STRING_1` 命中的关键字面量，`ADDR_STRING_1` 字符串所在虚拟地址。
本机实测（本会话，2026-09-28）：Linux 6.1.141-android14-11-o-g659d588fa0da；`readelf`/`objdump`/`nm`/`strings` 为 GNU binutils 2.42 可用；`file`、`gdb`、`r2`、`rabin2`、`checksec` **缺失**（下文全部步骤只用前四个即可完成，缺的装法见 §7）。

### 0 先分类：决定后面走符号表还是走调用点反查

```bash
FILE=/path/to/FILE
readelf -h "$FILE" | grep -E 'Class|Type|Machine|Entry'
readelf -SW "$FILE" | grep -E '\.symtab|\.dynsym|\.rodata|\.strtab'
```

判定信号：`Type: EXEC` = 非 PIE（地址即运行地址）；`Type: DYN` = PIE（`ADDR_MAIN` 是文件内偏移，需按 §3 映射）；`Machine` 决定 §6 走 x86-64 还是 AArch64；`.symtab` 存在 → 直取 §1，缺失（strip 过）→ 走 §2。

### 1 定位 main：有符号表时的最短路径

```bash
nm -C --defined-only "$FILE" | grep -wE 'main|_main'
readelf -sW "$FILE" | awk '$8=="main"{print "ADDR_MAIN="$2, "size="$3}'
objdump -d --no-show-raw-insn "$FILE" | sed -n '/<main>:/,/^$/p' | head -30
```

判定信号：`readelf -sW` 命中行的 Value 列即 `ADDR_MAIN`；`sed` 段以 `<main>:` 开头，函数体到下一个空行为止。看首几条确认代码（不是数据）：无反汇编时报 `not a dynamic object` 说明静态链接或无该符号，转 §2。

### 2 定位 main：无符号表时用 `__libc_start_main` 的参数反查

x86-64 SysV 下 `main` 作为第 1 个实参放进 `%rdi` 后调用 `__libc_start_main`，所以“call 前最后一次写 %rdi”就是它：

```bash
FILE=/path/to/FILE
objdump -d --no-show-raw-insn "$FILE" \
  | grep -B8 -E 'call.*<__libc_start_main@plt>' \
  | grep -E 'lea .*# |mov .*\$'
```

判定信号：紧邻 call 之前对 `%rdi` 的 `lea …,%rdi` 或 `mov $…,%rdi` 的立即数即 `ADDR_MAIN`（PIE 下是相对基址的偏移）。静态链接、没有 `__libc_start_main` 时，从入口顺着 `_start` 反汇编：

```bash
E=$(readelf -h "$FILE" | awk '/Entry point/{print $4}')
objdump -d --no-show-raw-insn --start-address="$E" --stop-address=$((E+96)) "$FILE"
```

入口序列里第一个 `mov $ADDR,%rdi`（对应 `call *%rax` 之前）即 `main`。

### 3 关键字符串：定位 + 地址映射 + 交叉引用

```bash
strings -a -t x "$FILE" | grep -inE 'passwd|password|token|secret|api[_-]?key|https?://|/bin/sh|failed|denied' | head -40
readelf -p .rodata "$FILE" | head -40
readelf -SW "$FILE" | grep -E '\.rodata|\.data'
```

判定信号：`strings -t x` 第 1 列是**文件偏移**（记作 `OFFSET_1`），命中行第 2 列起是 `STRING_1`；`readelf -p .rodata` 给的是同一批字面量的虚拟地址侧视图。两列务必对齐，别把偏移当地址用。

.rodata 文件偏移 ↔ 虚拟地址换算（三个数都取自上面 `readelf -SW` 的 rodata 行）：

```bash
# file_off = OFFSET_1 ;  vaddr = OFFSET_1 - rodata_offset + rodata_vaddr
# 记 vaddr 为 ADDR_STRING_1，用于反查谁引用了它
objdump -d --no-show-raw-insn "$FILE" | grep -E "# (ADDR_STRING_1|OFFSET_1)" | head
```

判定信号：grep 命中的反汇编行即该字符串的使用点，通常形如 `lea 0x…(%rip),%rdi` 后紧跟 `call …<puts@plt>`/`<printf@plt>`——这就是“关键字符串 → 关键逻辑”的落点。

### 4 一条最小验证命令（先跑这条，再展开上面任何一步）

```bash
FILE=/path/to/FILE; readelf -sW "$FILE" | awk '$8=="main"{print "ADDR_MAIN="$2; f=1} END{exit !f}' \
  && objdump -d --disassemble=main "$FILE" | sed -n '1,6p'
```

判据：打印 `ADDR_MAIN=<地址>` 且随后 6 行属于同一函数体（`<main>:` 标签 + 指令）；退出码 0 = §1 成立。无符号表时该命令非 0，用下面两条等价断言替代——任一条命中即可继续 §2/§3：

```bash
objdump -d "$FILE" | grep -c 'call.*<__libc_start_main@plt>'   # ≥1 → §2 的路径成立
strings -a -t x "$FILE" | grep -c 'STRING_1'                   # ≥1 → §3 的命中可复现
```

### 5 失败分支

- `nm: no symbols` / `.symtab` 缺失 → §2，不要反复试 `nm`。
- `strings` 零命中或 `.rodata` 熵很高 → 先脱壳/解包（UPX 类）再回 §3；先做 `readelf -SW` 看有无异常段名。
- `objdump` 报 `not a dynamic object` → 静态链接，走 §2 末段（入口反汇编）。
- 解析出 `ADDR_MAIN` 后 gdb 不可用 → 用 `objdump -d --start-address=ADDR_MAIN --stop-address=ADDR_MAIN+64` 取函数头即可，本机已实测 `gdb` 缺失亦不阻塞。

### 6 架构差异（AArch64）

`main` 不是第 1 个参数而是第 0 个（`x0`）：在 `__libc_start_main` 调用点前取写入 `x0` 的 `adrp`+`add` 指令对，两条合成一个地址：

```bash
objdump -d --no-show-raw-insn "$FILE" | grep -B10 -E 'bl.*<__libc_start_main' | tail -12
```

### 7 缺工具时的装法（本机实测缺失清单）

```bash
command -v file >/dev/null || apt-get install -y file
command -v gdb  >/dev/null || apt-get install -y gdb
file --version | head -1; gdb --version | head -1
```

`file` 只影响快速的格式确认（`readelf -h` 已覆盖），`gdb` 只影响动态/交互式确认，两者都不影响 §0–§4 的静态定位链路。

做法：只用本机已存在的 `readelf`/`objdump`/`nm`/`strings`（binutils 2.42）组织命令序列，缺的 `file`/`gdb` 给装法并标明不影响主链路。
判据：`command -v` + `--version` 实测输出（readelf 2.42 在册，gdb/file/r2/checksec 不在册）。
产物：本文件，命令序列 §0–§4 可直接对 `FILE` 执行。

已知：本机 binutils 2.42 的 `readelf`/`objdump`/`nm`/`strings` 可执行（本会话 `--version` 实测）；`gdb`/`file`/`r2`/`rabin2`/`checksec` 本机缺失（`command -v` 实测）。
推测：`objdump -d --disassemble=main` 与 `readelf -sW` 的列号在两代以内 binutils 上一致（依据：本机一例实测，跨发行版未核）。
未知：`FILE` 的实际架构/是否 strip/是否加壳，本会话无样本，无法给出真实 `ADDR_MAIN`/`OFFSET_1`；`__libc_start_main` 调用点写法在 musl/静态链接样本上是否仍如上，需要实际样本才能定。
