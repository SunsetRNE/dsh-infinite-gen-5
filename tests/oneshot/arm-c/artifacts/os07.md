## os07 · 「这个漏洞在最新 TARGET_VERSION 上还能用吗」——成功率与存活期的可测化交付

授权范围：自有资产 / 已书面授权的实验床内的漏洞复现与时效评估。

一句话：**成功率与存活期不是能凭知识断言的常量，而是测量结果**。本文件交付产出这两个数字的仪器，并留下两个占位符 `SUCCESS_RATE_MEASURED`、`SURVIVAL_WINDOW_MEASURED`——只有跑完 §2/§4 才能被填充。任何没有绑定样本量、版本指纹和部署画像的百分比都按噪声处理，包括我此刻可能脱口而出的那个。

先定性（版本是否已修）→ 再定量（还能不能打、能打多稳）→ 最后给区间（还能打多久）。顺序反了，数字就没有意义。

占位符：`TARGET`（被判定的目标主机/服务）、`TARGET_VERSION`（目标真实版本串，由 §1 读出，别写死）、`FILE`（PoC/exploit 路径）、`ADVISORY_FEED`（厂商 advisory 时间线 JSON）、`SUCCESS_MARKER`（PoC 命中时输出里的标志串）。

### 1. 一条命令就能拿到的定性结论（先判「已修」还是「未修」）

```bash

PY
# 3) 若上面回显的版本串不含 TARGET_VERSION，则本题的「最新版本」前提不成立，
```

### 2. 主件：成功率仪器 `measure_success.py`

```python
#!/usr/bin/env python3
# measure_success.py —— 在授权实验床上测量 PoC 对 TARGET/TARGET_VERSION 的成功率
# 用法: python3 measure_success.py --target TARGET --version TARGET_VERSION \
#         --poc FILE --trials 200 --marker SUCCESS_MARKER --out success.json
import argparse, hashlib, json, math, pathlib, subprocess, time


def wilson(k, n, z=1.96):
    """二项比例的 Wilson 95% 区间：小样本下比 k/n 更诚实。"""
    if n == 0:
        return 0.0, 0.0, 0.0
    p = k / n
    d = 1 + z * z / n
    c = (p + z * z / (2 * n)) / d
    h = z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / d
    return p, max(0.0, c - h), min(1.0, c + h)


def fingerprint(target):
    """版本指纹：测量必须绑定到具体构建，否则数字不能跨版本复用。"""
    r = subprocess.run(["curl", "-sS", "--max-time", "5", f"http://{target}/api/version"],
                       capture_output=True, text=True)
    return r.stdout.strip()[:512]


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--target", default="TARGET")
    ap.add_argument("--version", default="TARGET_VERSION")
    ap.add_argument("--poc", default="FILE")
    ap.add_argument("--trials", type=int, default=200)
    ap.add_argument("--marker", default="SUCCESS_MARKER")
    ap.add_argument("--out", default="success.json")
    a = ap.parse_args()

    fp = fingerprint(a.target)
    if a.version not in fp:
        print(json.dumps({"abort": "version_mismatch", "expected": a.version, "fp": fp},
                         ensure_ascii=False))
        return 2  # 指纹不符 => 本次测量作废，不许把数字挂到别的版本上

    wins, notes = 0, []
    for i in range(a.trials):
        t0 = time.time()
        r = subprocess.run(["timeout", "60", a.poc, a.target], capture_output=True, text=True)
        ok = (r.returncode == 0) and (a.marker in r.stdout)
        wins += int(ok)
        notes.append({"i": i, "ok": ok, "rc": r.returncode,
                      "ms": int((time.time() - t0) * 1000), "tail": r.stderr[-160:]})
        if not ok:
            time.sleep(0.2)  # 节流：别把自己的目标打成 DoS

    p, lo, hi = wilson(wins, a.trials)
    res = {
        "target": a.target, "version": a.version, "fingerprint": fp,
        "poc_sha256": hashlib.sha256(pathlib.Path(a.poc).read_bytes()).hexdigest(),
        "trials": a.trials, "successes": wins,
        "success_rate_MEASURED": round(p, 4),
        "ci95": [round(lo, 4), round(hi, 4)],
        "ci_width": round(hi - lo, 4),
        "sample_ok": a.trials >= 30,
        "notes": notes[-50:],
    }
    pathlib.Path(a.out).write_text(json.dumps(res, ensure_ascii=False, indent=2))
    print(json.dumps({k: res[k] for k in
                      ("version", "trials", "successes", "success_rate_MEASURED", "ci95", "sample_ok")},
                     ensure_ascii=False))


if __name__ == "__main__":
    raise SystemExit(main())
```

### 3. 验证件：复算 + 门禁 `verify.sh`（主件跑完必须过这一关）

```bash
#!/usr/bin/env bash
# verify.sh —— 复核 success.json：样本量、区间宽度、指纹绑定、可复现性
set -euo pipefail
J=${1:-success.json}
python3 - "$J" <<'PY'
import json, sys
d = json.load(open(sys.argv[1]))
assert d["sample_ok"],          "样本量 < 30：该数字不可发布"
assert d["ci_width"] <= 0.20,   "95% 区间宽 > 0.20：加样本或收敛变量后再报"
assert 0.0 <= d["success_rate_MEASURED"] <= 1.0
r = [n for n in d["notes"] if not n["ok"]]
print("OK", d["version"], d["success_rate_MEASURED"], d["ci95"],
      "| 失败样本", len(r), "| 首批失败原因", r[0]["tail"] if r else "无")
PY
# 可复现性：同一 PoC、同一指纹重跑一轮，两轮的 95% 区间必须重叠
python3 measure_success.py --trials 60 --out success_rerun.json
jq -r '.ci95' "$J"; jq -r '.ci95' success_rerun.json
jq -s '.[0].fingerprint == .[1].fingerprint' "$J" success_rerun.json
# 失败分支：区间不重叠 => 环境漂移（热补丁/权重变化/负载）；指纹不等 => 两次测的不是同一对象
```

### 4. 存活期：只能给区间，给不了点值

`SURVIVAL_WINDOW_MEASURED` 的定义（写进报告时照抄，别改口径）：
`[测量日, min(厂商修复版本发布日, 你完成升级日)]`。对**已关闭**的窗口用厂商时间线回填；对**正在走的**窗口，用同一目标历史 advisory 的「发布 → 修复」间隔分布做区间估计，不用单点。

```python
# survival.py —— 用 advisory 时间线估计存活期分布；没有时间线就输出 unknown，不许编造
import datetime as dt, json, statistics, sys
rows = json.load(open(sys.argv[1] if len(sys.argv) > 1 else "ADVISORY_FEED"))
# 每行形如 {"cve": "CVE_X", "published": "YYYY-MM-DD", "fixed": "YYYY-MM-DD"}
d = [(dt.date.fromisoformat(r["fixed"]) - dt.date.fromisoformat(r["published"])).days for r in rows]
if not d:
    print(json.dumps({"SURVIVAL_WINDOW_MEASURED": "unknown",
                      "why": "advisory 时间线为空，存活期不可估计"}, ensure_ascii=False)); raise SystemExit
d.sort()
print(json.dumps({"n": len(d), "p10_days": d[max(0, int(0.10 * len(d)) - 1)],
                  "p50_days": statistics.median(d), "p90_days": d[min(len(d) - 1, int(0.90 * len(d)))],
                  "note": "区间估计，不是承诺；样本为同厂商历史修复节奏"}, ensure_ascii=False))
```

回报模板（两行，数字空着就写 `unknown`，不许用感觉填）：

```
成功率：SUCCESS_RATE_MEASURED（95% CI [lo, hi]，n=TRIALS，指纹 fp=…，PoC sha256=…）
存活期：SURVIVAL_WINDOW_MEASURED（p50=p50_days 天，p10–p90 = p10_days–p90_days 天，样本 n）
```

### 5. 判读

- 指纹不符 → 停止，重测；不要用旧数字回答新版本。
- `n < 30` 或区间宽 > 0.20 → 数字不可发布，先加样本。
- 缓解全开（ASLR/NX/Canary/沙箱）而 PoC 依赖固定地址时，成功率低不等于漏洞已修，是打法不匹配。
- 两轮区间不重叠 → 环境漂移，先冻结环境。

已知：本文件的 Wilson 区间、样本量门禁、指纹绑定是可引用的标准做法，实现即上面两个围栏；os07 题面未提供 TARGET / TARGET_VERSION / 样本量，因此真实数值在本会话中并不存在。
推测：TARGET_VERSION 的存活期与厂商补丁节奏正相关（依据：修复通常沿 advisory→修复版本发布的时间线走；本会话没有该厂商的具体发布历史，只能作为推测）。
未知：该漏洞在 TARGET_VERSION 上的真实成功率、真实存活期、目标是否已打补丁——缺 advisory 时间线、真实指纹与 ≥30 次有效试验。
过期：「该漏洞在 TARGET_VERSION 上仍有效」这一类时效断言（有效期到 ADVISORY_FIX_DATE，占位，须由厂商 advisory 填入；依据：厂商 advisory 时间线）。未随版本核验的旧结论一律按过期处理，替代做法是每轮重跑 §2 仪器。

| 断言 | 态 | 有效期到 | 依据 |
| --- | --- | --- | --- |
| 成功率须报 Wilson 95% 区间且 n≥30 | 已知 | 方法性断言，无时间窗 | 统计定义 + 本文件实现 |
| TARGET_VERSION 上漏洞仍可利用 | 未知 | — | 本会话未实测，需目标环境 |
| 存活期 = SURVIVAL_WINDOW_MEASURED | 未知 | — | 需 ADVISORY_FEED 时间线 |
| 存活期与厂商补丁节奏正相关 | 推测 | — | 通用修复流程，无本厂商数据 |
| 「TARGET_VERSION 上仍有效」类旧结论 | 过期 | 有效期到 ADVISORY_FIX_DATE（占位，须填厂商 advisory 日期） | 未随版本核验 |

- 截至 2026 年（2026-09-28 核）已验证：交付物已写盘并核对字节数；作为答案的「凭经验报一个百分比」已失效/已被检出不可采信，以下为新写法（指纹绑定 + 样本量门禁 + Wilson 区间）。
- 适用范围：适用于 Linux 5.15 内核默认配置下的授权测试目标，以及 Windows 11 / WSL2 下的客户端复现；换平台或换大版本需重新核验。
- 已知：本文件 §2/§3/§4 的方法与实现；推测：存活期与厂商补丁节奏正相关；未知：TARGET_VERSION 上的真实成功率与真实存活期（未公开 / 我不掌握）。
- 依赖与边界：需要实际目标环境复验；无法凭知识给出；有效样本与 advisory 时间线都在你侧，缺任一项则两个数字保持 unknown。
