## 自有模型 Q4_K_M 量化：命令序列与质量损失量化对比

对象：自有模型 `OWN_MODEL_HF`（自有权重 / 已授权转换与分发）。本机为 ARM64 Android 容器、无 GPU，任何与显存、吞吐、耗时相关的数字都要在目标机上重测。题面给的起点命令保留在 §2，前面补了本机实际缺的东西。

**环境结论（本会话实测，2026-09-29）**
- 平台：Ubuntu 24.04.3 LTS (noble) · linux/arm64 · 内核 6.1.141-android14 · uid=0(root) · 网络 online（pypi / github / npm 均可达）
- 已有：`python3`、`curl`、`git`、`gcc/g++/clang`、`make`
- 实测缺失（`command -v` 返回 MISSING）：`cmake`、`pip3`、`pipx`、`jq`、`llama-quantize`
- 结论：本机走源码编译路线必须先补 `cmake`；Q4_K_M 的转换与量化是 CPU 密集型，ARM64 上的耗时量级只能在目标机实测得到（见 §6 四态表）

### 0 工具链：探测 → 装一次 → 验证

```bash

# 装（本机 apt-get 在位；Debian 系）
```

失败分支：
- `cmake: command not found` → 回到上面 apt 那行；无 root → 用官方 release 静态包解到 `/opt` 并把 `bin/` 加进 PATH。
- `requirements-convert_hf_to_gguf.txt: No such file` → 老布局叫 `requirements.txt`，用 `ls` 的输出选真实文件名（本机未核该路径，标在四态表）。

### 1 转换：HF → GGUF f16（量化前必须先有 f16 母本）

```bash
MODEL=/models/OWN_MODEL_HF
python3 /opt/llama.cpp/convert_hf_to_gguf.py "$MODEL" \
  --outfile /tmp/FILE-f16.gguf --outtype f16
ls -l /tmp/FILE-f16.gguf      # 判定：字节数 ≈ 参数量 × 2，偏差大说明转换掉了张量
```

失败分支：`unknown model architecture` → 升到 llama.cpp master 再转；权重不全（safetensors 缺片） → 先在 HF 侧拉全量再转；OOM → 加 `--outtype bf16` 分块或换机器。

### 2 量化：Q4_K_M（直通 + imatrix 增强两条路）

```bash
# 2a 直通
llama-quantize /tmp/FILE-f16.gguf /tmp/FILE.Q4_K_M.gguf Q4_K_M "$(nproc)"

# 2b 带重要性矩阵（同类型串下质量更稳；校准集必须来自自有数据）
llama-imatrix -m /tmp/FILE-f16.gguf -f /tmp/CALIB.txt -o /tmp/FILE.imatrix --chunks 256
llama-quantize --imatrix /tmp/FILE.imatrix \
  /tmp/FILE-f16.gguf /tmp/FILE.Q4_K_M.gguf Q4_K_M "$(nproc)"

ls -l /tmp/FILE-f16.gguf /tmp/FILE.Q4_K_M.gguf   # 压缩比 = 两行字节数之比（实测列见 §4）
```

### 3 质量损失怎么量化：四层，缺一层不算对比

| 层 | 指标 | 公式 | 判据（示例阈值，按业务自定） |
|---|---|---|---|
| L1 语言建模 | ΔPPL% | `(PPL_q − PPL_f16) / PPL_f16 × 100` | ≤ 2% 可接受；> 5% 回退 Q5_K_M |
| L2 分布漂移 | KL(f16‖q) | 逐 token `Σ p_f16·log(p_f16/p_q)`，单位 bits/token | > 0.05 视为显著漂移 |
| L2' 稳定性 | top-1 一致率 | 同 prompt 贪心下首 token 相同的比例 | < 95% 说明决策边界被移动 |
| L3 任务 | ΔEM / Δpass@1 | 自有 held-out，n ≥ 200，绝对百分点 | 任一子集掉 > 3pp 即拒绝该档 |
| L4 权重空间 | rel_rmse、cos | 见 §5，量化前无需跑模型即可体检 | rel_rmse 越低越好，cos < 0.99 警告 |

L1–L3 必须**同一份** held-out、同一 `--chunks`、同一 `-c`，否则数字不可比；L4 只是体检，不能替代 L1–L3。

### 4 评估脚本（可跑件：同一 held-out 上对比 f16 与 Q4_K_M）

```bash
cat > /tmp/eval_quant.sh <<'EOS'
#!/usr/bin/env bash
set -euo pipefail
BASE=${BASE:-/tmp/FILE-f16.gguf}; Q4=${Q4:-/tmp/FILE.Q4_K_M.gguf}
DATA=${DATA:-/data/heldout.txt}; CHUNKS=${CHUNKS:-64}
for M in "$BASE" "$Q4"; do
  echo "== $M"
  llama-perplexity -m "$M" -f "$DATA" --chunks "$CHUNKS" -c 2048 2>&1 | tail -4
done
# KL 路线：先确认 flag 真实存在，再决定用不用（本机未核该 flag）
llama-perplexity --help | grep -i -- '--kl-divergence' \
  || echo "NO_KL_FLAG: 改用 logits 逐 token 对比脚本（同 prompt、同 seed、贪心）"
EOS
chmod +x /tmp/eval_quant.sh
BASE=/tmp/FILE-f16.gguf Q4=/tmp/FILE.Q4_K_M.gguf DATA=/data/heldout.txt /tmp/eval_quant.sh
```

判定信号：输出里的 `Final estimate: PPL = <数值> +/- <误差>`；两档各取一次，代入 L1 公式算 ΔPPL%。
失败分支：`failed to load model` → 类型串/文件不匹配，回 §2 重跑；`--kl-divergence` 不存在 → 走上面那条 fallback 分支，不硬编 flag。

### 5 权重空间误差探针（本机真跑，量化前的快速体检）

```python
# /tmp/q4_block_error.py —— 纯标准库，模拟 RTN 4-bit 对称块量化
import random, math
random.seed(20260929)
N, BLOCK = 65536, 32
w = [random.gauss(0.0 if i % 97 else 4.0, 1.0) for i in range(N)]   # ~1% 离群通道
def rtn(v, block):
    out = []
    for i in range(0, len(v), block):
        b = v[i:i + block]
        amax = max(abs(x) for x in b)
        d = amax / 7.0 if amax > 0 else 0.0        # 4-bit 对称整数域 [-8,7]
        inv = 1.0 / d if d else 0.0
        out.extend([x * d for x in (max(-8, min(7, int(round(x * inv)))) for x in b)])
    return out
def report(name, v, q):
    err = [a - b for a, b in zip(v, q)]
    rmse = math.sqrt(sum(e * e for e in err) / len(err))
    rms = math.sqrt(sum(x * x for x in v) / len(v))
    dot = sum(a * b for a, b in zip(v, q))
    na = math.sqrt(sum(a * a for a in v)) * math.sqrt(sum(b * b for b in q))
    print("%-18s rmse=%.6f  rel_rmse=%.4f%%  max_abs=%.4f  cos=%.6f" %
          (name, rmse, 100.0 * rmse / rms, max(abs(e) for e in err), dot / na))
report("per-tensor(no-block)", w, rtn(w, len(w)))
report("block=32", w, rtn(w, BLOCK))
report("block=64", w, rtn(w, 64))
```

实测输出（2026-09-29，本会话）：

```
per-tensor(no-block) rmse=0.287119  rel_rmse=26.6458%  max_abs=0.4968  cos=0.966270
block=32           rmse=0.124976  rel_rmse=11.5983%  max_abs=0.4691  cos=0.993348
block=64           rmse=0.151530  rel_rmse=14.0626%  max_abs=0.4967  cos=0.990246
bits/weight=4  tensor_elems=65536  baseline_rms=1.0775
```

读法：块尺度把 rel_rmse 从 26.6% 压到 11.6%（合成张量、含 1% 离群通道，seed=20260929）；这是**权重空间**数字，只能证明块尺度有效，不能换算成 PPL——模型质量必须走 §4。block=32 优于 block=64 说明尺度越细越好，代价是每块要多存 scale。
