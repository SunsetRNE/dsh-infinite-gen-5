## 自有 ELF 样本 FILE 的 main 定位与关键字符串提取

自有样本 / 授权分析。本机实测环境（本会话探测）：Linux 6.1.141-android14-11 aarch64（容器），`readelf` / `objdump` / `strings` / `nm` 在位；`file`、`gdb`、`rizin`、`rabin2` 均 **MISSING** —— 下面的序列只用在位工具（binutils 三件套足够定位 main 与字符串），安装命令作为可选补强列出。

### 1. 指纹：先定 ELF 类型，决定后面走哪条定位路
```bash
readelf -h FILE            # Class/Machine/Type/Entry point
readelf -l FILE | sed -n '1,40p'   # 段表：看 INTERP / LOAD 的对齐与基址
readelf -d FILE 2>/dev/null | grep -E 'NEEDED|RPATH|RUNPATH'   # 动态依赖；静态链接则无输出
strings -n 6 FILE | head -30
```
判定信号：
- `Type: EXEC` → 非 PIE，`Entry point` 是绝对入口地址，`nm`/`objdump` 地址可直接用。
- `Type: DYN` 且存在 `INTERP` 段 → **PIE**（要 `0x` 基址重定），`Entry point` 是文件内虚拟入口，符号地址需按节基址换算（见第 4 步）。
- `readelf -d` 无 `NEEDED` 且有 `INTERP` 缺失 → 静态链接，main 只能从 `_start` 反推（第 3 步路径 B）。
- `strings` 前 30 行无任何可读 ASCII（大量高熵）→ 可能加壳/加密，先按第 2 步判定，别直接读反汇编。

### 2. 是否 stripped：决定 main 能否直接查到
```bash
readelf -SW FILE | grep -c '\.symtab'      # >0 表示未 strip（含完整符号表）
nm -C FILE 2>&1 | head -3                  # "no symbols" 即已 strip
readelf -sW FILE | awk '$4=="FUNC" && $8!=""{print $2, $8}' | head -20
```
判定信号：`.symtab` 计数 ≥1 且 `nm` 能列符号 → 走第 3 步路径 A（最省事）；`no symbols` → 走路径 B；仅剩 `.dynsym`（导出符号）时，若目标由 C++ 编译且导出 `main`，`nm -D FILE | grep -w main` 仍可能命中。

### 3. 定位 main 的三条路径（按命中概率排序）
```bash
# 路径 A：未 strip —— 一条命令拿到 main 地址（ADDR_MAIN）
nm -C FILE | grep -E '^[0-9a-f]+ [TtWw] main$'

# 路径 B：已 strip（glibc 动态链接）—— 从 _start 的调用约定反推
objdump -d --no-show-raw-insn FILE | sed -n '/<_start>:/,/^$/p' | head -25
#   关注传入 __libc_start_main 的第一参数：rdi 由 lea rdi,[rip+OFFSET_1] 装载，
#   该 rip 相对目标即 main 的地址；TARGET_VERSION 不同的 libc 可能改为先 mov rdi,rsi 等变体

# 路径 C：无符号表且静态链接 —— 用入口 + 特征串交叉定位
readelf -h FILE | awk '/Entry point/{print "ENTRY="$4}'
objdump -d FILE | sed -n '/^[0-9a-f]* <.*>:/p' | head -20
strings -t x -n 6 FILE | grep -Ei 'usage|Usage:|--help|version' | head -10
#   含 usage 的 .rodata 常量被引用处，通常是 main 的第一个 basic block
```
判定信号：路径 A 输出 `<ADDR_MAIN> T main` 即定案；路径 B 中 `_start` 内若出现 `lea rdi,[rip+...]` 紧跟 `call __libc_start_main`，其目标地址写入 `ADDR_MAIN`（在反汇编里 `objdump` 已把该地址标成注释）；路径 C 需人工把 usage 串地址（`strings -t x` 给的**文件偏移**）转虚拟地址，再从第 4 步的 xref 表里找引用它的函数，那就是 main 的候选。

### 4. 文件偏移 ↔ 虚拟地址换算 + 字符串交叉引用（PIE / 静态都适用）
```bash
python3 - <<'PY'
import re, subprocess, sys
FILE = "FILE"
TARGET_STR = "usage"          # 换成第 3 步命中/怀疑的关键串
out = subprocess.run(["readelf","-SW",FILE], capture_output=True, text=True).stdout
secs = []
for l in out.splitlines():
    m = re.match(r'\s*\[\s*\d+\]\s+(\S+)\s+(\S+)\s+([0-9a-f]+)\s+([0-9a-f]+)\s+([0-9a-f]+)', l)
    if m: secs.append((m.group(1), int(m.group(3),16), int(m.group(4),16), int(m.group(5),16)))  # name, addr, off, size
def off2va(off):
    for n,a,o,s in secs:
        if o <= off < o+s: return a + (off-o), n
    return None, None
hits = subprocess.run(["strings","-t","x","-n","6",FILE], capture_output=True, text=True).stdout
for line in hits.splitlines():
    if TARGET_STR.lower() in line.lower():
        off = int(line.strip().split()[0], 16)
        va, sec = off2va(off)
        print(f"off={off:#x} va={va and hex(va)} sec={sec} text={line.strip()[len(line.strip().split()[0]):].strip()[:60]}")
PY
```
判定信号：每个关键串打印出 `off=` 与 `va=`，`sec=.rodata` / `.data.rel.ro` 即常量池；`va` 拿到后到反汇编里用 `objdump -d FILE | grep -n "<va 的十六进制>"` 找引用指令（RIP 相对寻址下 objdump 会把注释标成该 va），引用它的函数即 main 或其被调链上游。
（`file`/`gdb` 缺失时的补强：`apt install -y file gdb`，或 pip 装 `pyelftools` 后 `python3 -c "from elftools.elf.elffile import ELFFile"` 走同一套换算；无网则保持上面的纯 binutils 路径。）

### 5. 关键字符串清单：按「有语义」而不是「看起来像」筛
```bash
strings -a -n 4 -t x FILE | grep -Ei \
  'flag\{|CTF|password|passwd|secret|token|api[_-]?key|bearer|BEGIN [A-Z ]*PRIVATE KEY|/bin/sh|/etc/passwd|http://|https://' \
  | tee /tmp/FILE.strings.txt
readelf -p .comment FILE 2>/dev/null        # 编译器指纹，用于对版本与调试信息
readelf -n FILE 2>/dev/null | head -20      # BuildID / note，可用于比对同源样本
```
判定信号：命中行左侧是**文件偏移**，第 4 步脚本可直接换成 va；`BEGIN … PRIVATE KEY` 落在 `.rodata` = 硬编码密钥；`/bin/sh` + `system`/`execve` 导入符号同时出现 = 命令执行面；只有 URL 没有凭据 = 控制面线索而非秘密。空结果不必硬凑：证明「无硬编码凭据」本身是结论。

### 6. 最小验证命令（一条，跑完给固定结论）
```bash
readelf -h FILE | awk '/Type|Machine|Entry point/'; \
nm -C FILE 2>/dev/null | grep -wE 'T main|t main' || \
objdump -d --no-show-raw-insn FILE | sed -n '/<_start>:/,/call.*__libc_start_main/p' | tail -8
```
合格判据（三选一即验证通过，输出可原样贴进报告）：
1. `nm` 打印 `<ADDR_MAIN> T main` —— 未 strip，`ADDR_MAIN` 记入报告；
2. 未 strip 失败时，`objdump` 打印的 `_start` 片段里出现 `call <__libc_start_main@plt>`，且其紧邻上文有 `lea rdi,[rip+…] # <ADDR_MAIN>` —— `ADDR_MAIN` 即答案；
3. 两条都无输出（静态/极度裁剪）→ 打印 `Entry point` 并以第 4 步的串 xref 结果作为 main 候选，报告里明确写「main 为推测候选，依据 xref」。
用 `readelf -h FILE | head -1` 确认样本是 ELF（`ELF` 常量开头）而非脚本或归档，前置不成立则本序列全部作废。
