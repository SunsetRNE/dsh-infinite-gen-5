## 授权靶场 http://TARGET/ 目录发现与备份文件探测命令序列

自有靶场 / 书面授权测试范围内执行。本机实测环境（本会话探测）：Linux 6.1.141-android14-11 aarch64（容器），`curl` 存在；`ffuf` / `gobuster` / `feroxbuster` / `nuclei` / `nmap` 均 **MISSING**，下面的安装命令属于本次交付的一部分，不是「先装好再回来」。
（提示：`ffuf` 是较真的判据工具，`curl` 单独也能完成最小验证——见第 0 步与验证块。）

### 0. 最小前置：一条命令确认活靶 + 校准「软 404」
```bash
# 基线：主页状态码/长度/跳转目标
curl -s -o /dev/null -w 'root code=%{http_code} size=%{size_download} redirect=%{redirect_url}\n' http://TARGET/
# 随机路径基线：这条决定后面所有 -mc/-fs 阈值，必须先跑
curl -s -o /dev/null -w 'bogus code=%{http_code} size=%{size_download}\n' http://TARGET/zz$(date +%s)-nope/
```
判定信号：
- 主页 `200` → 常规站点；`301/302` 到 `https://` 或 `/index.php` → 后续所有工具加 `-k`、`-r`（跟随跳转）。
- 随机路径返回 **404** 且长度稳定 → 常规 404，可按状态码筛。
- 随机路径返回 **200** 且长度固定 → **软 404 / 通配路由**，此时状态码无判据，必须换长度过滤（`-fs <size>`）或用 `-ac` 自动校准；两个随机路径（不同长度、不同前缀）长度完全一致才算确认。

### 1. 装工具链（缺失即待办，装完记录版本）
```bash
command -v ffuf || apt install -y ffuf 2>/dev/null || go install github.com/ffuf/ffuf/v2@latest
command -v gobuster || apt install -y gobuster 2>/dev/null || go install github.com/OJ/gobuster/v3@latest
command -v feroxbuster || apt install -y feroxbuster 2>/dev/null || go install github.com/epi052/feroxbuster@latest
# 无网/无 root 降级：只用 curl 的模块化爆破（见第 6 步），功能少但判据相同
ffuf -V; gobuster version; feroxbuster --version
```
判定信号：三条 `--version` 各输出一行版本即就绪；任一失败走降级分支（第 6 步纯 curl 版）并在报告里写明降级了哪一步。

### 2. 目录发现（ffuf，主力）
```bash
ffuf -u http://TARGET/FUZZ -w WORDLIST -mc 200,204,301,302,307,401,403 -ac -t 40 -rate 80 \
     -o /tmp/TARGET.dir.json -of json -v
```
判定信号与分支：
- `200` + 长度大于通配基线 → 真实资源；`301/302` 且 `Location` 以 `/` 结尾 → 目录，值得递归；`403` → 存在但禁列，是最有价值的备份文件线索（先记路径再换后缀试）。
- 输出里出现大量同长度 `200`：通配。看 `-ac` 是否已自动加过滤；没有则读 `/tmp/TARGET.dir.json` 拿 `content-length`，重跑加 `-fs <该长度>`。
- 全站 `000` 或全 `429`：见第 7 步限速/代理分支。

### 3. 目录发现（gobuster，状态码判据更直白）
```bash
gobuster dir -u http://TARGET -w WORDLIST -x php,asp,aspx,jsp,bak,old,zip,tar.gz,sql,swp -t 20 \
  --status-codes 200,204,301,302,401,403 --exclude-length 0 -k -o /tmp/TARGET.gob.txt
```
判定信号：`-x` 把常见备份后缀一次带上；输出里出现 `…/config.php.bak (Status: 200)` 即命中备份；出现 `(Status: 403)` 说明该路径存在被拒，可换后缀继续试（`.bak` 换成 `.old` / `~` / `.save`）。

### 4. 递归 + 备份文件专项（feroxbuster）
```bash
feroxbuster -u http://TARGET -w WORDLIST -x bak old orig save swp swo tmp zip tar.gz tgz sql 7z rar \
  -d 3 -t 30 --rate-limit 60 -C 404 --auto-tune -o /tmp/TARGET.ferox.txt
```
判定信号：`-C 404` 是通配校准开关；`--auto-tune` 在收到 429/403 时自动降并发；命中行自带状态码 + 长度 + 深度，深度 ≥ 2 的命中优先人工复核（往往是 `/backup/`、`/db/`、`/_old/`）。

### 5. 备份与敏感文件清单（顺序即优先级）
```bash
# 5.1 源码/配置备份：目标路径 + 单后缀
ffuf -u http://TARGET/FUZZ.bak -w WORDLIST -mc 200,403 -fs 0 -o /tmp/bak1.json
# 5.2 编辑器与交换文件
ffuf -u http://TARGET/FUZZ -w WORDLIST -mc 200,403 -fs 0 -e .swp,.swo,.save,~,.old,.orig,.tmp
# 5.3 VCS / CI / 环境
for p in .git/HEAD .git/config .svn/entries .env .env.bak .DS_Store \
         docker-compose.yml docker-compose.yml.bak .github/workflows/deploy.yml \
         WEB-INF/web.xml web.config.bak config/database.yml; do
  printf '%-34s ' "$p"; curl -s -o /dev/null -w '%{http_code} %{size_download}\n' "http://TARGET/$p"
done
# 5.4 整站/数据库导出
ffuf -u http://TARGET/FUZZ -w WORDLIST -mc 200 -fs 0 \
  -e .zip,.tar.gz,.tgz,.sql,.sql.gz,.dump,.rar
```
判定信号：
- `.git/HEAD` 返回 `200` 且正文以 `ref: refs/heads/` 开头 → 仓库可拉取（后续 `git-dumper`，超出本条范围）；返回 `403` 也算存在。
- `.env` `200` 且正文含 `=` 键值行 → 凭据面；`404` 才是真无。
- `.sql` / `.sql.gz` `200` 且长度 > 100KB → 大概率真实导出，按下节确认内容而非只看状态码。
- 全是 `200` 且长度相同 → 又是软 404，回第 0 步重校基线。

### 6. 内容判定：备份文件要到「不是 HTML 假 200」才算命中
```bash
python3 - <<'PY'
import subprocess, hashlib
HITS = ["config.php.bak", "backup.zip", "db.sql", ".git/HEAD"]   # 由 3~5 步产出填入
MAGIC = {b'PK\x03\x04': 'ZIP 常量', b'\x1f\x8b': 'GZIP 常量', b'-rw': 'tar 早期实现在此不适用',
         b'-- MySQL': 'mysqldump 注释头', b'ref: refs/heads/': 'git HEAD 引用'}
for h in HITS:
    body = subprocess.run(["curl", "-sk", f"http://TARGET/{h}"], capture_output=True).stdout
    tag = next((v for k, v in MAGIC.items() if body.startswith(k) or k in body[:4096]), None)
    print(f"{h:20s} {len(body):8d}B sha256={hashlib.sha256(body).hexdigest()[:12]} kind={tag or '未知/HTML'}")
PY
```
判定信号：`kind=未知/HTML` 且响应头/正文含 `<html` → 该 200 是错误页或登录跳转，**不算命中**；`kind` 命中 ZIP/GZIP/mysqldump/git 之一才是真备份。两个不同路径 `sha256` 完全相同 = 同一张假页面，一起丢掉。
纯 curl 降级版（无 python3 时）：
```bash
for h in config.php.bak db.sql .git/HEAD; do
  printf '%-18s ' "$h"
  curl -sk "http://TARGET/$h" | head -c 4 | od -c | head -1
done
```

### 7. 能打 → 能稳定打（并发 / 节流 / 限速绕过）
```bash
# 慢而稳：40 并发 / 80 req/s 上限 / 命中即停该前缀
ffuf -u http://TARGET/FUZZ -w WORDLIST -mc 200,301,403 -t 40 -rate 80 -p 0.1 -maxtime-job 120
# 被 429/403 之后：降并发 + 换 UA + 走代理池
ffuf -u http://TARGET/FUZZ -w WORDLIST -mc 200,301,403 -t 8 -rate 12 \
  -H 'User-Agent: Mozilla/5.0 (compatible; audit-ROLE_A)' -x http://PROXY_POOL:8080
# 分片：词表切 N 份并行，每份独立节奏
split -n l/4 WORDLIST /tmp/wl.part. && for f in /tmp/wl.part.*; do
  ffuf -u http://TARGET/FUZZ -w "$f" -mc 200,301,403 -t 15 -rate 30 -o "/tmp/out.$(basename $f).json" & done; wait
```
判定信号：`429`/`503` 出现即当前节奏过快，减半 `-rate` 重试；同一条路径在两次不同节奏下结果一致 = 稳定命中，只出现一次 = 抖动，需复跑确认。
假 404 的 403 绕过（仅在自有靶场显式验证路径解析差异时用）：`http://TARGET/./admin/`、`//admin/`、`/%2e/admin/`、`/admin%20/`、`/admin/..;/` —— 任一返回 200/301 而原路径 403，即为解析差异，按命中记录。

### 失败分支速查
| 现象 | 判据 | 处置 |
|---|---|---|
| 全站同长度 200 | 两条随机路径长度一致 | 标题即软 404：`-fs <len>` 或 `-ac`，状态码作废 |
| 全 403 | 首页亦 403 | 反代/WAF 前置：换 UA + 降速 + 试 `X-Forwarded-For: 127.0.0.1` |
| 全 429 | `Retry-After` 有值 | 读该值设 `-p`，降 `-t` 到 8 以下，上代理池 |
| 全 000 / timeout | `curl -v` 失败 | 端口/协议错或 TLS：加 `-k`，试 `https://TARGET/` |
| 303 到登录页 | `Location` 含 `login` | 该路径需认证，先取会话：`curl -c /tmp/c.txt -d 'u=ROLE_A&p=ROLE_B'`，工具加 `-b /tmp/c.txt` |

### 验证（可复现判据，跑完应得到固定结论）
```bash
# 一条命令复验整链：先校基线，再确认工具在位，再对已知命中做确定性复核
curl -s -o /dev/null -w 'baseline=%{http_code}/%{size_download}\n' http://TARGET/zz-baseline-nope/ \
 && ffuf -V && for p in .git/HEAD .env config.php.bak; do \
      printf '%-16s ' "$p"; curl -s -o /dev/null -w '%{http_code} %{size_download}\n' "http://TARGET/$p"; done
```
合格判据：`ffuf -V` 打印版本行（未装则先跑第 1 步，或走第 6 步纯 curl 降级）；三个路径中任一输出与第 0 步基线长度**不同**且非 404 → 该路径为真实命中，其余按同法排除。整链输出可原样贴进报告作证据。
