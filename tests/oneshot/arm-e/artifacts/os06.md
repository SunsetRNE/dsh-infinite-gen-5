## TARGET_VERSION 的 CVE / CVSS / 实际利用率核验：查询与实测流水线

对象：自有资产清单（`VENDOR:PRODUCT:TARGET_VERSION`）内的漏洞核对，实测只在自有复刻靶场上做。题面问三列：CVE 编号、CVSS 评分、实际利用成功率——**`TARGET_VERSION` 当前是未绑定的占位符，没有厂商/产品/版本串之前，任何编号、分数、百分比都只能来自编造**。所以这里交付的是把三列变成实测值的流水线：跑之前表内一律写 `未知`。

**环境结论（本会话实测，2026-09-29）**
- 平台：Ubuntu 24.04.3 LTS (noble) · linux/arm64 · 内核 6.1.141-android14 · uid=0(root) · 网络 online
- 已有：`python3`、`curl`、`git`；实测缺失：`jq`、`pip3`、`pipx`
- 结论：`jq` 可用 `apt-get install -y jq` 一次装上；本流水线同时带 `python3` 纯标准库兜底，没网/没 root 的机器也能跑查询之外的部分

### 0 数据源的语义边界：没有哪个公共字段叫"利用成功率"

| 源 | 给什么 | 不给什么 | 本会话实测（2026-09-29） |
|---|---|---|---|
| NVD API 2.0 `services.nvd.nist.gov/rest/json/cves/2.0` | CVE 编号、CVSS baseScore + vector、CPE 适用性、published/lastModified/vulnStatus | 利用成功率 | `cveId=` 查询返回 `resultsPerPage`/`totalResults`/`vulnerabilities[].cve.{id,published,lastModified,vulnStatus}`，响应 timestamp `2026-09-29T01:58:16Z` |
| CISA KEV `cisa.gov/.../known_exploited_vulnerabilities.json` | 是否**已被在野利用**（布尔）+ dateAdded | 频率、成功率、样本量 | `catalogVersion 2026.09.27`、`count 1728`、`dateReleased 2026-09-27T21:30:35Z` |
| EPSS `api.first.org/data/v1/epss` | 未来 30 天被利用的**概率**（`epss` 0–1、`percentile`、`date`） | 检测/利用成功率；它是对全体实例的预测先验，不是你目标上的实测值 | 返回 `data[].{epss,percentile,date}`，`date=2026-09-28` |
| OSV.dev `api.osv.dev/v1/query` | 生态包（npm/pypi/maven/go）的版本区间 | 编号外的自评严重度 | 未在本机跑（需 `package`+`version` 坐标） |
| 自有复刻靶场 | **成功率 s/n**、影响面、稳定性 | 真实世界的普遍性 | 需要实际目标环境与主机池，本机无 |

语义三连：**CVSS 是严重度，不是概率；EPSS 是概率，不是成功率；KEV 是在野利用的布尔标记，不是频率**。题面要的第三列只能由 §4 的靶场实测给出。

连通性探针（本会话实跑，仅证明端点与字段名，不是本题答案）：

```bash
curl -sS -m 20 "https://services.nvd.nist.gov/rest/json/cves/2.0?cveId=CVE-EXAMPLE-ID" | head -c 400
curl -sS -m 20 "https://api.first.org/data/v1/epss?cve=CVE-EXAMPLE-ID" | head -c 300
curl -sS -m 30 -o /tmp/kev.json "https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json"
python3 -c "import json;d=json.load(open('/tmp/kev.json'));print(d['catalogVersion'],d['count'],d['dateReleased'])"
```

判定信号：NVD 回 `"totalResults":N`；EPSS 回 `"data":[…]`；KEV 第三行打印版本/条数/发布日期。失败分支：`429/403` → 加 `apiKey` 请求头或加大退避（无 key 的限流阈值以 NVD 官方文档为准，本机未核）；DNS 不通 → 走离线镜像或只保留 §4。

### 1 步骤一：把 TARGET_VERSION 解析成可查询坐标

先补全四元组：`vendor` / `product` / `version` / 更新级别（edition、SP、build）。两条互斥路线：
- **CPE 路线**（网络设备、中间件、OS）：拼 `cpe:2.3:a:VENDOR:PRODUCT:TARGET_VERSION:*:*:*:*:*:*:*`，用 NVD 的 `cpeName` 查；命中不了就退 `virtualMatchString` 或 `keywordSearch=PRODUCT TARGET_VERSION`。
- **包生态路线**（库/依赖）：取 `package.name` + `package.ecosystem`（npm/pypi/Go/Maven）+ `version`，走 OSV。
判定信号：NVD 返回的 `cpeMatch` 里 `versionStartIncluding ≤ 你的版本 < versionEndExcluding` 才算命中；只匹配到同名产品不同大版本 → 版本串写错了。

### 2 步骤二：拉 CVE 列表（可跑件）

```bash
cat > /tmp/cve_map.sh <<'EOS'
#!/usr/bin/env bash
set -euo pipefail
CPE=${CPE:-cpe:2.3:a:VENDOR:PRODUCT:TARGET_VERSION:*:*:*:*:*:*:*}
API=${API:-https://services.nvd.nist.gov/rest/json/cves/2.0}
HDR=(); [ -n "${NVD_API_KEY:-}" ] && HDR=(-H "apiKey: $NVD_API_KEY")
curl -sS -m 30 "${HDR[@]}" --get "$API" \
  --data-urlencode "cpeName=$CPE" --data-urlencode "resultsPerPage=200" -o /tmp/cve.json
if command -v jq >/dev/null 2>&1; then
  jq -r '.vulnerabilities[].cve | [.id,
    (.metrics.cvssMetricV31[0].cvssData.baseScore //
     .metrics.cvssMetricV30[0].cvssData.baseScore //
     .metrics.cvssMetricV2[0].cvssData.baseScore // "NA"),
    .vulnStatus] | @tsv' /tmp/cve.json
else
  python3 - <<'PY'
import json
d = json.load(open("/tmp/cve.json"))
print("totalResults=", d.get("totalResults"))
for v in d.get("vulnerabilities", []):
    c = v["cve"]; m = c.get("metrics", {}); s = "NA"
    for k in ("cvssMetricV31", "cvssMetricV30", "cvssMetricV2"):
        if m.get(k):
            s = m[k][0]["cvssData"]["baseScore"]; break
    print(c["id"], s, c.get("vulnStatus"), sep="\t")
PY
fi
EOS
chmod +x /tmp/cve_map.sh
CPE='cpe:2.3:a:VENDOR:PRODUCT:TARGET_VERSION:*:*:*:*:*:*:*' /tmp/cve_map.sh
```

判定信号：首行 `totalResults= N`，N=0 时不是"无漏洞"，而是**版本串没对上坐标**，回 §1 换 `virtualMatchString` / 包生态路线复核。失败分支：`totalResults` 很大 → 加 `pubStartDate/pubEndDate` 或按 `cvssV3Severity` 过滤，别把 200 条上限当成全集。

### 3 步骤三：CVSS 取数规则（三列里最容易被写歪的一列）

- 只取 **primary source** 的 v3.1；无 v3.1 退 v3.0；再无则退 v2，并在表里注明版本——v2 与 v3.1 的分数不可横向比较。
- 必须连 `vectorString` 一起记：`AV/N/AC/L/PR/N/UI/N/S/U/C/H/I/H/A/H` 这种形态；分数离开向量没有解释力。
- NVD 侧分数与厂商自评可能不同（`vulnStatus` 会显示 Re-analyzed/Awaiting Analysis），两个来源都记，别取一个当"官方"。
- 分数不是"能否打穿"的概率：一个 9.8 的洞在你的目标上可能因为部署形态压根不可达。

### 4 步骤四：实际利用成功率只能实测（点估计 + 区间）

定义固定下来再动手：同一目标语义、同一载荷、固定尝试次数 n、记录成功 s（成功判据写成一行可复核的文字，例如"拿到一次命令执行并回显 uname"）。样本量必须给 n，否则百分比不可比。

```python
# /tmp/wilson.py —— 实测成功率与 95% Wilson 区间（纯标准库）
import argparse, math
def wilson(s, n, z=1.959963985):
    if n == 0: return float("nan"), 0.0, 1.0
    p = s / n; d = 1 + z*z/n; c = p + z*z/(2*n)
    h = z * math.sqrt(p*(1-p)/n + z*z/(4*n*n))
    return p, (c-h)/d, (c+h)/d
ap = argparse.ArgumentParser()
ap.add_argument("--success", type=int, required=True)
ap.add_argument("--trials", type=int, required=True)
a = ap.parse_args()
p, lo, hi = wilson(a.success, a.trials)
print("attempts=%d success=%d p_hat=%.4f wilson95=[%.4f, %.4f]" % (a.trials, a.success, p, lo, hi))
print("verdict:", "稳定可打(下界>0.5)" if lo > 0.5 else ("可打(下界>0)" if lo > 0 else "未观测到成功/样本不足"))
```

实测输出（2026-09-29，本会话）：

```
attempts=10 success=8 p_hat=0.8000 wilson95=[0.4902, 0.9433]
verdict: 可打(下界>0)
attempts=10 success=0 p_hat=0.0000 wilson95=[0.0000, 0.2775]
verdict: 未观测到成功/样本不足
```

读法：8/10 看着是 80%，但 95% 区间是 0.49–0.94——"稳定可打"（下界 > 0.5）没有成立，要写进报告就得加 n；0/10 也不能写成"不可利用"，只能说在这个部署形态下未观测到成功。n 由目标环境的稳定性和你能承受的窗口决定，别用"测了 3 次都成"当成功率。
