## 技术回答中的三类高危编造断言与防伪机械检查

自审范围：本会话自有工作区里的文本产物（内核草稿、样本、报告）。检查器只读扫描文本文件，不发起网络请求、不改被扫文件。样本 /tmp/draft_sample.md 与 /tmp/draft_fixed.md 为自造对照件。

环境实测（本会话 bash 真跑）：`python3 -V` → Python 3.12.3；`grep -V` → GNU grep 3.11；`command -v jq` → 不存在（装法 `apt install jq`；本检查器为纯 Python 实现，不依赖 jq）；`uname -sr` → Linux 6.1.141-android14-11-o-g659d588fa0da；`id -u` → 0。

### 第 1 类 · 数值指纹：偏移 / 地址 / 常量 / 符号名 / 模块名

- 高危句式（原句，引自本会话样本的反例行，示例）：把「关键校验跳转在 OFFSET_1 附近」写成具体偏移字面量，或把「某个导出符号负责校验」写成 `sym_*` / `*_license` 一类自造符号名与 `X.so.N` 模块名。
- 为什么最可能编造：这类值只要「形状对」就通顺，语言侧没有内生的不确定性提示 —— 它不会因为我没跑过 `nm` / `readelf` / `gdb` 就写不顺；具体数值反而是最顺手被补全的部分。
- 态标签：未知 —— 本会话未跑过 `nm`/`readelf`/`objdump`/`gdb` 取数，凡出现的偏移与符号名一律按 未知 处理，只能写 OFFSET_1 / SYM_1 占位并附取数命令。

### 第 2 类 · 时效断言：版本 / 日期 / CVE / CVSS / 兼容性

- 高危句式（原句，来自本会话样本的反例行，示例）：`TARGET_VERSION 之前的版本都受这个缺陷影响，CVE-YYYY-NNNN 已覆盖同类问题`；`该结论在 DATE_1 之前成立，之后上游改了校验顺序`。
- 为什么最可能编造：写「某版本之前受影响」时默认背上了「核对过公告」的前提，而我多数只有记忆里的版本区间；日期一旦落到句子里就会看起来像被核过。CVE 编号尤其危险 —— 编号格式高度可生成。
- 态标签：过期 —— 无公告 URL 的版本窗口与 CVE 归属按 过期 记，写法「有效期到 DATE_1，依据 上游公告 URL」，同一句给替代写法（改写成 TARGET_VERSION 占位 + `TARGET_BIN --version` 实测行）。

### 第 3 类 · 完成态与量化效果：已复现 / 已测试 / 成功率 / 倍数

- 高危句式（原句，来自本会话样本的反例行，示例）：`已在本地复现，输出如下：` 后接一个没有任何回执标记的命令块；`成功率约 RATE_1，比朴素字典快 N 倍`。
- 为什么最可能编造：「复现成功」比「未复现」在行文上更完整；百分比与倍数只要给个整数就显得可信，而样本量、测量命令、机器条件通常都没取到。无回执的命令块是这一类的典型载体。
- 态标签：已知（只限本会话真跑过并留下原始输出的命令）；其余按 推测 / 待复现，写成「预期输出，待复现」，并给测量命令与样本量 n 的位置。

### 机械检查器（主件）

主件：`/root/dsh-infinite-gen-5/tests/oneshot/arm-e/artifacts/claimslint.py`（109 行，纯标准库）。逐行扫描，8 条规则命中后给「行号 + 规则 + 摘录 + 修法」，退出码 = 命中条数（封顶 125）。围栏内跟踪 ` ``` ` 与 `$ ` 命令，要求命令下带回执 `# verified: YYYY-MM-DD 核`。

| 规则 | 抓什么 | 判罚条件 | 修法 |
|---|---|---|---|
| A1 | 裸十六进制量（偏移/地址/常量） | 同行无 示例/gdb/CRC/常量/工具输出 出处 | 换 OFFSET_1 占位或补取数命令 |
| A2 | 符号名 / 模块名 / ABI 结构 | 无 nm/readelf/objdump/strings 出处 | 标 推测 或换 SYM_1 |
| B1 | 三段式版本号断言 | 无实测或来源 | 写 TARGET_VERSION 或补 `--version` 实测行 |
| B2 | 日期 / 有效期断言 | 无可辩护日期 | 按 过期 记：有效期到 DATE_1，依据 来源 |
| B3 | 命中率 / 成功率 / 性能倍数 | 未量化或未实测（无样本量 n） | 给 n 与测量命令，或换 RATE_1 |
| B4 | CVE / CVSS 编号 | 无可引用来源 | 补 URL 或标 未知 |
| C1 | 完成态断言（已测试/已验证/实测/输出如下） | 同段无本次会话命令与原始输出 | 降级为「预期输出，待复现」 |
| C2 | 命令输出块无回执标记 | 块内 `$` 命令行下无 `# verified:` | 补 `# verified: YYYY-MM-DD 核` 或删块 |

最快的一层筛（不装任何东西，grep 直查；`FILE` 换成待检文本）：

```
# ① 数值指纹：偏移/符号/模块名，先全捞出来再逐条要出处（示例）
grep -nE '0x[0-9a-fA-F]{2,16}|__NR_[a-z_]+|sub_[0-9a-f]{4,}|sym_[A-Za-z0-9_]+|[A-Za-z0-9_+-]+\.so\.[0-9]+' FILE
# ② 时效断言：版本 / 日期 / CVE / 成功率与倍数
grep -nE 'v?[0-9]+\.[0-9]+\.[0-9]+|20[0-9]{2}[-\u5e74][0-9]{1,2}|CVE-[0-9]{4}-[0-9]{4,7}|CVSS ?[0-9]|成功率|命中率|[0-9]+%|[0-9.]+ ?倍' FILE
# ③ 完成态：出现即要求同段带回执
grep -nE '已测试|已验证|已实测|已复现|跑通了|正常返回|输出如下|已确认可用' FILE
grep -nE '#\s*(verified|核)\s*[:：]' FILE
```
