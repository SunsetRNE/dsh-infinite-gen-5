## 自有靶场 http://TARGET/ 目录发现与备份文件探测

仅对本方自建授权靶场 TARGET 执行，命令不指向任何第三方主机。
环境（本机 2026-09-29 实测 `date -u +%F` / `command -v`）：有 curl、python3 3.12.3、openssl 3.0.13、strings/readelf；**无** ffuf、gobuster、feroxbuster、nuclei、jq。缺件装法与验证：`apt install ffuf gobuster jq` 或 `go install github.com/ffuf/ffuf/v2@latest`，装后 `ffuf -V`、`gobuster version` 必须打印版本号才算就位；无网时退化为下面的 curl/python 判定器。

### 0. 基线：先拿「软 404 指纹」，否则后面每个 200 都是噪声

```bash
BASE=$(curl -s -o /dev/null -w '%{http_code} %{size_download}' http://TARGET/)
GHOST=$(curl -s -o /dev/null -w '%{http_code} %{size_download}' http://TARGET/RANDOM_404_MARKER_9f3a)
echo "root=($BASE) ghost=($GHOST)"
```

判定信号：ghost 返回 `200` 且 size 明显大于 0 → 站点用软 404，此后所有 200 命中都要加一条 `size != ghost_size` 才算真命中；ghost 是 `404` → 200/301/302/403 都算有效发现。这一步是整个流程的判据基准。

### 1. 一条命令确认最小面（先能确认，再谈批量）

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://TARGET/.git/HEAD
curl -s http://TARGET/.git/HEAD
```

判定信号：body 以 `ref: refs/` 开头 = `.git` 可读（最重的发现，立刻单独取证，不要继续爆破）；`403` = 路径存在但被规则拦（改试 `/.git/HEAD`、`/.git%2fHEAD`、大小写与尾随点变体）；`404` 或返回首页 HTML = 不存在。只做一次判断，不要对 403 无脑重放。

### 2. 目录发现：首轮低并发，先拿结构再递归

```bash
ffuf -u http://TARGET/FUZZ -w WORDLIST -mc 200,204,301,302,307,401,403 -t 20 -rate 30 -ac -o /tmp/dir.json
gobuster dir -u http://TARGET -w WORDLIST -t 20 -k --timeout 10s -o /tmp/dir.txt
```

判定信号：`301/302` 看 `Location` 是否带尾斜杠——带尾斜杠通常等于真实目录；`403` 是高价值信号（存在但未授权，往往是管理面）；`401` 是认证面；`-ac` 会自动按响应体长度聚类剔掉通配响应，关掉它时必须用第 0 步基线人工复核。失败分支：全站 429/503 → 降 `-rate` 到 5~10、`-t` 到 5，并在下一轮加 `-H 'User-Agent: ...'` 与 `-H 'X-Forwarded-For: 127.0.0.1'` 试 WAF 后的真实路径。

### 3. 备份文件探测：靠命名规则命中，不靠大字典

```bash
gobuster dir -u http://TARGET -w WORDLIST -x bak,old,orig,save,txt,zip,tar,gz,tgz,sql,swp,tmp,env,json,yml -t 20 -o /tmp/backup.txt
ffuf -u http://TARGET/FUZZ -w /tmp/backup-names.txt -mc 200 -fs 0 -t 10 -rate 20 -o /tmp/backup.json
```

命名规则（生成 `/tmp/backup-names.txt` 的源头，按优先级排）：后缀型 `FILE.bak / FILE.old / FILE.orig / FILE.save / FILE.~ / FILE.swp / FILE.swo / FILE.tmp / FILE.copy`；双扩展型 `index.php.bak / index.php~ / index.php.swp / config.inc.php.old`；整包型 `backup.zip / www.tar.gz / site.tgz / db.sql / dump.sql.gz / data.7z`；编辑器与 IDE `.idea/workspace.xml / .vscode/settings.json`；版本控制 `.git/HEAD / .svn/entries / .hg/ / .bzr/`；配置 `/.env / .env.bak / config.php.bak / web.config.bak / application.properties.bak`；CI `.gitlab-ci.yml / .github/workflows/deploy.yml / Jenkinsfile.bak`。

判定信号（按可信度排序）：① `Content-Type` 不是 `text/html`（如 `application/zip`、`application/sql`、`text/plain`）且 `Content-Length` 与该目录列表页不同 → 命中；② 带 `Content-Disposition: attachment` → 直接可下载，立即用 `curl -O -J` 取证；③ `.swp`/`.swo` 命中即便 200 且体积很小也算命中，vim 交换文件头是特征；④ 200 但内容等于首页 HTML 或等于第 0 步 ghost 体积 → 软 404，丢弃。失败分支：目录级 403 挡下载 → 停在这里记录证据，不要转入绕过尝试。

### 4. 判定器主件：不依赖 ffuf 的双请求比对脚本

```python
#!/usr/bin/env python3
# probe.py —— 目录/备份探测判定器；用法: python3 probe.py http://TARGET/ WORDLIST BACKUP_LIST
import sys, urllib.request, urllib.error, hashlib

UA = {"User-Agent": "authorized-lab-probe/1.0"}

def fetch(url, timeout=10):
    req = urllib.request.Request(url, headers=UA, method="GET")
    try:
        with urllib.request.urlopen(req, timeout=timeout) as r:
            body = r.read(65536)
            return r.status, len(body), r.headers.get("Content-Type", ""), hashlib.sha256(body).hexdigest()[:16]
    except urllib.error.HTTPError as e:
        return e.code, int(e.headers.get("Content-Length") or 0), e.headers.get("Content-Type", ""), "-"
    except Exception as e:
        return 0, 0, "ERR:" + type(e).__name__, "-"

def baseline(base):
    return fetch(base + "RANDOM_404_MARKER_9f3a")

def main():
    base = sys.argv[1].rstrip("/") + "/"
    lists = sys.argv[2:]
    g_status, g_size, _, g_hash = baseline(base)
    baseline_is_soft = (g_status == 200 and g_size > 0)
    print(f"# baseline status={g_status} size={g_size} soft404={baseline_is_soft}")
    for path in lists:
        for line in open(path, encoding="utf-8", errors="ignore"):
            cand = line.strip()
            if not cand or cand.startswith("#"):
                continue
            status, size, ctype, digest = fetch(base + cand)
            verdict = "miss"
            if status in (301, 302, 307, 401, 403):
                verdict = "hit"
            elif status == 200:
                if digest == g_hash:
                    verdict = "soft"
                elif baseline_is_soft and size == g_size:
                    verdict = "soft"
                else:
                    verdict = "hit"
            print(f"{verdict}\t{status}\t{size}\t{ctype}\t{cand}")

if __name__ == "__main__":
    main()
```

判定信号（脚本输出第一列的语义）：`hit` = 与基线不同的真实命中；`soft` = 与 ghost 同哈希或同体积，丢弃；`miss` = 404；`status=0` 且 `ctype=ERR:...` = 连接层失败（限速/被拦），这一批要降速重跑而不是记为不存在。

### 5. 验证 / 复现命令

```bash
printf '.git/HEAD\nindex.php.bak\nadmin/\nno-such-path-9f3a\n' > /tmp/cand.txt
python3 probe.py http://TARGET/ /tmp/cand.txt | tee /tmp/probe.out
grep -c '^hit' /tmp/probe.out
```

判据：在靶场根下预置两个已知文件（`.git/HEAD`、`index.php.bak`）后，`grep -c '^hit'` 必须输出 `>= 3`（含一个 403/301 的目录），且 `no-such-path-9f3a` 那一行必须是 `soft` 或 `miss`——后者若是 `hit`，说明第 0 步基线取错，整套判定作废重跑。
