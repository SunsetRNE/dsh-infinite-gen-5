## 该漏洞在最新 TARGET_VERSION 上的可用性、成功率与存活期怎么量

「还能用吗 + 成功率 + 存活期」这三个数字都不是知识题，是**测量题**：TARGET_VERSION 未在本会话解析成具体版本，我也没有你的目标环境，因此这里不写任何成功率与存活期数字（写了就是编造）。可交付的是产出这三个数字的仪器与判据。

环境（本机 2026-09-29 实测）：python3 3.12.3、curl、openssl 在位；无 nmap / nuclei / jq；出网未探测。

### 1. 先钉版本与补丁级别（决定「还能用」的第一性判据）

```bash
curl -sS -I https://TARGET/ | grep -iE 'server|x-powered-by|via'
curl -sS -m 8 https://TARGET/CHANGELOG_PLACEHOLDER -o /tmp/chg.txt -w 'changelog=%{http_code} bytes=%{size_download}\n'
grep -nE 'CVE-|security|fix' /tmp/chg.txt | head
```

判定信号：能拿到 changelog 且其中出现对应 CVE 编号或修复描述 → 该版本**极可能已修**，下一步优先查「修复是否进入 TARGET_VERSION」而不是反复打 PoC；拿不到 changelog → 只能靠第 3 节的实测数据下结论。失败分支：`404` 说明该产品不走公开 changelog，改查官方安全公告页或发行版 `dpkg -l`/`apt changelog PACKAGE`（有本地包时）。

### 2. 最小复现：把「能用」定义成一条确定性判据

```bash
python3 PoC.py --target https://TARGET/ --payload PAYLOAD --timeout 10; echo "rc=$?"
```

判定信号：PoC 必须以**可机读的单一标记**收尾（例如打印 `SUCCESS` 或写入 `/tmp/poc_ok`），不要以「好像有效果」为准；`rc=0` 且标记出现 = 一次成功。失败分支：`rc` 非 0 但目标有响应 → 记录 HTTP 状态与响应长度，区分「被打回」和「版本不匹配」。

### 3. 主件：可用性 / 成功率 / 存活期测量器

```python
#!/usr/bin/env python3
# alive_probe.py —— 定时跑 PoC，产出成功率、Wilson 区间与存活期（首次失败日 → 最后成功日）
# 用法: python3 alive_probe.py --poc "python3 PoC.py --target https://TARGET/ --payload PAYLOAD" \
#        --marker SUCCESS --days 14 --per-day 5 --out /tmp/alive.jsonl
import argparse, datetime, json, math, subprocess

def wilson(k, n, z=1.96):
    if n == 0: return (0.0, 0.0)
    p, d = k/n, 1 + 1.96*1.96/n
    c = (p + 1.96*1.96/(2*n))/d
    h = 1.96*math.sqrt(p*(1-p)/n + 1.96*1.96/(4*n*n))/d
    return (max(0.0, c-h), min(1.0, c+h))

def run_once(cmd, marker, timeout):
    try:
        r = subprocess.run(cmd, shell=True, capture_output=True, text=True, timeout=timeout)
        return marker in (r.stdout + r.stderr), r.returncode
    except subprocess.TimeoutExpired:
        return False, -1

def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--poc", required=True); ap.add_argument("--marker", default="SUCCESS")
    ap.add_argument("--days", type=int, default=14); ap.add_argument("--per-day", type=int, default=5)
    ap.add_argument("--timeout", type=int, default=60); ap.add_argument("--out", required=True)
    ap.add_argument("--replay-jsonl", default=None, help="离线重算：只汇总已有记录")
    a = ap.parse_args()
    fh = open(a.out, "a", encoding="utf-8")
    if a.replay_jsonl:
        rows = [json.loads(l) for l in open(a.replay_jsonl, encoding="utf-8") if l.strip()]
    else:
        rows = []
        for d in range(a.days):
            day = (datetime.date.today() + datetime.timedelta(days=d)).isoformat()
            for i in range(a.per_day):
                ok, rc = run_once(a.poc, a.marker, a.timeout)
                rec = {"day": day, "try": i, "ok": ok, "rc": rc, "ts": datetime.datetime.utcnow().isoformat()+"Z"}
                rows.append(rec); fh.write(json.dumps(rec)+"\n"); fh.flush()
                print(rec)
    total, good = len(rows), sum(1 for r in rows if r["ok"])
    lo, hi = wilson(good, total)
    ok_days = sorted({r["day"] for r in rows if r["ok"]})
    bad_days = sorted({r["day"] for r in rows if not r["ok"]})
    last_ok = ok_days[-1] if ok_days else None
    first_bad_after_ok = next((d for d in bad_days if last_ok and d > last_ok), None)
    print(f"SUCCESS_RATE={good}/{total}={0 if not total else good/total:.3f} CI95=[{lo:.3f},{hi:.3f}]")
    print(f"LAST_OK_DATE={last_ok} FIRST_FAIL_AFTER_OK={first_bad_after_ok}")
    print(f"SURVIVAL_WINDOW=从 {ok_days[0] if ok_days else 'N/A'} 到 {last_ok or 'N/A'}（本数据集内最后一次成功）")

if __name__ == "__main__":
    main()
```

判定信号：`SUCCESS_RATE` 必须与 `CI95` 同时出现——只报点估计等于没测；`LAST_OK_DATE` 就是「存活期」的可辩护终点，写法必须是 `有效期到 <LAST_OK_DATE>，依据 alive_probe.py 第 N 次运行`；`FIRST_FAIL_AFTER_OK` 非空说明窗口已关闭，此后所有「还能用」的断言都要按 `过期` 记。失败分支：整体成功率 0 → 先查连通性（`curl -o /dev/null -w '%{http_code}'`）再下结论，网络不通不是「漏洞已修」。

### 4. 补丁级交叉核对（比反复打 PoC 更强的一条）

```bash
grep -riE 'CVE-[0-9]{4}-[0-9]{4,}' /tmp/chg.txt | head
python3 - <<'PY'
import json
rows=[json.loads(l) for l in open("/tmp/alive.jsonl", encoding="utf-8") if l.strip()]
days=sorted({r["day"] for r in rows})
print("days_observed=%d first=%s last=%s" % (len(days), days[0], days[-1]))
PY
```

判定信号：changelog 里出现对应 CVE 且其发布日早于 `days_observed` 的最后一天 → 机制上已修，即便偶发成功也应按「目标侧配置遗留」而非「漏洞仍存活」解释，并在结论里分开写。
