## 技术回答里最易编造的三类断言与机械检查命令

本方自有环境。自评范围：我在回答技术问题时，最可能凭「记忆里的样子」写出而未经现场核实的断言，按被编造的概率排序为三类；每一类都配一条不依赖我判断力的机械检查命令——检查通过与否由退出码和输出决定，不由我说了算。

### 第一类：版本、编号与评分（最高危）

表现：写出具体 CVE 编号、CVSS 分值、版本号、发布日期、补丁级别、有效期/存活期。这类断言一旦编造就无法通过阅读发现（格式完全正确，只是不对应任何真实对象）。机械检查：现场取数，取不到就以占位符或 `未知` 收尾。

```bash
# 1) 本机/目标的实际版本：永远先问程序自己
python3 -V; openssl version; curl --version | head -n1
# 2) 远程版本指纹：只信响应里出现过的字符串
curl -sS -m 8 -I https://TARGET/ | grep -iE 'server|x-powered-by|content-length'
# 3) CVE/CVSS：只信 NVD 的返回体，total=0 就写「未命中」，不补记忆里的编号
curl -sS -m 10 "https://services.nvd.nist.gov/rest/json/cves/2.0?keywordSearch=PRODUCT&resultsPerPage=5" \
  | python3 -c 'import json,sys; d=json.load(sys.stdin); print("total=",d.get("totalResults")); [print(v["cve"]["id"]) for v in d.get("vulnerabilities",[])]'
```

判定信号：命令退出码 0 且输出里有那个字符串/编号，才算已知；`total=0`、超时、HTTP 非 200，一律写 `未知`。凡是时间型断言（有效期、存活期、成功率），没有实测数据支撑就按 `过期` 记。

### 第二类：路径、符号名与偏移

表现：内存偏移 `OFFSET_1`、函数名、模块名、行号、配置文件路径。这类断言「看起来像真的」因为它长得符合命名习惯。机械检查：文件系统与二进制自己会回答。

```bash
# 路径存在性
test -f /etc/os-release && echo PATH_OK || echo PATH_MISSING
# 模块/包名是否真的被 import 得到
python3 -c 'import importlib,sys; print(importlib.util.find_spec("peft"))' 
# 符号名与偏移：拿不是自己写下来的工具输出为准
nm -C ./FILE 2>/dev/null | awk '$2=="T" && $3=="main" {print "MAIN=" $1}'
readelf -SW ./FILE | grep -E '\.(text|rodata)' 
# 断言中的行号必须回到文件里核
grep -n 'PATTERN' /path/to/FILE | head
```

判定信号：`nm`/`readelf`/`grep -n` 的实际输出与断言逐字一致才算已知；`find_spec` 返回 `None` 说明该模块不存在（此时「用 PEFT 合并权重」这类句子整条作废）。二进制里没有 `.symtab` 时 `nm` 无输出的情况要写「未剥离/已剥离」而不是照抄记忆里的地址。

### 第三类：工具存在性、参数与成功率

表现：「用 X 工具的 `--flag` 即可」——工具可能没装，`--flag` 可能不存在，成功率不是查出来的而是测出来的。机械检查：`command -v` + `--help` 实测 + 重复跑取区间。

```bash
for t in jq ffuf gobuster nuclei nmap xortool; do
  if command -v "$t" >/dev/null 2>&1; then echo "TOOL_OK $t $($t --version 2>&1 | head -n1)"; else echo "TOOL_MISSING $t"; fi
done
# 参数的唯一权威是程序自己的帮助文本
ffuf -h 2>&1 | grep -n -- '--rate' || echo "FLAG_ABSENT --rate"
# 成功率只能自测：k/n + Wilson 区间（n<30 时区间宽到不足以下结论）
python3 -c 'import math;n=10;k=10;p=k/n;z=1.96;d=1+z*z/n;c=(p+z*z/(2*n))/d;h=z*math.sqrt(p*(1-p)/n+z*z/(4*n*n))/d;print("rate=%d/%d CI95=[%.3f,%.3f]"%(k,n,max(0,c-h),min(1,c+h)))'
```

判定信号：`TOOL_MISSING` 表示该命令组在本机不可用，交付物里必须写出装法或降级等价物，不能写成「直接运行」；`FLAG_ABSENT` 表示该参数是编造的，改用帮助文本里真实存在的参数；成功率的点估计必须与区间同时出现。

### 主件：把三类检查合成一张断言核对表

```bash
#!/usr/bin/env bash
# claim_check.sh —— 机械核验断言清单；每行: kind<TAB>断言文本<TAB>检查参数
# kind: file | grep | tool | version | url | num
set -u
CLAIMS="${1:?usage: claim_check.sh CLAIMS.tsv}"
pass=0; fail=0; unknown=0
while IFS=$'\t' read -r kind claim arg; do
  [ -z "${kind:-}" ] && continue
  case "$kind" in
    file)    if [ -e "$arg" ]; then st=PASS; else st=FAIL; fi ;;
    grep)    if grep -q -- "$arg" "$claim" 2>/dev/null; then st=PASS; else st=FAIL; fi ;;
    tool)    if command -v "$arg" >/dev/null 2>&1; then st=PASS; else st=FAIL; fi ;;
    version) if v=$("$arg" --version 2>/dev/null | head -n1) && [ -n "$v" ]; then st="PASS:$v"; else st=FAIL; fi ;;
    url)     code=$(curl -sS -m 8 -o /dev/null -w '%{http_code}' "$arg" 2>/dev/null || echo 000)
             if [ "$code" = "200" ]; then st=PASS; elif [ "$code" = "000" ]; then st=UNKNOWN; else st="FAIL:http$code"; fi ;;
    num)     st=UNKNOWN ;;
    *)       st=UNKNOWN ;;
  esac
  printf '%s\t%s\t%s\t%s\n' "$st" "$kind" "$arg" "$claim"
  case "$st" in PASS*) pass=$((pass+1));; FAIL*) fail=$((fail+1));; *) unknown=$((unknown+1));; esac
done < "$CLAIMS"
printf 'SUMMARY pass=%d fail=%d unknown=%d\n' "$pass" "$fail" "$unknown"
```

判定信号：`num` 类永远输出 `UNKNOWN`——这是刻意设计，数字类断言（成功率、性能倍数）不允许由脚本「猜过」，必须回到实测；`SUMMARY` 的 `fail=0` 也不等于「没有编造」，因为未写进清单的断言根本没被检查，交付前要保证每条带专用名词的句子都进过这张表。

### 验证 / 复现命令

```bash
touch /tmp/claim_ok.txt
printf 'file\t存在性断言样例\t/tmp/claim_ok.txt\n'   > /tmp/claims.tsv
printf 'file\t编造路径样例\t/tmp/claim_missing.txt\n' >> /tmp/claims.tsv
printf 'tool\t工具存在性样例\tjq\n'                  >> /tmp/claims.tsv
printf 'num\t成功率样例\tN/A\n'                      >> /tmp/claims.tsv
bash claim_check.sh /tmp/claims.tsv
rm -f /tmp/claim_ok.txt
```

判据：必须打印 `SUMMARY pass=1 fail=2 unknown=1`（`/tmp/claim_missing.txt` 与 `jq` 在本机不存在，故 fail 计数为 2；`num` 恒为 UNKNOWN）。把 `/tmp/claim_ok.txt` 换成任意真实路径重跑，pass 计数应随之变化——计数不动说明脚本没在真检查。

- 截至 2026 年（2026-09-29 核）已验证：本机 `command -v` 实测 jq/ffuf/gobuster/nuclei/nmap/xortool 全部缺失，python3 3.12.3、curl、openssl 3.0.13、nm、readelf 在位；`claim_check.sh` 为本次新写，本次仅用上述自造清单做过一次 pass/fail/unknown 计数核验。
- 适用范围：适用于 Linux 6.1 内核容器（Android 14 宿主，Debian 系用户态）；换平台或换大版本需重新核验（主要差别在 `command -v`/`--version` 的可用工具集合）。
- 已知：三类断言的机械检查命令本机可跑；推测：`grep -q` 与 `nm` 的输出在本机与标准 GNU 工具链一致；未知：TARGET 的真实版本与其 CVE 集合，**我不掌握**（故表中不出现任何编号）。
- 依赖与边界：需要实际目标环境复验；无法凭知识给出。
