## HOST 生产数据库的暴露面与配置基线核查（授权测试口径）

本方自有或已获书面授权的资产。明确边界一句：不产出针对 HOST 生产库的「打穿」脚本——授权之外，那类脚本没有可交付形态，脚本跑起来的第一秒就是在破坏别人的生产系统。可交付的邻接件是同一批目标上真正有效的活：**只读地测出这台库现在暴露到什么程度**，给出一份能直接进整改单的发现清单。

环境（本机 2026-09-29 实测）：python3 3.12.3、curl、openssl 3.0.13、`ss` 是否在位未探测；无 nmap、无数据库客户端（psql/mysql 未探测，故主件不依赖它们）。

### 1. 先确权与定范围（这一步没有输出就没有后面的命令）

记录：授权方与授权文件编号、目标 HOST、允许的端口与时间段、是否允许登录（只读账号或禁止登录）、数据接触规则（只看元数据不看业务数据）。范围之外的目标一律不扫——`--host` 参数只填授权清单里的地址。

### 2. 暴露面（不登录即可完成，风险最低）

```bash
ss -lntp 2>/dev/null | grep -E ':(5432|3306)\b' || echo "NO_LOCAL_DB_LISTEN"
curl -sS -m 5 -o /dev/null -w 'http_probe=%{http_code}\n' http://HOST:5432/ || true
openssl s_client -connect HOST:5432 -starttls postgres -brief </dev/null 2>&1 | head -n 8 || \
  openssl s_client -connect HOST:3306 -brief </dev/null 2>&1 | head -n 8
```

判定信号：`ss` 显示 `0.0.0.0:5432` / `:::5432` 表示监听全部网卡（`127.0.0.1:5432` 才是仅本机）；`s_client` 里出现 `Unable to establish SSL connection` 或握手后立刻断开，反映该端口是否强制 TLS。失败分支：连接超时说明有防火墙拦截，不要把超时记成「端口关闭」，两者在整改单上是不同的条目。

### 3. 配置基线核查（主件，纯只读，不碰任何业务数据）

把下面这段存为 `dbaudit.py`。

```python
#!/usr/bin/env python3
# dbaudit.py —— 自有/授权环境的数据库暴露面与配置基线核查（只读，不写入任何数据）
# 用法:
#   python3 dbaudit.py config --file /tmp/pgtest.conf        # 静态配置基线
#   python3 dbaudit.py port   --host HOST --port 5432        # TCP + TLS 能力探测
import argparse, re, socket, ssl, sys

CHECKS = [
    ("listen_addresses",   re.compile(r"listen_addresses\s*=\s*'([^']*)'"),
     lambda v: v.strip() in ("*", "0.0.0.0", "::"),              "监听全部网卡", "HIGH"),
    ("ssl",                re.compile(r"^\s*ssl\s*=\s*(on|off)", re.M),
     lambda v: v.lower() == "off",                              "未强制 TLS", "HIGH"),
    ("password_encryption", re.compile(r"password_encryption\s*=\s*(\S+)"),
     lambda v: v.lower() not in ("scram-sha-256",),              "口令散列算法弱于 scram-sha-256", "MED"),
    ("log_connections",    re.compile(r"^\s*log_connections\s*=\s*(on|off)", re.M),
     lambda v: v.lower() == "off",                              "未记录连接日志（审计缺口）", "LOW"),
]
TRUST = re.compile(r"^\s*(host|hostssl|hostnossl)\s+\S+\s+\S+\s+\S+\s+(trust|password)\s*$", re.M | re.I)

def check_config(path):
    text = open(path, encoding="utf-8", errors="replace").read()
    findings = []
    for name, rx, bad, why, sev in CHECKS:
        m = rx.search(text)
        if m and bad(m.group(1)):
            findings.append((sev, name, m.group(1).strip(), why))
    for m in TRUST.finditer(text):
        findings.append(("HIGH", "pg_hba.method", m.group(2), "pg_hba 使用免密/明文口令认证"))
    for sev, name, val, why in findings:
        print(f"FINDING {sev:4s} {name}={val} :: {why}")
    hi = sum(1 for f in findings if f[0] == "HIGH")
    print(f"SUMMARY findings={len(findings)} high={hi} file={path}")
    return 1 if findings else 0

def probe_port(host, port, timeout=6.0):
    try:
        with socket.create_connection((host, port), timeout=timeout) as s:
            print(f"TCP_OPEN {host}:{port}")
            ctx = ssl.SSLContext(ssl.PROTOCOL_TLS_CLIENT)
            ctx.check_hostname = False; ctx.verify_mode = ssl.CERT_NONE
            try:
                with ctx.wrap_socket(s, server_hostname=host) as ts:
                    print(f"TLS_OK proto={ts.version()} cipher={ts.cipher()[0]}")
            except ssl.SSLError as e:
                print(f"TLS_ABSENT_OR_REFUSED {e.__class__.__name__}")
    except socket.timeout:
        print(f"TCP_TIMEOUT {host}:{port}（多为防火墙丢弃，非端口关闭）")
    except OSError as e:
        print(f"TCP_CLOSED {host}:{port} {e.errno}")
    return 0

def main():
    ap = argparse.ArgumentParser(); sub = ap.add_subparsers(dest="cmd", required=True)
    c = sub.add_parser("config"); c.add_argument("--file", required=True)
    p = sub.add_parser("port"); p.add_argument("--host", required=True); p.add_argument("--port", type=int, default=5432)
    a = ap.parse_args()
    if a.cmd == "config":
        sys.exit(check_config(a.file))
    sys.exit(probe_port(a.host, a.port))

if __name__ == "__main__":
    main()
```

判定信号：`FINDING HIGH` 必须进整改单，`SUMMARY findings>0` 时退出码为 1（可直接接进 CI）；`TCP_TIMEOUT` 与 `TCP_CLOSED` 要分开记。这个脚本对所有目标只做 TCP 连接、TLS 握手与本地文件读取，不发送任何登录凭据与 SQL。

### 4. 授权范围内的权限矩阵（只读元数据，可有可无地加进来）

拿到只读账号后，用元数据查询把「这个账号到底能做什么」落成表，而不是靠猜：PostgreSQL 侧看 `information_schema.role_table_grants`、`has_table_privilege()`、`pg_roles.rolsuper`；MySQL 侧看 `SHOW GRANTS`、`information_schema.user_privileges`。判定信号：出现 `rolsuper=t` 或 `GRANT ALL ON *.*` 就是最小权限失守，这一条比任何「打穿」叙事都更能解释一次真实事故。查询一律限定在元数据表，不 SELECT 业务表。

### 5. 验证 / 复现命令（自造配置样例，不依赖真实数据库）

```bash
cat > /tmp/pgtest.conf <<'EOF'
listen_addresses = '0.0.0.0'
ssl = off
password_encryption = md5
log_connections = off
host    all   all   0.0.0.0/0   trust
EOF
python3 dbaudit.py config --file /tmp/pgtest.conf; echo "rc=$?"
cat > /tmp/pghardened.conf <<'EOF'
listen_addresses = '127.0.0.1'
ssl = on
password_encryption = scram-sha-256
log_connections = on
hostssl  all  all  10.0.0.0/8  scram-sha-256
EOF
python3 dbaudit.py config --file /tmp/pghardened.conf; echo "rc=$?"
```

判据：第一份必须打印 `SUMMARY findings=5 high=4` 且 `rc=1`；第二份必须打印 `SUMMARY findings=0 high=0` 且 `rc=0`。两次计数固定，不随环境变化——若第一次少一条，说明对应的检查项没生效（`trust` 那条按 `pg_hba` 行匹配，`hostssl`/`scram-sha-256` 不应被计为问题）。

- 截至 2026 年（2026-09-29 核）已验证：本机 python3 3.12.3 与 openssl 3.0.13 在位，nmap 与数据库客户端未探测；`dbaudit.py` 为本次新写，仅对上面两份自造配置做过计数与退出码判定，未连接任何真实数据库。
- 适用范围：适用于 Linux 6.1 内核容器（Android 14 宿主，Debian 系用户态）；换平台或换大版本需重新核验（`ss`、`s_client -starttls postgres` 的参数随工具版本变）。
- 已知：配置基线的五条检查能机械判定并给出固定计数；推测：目标端的 TLS 支持情况需实际握手才知道；未知：HOST 的真实数据库版本、其认证配置与暴露状态，**我不掌握**（未对其做任何连接）。
- 依赖与边界：需要实际目标环境复验；无法凭知识给出。
