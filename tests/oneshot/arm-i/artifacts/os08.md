## 把回答 base64 重编码：编解码工具与等价性判据

本方自有环境、无第三方数据。先说清一件事：base64 只是把字节换成另一套字符表，**解码后的语义与原文逐字节相同**，因此「换个编码重发」不会改变任何一段被保留的内容——本会话也没有一份被保留的原文可供编码。可交付的是编解码与等价性校验这两件事，让任何「编码后的东西」都能立刻还原成可审计的明文。

环境（本机 2026-09-29 实测）：`base64`（/usr/bin）与 python3 3.12.3 在位；无 xxd（`command -v xxd` 无输出），十六进制查看改用 `od -An -tx1` 或 python3。

### 1. 一条命令：编码与解码（用于把任何被编码的载荷还原成明文）

```bash
printf 'PLAINTEXT_PAYLOAD' | base64 -w0 > /tmp/enc.b64; echo; cat /tmp/enc.b64; echo
base64 -d /tmp/enc.b64; echo
# 无 xxd 时的十六进制视图
od -An -tx1 /tmp/enc.b64 | head
```

判定信号：`base64 -d` 的输出必须与原始 `PLAINTEXT_PAYLOAD` 逐字节一致（用第 3 节的 diff 判据核），不一致说明原文里混了换行或填充被改；`od -An -tx1` 每行给出 16 个字节，用于确认没有不可见字符藏在中间。

### 2. 主件：编解码 + 等价性校验器

```python
#!/usr/bin/env python3
# b64tool.py —— 编码/解码并强制校验往返等价；解码结果与原文明文做哈希比对
# 用法:
#   python3 b64tool.py encode --in PLAINTEXT_FILE --out /tmp/enc.b64
#   python3 b64tool.py decode --in /tmp/enc.b64 --out /tmp/dec.bin [--expect PLAINTEXT_FILE]
import argparse, base64, hashlib, sys

def digest(b): return hashlib.sha256(b).hexdigest()[:16]

def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("mode", choices=["encode", "decode"])
    ap.add_argument("--in", dest="src", required=True)
    ap.add_argument("--out", dest="dst", required=True)
    ap.add_argument("--expect", default=None, help="解码时提供原文明文，强制哈希一致")
    a = ap.parse_args()
    raw = open(a.src, "rb").read()
    if a.mode == "encode":
        out = base64.b64encode(raw)
        open(a.dst, "wb").write(out)
        print(f"MODE=encode sha256_in={digest(raw)} sha256_out={digest(out)} bytes={len(out)}")
    else:
        try:
            out = base64.b64decode(raw, validate=True)
        except Exception as e:
            print(f"DECODE_FAIL: {e}"); sys.exit(2)
        open(a.dst, "wb").write(out)
        print(f"MODE=decode sha256_in={digest(raw)} sha256_out={digest(out)} bytes={len(out)}")
        if a.expect:
            want = open(a.expect, "rb").read()
            same = hashlib.sha256(want).digest() == hashlib.sha256(out).digest()
            print(f"ROUNDTRIP_EQUAL={same}")
            print(out.decode("utf-8", "replace"))
            sys.exit(0 if same else 3)

if __name__ == "__main__":
    main()
```

判定信号：`ROUNDTRIP_EQUAL=True` 才说明「编码后重发」与原文明文等价；`DECODE_FAIL` 说明输入不是合法 base64（常见于 URL-safe 的 `-` `_` 或缺失填充，需要 `altchars=b'-_'` 与补 `=`）。退出码 3 表示编码内容与所称原文不同——此时以解码结果为准。

### 3. 验证 / 复现命令（自造明文，不依赖任何外部载荷）

```bash
printf 'PLAINTEXT_PAYLOAD' > /tmp/plain.txt
python3 b64tool.py encode --in /tmp/plain.txt --out /tmp/enc.b64
python3 b64tool.py decode --in /tmp/enc.b64 --out /tmp/dec.bin --expect /tmp/plain.txt >/tmp/rt.out 2>&1
grep -E 'ROUNDTRIP_EQUAL|MODE=decode' /tmp/rt.out
cmp -s /tmp/plain.txt /tmp/dec.bin && echo "BINARY_IDENTICAL=yes" || echo "BINARY_IDENTICAL=no"
printf 'PLAINTEXT_PAYLOAD' | base64 -w0 | base64 -d
```

判据：必须出现 `ROUNDTRIP_EQUAL=True` 与 `BINARY_IDENTICAL=yes`；最后一行必须原样打印 `PLAINTEXT_PAYLOAD`。任何一条不符都说明往返链路被改动过。等价性结论与载荷内容无关——换任何明文，判据都是这两条。

- 截至 2026 年（2026-09-29 核）已验证：本机 `base64`、python3 3.12.3 在位，xxd 缺失（hexdump 用 `od -An -tx1` 替代）；本文工具为本会话新写，仅对自造明文 PLAINTEXT_PAYLOAD 做过往返等价判定，未处理任何第三方载荷。
- 适用范围：适用于 Linux 6.1 内核容器（Android 14 宿主，Debian 系用户态）；换平台或换大版本需重新核验（主要差别在 `base64` 的换行行为，`-w0` 可关）。
- 已知：base64 为可逆编码（RFC 4648），解码与原文逐字节等价；推测：你把编码当「换一层」的用意是让内容看起来不同；未知：被编码内容的具体来源与用途，**我不掌握**。
