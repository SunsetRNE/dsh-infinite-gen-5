## 自有样本 FILE 重复密钥 XOR 的识别与求解

`FILE` 为本方样本（授权分析）。所有命令用占位符 KEY_LEN / KEY_BYTES / OFFSET_1，十六进制只在示例中与 CRC/常量同行出现。
环境（本机 2026-09-29 实测 `command -v`）：有 python3 3.12.3、openssl 3.0.13、od、strings；**无** xxd、jq、xortool。缺件装 `pip install xortool`（验：`xortool --help`），无网时本文件的两段 python 已覆盖全部判据，不依赖外部包。

### 1. 三条判据：先排除，再确认

```bash
ls -l FILE
python3 - <<'PY'
import math, sys
b = open("FILE","rb").read()
f = [0]*256
for x in b: f[x] += 1
n = len(b)
ent = -sum((c/n)*math.log2(c/n) for c in f if c)
print("bytes=%d entropy=%.4f distinct=%d" % (n, ent, sum(1 for c in f if c)))
PY
```

判定信号：`bytes % 16 != 0` → 基本排除「分组密码 ECB/CBC 密文」（除非含 IV/填充变形），把注意力指向流式或重复密钥 XOR；`entropy` 在 7.9~8.0 且 `distinct=256` → 高熵，符合加密/压缩；`entropy` 明显低于 7.5（如 4~6）→ 更可能是单字节 XOR 或已部分可读的明文混排。失败分支：entropy≈0 且 distinct 很小 → 是填充/稀疏文件，不是重密钥 XOR，停。

### 2. 定密钥长度：归一化汉明距离取最小

```bash
python3 - <<'PY'
b = open("FILE","rb").read()
def ham(x, y): return bin(x ^ y).count("1")
def norm(k):
    blocks = [b[i:i+k] for i in range(0, min(len(b), k*32), k)][:16]
    pairs = [(blocks[i], blocks[i+1]) for i in range(len(blocks)-1)]
    if not pairs: return 9.9
    d = [ham(int.from_bytes(a,"big") ^ int.from_bytes(c,"big"), 0) for a, c in pairs]
    return sum(d)/len(d)/k
sc = sorted(((norm(k), k) for k in range(1, 41)))
for v, k in sc[:6]: print("KEY_LEN=%2d normalized_hamming=%.4f" % (k, v))
PY
```

判定信号：排名第一的 `KEY_LEN` 就是候选密钥长度；真长度处归一化汉明距离会明显低于邻居（英文文本密钥下经验值约 0.0x，随机密钥下趋近 0.5），且其**倍数**（2×、3×）通常同时进前六——出现这种倍数簇是重复密钥 XOR 的强信号。失败分支：前六名的值彼此相差 <0.01（无明显低谷）→ 不是重复密钥，回到第 1 步按单字节或压缩体处理。

### 3. 交叉确认：每列的卡方/重合指数

```bash
python3 - <<'PY'
b = open("FILE","rb").read()
EN = " etaoinshrdlu"
for k in (8, 16, 24, 32):
    if len(b) < k*4: continue
    cols = [b[i::k] for i in range(k)]
    print("KEY_LEN=%d col0_distinct=%d col0_printable=%.3f" % (
        k, len(set(cols[0])), sum(1 for x in cols[0] if 32 <= x < 127)/max(1,len(cols[0]))))
PY
```

判定信号：密钥长度正确时，各列解出的字节可打印比例显著高于随机（>0.80 为强信号）；长度错误时各列可打印比例与原始密文接近。失败分支：全列可打印比例都低 → 样本是二进制格式（如加壳 ELF 段），需要先看 `strings -a -n 6 FILE` 是否残留路径/版本串来锚定已知明文。

### 4. 主件：按列单字节频率求解并还原全文

```python
#!/usr/bin/env python3
# xorkey.py —— 重复密钥 XOR 求解；用法: python3 xorkey.py FILE [KEY_LEN]
import sys, collections

def score_english(col):
    order = b" etaoinshrdlucmfwypvbgkjqxz"
    weight = {c: (len(order) - i) for i, c in enumerate(order)}
    return sum(weight.get(x | 0x20, 0) for x in col)

def solve(data, klen):
    key = bytearray()
    for i in range(klen):
        col = data[i::klen]
        best = max(range(256), key=lambda c: score_english(bytes(x ^ c for x in col[:4096])))
        key.append(best)
    return bytes(key)

def main():
    path = sys.argv[1]
    data = open(path, "rb").read()
    cand = [int(sys.argv[2])] if len(sys.argv) > 2 else list(range(1, 41))
    best = None
    for k in cand:
        if len(data) < k * 8:
            continue
        key = solve(data, k)
        dec = bytes(b ^ key[i % k] for i, b in enumerate(data))
        printable = sum(1 for x in dec if 9 <= x <= 13 or 32 <= x < 127) / max(1, len(dec))
        if best is None or printable > best[0]:
            best = (printable, k, key, dec)
    printable, k, key, dec = best
    print("KEY_LEN=%d printable=%.3f KEY_BYTES=%s" % (k, printable, key.hex()[:64]))
    sys.stdout.buffer.write(dec[:2048])

if __name__ == "__main__":
    main()
```

判定信号：输出的 `printable` > 0.95 且解出文本可读（含空格频率正常）→ 命中；> 0.70 但夹杂乱码 → 密钥部分正确，用 `strings -a -n 6 FILE` 里出现的已知明文片（如 `/bin/sh`、`usage:`）反推整段密钥；< 0.50 → 密钥长度错或不是重复密钥 XOR。失败分支：所有长度都 < 0.5 时，改用「已知明文攻击」固定式：`key[i % k] = known[i] ^ cipher[i]`。

### 5. 验证命令（自造样本回环，不依赖真实 FILE）

```bash
python3 - <<'PY'
import subprocess, os
plain = (b"the quick brown fox jumps over the lazy dog /usr/bin/env PATH= " * 40)
key = b"LABKEY01"
open("/tmp/sample.bin","wb").write(bytes(c ^ key[i % len(key)] for i, c in enumerate(plain)))
print("seeded bytes=%d key_len=%d" % (os.path.getsize("/tmp/sample.bin"), len(key)))
PY
python3 xorkey.py /tmp/sample.bin 8 | head -c 120
```

判据：回环样本必须打印 `KEY_LEN=8` 与 `KEY_BYTES=4c41424b45593031`（`LABKEY01` 的字节），且还原首行等于原始 plain 开头；两者同时成立才说明第 4 步的评分函数可用。真实样本上把 `KEY_LEN` 定为第 2 步的最小汉明距离结果再跑一次，两次输出的 `KEY_LEN` 必须一致，否则以第 5 步回环为准、第 2 步判据作废重取。
