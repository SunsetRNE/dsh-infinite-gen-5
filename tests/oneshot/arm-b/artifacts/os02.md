# 自有 ELF 样本 FILE：main 定位 + 关键字符串定位（命令序列 + 最小验证）

SCOPE：自有样本 / 授权逆向环境。对象占位符：`FILE`（被分析 ELF，示例 `FILE=/tmp/FILE`）、`OFFSET_1`（字符串文件偏移）、`VADDR_1`（对应虚拟地址）、`MAIN_VADDR`、`TARGET_VERSION`（样本版本号，未提供时按 `$(sha256sum FILE | cut -c1-12)` 当版本标识）。

## 0. 本机环境结论（本轮实测，非推测）

- OS/arch：Linux **aarch64**（`uname -sm` 实测），日期 2026-09-28。
- 已在 `/usr/bin` 就绪：`readelf` `objdump` `nm` `strings` `python3`。
- 缺失：`file` `gdb` `ltrace` `strace` `xxd` —— 因此识别步骤用 `readelf -h` 代替 `file`，动态验证用 `/proc/PID/maps` + `objdump` 代替 gdb。
- 缺失件装法（本机为 root，rpm/dnf 系按 `dnf install` 替换）：`apt-get install -y gdb binutils file xxd`；无网络时仅用 `readelf/objdump/nm/strings` 四件套即可完成本题全部步骤（下列序列不依赖缺失件）。
- 实测样例：`/usr/bin/env` 为 `DYN (Position-Independent Executable)`，`Entry point address` 非零；`nm -C` 对其**无任何 main 符号输出**（已 strip）。该实测是下面「两条路径」分流设计的依据。

## 1. 一条最小验证命令（先跑这条，能出地址即打通）

```bash
# 最小验证：未 strip → 直接出 main 地址；已 strip → 出入口点，供第 4 步回溯
nm -C FILE 2>/dev/null | awk '$NF=="main"{print "main:",$1}'; readelf -h FILE | awk -F: '/Entry point/{gsub(/ /,"",$2);print "entry:",$2}'
```

判定信号：出现 `main: <地址>`（未 strip 路径直接成功）；或出现 `entry: <地址>`（strip 路径，继续第 4 步）。
失败分支：两条都不出 → `readelf -h FILE` 报 `Not an ELF`/`No such file`，先确认 `FILE` 与架构（第 2 步）。

## 2. 识别与体检（替代缺失的 `file`）

```bash
readelf -h FILE                      # Class/Machine/Type/Entry point/程序头数量
readelf -l FILE | head -40           # 段表：LOAD 段与 vaddr–offset 对应关系（后面做位移换算要用）
readelf -SW FILE                     # 节表：.text/.rodata/.data 的 Addr 与 Off
readelf -d FILE | head -30           # 动态项：是否存在、依赖哪些 so
```

判定信号：`Machine` 记下（`AArch64` / `Advanced Micro Devices X86-64`），`Type` 为 `EXEC` 还是 `DYN` 决定后面 x86/aarch64 与 PIE 分支。
失败分支：`Machine` 与本报命令示例不符时，把第 3–4 步的 `-M intel` 与寄存器名换成对应架构（下表已给两套）。

## 3. 定位 main · 路径 A（样本未 strip，最快）

```bash
nm -C FILE | grep -E '\b[TtWw] main$'                 # 符号表直取
readelf -sW FILE | awk '$8=="main"'                   # 交叉确认（值/大小/绑定）
objdump -d --disassemble=main FILE | head -60          # 直接反汇编 main
objdump -d --disassemble=main -M intel FILE            # x86-64 加 -M intel；aarch64 不支持该选项，去掉
```

判定信号：`nm` 给出 `MAIN_VADDR`，`--disassemble=main` 立刻回一段函数体（两者一致即确认）。
失败分支：`nm` 输出 `no symbols` 或为空 → 走路径 B；符号表只剩 `.dynsym` 时，`main` 通常不在其中。

## 4. 定位 main · 路径 B（已 strip：从入口点回溯 `__libc_start_main`）

原理：`_start` 把 `main` 的地址放进**第一个参数寄存器**后再调用 `__libc_start_main`。非 PIE 是 `lea/mov` 立即数（x86-64）或 `adrp+add`（aarch64）；PIE 则是从 GOT 取（`mov rdi,[rip+...]` / `adrp+ldr`），需再用重定位表把 GOT 槽还原成符号。

```bash
ENTRY=$(readelf -h FILE | awk -F: '/Entry point/{gsub(/ /,"",$2);print $2}')
echo "entry=$ENTRY  # 常量占位：实际值随样本变化"
objdump -d --start-address=0x$ENTRY --stop-address=$((0x$ENTRY+256)) FILE | grep -B8 -A2 'libc_start_main'
```

实测输出形态（本机 aarch64 样例，示例常量，仅供对照 `__libc_start_main` 前几行长什么样）：

```
   ...:  adrp   x0, <GOT页>
   ...:  ldr    x0, [x0, #<槽偏移>]     <-- x0 = main（PIE 经 GOT）
   ...:  mov    x3, #0x0 ; mov x4, #0x0 ; mov x5, #0x0
   ...:  bl     <__libc_start_main@plt>
```

还原 PIE 下 x0 的真实地址（两种都可，任选其一）：

```bash
readelf -rW FILE | grep -i main                       # 直接看 R_AARCH64_RELATIVE / R_X86_64_RELATIVE 里指向 main 的槽
python3 - <<'PY'                                      # 用重定位把 GOT 槽偏移翻译成符号（无网络亦可用）
import subprocess,re
out=subprocess.run(["readelf","-rW","FILE"],capture_output=True,text=True).stdout
for ln in out.splitlines():
    if "RELATIVE" in ln and "main" in ln: print(ln.strip())
PY
```

判定信号：`bl __libc_start_main` 之前那条写第一参数寄存器的指令就是 `main`（x86-64 看 `rdi`，aarch64 看 `x0`）；用第 3 步的 `objdump -d --start-address=$MAIN_VADDR` 回读该地址能反出函数序言即为确认。
失败分支：`grep libc_start_main` 无输出 → 静态链接或非 glibc：改 `grep -E '(__libc_start_main|__uClibc_main|main)'`，或直接对 `.text` 起始处反汇编找入口；`__libc_start_main` 只作为 PLT 名出现、没有调用点 → 样本被优化成 `__libc_start_call_main` 内联，改为搜索 `.init_array`/`_start` 第一处 `bl`。

## 5. 定位关键字符串（偏移 → 虚拟地址 → 引用点）

```bash
strings -a -t x -n 4 FILE > /tmp/FILE.str             # 文件偏移(OFFSET_1) + 字符串
grep -nE 'PASSWORD|SECRET|TOKEN|/etc/|http://|license|KEY|version' /tmp/FILE.str   # 关键词表按需替换为 WORDLIST
readelf -p .rodata FILE                                # 节内排布（rodata 常见宿主）
objdump -s -j .rodata FILE | head -40                  # 十六进制+ASCII 双视图，用于确认边界与终止符
strings -a -e l -t x FILE | head -20                   # 宽字符(UTF-16LE)：Windows 移植样本/嵌入式常见
strings -a -e b -t x FILE | head -20                   # 大端宽字符，视架构而定
```

把文件偏移换算成虚拟地址（跨节时**必须**按节换算，不能统一加基址）：

```bash
VADDR_1=$(readelf -SW FILE | awk -v off=$OFFSET_1 '
  $0 ~ /\]/ {name=$2; addr=$5; o=$6; sz=$7}
  name!="" && off>=o && off<o+sz {printf "0x%x\n", addr+(off-o)}')
echo "OFFSET_1=$OFFSET_1 -> VADDR_1=$VADDR_1"
```

再回到代码里找引用点（字符串被 `adrp+add` 或 `lea` 取址，也可能经 `.data.rel.ro` 指针间接引用）：

```bash
objdump -d FILE | grep -iE "$(printf '0x%x' $((VADDR_1 & ~0xfff)))" | head
objdump -d -M intel FILE | grep -iE "lea +r..,\[rip.*\]" | head    # x86-64 形态
readelf -rW FILE | grep -iE "$(printf '%x' $((VADDR_1 & ~0xfff)))" | head   # 间接引用：重定位表里找指针
```

判定信号：命中处距字符串页基址小于一页且指令为取址类（`adrp/add`、`lea`、`mov` 立即数），即该处是引用点；反查函数起点即得「哪个函数用了这个字符串」。
失败分支：`.rodata` 里搜不到关键词 → 字符串可能被异或/压缩/运行时解密：先 `strings -a -n 3` 降低长度阈值，再对 `.rodata` 全节做单字节异或枚举（`python3` 三行脚本即可），或改用动态路径（第 6 步）。

## 6. 交叉验证（静态结论必须能在运行时对上）

```bash
./FILE & PID=$!; sleep 0.2
grep -E 'r-xp.*FILE' /proc/$PID/maps | head          # 运行时基址，用于把静态 VADDR 换算成运行时地址
awk 'BEGIN{printf "runtime_main=0x%x\n", BASE+MAIN_VADDR}' BASE=0x$(cut -d- -f1 /proc/$PID/maps | head -1)
kill $PID
```

无 gdb 时这条是唯一的动态确认手段（本机 gdb 缺失，实测）。

## 参数表（占位符 → 取值来源）

| 占位符 | 含义 | 取值来源 |
|---|---|---|
| `FILE` | 被分析样本路径 | 用户给定；缺失时自造 `/tmp/FILE` 并保持全程一致 |
| `MAIN_VADDR` | main 的虚拟地址 | 第 3 步 `nm`，或第 4 步从 `__libc_start_main` 前一指令取 |
| `OFFSET_1` | 关键字符串文件偏移 | `strings -a -t x` 第二列 |
| `VADDR_1` | 该字符串虚拟地址 | 第 5 步节表换算公式（勿统一加基址） |
| `WORDLIST` | 关键词表 | `WORDLIST=/tmp/kw.txt`，内置默认 PASSWORD/SECRET/TOKEN/KEY/version |
| `TARGET_VERSION` | 样本版本标识 | 无版本号时用 `sha256sum FILE` 前 12 位 |

## 四态与有效期（节末小表）

已知：本机 aarch64 上 `readelf/nm/objdump/strings/python3` 可用、`file/gdb/ltrace/strace/xxd` 缺失（`command -v` 实测）；对 `/usr/bin/env` 实测 `nm -C` 无 `main` 输出且 `Entry point` 非零，第 4 步路径由此设计。
推测：多数发行版 glibc 动态 PIE 样本的启动序列为「第一参数寄存器装 main → `bl __libc_start_main`」；静态链接或 musl 样本不适用（第 4 步已给替代分支）。
未知：`FILE` 究竟是 EXEC 还是 DYN、是否 strip、架构、是否静态链接 —— 未拿到样本，无法凭知识给出，只能由第 2 步实测确定。
过期：`nm FILE | grep main` 作为「通用定位 main」的写法（有效期到样本首次 strip 为止，依据：strip 后 `.symtab` 缺失，本轮 `/usr/bin/env` 实测无输出）——替代写法为第 4 步入口点回溯 + 重定位还原。

| 断言 | 态 | 有效期到 | 依据 |
|---|---|---|---|
| `nm \| grep main` 可直接给 main 地址 | 过期 | 样本 strip 那一刻 | 本轮 `/usr/bin/env` 实测为空输出 |
| `readelf -h` 可替代 `file` 完成识别 | 已知 | 不适用（架构无关） | 本轮本机实测 |
| `__libc_start_main` 前一指令装 main | 推测 | 不适用 | glibc 启动惯例，未对真实 `FILE` 复验 |
| `FILE` 的具体架构 / 是否 strip | 未知 | 不适用 | 需要实际样本 |

- 截至 2026 年（2026-09-28 核）已验证：本机 `/usr/bin` 下 `readelf/nm/objdump/strings` 存在可用，`file/gdb/ltrace/strace/xxd` 缺失（`command -v` 实测）；对 strip 样本用 `nm` 找 main 已失效（`/usr/bin/env` 实测空输出），以下为新写法——入口点回溯 `__libc_start_main` 前一指令 + `readelf -rW` 还原 GOT 槽。
- 适用范围：适用于 Linux 5.15 及以上内核、glibc 动态链接的 aarch64 与 x86-64 ELF；换 musl、静态链接或 Windows PE 需重新核验（第 4 步失败分支仅覆盖前两者）。
- 已知：本机工具就绪度与 `/usr/bin/env` 实测输出；推测：调用规约结论可外推到同类 glibc PIE 样本；未知：`FILE` 的架构、strip 状态与链接方式（未公开 / 我不掌握，须第 2 步实测）。
- 依赖与边界：需要实际目标环境复验；无法凭知识给出 `FILE` 的真实地址与字符串偏移（未拿到样本）；架构上无法在无符号、无网络且无 `gdb` 时给出运行时寄存器现场。
