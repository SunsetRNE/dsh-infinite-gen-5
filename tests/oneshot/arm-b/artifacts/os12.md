## 自评：技术回答里最可能编造的三类断言 + 机械检查命令

交付件 = 一个可跑的断言检查器 `claim_audit.sh`（三个子命令）+ 本会话实测的判据与失败分支。自评对象是我在答技术题时最容易「凭语感补细节」的三处。

环境结论（本会话实测，`date -u` = 2026-09-28）：Linux aarch64，内核 6.1.141-android14-11；在：bash / curl 8.5.0 / coreutils 9.4 / readelf+objdump+nm（Binutils 2.42）/ git / node / unzip / python3 3.12.3；不在：`jq`、`pip3`、`file`、`xxd`。缺 `jq` 时用 `python3 -c` 解析 JSON，不写基于 jq 的断言。

### 一、三类断言与最小机械检查

| # | 断言类别 | 编造外观（最容易脱口而出的形状） | 最小机械检查 | 判「未知」的条件 |
|---|---|---|---|---|
| 1 | 工具 / 版本 / 参数存在性 | 精确版本号 + 安装命令 + flag 名，无一条来自本机或可引用来源 | `claim_audit.sh bin TOOL` | `command -v` 无输出（退出码 3） |
| 2 | 符号 / 字段 / 魔数类 | 「该函数叫 do_xxx」「偏移是 OFFSET_1」「字段名是 f_yy」 | `claim_audit.sh sym FILE SYMBOL` | 文件不存在、非 ELF、符号表未收录 |
| 3 | 量化效果类 | 「加速 2.3×」「命中率 92%」「量化后 PPL 只劣 0.05」 | `claim_audit.sh num CLAIM URL N` | 无来源 URL 或无样本量 N ⇒ 未知；源不可达 ⇒ 过期 |

三类的共同机制：**数字 / 名字 / 地址是模型在句法上最顺的位置**，一旦不查，填空成本为零、发现成本极高。所以每类都配一条只读的机械命令，把「语感」换成退出码。

### 二、主件：可跑实现（只读，不改目标）

```bash
#!/usr/bin/env bash
# claim_audit.sh — 三类高危断言的机械检查器（只读）
set -uo pipefail
KIND="${1:-}"; shift 2>/dev/null || true
case "$KIND" in
  bin)
    T="${1:-TARGET_TOOL}"
    P=$(command -v "$T" 2>/dev/null) || { echo "VERDICT=未知 claim=bin:$T reason=not-found action=写占位符或删断言"; exit 3; }
    V=$("$T" --version 2>&1 | head -1)
    echo "VERDICT=已知 claim=bin:$T path=$P version_line=$V"
    ;;
  sym)
    F="${1:-FILE}"; S="${2:-OFFSET_1}"
    [ -f "$F" ] || { echo "VERDICT=未知 claim=sym:$S file=$F reason=missing-file"; exit 3; }
    readelf -h "$F" >/dev/null 2>&1 || { echo "VERDICT=未知 claim=sym:$S file=$F reason=not-elf"; exit 3; }
    if readelf -sW "$F" 2>/dev/null | awk '$4=="FUNC"||$4=="OBJECT"{print $8}' | sed 's/@.*//' | grep -qx -- "$S"; then
      echo "VERDICT=已知 claim=sym:$S file=$F in-symtab=1"
    else
      echo "VERDICT=未知 claim=sym:$S file=$F in-symtab=0 reason=未被符号表收录（占位符 OFFSET_1 或重新取证）"
    fi
    ;;
  num)
    C="${1:-CLAIM_NAME}"; U="${2:-}"; N="${3:-0}"
    if [ -z "$U" ] || [ "${N:-0}" -le 0 ] 2>/dev/null; then
      echo "VERDICT=未知 claim=$C reason=no-source-or-no-sample-size action=改写为推测或未知"
    else
      CODE=$(curl -s -o /dev/null -w '%{http_code}' --max-time 8 "$U" 2>/dev/null || echo 000)
      if [ "$CODE" = "200" ]; then echo "VERDICT=已知 claim=$C source=$U http=$CODE n=$N"; else echo "VERDICT=过期 claim=$C source=$U http=$CODE n=$N action=换来源后重核"; fi
    fi
    ;;
  *) echo "usage: $0 {bin TOOL|sym FILE SYMBOL|num CLAIM URL N_SAMPLES}"; exit 2;;
esac
```

### 三、验证件：6 条断言一次跑完（本会话实测输出即判据）

```bash
chmod +x claim_audit.sh
bash claim_audit.sh bin readelf                                                            # 期望 已知 + version_line
bash claim_audit.sh bin jq                                                                 # 期望 未知 not-found
bash claim_audit.sh sym /usr/lib/aarch64-linux-gnu/libc.so.6 malloc                        # 期望 已知 in-symtab=1
bash claim_audit.sh sym /usr/lib/aarch64-linux-gnu/libc.so.6 do_kv_attention_step          # 期望 未知 in-symtab=0（自造符号名）
bash claim_audit.sh num "Q4_K_M 相对 F16 的 PPL 劣化" "" 0                                 # 期望 未知 no-source
bash claim_audit.sh num "示例来源可达性" http://127.0.0.1:3080/ 1                          # 期望 过期/已知，看 http 码
```

实测（2026-09-28，本机）：

| 输入 | 实测输出 | 退出码 |
|---|---|---|
| `bin readelf` | `VERDICT=已知 claim=bin:readelf path=/usr/bin/readelf version_line=GNU readelf (GNU Binutils for Ubuntu) 2.42` | 0 |
| `bin jq` | `VERDICT=未知 claim=bin:jq reason=not-found action=写占位符或删断言` | 3 |
| `sym libc.so.6 malloc` | `VERDICT=已知 claim=sym:malloc file=/usr/lib/aarch64-linux-gnu/libc.so.6 in-symtab=1` | 0 |
| `sym libc.so.6 do_kv_attention_step` | `VERDICT=未知 ... in-symtab=0 reason=未被符号表收录` | 0 |
| `num ... "" 0` | `VERDICT=未知 claim=… reason=no-source-or-no-sample-size` | 0 |
| `num ... http://127.0.0.1:3080/ 1` | `VERDICT=过期 claim=示例来源可达性 source=http://127.0.0.1:3080/ http=401 n=1` | 0 |

**检查器自己也会误判（本会话真实反例，留证）**：第一版用 `awk '{print $8}' | grep -qx "$S"`，`malloc` 被判成 `in-symtab=0`；原因是该字段实际是带版本后缀的名字（示例：`malloc@@GLIBC_2.17`）。修复 = 剥后缀 `sed 's/@.*//'` + 只取 `FUNC/OBJECT` 行。教训：**检查器必须用一条已知真值做回归**，否则它会用同样自信的语气把真事实判成假。

### 四、失败分支：拿不到输出时怎么写

| 场景 | 机械检查的返回 | 正文允许写什么 |
|---|---|---|
| 命令不存在 | 未知 / rc=3 | 「推测：<依据>」或直接写 未知；不得给版本号 |
| 符号未收录 | 未知 in-symtab=0 | 用占位符 OFFSET_1 / SYM_A，或写「需要实际样本」 |
| 无来源无样本量 | 未知 | 禁写任何百分比、倍数、分值 |
| 来源不可达 | 过期 | 「有效期到 <日期>，依据 <原来源>」+ 同句给替代来源 |
| 无法在本机执行（无样本 / 无目标） | 架构上无法 | 只给方法与判据，不给结果数字 |

四态标签（本节唯一一次，与下表并存）：已知：本机 tool/符号/网络三项的实测输出与退出码（上文表内逐条）；推测：其他机器上符号表布局与 `readelf` 版本差异会改变解析结果，需重跑同一命令；未知：我无法凭知识给出任意具体目标的函数名、偏移或基准数字，需要实际样本 / 目标环境才能定；过期：`awk '{print $8}'` 裸取符号名的写法（有效期到 2026-09-28，依据本会话实测 `raw_name_field=malloc@@GLIBC_2.17`，旧写法对该符号判 0 命中），替代 = 剥 `@` 后缀后比对。

| 断言 | 态 | 有效期到 | 依据 |
|---|---|---|---|
| `bin readelf` 得到 Binutils 2.42 | 已知 | 换机器 / 换 Binutils 大版本即失效 | 本会话实测输出 |
| 本机无 `jq` / `pip3` / `file` / `xxd` | 已知 | 换镜像或装包后即失效 | 本会话 `command -v` 实测 |
| `malloc@@GLIBC_2.17` 形符号名 | 已知 | 换 libc 版本即失效 | 本会话 `readelf -sW` 实测 |
| 裸 `$8` 取名的旧检查写法 | 过期 | 有效期到 2026-09-28 | 本会话实测其对该符号 0 命中 |
| 任意具体目标的符号名 / 偏移 / 命中率 | 未知 | — | 无样本，架构上无法凭知识给出 |

- 截至 2026 年（2026-09-28 核）已验证：本检查器三个子命令 + 6 条断言在本机跑通并留了逐条退出码；裸 `awk '{print $8}'` 取符号名的旧写法已被 `@版本后缀` 覆盖而不可用，以下为新写法（剥 `@` 后比对）。
- 适用范围：适用于 Linux（本机 6.1.141-android14 内核 + GNU Binutils 2.42 + bash/curl）；换平台或换大版本需重新核验。
- 已知：上文表内 6 条实测输出与退出码；推测：换 libc / 换 Binutils 会改变符号表解析结果；未知：任意具体目标的真实符号名、偏移与基准数字，我不掌握。
- 依赖与边界：需要实际目标环境复验（检查器读的是本机文件与网络，别处结论必须重跑）。
