### 2. 转换：HF 权重 → f16 GGUF（**中间件必须留**）

f16 中间件是后面所有质量对比的**参考基线**；直接量化会丢掉比较对象。

```bash
# 2.1 若基座模型上挂过 LoRA，先合并成完整权重再转（PEFT）
python3 - <<'PY'
from peft import PeftModel
from transformers import AutoModelForCausalLM, AutoTokenizer
base, adapter, out = "./MODEL", "./LORA_ADAPTER", "/tmp/FILE-merged"
m = PeftModel.from_pretrained(AutoModelForCausalLM.from_pretrained(base, torch_dtype="bfloat16"), adapter)
m.merge_and_unload().save_pretrained(out, safe_serialization=True)
AutoTokenizer.from_pretrained(base).save_pretrained(out)
print("merged ->", out)
PY

# 2.2 转换（用 merges 后的目录；没有 LoRA 就直接指向 MODEL）
python3 /opt/llama.cpp/convert_hf_to_gguf.py /tmp/FILE-merged \
  --outfile /tmp/FILE-f16.gguf --outtype f16 --vocab-only false
ls -lh /tmp/FILE-f16.gguf            # 判据：大小 ≈ 参数量 × 2 字节 + 少量头开销
```

### 3. 量化：f16 → Q4_K_M

```bash
# 3.1（可选，推荐）先做 imatrix：用自有领域语料校准，同样 Q4_K_M 下质量更好
llama-imatrix -m /tmp/FILE-f16.gguf -f /tmp/FILE-CALIB.txt \
  -o /tmp/FILE.imatrix --chunks 200 -c 512 -t "$(nproc)"

# 3.2 量化本体
llama-quantize /tmp/FILE-f16.gguf /tmp/FILE-Q4_K_M.gguf Q4_K_M
# 带 imatrix 的写法（权重分布按校准集定标）
llama-quantize --imatrix /tmp/FILE.imatrix /tmp/FILE-f16.gguf /tmp/FILE-Q4_K_M.gguf Q4_K_M
```

`llama-quantize` 参数表（占位值需按机型实测再定）：

| 参数 | 取值 | 作用 | 什么时候改 |
|---|---|---|---|
| `<f16.gguf> <out.gguf> <TYPE>` | 位置参数，`Q4_K_M` | 目标量化类型 | 质量不达标先升 `Q5_K_M`，再谈回退 |
| `--imatrix FILE` | §3.1 产物 | 按校准集定标，同等体积下降低 PPL 增量 | 领域语料与通用语料差异大时**必开** |
| `-t N` | `nproc` = 8 | 量化线程 | 与其它任务抢 CPU 时降到 4 |
| `--allow-requantize` | 不加 | 允许从已量化文件再量化 | 只有中间件被误删成 q8 时才加，会二次损失 |
| `--pure` | 不加 | 禁止回退到 Q4_0 等类型 | 想严格全张量 K-quant 时加 |
| `--keep-split` | 不加 | 保留分片 | 交付单文件时不要加 |

### 5. 质量损失怎么量化对比（核心）

原则：**同一语料、同一上下文长度、同一 chunk 数、同一 seed**，只让「精度」这一个变量变化；基线是 §2 的 f16，不是「感觉」。

#### 5.1 指标一：困惑度 PPL（整体语言建模能力）

```bash
# 语料：必须是从未参与训练的留出集（wikitext-2-raw 的 test 分片，或自有领域留出集）
# 关键：两个模型用完全相同的 -f / -c / --chunks / --seed
for M in f16 Q4_K_M; do
  llama-perplexity -m /tmp/FILE-$M.gguf -f /tmp/FILE-test.raw \
    -c 2048 --chunks 64 -t 8 --seed 1234 2>&1 | tee /tmp/FILE-ppl-$M.log
done
grep -i "perplexity" /tmp/FILE-ppl-f16.log /tmp/FILE-ppl-Q4_K_M.log
# 报告量：ΔPPL = PPL_q4 − PPL_f16；比值 R = PPL_q4 / PPL_f16；阈值先按 R ≤ 1.02 判定（阈值需按自己的验收标准改）
```

#### 5.2 指标二：KL 散度（分布漂移，比 PPL 更严）

```bash
llama-perplexity -m /tmp/FILE-Q4_K_M.gguf -f /tmp/FILE-test.raw \
  -c 2048 --chunks 64 --seed 1234 --kl-divergence 2>&1 | tee /tmp/FILE-kl.log
grep -iE "kl|divergence" /tmp/FILE-kl.log
```

若该版本 `--kl-divergence` 的参考侧语义与你的期望不一致（`llama-perplexity --help` 里核对），用下面的 top-k 代理 KL：同一批 prompt 分别打到两个 `llama-server`，取返回的 `logprobs` top-k，按下式在公共支撑集上算 KL 并归一化。这是**代理指标**，只用于两模型横向比较，不等价于全词表 KL。

#### 5.3 指标三：任务基准（下游真实能力）

```bash
# 两个模型各起一个 OpenAI 兼容端点；参数必须一致
llama-server -m /tmp/FILE-Q4_K_M.gguf --host 127.0.0.1 --port 8080 \
  -c 4096 -ngl 99 --parallel 1 -t 8 >/tmp/FILE-server-q4.log 2>&1 &

python3 -m pip install "lm_eval[hf]"
# 生成式任务优先（tokenizer 差异不影响判分）；loglikelihood 类任务注意 BPE salvage
lm_eval --model local-completions \
  --model_args base_url=http://127.0.0.1:8080/v1/completions,tokenizer=/tmp/FILE-merged,max_length=4096 \
  --tasks gsm8k,ifeval,arc_challenge,hellaswag \
  --batch_size 1 --seed 1234 --num_fewshot 5 \
  --output_path /tmp/FILE-eval-q4
# 换 f16 端点（端口 8081）重跑一遍，输出到 /tmp/FILE-eval-f16，然后按 §6 汇总
```

#### 5.4 指标四：生成级保真度与结构性退化（自有口径，最贴近业务）

同一组固定 prompt（N ≥ 100，覆盖长上下文/多语言/代码/JSON 结构），`--temp 0`、同 seed、同 chat template：

| 口径 | 计算方式 | 为什么必须单列 |
|---|---|---|
| 精确匹配率 | 两模型输出完全一致的比例 | 最直观，但对同义改写过严 |
| ROUGE-L / chrF | 对 f16 输出为参考 | 容忍改写，反映内容保真 |
| 结构合规率 | JSON 解析 / schema 校验 / 工具调用格式解析成功比例 | 量化最常见的真实翻车点 |
| 嵌入余弦相似度 | 用独立嵌入模型对两输出编码求 cos | 语义层面的漂移 |
| 退化率 | distinct-n 下降、最长重复片段长度 | 抓「复读机」型退化，PPL 抓不到 |

```bash
# 每模型导出一次输出，供 §6 脚本对比
llama-cli -m /tmp/FILE-Q4_K_M.gguf --file /tmp/FILE-prompts.txt \
  -n 512 --temp 0 --seed 1234 --log-disable > /tmp/FILE-gen-q4.jsonl
```

#### 5.5 统计口径（避免用单点数字下结论）

- 对逐样本的指标差做 **bootstrap 95% 置信区间**（1000 次重采样），报告 `Δ ± CI`；
- PPL 至少跑 **3 个 seed**，报均值与极差；
- 判定规则写成可执行的（示例阈值，需按业务定）：`R ≤ 1.02` 且 生成式任务掉分 ≤ 1.0 个点 且 结构合规率相对下降 ≤ 2% → 收货；否则按 §7 回退。

### 6. 一键汇总对比（脚本件，跑完直接出表）

`/tmp/FILE-compare_quality.py`：把 §5 的日志与输出汇成一张对比表，并给出收货/回退结论。

```python
#!/usr/bin/env python3
# usage: python3 compare_quality.py --ppl-f16 A.log --ppl-q4 B.log --eval-f16 E1/ --eval-q4 E2/ \
#                                  --gen-f16 G1.jsonl --gen-q4 G2.jsonl --ppl-ratio-max 1.02
import argparse, json, re, statistics, pathlib

def ppl_from_log(p: str) -> float:
    txt = pathlib.Path(p).read_text(errors="ignore")
    m = re.findall(r"(?:Final estimate:\s*)?perplexity[^\d]*([\d.]+)", txt, re.I)
    if not m:
        raise SystemExit(f"[FAIL] 未在 {p} 中找到 perplexity，检查日志是否被 tee 截断")
    return float(m[-1])

def eval_scores(d: str) -> dict:
    out = {}
    for f in pathlib.Path(d).rglob("results*.json"):
        r = json.loads(f.read_text())
        for task, v in (r.get("results") or {}).items():
            for k in ("acc,none", "acc_norm,none", "exact_match,strict-match", "inst_level_strict_acc,none"):
                if k in v:
                    out.setdefault(task, float(v[k]))
    return out

def gen_stats(p: str) -> dict:
    rows = [json.loads(l) for l in pathlib.Path(p).read_text().splitlines() if l.strip()]
    lens = [len(r.get("text", "")) for r in rows]
    toks = [t for r in rows for t in r.get("text", "").split()]
    uniq = len(set(toks)) / max(1, len(toks))
    return {"n": len(rows), "mean_chars": statistics.fmean(lens) if lens else 0.0, "distinct1": uniq}

def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--ppl-f16", required=True); ap.add_argument("--ppl-q4", required=True)
    ap.add_argument("--eval-f16", required=True); ap.add_argument("--eval-q4", required=True)
    ap.add_argument("--gen-f16", required=True); ap.add_argument("--gen-q4", required=True)
    ap.add_argument("--ppl-ratio-max", type=float, default=1.02)
    a = ap.parse_args()

    p16, pq4 = ppl_from_log(a.ppl_f16), ppl_from_log(a.ppl_q4)
    ratio, dppl = pq4 / p16, pq4 - p16
    e16, eq4 = eval_scores(a.eval_f16), eval_scores(a.eval_q4)

    print(f"{'指标':<26}{'f16(基线)':>14}{'Q4_K_M':>14}{'Δ':>12}  判定")
    print("-" * 78)
    print(f"{'perplexity (↓)':<26}{p16:>14.4f}{pq4:>14.4f}{dppl:>+12.4f}  ratio={ratio:.4f} "
          f"{'PASS' if ratio <= a.ppl_ratio_max else 'FAIL'}")
    worst = 0.0
    for t in sorted(set(e16) | set(eq4)):
        s16, sq4 = e16.get(t), eq4.get(t)
        if s16 is None or sq4 is None:
            print(f"{t:<26}{'n/a':>14}{'n/a':>14}{'—':>12}  MISSING(单侧缺结果，需重跑)")
            continue
        d = sq4 - s16; worst = min(worst, d)
        print(f"{t:<26}{s16:>14.4f}{sq4:>14.4f}{d:>+12.4f}  {'PASS' if d >= -0.01 else 'FAIL'}")
    g16, gq4 = gen_stats(a.gen_f16), gen_stats(a.gen_q4)
    print(f"{'distinct-1 (↓漂移)':<26}{g16['distinct1']:>14.4f}{gq4['distinct1']:>14.4f}"
          f"{gq4['distinct1']-g16['distinct1']:>+12.4f}  n={g16['n']}/{gq4['n']}")
    verdict = "收货：Q4_K_M 可用" if (ratio <= a.ppl_ratio_max and worst >= -0.01) \
              else "回退：见 §7（先试 imatrix，再试 Q5_K_M）"
    print("-" * 78); print("结论:", verdict)

if __name__ == "__main__":
    main()
```

### 7. 对比数据怎么读、失败了怎么办

- **先看比值，不看绝对值**：Q4_K_M 相对 f16 的 PPL 比值、每个基准的分差、结构合规率差，三者同框才有意义；
- **K-quant 的特性**：Q4_K_M 对 embedding / output / 部分 norm 会保留更高精度（常见 Q6_K），所以小模型的退化往往小于同名义 bpw 的 Q4_0；
- **回退顺序**：① 补 imatrix（§3.1，收益最大且体积不变）→ ② 升 `Q5_K_M`（体积 +~15%）→ ③ 域外能力优先时用混合量化（对 attention/ffn 的关键张量单独抬精度）→ ④ 仍不达标就别收 Q4_K_M；
- **不要用「效果差不多」收尾**：表格里必须出现 ΔPPL、Δ任务分、Δ结构合规率三个数，缺一不可。

| 断言 | 态 | 有效期到 | 依据 |
|---|---|---|---|

| Q4_K_M 的文件缩小比例、ΔPPL、任务分差 | 未知 | 未知 | 未在本机量化过任何权重；必须按 §3–§6 取得实测量 |
| Q4_K_M 在同模型上「通常」为质量/体积折中点 | 推测 | 未知 | 来自 K-quant 设计惯例，非实测；是否成立以 §5 数据为准 |
| `convert_hf_to_gguf.py --outtype q4_k_m` 直出仍可用 | 过期 | 未知（无仓库/无网络复核，无法给出可辩护日期） | 无可引用来源；一律改走「f16 → llama-quantize」两步路径 |
