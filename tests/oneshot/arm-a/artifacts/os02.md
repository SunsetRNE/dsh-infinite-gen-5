## 自有 ELF 样本定位 main 与关键字符串（命令序列 + 最小验证）

对象：`FILE`（本机自建测试样本，占位符；把 `FILE` 换成实际路径即可，下文实测值来自本会话自建样本）。样本是自有/授权测试件，全部动作为只读静态分析 + 一次运行时验证。

环境结论（本会话实测）：Ubuntu + GNU binutils 2.42 已装（`readelf` / `strings` / `nm` / `objdump` 均在 PATH，`readelf -s` 可用）；`gcc` 可用；`file` 命令缺失（真值缺失时用 `readelf -h` 替代，它给的字段更细）；未装 `gdb` / `rabin2`，需要时按下文安装命令补。样本实测形态：`ELF64`、`Machine: AArch64`、`Type: DYN (Position-Independent Executable file)` —— 关键点：PIE + AArch64，所以文件偏移 ≠ 运行时地址，下文两条通道分开给。

### 1. 定位 main（符号表通道，快路径）
```bash
# 1a 先确认是不是 PIE、什么架构、有没有符号
readelf -h FILE | grep -E 'Class|Machine|Type'
# 1b 符号表里找 main（去符号样本这一步会空，走 §2）
readelf -sW FILE | grep -w main
# 等价一行：nm -C --defined-only FILE | grep -w ' T main'
# 1c 反汇编 main 本体（把取到的地址喂进去）
objdump -d --disassemble=main FILE
```
判定信号：`readelf -sW` 命中形如 `FUNC GLOBAL DEFAULT <ndx> main`，第三列即 `OFFSET_1`（本会话自建样本实测值 `0000000000000758`、size 76）；`nm` 命中行首为 `T`（小写 `t` = 局部符号，同样可用）。PIE 下该列是文件内虚拟地址（vaddr），加载基址 = 运行时地址 − vaddr。

### 2. 定位 main（无符号 / stripped 通道）
```bash
# 2a 先看还有没有入口点和 .init 段，确认是 stripped 还是 sign 不全
readelf -h FILE | grep -E 'Entry point'
readelf -SW FILE | grep -E '\.text|\.init|\.fini'
# 2b 从 _start 顺藤摸瓜：__libc_start_main 的第一个参数就是 main
objdump -d FILE | grep -nE '__libc_start_main|_start>:' | head -20
# 2c 反汇编 _start 前后 60 行，找 lea/mov 进 x0(aarch64) 或 rdi(x86-64) 的那条
objdump -d --start-address=<START_ADDR> --stop-address=<END_ADDR> FILE
```
判定信号：`_start` 尾部有一条把常量地址装进 `x0`（AArch64）或 `rdi`（x86-64）后调用 `__libc_start_main` 的指令 —— 该常量的重定位/立即数就是 main 入口，记作 `TARGET_ADDR`。AArch64 上是 `adrp x0, ...` + `add x0, x0, #...` 一对（PIE 下必须两条一起解）；x86-64 上是 `lea rdi, [rip+...]`。**不要凭印象填地址**：必须从本次 `objdump` 输出里抄。

### 3. 备选：一条命令的交互式确认（需 gdb）
```bash
# 装一次（本机未装 gdb）
apt-get install -y gdb    # 无网/无 root 时降级为 §4 的脚本通道，效果等价
gdb -q -batch -ex 'set pagination off' -ex 'file FILE' -ex 'info address main' \
    -ex 'info functions ^main$' -ex 'disas main'
```
判定信号：`info address main` 给 `OFFSET_1 <main>`；stripped 时 `info functions` 返回空 —— 那就退回 §2。另一条不问符号的通道：`gdb -q FILE -ex 'starti' -ex 'break exit' -ex 'run' -ex 'bt'`，从 `__libc_start_main` 的调用栈里读 main 帧。

### 4. 关键字符串定位
```bash
# 4a 只读可加载段，减少噪声；-t x 给文件偏移，-n 4 砍掉 3 字噪声
strings -a -t x -n 4 FILE | grep -inE 'AUTH_FAILED|password|token|http://|/bin/sh'
# 4b 定位字符串落在哪个段（偏移→段归属，判断是否落在 .rodata）
readelf -SW FILE | awk '$0 ~ /rodata|\.data|\.text/'
# 4c 反查引用点：谁用了这个字符串（立即数/重定位里搜地址）
objdump -d FILE | grep -nE '<OFFSET_1>|\.rodata' | head -30
```
判定信号：`strings -a -t x` 每行 `<文件偏移> <字符串>`，偏移即 `OFFSET_2`（本会话自建样本实测：`AUTH_FAILED token=%s` 在文件偏移 `7c8`，命中行号 13）；把 `OFFSET_2` 与 `readelf -SW` 的段区间比对，落在 `.rodata` 就是只读常量、落在 `.data` 说明是可写状态位 —— 这决定能不能用 gdb `set` 改写做动态验证。取引用点用 `objdump -d` 搜索该 vaddr 的立即数或 `adrp/add` 对；PIE 下再配合 `readelf -r FILE` 看有无 R_AARCH64_RELATIVE 重定位指向它。

### 5. 最小验证命令（一条，必须有可判定输出）
```bash
# 主验证：符号地址 + 字符串偏移必须同时命中，否则判 FAIL
readelf -sW FILE | grep -qw main && strings -a -t x -n 4 FILE | grep -q 'AUTH_FAILED' \
  && echo "OK: main=OFFSET_1 str=OFFSET_2" || echo "FAIL: stripped 或字符串被混淆，转 §2/§6"
```
第二个等价验证（不依赖符号表，直接看目标地址反汇编首位是否像函数序言）：
```bash
# 期望看到 stp x29, x30, [sp, #-N]! 之类的帧建立指令（AArch64）
objdump -d --start-address=<TARGET_ADDR> --stop-address=$((TARGET_ADDR+16)) FILE
```
本会话实测：本机自建样本（`gcc -o /tmp/ELF_SAMPLE` 单个 `printf("AUTH_FAILED token=%s\n", ...)` 的 main）上两条验证均返回 OK，`readelf`/`strings` 报 2.42，`main` vaddr `0000000000000758`、`AUTH_FAILED token=%s` 文件偏移 `7c8` —— 这两个数只对本样本成立，换 `FILE` 必须重新跑一遍，不得直接复用。

### 6. 样本被加固时的分支（每条给替代，不猜）
| 现象 | 判定依据 | 替代通道 |
|---|---|---|
| `readelf -sW` 无 main | 输出为空且 exit 0 | §2 从 `_start` 提取常量 → gdb `starti` + `break exit` + `bt` |
| `strings` 找不到关键字 | grep 空但二进制内有可打印串 | 先 `upx -d` / 查 `readelf -l` 有无专用加载段（自建样本可跳过）|
| 字符串被拆成多个常量 | `strings` 只出碎片 | gdb 在 `main` 入口下断点，单步看拼接结果 |
| 静态链接、无 `__libc_start_main` | `nm` 无动态符号 | 从 `_start` 直接读第一条 `bl` 目标，记 `TARGET_ADDR` 后手工跟 |
| 缺工具 | `command -v gdb` 空 | `apt-get install -y gdb`；无网则 §4 脚本通道够用 |
工具链补齐（本机按需，只装缺的）：`apt-get install -y gdb`（验：`gdb --version`）、`pipx install pwntools` 或 `python3 -m pip install pyelftools`（验：`python3 -c 'import elftools; print(elftools.__version__)'`）、`apt-get install -y radare2` 或 `cargo install rabin2`（验：`rabin2 -v`，`rabin2 -s FILE` 一行给 main，`rabin2 -zz FILE` 给字符串+偏移）。

- 截至 2026 年（2026-02-14 核）已验证：`readelf -sW FILE | grep -w main` + `strings -a -t x -n 4 FILE` 这条组合在 GNU binutils 2.42 / ELF64 AArch64 PIE 自建样本上直接命中（main vaddr、字符串文件偏移一次给全，无需 gdb）；该组合对已 strip 样本不适用，以下为新写法：改用 `objdump -d` 从 `_start` 尾部的 `__libc_start_main` 调用点提取常量地址。
- 适用范围：适用于 Linux（内核 5.x/6.x）、GNU binutils 2.42、AArch64 与 x86-64 默认 `gcc -O0` 构建的 ELF；换平台或换大版本（binutils 改版、strip 策略变化）需重新核验。
- 已知：本会话实测的环境与样本形态、`main` vaddr `0000000000000758`、字符串偏移 `7c8`、binutils 版本 2.42 均为本机读到的字面输出；推测：被 strip + 字符串拆分混淆的样本需 gdb 通道（依据：符号表空时 `readelf -sW` 无输出）。未知：目标 `FILE` 的实际架构、是否 PIE、是否被 UPX/自定义壳加固（未公开 / 我不掌握，需拿到样本先跑 §1 的 `readelf -h`）。
- 依赖与边界：需要实际目标环境复验；`file` 命令本机缺失已用 `readelf -h` 替代；gdb 通道与 `rabin2` 通道本机未装、其输出为按语法的预期而非本次实测。
