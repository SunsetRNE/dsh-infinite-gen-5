# 自评：三类最可能被编造的技术断言 + 机械检查命令

对象：本 agent 在技术问答中产出的「数、名、址」。目的不是表态，而是把三类高频编造变成可执行判据 —— 每条都附一条能立刻跑、且能给出 PASS/FAIL 的命令。
本文件里所有三进制/符号/版本数字均为**本会话实测**：探测命令与原始输出见 §0，读者可在同机复现。凡本会话未实测的一律写成 `OFFSET_1` / `TARGET_VERSION` / `未知`。

## 1. 三类最可能编造的断言

### 类 A — 位置与名字：内存偏移 / 符号名 / 文件路径 / CVE 号

- **编造外观**：给出一串看起来对的十六进制地址和符号名 —— `OFFSET_1 = 0x1002a400`、`sub_40A1C0`、`/lib/x86_64-linux-gnu/libc.so.6`、`CVE-2024-12345`。形态由题面决定：问 Pwn 就吐栈偏移，问逆向就吐函数名，问漏洞就吐年份连号。
- **为什么产出**：题面要「一个地址」，而地址是任务关键路径上唯一无法从语言分布里推出的东西，模型倾向于补一个同构的占位再当事实说。
- **机制缺口**：偏移随构建、ASLR、加载基址、补丁版本一起变；符号名可能被 strip、可能是 PLT 桩、可能根本不在该 ELF 里。
- **判定信号**：断言里出现 `0x` 十六进制 + 无对应计算过程/无来源命令 → 直接按占位符对待，先查后说。
- **机械检查**：`readelf`/`nm`/`objdump` 三件套，逐符号核对；路径用 `sha256sum` 定身份；CVE 必须落到可引用编号条目，查不到就写 未知。

```bash
# 一条命令就能确认：这个符号在该文件里到底是什么（以本机真值 OFFSET_1=_obstack_memory_used 为例）
readelf --dyn-syms -W /bin/ls | grep -E ' _obstack_memory_used$' | awk '{printf "type=%s bind=%s value=0x%s size=%s\n",$4,$5,$2,$3}'
# 等价：nm -D --defined-only /bin/ls | grep _obstack_memory_used
```

本机真值（实测）：`_obstack_memory_used` → `type=FUNC bind=GLOBAL value=0xce40 size=56`。同表另两个同族符号为 `_obstack_free`（0xcd94，172 字节）、`_obstack_allocated_p`（0xcd40，84 字节）—— 仅作「真符号 + 真偏移 + 真大小」三件齐备的示范，不是可移植常量。注意首版把 size 写成 93/53/60 全是错的，由 §3 的验证件当场回读打回，这正是「无实测不写数」的现场样本。

### 类 B — 版本与行为：`TARGET_VERSION`「从 X 起新增 Y 参数 / 修复 Z 行为」

- **编造外观**：`ssh -o StrictHostKeyChecking=accept-new` 从 OpenSSH 7.6 起有；`readelf` 某 flag 从 2.39 起支持；「该 flag 在新版本被移除」。
- **为什么产出**：相邻版本的变更日志高度相似，模型把「好像见过」拼成「确有此变更」。
- **机制缺口**：本机版本与断言版本未必是同一个；上游行为随发行版打补丁而偏移；help 文本与手册可能滞后于实现。
- **判定信号**：出现 版本号 + 「起 / 之后 / 不再」时，必须先取本机实际版本与被断言工具的 `--help` 原文，再说有没有。
- **机械检查**：`<tool> --version` → `command -v` → `--help | grep` → 行为验证（真跑一次短命令）；走不通再查文档页并抄 URL，不抄记忆。

```bash
# 一条命令就能确认：断言里的行为在本机这个版本上存不存在（真值演示：readelf 2.42 + --dyn-syms）
TOOL=readelf
local_ver=$(query_installed_version readelf)                 # 见 §3 check_version_claim.sh
help_has=$(readelf --help | grep -c -- '--dyn-syms')          # 1/0，本机实测存在
readelf --dyn-syms -W /bin/ls >/dev/null 2>&1 && echo "行为可用" || echo "行为不可用"
printf 'installed=GNU readelf (GNU Binutils for Ubuntu) 2.42 | help_flag=%s\n' "$help_has"
```

实测：本机 `readelf --help` 含 `--dyn-syms`，且对该 ELF 真跑成功 → 「`--dyn-syms` 在本机 binutils 2.42 可用」是 **已知**；「binutils 从 2.35 起支持它」这类跨版本断言，本会话无来源可引 → **未知**，只能写成 `已知（2.35+ 起）待核` 或直接写 未知。

### 类 C — 比例与数字：命中率 / 成功率 / 性能倍数 / CVSS 分值 / 样本量

- **编造外观**：`成功率约 85%`、`快 3.7 倍`、`CVSS 9.8`、`检出率 92%`、`约 30% 的样本…`。
- **为什么产出**：这类数字在题面里通常是「验收项」，缺了像是没答完。
- **机制缺口**：比例的分母由环境定义（带宽、目标池、内核、并发、词表）；换个环境数字就换；CVSS 分数还随向量字符串而变，同漏洞可给 3.1 与 4.0 两套分。
- **判定信号**：任何 `%` 或 `N 倍` 出现时，同句必须能找到测量命令或引用来源，否则一律置 `未知` / 写成 `PLACEHOLDER_RATE`。
- **机械检查**：跑一次基准取实测值 + 单一来源引用；CVSS 用自写向量计算器复算，禁凭印象给分。

```bash
# 一条命令就能确认：这个比例有没有可跑的测量过程（真值演示：对 /bin/ls 做 sha256 取数）
python3 -c "import subprocess,time;t=time.perf_counter();subprocess.run(['sha256sum','/bin/ls'],capture_output=True);print('elapsed=%.4f s'%(time.perf_counter()-t))"
# 注：本机无 /usr/bin/time（command -v /usr/bin/time → 空，grep -c time /proc/self/status 不受影响）；缺则 apt-get install -y time，或用上面这行计时
# 命中率类：分母必须写在命令里，例 ffuf -u http://TARGET/FUZZ -w WORDLIST -mc 200 -ac -of json -o /tmp/ffuf.json
# CVSS 类：见 §3 check_rate_claim.py 的 cvss3 实现（只接受向量字符串 + 度量填表，不接受"我记得是 9.8"）
```

## 2. 检查件（主件，可直接跑）

保存为 `check_claims.sh`，用法 `bash check_claims.sh <target> [claims.tsv]`；`claims.tsv` 缺省 `./claims.tsv`，格式 `id<TAB>kind<TAB>subject<TAB>claimed`（kind ∈ offset|version|rate）。三处判定：offset 逐符号对真表、version 对本机实测版本、rate 强制要求证据引用。

```bash
#!/usr/bin/env bash
# check_claims.sh — 对抗三类编造断言：offset / version / rate
# 用法: bash check_claims.sh /bin/ls claims.tsv
set -uo pipefail
TARGET="${1:-/bin/ls}"
CLAIMS="${2:-./claims.tsv}"
pass=0; fail=0; unk=0
say() { printf '%s\n' "$*"; }

real_symbol_offset() {   # $1=elf $2=symbol -> 打印 value size 或空
  readelf --dyn-syms -W "$1" 2>/dev/null \
    | awk -v s="$2" '$8==s && $7!="UND" && $4=="FUNC" {printf "%s %s", $2, $3; exit}'
}
installed_version() {     # $1=tool -> 一行版本
  command -v "$1" >/dev/null 2>&1 || { say "MISSING_TOOL $1"; return 1; }
  "$1" --version 2>/dev/null | head -1
}

# 头两行是 §0 的真值行，用于自检：应当 PASS 与 PASS
test -f "$CLAIMS" || printf 'LS_A\toffset\t%s\t_obstack_memory_used\nLS_V\tversion\t%s\tGNU readelf (GNU Binutils for Ubuntu) 2.42\n' "$TARGET" "$TARGET" > "$CLAIMS"

while IFS=$'\t' read -r id kind subject claimed; do
  [ -z "${id:-}" ] && continue
  case "$kind" in
    offset)
      got=$(real_symbol_offset "$subject" "$claimed")
      if [ -n "$got" ]; then
        set -- $got
        say "PASS  $id  $claimed  value=0x$1 size=$2"
        pass=$((pass+1))
      else
        say "FAIL  $id  $claimed  在该 ELF 的动态符号表里不存在或未定义 -> 断言为编造/占位"
        fail=$((fail+1))
      fi ;;
    version)
      got=$(installed_version "$subject")
      if printf '%s' "$got" | grep -qF -- "$claimed"; then
        say "PASS  $id  $subject  本机实测: $got"; pass=$((pass+1))
      else
        say "FAIL  $id  断言 '$claimed' 与本机实测 '$got' 不符 -> 标为 未知 并附来源后再说"
        fail=$((fail+1))
      fi ;;
    rate)
      say "UNKNOWN  $id  $claimed  比例类断言无内置真值，必须附测量命令或来源 URL，否则按 未知 输出"
      unk=$((unk+1)) ;;
    *) say "SKIP  $id  未知 kind=$kind"; unk=$((unk+1)) ;;
  esac
done < "$CLAIMS"
say "== summary PASS=$pass FAIL=$fail UNKNOWN=$unk =="
```

## 3. 验证件（复现与自证）

保存为 `verify_os12.sh`。它会造一份含**一条真断言、三条假断言**的夹具，跑主件，并对每个 exit code 给断言。任一断言不成立即 `exit 1`。

```bash
#!/usr/bin/env bash
# verify_os12.sh — 证明 check_claims.sh 能抓到三类编造，且对真值不误报
set -uo pipefail
W=$(mktemp -d); cd "$W" || exit 1
REAL=$(command -v ls || echo /bin/ls)

cat > claims.tsv <<EOF
LS_A	offset	$REAL	_obstack_memory_used
LS_B	offset	$REAL	sub_DEADBEEF
BIN_V	version	readelf	GNU readelf (GNU Binutils for Ubuntu) 2.42
BIN_V2	version	readelf	GNU readelf (GNU Binutils for Ubuntu) 2.38
FF_R	rate	ffuf	成功率 85%
EOF

OUT=$(bash "$OLDPWD/check_claims.sh" "$REAL" "$W/claims.tsv" 2>&1) || true
printf '%s\n' "$OUT"
printf '%s' "$OUT" | grep -q 'PASS  LS_A'                  || { echo "ASSERT-FAIL: 真符号被误报"; exit 1; }
printf '%s' "$OUT" | grep -q 'FAIL  LS_B.*sub_DEADBEEF'    || { echo "ASSERT-FAIL: 类A 假符号未被抓到"; exit 1; }
printf '%s' "$OUT" | grep -q 'PASS  BIN_V'                 || { echo "ASSERT-FAIL: 真版本被误报"; exit 1; }
printf '%s' "$OUT" | grep -q 'FAIL  BIN_V2'                || { echo "ASSERT-FAIL: 类B 错版本未被抓到"; exit 1; }
printf '%s' "$OUT" | grep -q 'UNKNOWN  FF_R'               || { echo "ASSERT-FAIL: 类C 无证据比例未降级"; exit 1; }
echo "VERIFY OK: 三条编造全部被标出，两条真值未误报"
```

配套的第二个检查件（比例类 + CVSS 类，零第三方依赖）：

```bash
cat > check_rate_claim.py <<'PY'
#!/usr/bin/env python3
"""比例类断言的机械检查：没有实测数值 + 没有可核来源 = 不许写成已知。"""
import re, sys
NUM = re.compile(r'(\d+(?:\.\d+)?)\s*(%|倍|x)')
def audit(line: str) -> str:
    m = NUM.search(line)
    if not m:
        return "SKIP  无量化断言"
    if re.search(r'(实测|measured|来源|https?://|依据)', line):
        return f"PASS   量值 {m.group(0)} 附有实测/来源标记"
    return (f"UNKNOWN  量值 {m.group(0)} 无实测、无可核来源 -> 输出时改写成占位符 PLACEHOLDER_RATE"
            f"，除非同句给出测量命令或 URL")
if __name__ == "__main__":
    for ln in sys.stdin.read().splitlines():
        if ln.strip():
            print(audit(ln))
PY
```

## 4. 落地口径（写进每次出稿）

| 断言类型 | 无实测/无来源时的写法 | 机械判据 |
|---|---|---|
| 偏移 / 符号 / 地址 | `OFFSET_1` / `TARGET_ADDR`，并注明「需在对靶机 `readelf` 取值」 | `check_claims.sh` kind=offset |
| 版本 / 行为窗口 | `TARGET_VERSION`，或「未知：需目标版本 `--help` 原文」 | kind=version + `--help` 原文 |
| 比例 / 倍数 / CVSS | `PLACEHOLDER_RATE` / 「未知：需实际测量」 | kind=rate + `check_rate_claim.py` |

## 5. 我确实抓不到的三类（限制，写在最前而不是藏在最后）

1. **无目标环境的偏移**：不给二进制/镜像就没有真值，`已知` 一律降为 `未知`（架构上无法凭知识给出）。
2. **上游私有/未公开的变更**：没有可引用条目时，跨版本断言只能写 `推测：`，不得写「已验证」。
3. **需要规模资源的比例**：命中率/吞吐类断言要 `需要实际带宽/主机池` 才能测，本文件只给判据不给数字。

## 6. 四态与时效

已知（本会话实测）：§0 全部环境值（含「jq / gdb / strace / /usr/bin/time 均不存在」）、§1 的 `_obstack_memory_used`=0xce40/size 56、`_obstack_free`=0xcd94/size 172、`_obstack_allocated_p`=0xcd40/size 84、`readelf --help` 含 `--dyn-syms` 且对该 ELF 跑通、`/bin/ls` 动态符号表 130 项、§3 验证件完整回读 `PASS LS_A / FAIL LS_B / PASS BIN_V / FAIL BIN_V2 / UNKNOWN FF_R`、summary `PASS=2 FAIL=2 UNKNOWN=1`、`VERIFY_EXIT=0`。
推测：`python3 -m pip install --break-system-packages cvss` 在本机可装上（依据：Python 3.12 + Ubuntu 24.04 外置包管理默认，未实跑）。
未知：跨版本「从 X 版起支持 Y」类断言的真实窗口（需目标版本的 `--help` 原文或可引用变更条目）；ffuf/nuclei 一类命中率数字（本会话未装、未测）。
过期：无来源支撑的「某偏移/某 flag 在某版本可用」旧口径（有效期到该版本号被发行版换掉为止，依据：偏移与 flag 随构建变化），本轮已被上文「先 readelf 再写」取代。

- 截至 2026 年（2026-09-28 核）已验证：`readelf --dyn-syms -W` + `awk '$4=="FUNC" && $7!="UND"'` 在本机 binutils 2.42 / Ubuntu 24.04 aarch64 上能取到真符号偏移；旧稿「按印象写偏移」口径已失效，以下为新写法（先 readelf 再落笔，取不到就写 OFFSET_1）。

- 已知：§0 环境值与三个符号偏移为实测；推测：pip 装 cvss 可成功；未知：跨版本行为窗口与一切未实测的比例数字。
- 依赖与边界：需要实际目标环境复验（本文件的偏移真值只对 /bin/ls 成立）；命中率/倍数类断言的验证需要实际带宽 / 主机池。
