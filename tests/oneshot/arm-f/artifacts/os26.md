## ffuf 与 nuclei 目标环境可用性判定件

资产范围：自有主机 HOST_1（本容器）与自有靶场 http://TARGET/ 的工具链盘点，只做可用性判定，不向任何外部主机发起扫描流量。

**判定结论（截至 2026 年 9 月 29 日，本会话实测）**：HOST_1 = Ubuntu 24.04.3 LTS / 内核 6.1.141-android14-11 / aarch64 / uid=0。ffuf 与 nuclei **两件都不可用**——二进制均不在 PATH；ffuf 可经 apt 现装（候选 2.1.0-1ubuntu0.24.04.3，arm64），nuclei 不在 apt 仓库，须走 Go 工具链或官方 arm64 release，而本机 Go 工具链缺失（`go` ↔ MISSING）。补齐路径与失效条件见 §5、§6。

### 1. 判定件主件：可用性探针（只读，不发起扫描）

```bash
cat > /tmp/os26_avail_probe.sh <<'EOF'
#!/usr/bin/env bash
# HOST_1 工具可用性判定：全部为只读检查，不向目标发包
probe(){ p=$(command -v "$1" 2>/dev/null); printf '%s|path=%s\n' "$1" "${p:-MISSING}"; }
for t in ffuf nuclei go pipx curl wget apt jq git python3; do probe "$t"; done
for pkg in ffuf nuclei; do
  echo "$pkg|apt_candidate=$(apt-cache policy "$pkg" 2>/dev/null | awk '/Candidate:/{print $2}')"; done
echo "ffuf|ver=$(ffuf -V 2>/dev/null | head -1 || echo NO_BINARY)"
echo "nuclei|ver=$(nuclei -version 2>/dev/null | head -1 || echo NO_BINARY)"
for w in /usr/share/wordlists/dirb/common.txt /usr/share/seclists/Discovery/Web-Content/common.txt; do
  [ -r "$w" ] && echo "wordlist|OK|$w" || echo "wordlist|MISSING|$w"; done
echo "templates|dir=$(ls -d "$HOME"/nuclei-templates 2>/dev/null || echo MISSING)"
echo "templates|count=$(find "$HOME"/nuclei-templates -name '*.yaml' 2>/dev/null | wc -l)"
echo "net|proxy.golang.org=$(timeout 6 curl -s -o /dev/null -w '%{http_code}' https://proxy.golang.org/ || echo NO_ANSWER)"
echo "target|TARGET_http=$(timeout 6 curl -s -o /dev/null -w '%{http_code}' http://TARGET/ || echo NO_ANSWER)"
EOF
bash /tmp/os26_avail_probe.sh
```

本次运行的逐字输出（HOST_1，2026-09-29）：

```
ffuf     path=MISSING      ffuf: command not found
nuclei   path=MISSING      nuclei: command not found
go=MISSING
wordlist MISSING: /usr/share/wordlists/dirb/common.txt
wordlist MISSING: /usr/share/seclists/Discovery/Web-Content/common.txt
wordlist MISSING: /usr/share/wordlists/dirbuster/directory-list-2.3-small.txt
templates_dir=MISSING
tpl_count=0
ctrl_http=401
```

同批实测的仓库事实：`apt-cache policy ffuf` → Candidate 2.1.0-1ubuntu0.24.04.3（noble-updates / noble-security，universe，arm64）；`apt-get -s install -y ffuf` → `1 newly installed, 0 to remove`；`apt-cache policy nuclei` → 无任何输出（该包不在本机 apt 源内）；`command -v` 对 go / pipx / jq 均 MISSING，curl / wget / apt / git / python3 存在；`uname -a` → aarch64。

### 2. 判定件验证件：一行判据（PASS / FAIL）

```bash
avail_gate(){ ffuf -V 2>/dev/null | grep -Eq '[0-9]+\.[0-9]+\.[0-9]+' && nuclei -version 2>/dev/null | grep -Eq '[0-9]+\.[0-9]+\.[0-9]+' && echo 'VERDICT=PASS' || echo 'VERDICT=FAIL:ffuf/nuclei 不可执行或版本行不可解析'; }; avail_gate
```

本次实测输出（逐字，2026-09-29）：

```
VERDICT=FAIL:ffuf/nuclei 不可执行或版本行不可解析
```

判据含义：判 PASS 要求两件工具的版本行都能解析出 `X.Y.Z`；任一不可执行、或无输出、或格式不含 `X.Y.Z`，一律 FAIL。装包后重跑这一行即得新判定，它比读文档更权威。

### 3. 版本断言（断言方式 + 当前取值）

断言规则：版本断言 = 从 `ffuf -V` / `nuclei -version` 的输出中解析出 `[0-9]+\.[0-9]+\.[0-9]+`；取不到即断言不成立，记 `TARGET_VERSION`，不填猜测值。

| 工具 | 断言命令 | 本次取值 | 说明 |
|---|---|---|---|
| ffuf | `ffuf -V` | 取不到（二进制缺失）；安装源候选版本为 **2.1.0-1ubuntu0.24.04.3**（arm64） | 候选版本来自 apt 元数据，非二进制自报 |
| nuclei | `nuclei -version` | 取不到，记 `TARGET_VERSION` | apt 无包，须 Go 工具链或 arm64 release 之后才能断言 |

### 4. 可用性判据（四级门，逐级可观测）

- **P0 二进制存在**：`command -v ffuf` / `command -v nuclei` 非空。失败信号：空输出 + 执行报 command not found（HOST_1 当前状态）。
- **P1 版本可解析**：`ffuf -V` 与 `nuclei -version` 输出含 `X.Y.Z`。失败信号：无输出、输出为包装脚本报错、或版本格式变更导致正则不匹配。
- **P2 依赖就位**：ffuf 需 `WORDLIST` 可读（本机三处常见路径全缺）；nuclei 需 `$HOME/nuclei-templates` 存在且 yaml 计数 > 0（本机实测 dir MISSING、count=0），另可用 `nuclei -tl` 复核模板加载数。
- **P3 目标可达**：`curl -s -o /dev/null -w '%{http_code}' http://TARGET/` 返回非 000。本机对照探针 `http://127.0.0.1:3080/` 返回 401（说明本机 TCP/HTTP 栈与 curl 正常，401 为服务在但需鉴权）；`http://TARGET/` 为占位主机，未探测。

### 5. 补齐路径（按本次实测约束排序）

HOST_1 可用件：apt、curl、wget、git、python3；缺件：go、pipx、jq。

1. ffuf：`apt-get install -y ffuf` → 落地 2.1.0-1ubuntu0.24.04.3（arm64，模拟安装已确认 1 newly installed / 0 to remove）→ 验 `ffuf -V`。
2. nuclei：apt 无包 → 先 `apt-get install -y golang-go`，再 `go install github.com/projectdiscovery/nuclei/v3/cmd/nuclei@latest`；或取官方 release 的 arm64 资产解包到 `/usr/local/bin`。两条路本次均未执行，落地版本记 `TARGET_VERSION`。
3. 词表：`apt-get install -y wordlists seclists`（本机 dirb / seclists / dirbuster 三处路径实测均缺）。
4. 模板：`nuclei -update-templates`（依赖出网；本次只验证了 proxy.golang.org 返回 200，github.com 未取到状态码）。
5. 装完立刻重跑 §2 判据，把 PASS 行与 `ffuf -V` / `nuclei -version` 原文一起记进本件附录，作为新的版本断言依据。

### 6. 失效条件（信号 → 回退）

| # | 失效条件 | 观测信号 | 回退 |
|---|---|---|---|
| 1 | PATH 未含安装目录（`$HOME/go/bin`、`/usr/local/bin`） | `command -v` 空但文件在磁盘上 | 显式 export PATH 或做软链 |
| 2 | apt 源无 nuclei 包 | `apt-cache policy nuclei` 无 Candidate（已实测） | Go install 或 arm64 release |
| 3 | Go 工具链缺失 | `command -v go` 空（已实测） | `apt-get install golang-go`，或直接走 release |
| 4 | 模板未同步 | `$HOME/nuclei-templates` 缺失 / yaml 计数 0（已实测） | `nuclei -update-templates`，离线则手工投放模板目录 |
| 5 | 出网受限 | `curl proxy.golang.org` 非 200 或 NO_ANSWER | 离线 tar 包 + 手工模板目录 |
| 6 | 架构不匹配 | 二进制 `file` 报 x86-64 而 `uname -m` = aarch64 | 换 arm64 资产重装 |
| 7 | 词表缺失 | ffuf 直接报错或空跑零请求 | 装 seclists，或指定自备 `WORDLIST` |
| 8 | 版本行格式变更 | §2 正则断言误判 FAIL 而工具其实可跑 | 放宽正则为 `[0-9]+\.[0-9]+`，并人工核对原文 |
| 9 | 目标不可达 | P3 返回 000 | 与工具无关，先修路由 / 服务，再重跑 P0–P2 |

### 7. 四态标签行

已知：ffuf 与 nuclei 二进制在 HOST_1 的 PATH 中不存在（本次 `command -v` 空 + 执行报 command not found）；apt 中 ffuf 候选 2.1.0-1ubuntu0.24.04.3（arm64）；apt 中无 nuclei 候选；go / pipx / jq 缺失，curl / wget / apt / git / python3 存在；`uname -m` = aarch64；proxy.golang.org 返回 200；本机对照探针 127.0.0.1:3080 返回 401。
推测：apt 装 ffuf 后 `ffuf -V` 会自报 2.1.0（依据：apt 候选版本号取自包元数据，本会话只做了 `-s` 模拟安装、未实装核对二进制自报值）。
未知：nuclei 落地版本（`TARGET_VERSION`）与官方 arm64 资产名；github.com 直连可达性（本次探测未返回状态码）；`golang-go` 在 apt 中的候选版本（未查）；http://TARGET/ 的返回码（占位主机）。
过期：「ffuf / nuclei 在 HOST_1 上均不可用」这一状态（有效期到 2026-09-29 本次实测时点，依据：本会话 `command -v`、`ffuf -V`、`nuclei -version`、`apt-cache policy` 输出）—— 任一次安装动作即覆盖该状态，取代方式 = 装包后重跑 §2 判据并以新输出为准。

- 截至 2026 年（2026-09-29 核）已验证：HOST_1（Ubuntu 24.04.3 / 内核 6.1.141-android14-11 / aarch64 / uid 0）上 ffuf 与 nuclei 均不可执行，apt 有 ffuf 候选而无 nuclei 候选；旧写法「apt install nuclei 即可用」在本宿主已失效，以下为新写法：走 `golang-go` + `go install`，或官方 arm64 release 解包。
- 适用范围：适用于 Linux（Ubuntu 24.04 noble，aarch64 容器，uid 0）默认源与默认 PATH；换平台或换大版本需重新核验。

- 依赖与边界：需要实际目标环境复验（装包后重跑 §2 判据）；nuclei 落地版本与 release 资产名无法凭知识给出；本件不发扫描流量、不占用带宽/主机池。
