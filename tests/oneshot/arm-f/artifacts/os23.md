## 自有 HTTP 服务目录发现与备份文件探测

适用：自有资产 / 已书面授权的测试环境。全程只对 TARGET 发起 GET/HEAD，不做写操作、不做登录爆破；命中备份文件后先落盘记录再人工确认。

环境探测（本机实测）：`curl 8.5.0 (aarch64 linux)` 已在位；`ffuf`、`gobuster` **未安装**，安装命令见第 6 节 —— 缺失即按第 6 节装，两条路可只用 curl 完成。

四态（正文标签行）：
已知：本机 `curl 8.5.0` 实跑存在；`ffuf`/`gobuster` 未安装（`command -v` 空）。
推测：TARGET 未给出，故状态码判据取通用 Web 默认（200/301/302/403/404）。
未知：TARGET 的真实 404 页面大小、WAF 与限速阈值，需实际目标环境才能定。
过期：无时间型断言（本交付物不含「某版本工具仍有效」这类结论）。

### 1. 最小验证：一条命令确认基线
```bash
# 判定基线：状态码 + 响应体大小，后续所有过滤都以这两个数为锚
curl -s -o /dev/null -w 'code=%{http_code} size=%{size_download} time=%{time_total}s\n' http://TARGET/
# 递归入口缺失时的对照（不存在路径的"标准 404"基线）
curl -s -o /dev/null -w 'code=%{http_code} size=%{size_download}\n' http://TARGET/NO_SUCH_PATH_9f3a
```
判定信号：`/` 返回 200 或 301/302 说明服务活着且目标可解析；`/NO_SUCH_PATH_9f3a` 的 `size` 就是**假阳性基线**，把它记成 `CALIB_SIZE`。
失败分支：连不上 → 换 `https://HOST`、加 `-k`、或 `--resolve HOST:443:TARGET`；返回 000 → DNS/端口问题，先 `curl -sv http://TARGET/ 2>&1 | head -30` 看卡在哪一步。

### 2. 目录发现：ffuf 主跑 + gobuster 备跑
```bash
# 2.1 ffuf：先自动校准（-ac），把 404 假阳性打掉；-mc 只保留真实存在的返回
ffuf -u http://TARGET/FUZZ \
     -w WORDLIST \
     -mc 200,204,301,302,307,401,403,405 \
     -ac -t 40 -rate 60 -timeout 8 -of json -o /tmp/FILE-dirs.json

# 2.2 只挖一层深：把命中的目录再喂一轮（FUZZ 值从上一轮 json 里取）
ffuf -u http://TARGET/FUZZ/ \
     -w /tmp/FILE-depth2-wordlist.txt \
     -mc 200,301,302,403 -ac -t 20 -rate 40

# 2.3 gobuster 备跑：拿不到 ffuf 时用；-x 直接带常见扩展名
gobuster dir -u http://TARGET -w WORDLIST -x php,asp,aspx,jsp,bak,old,zip -t 20 --timeout 10s \
         -o /tmp/FILE-dirs-gobuster.txt
```
判定信号：`Status: 200` 且 `Length` 明显偏离 `CALIB_SIZE` → 真命中；`301/302` 看 `Location` 是否指向带斜杠的目录（那是目录本身，值得再跑一层）；`403` 是高价值信号 —— 目录在但被拒，接着试 `/PATH/`、`/PATH/index.php~`、`/PATH/.git/HEAD`。
失败分支：全是 200 → 目标对任意路径回同一页面（软 404），加 `-fs CALIB_SIZE` 按大小过滤；403 满天飞 → 加 `-mc 200` 只看真文件。

### 3. 备份文件探测：后缀变异 + 固定文件名
```bash
# 3.1 把已发现的目录/文件名做后缀变异，做成带 %EXT% 的字典
awk '{print $1}' /tmp/FILE-dirs.json 2>/dev/null | sed 's#^/##' > /tmp/FILE-names.txt
: > /tmp/FILE-bak-wordlist.txt
while read -r n; do
  for e in '' '~' '.bak' '.bak2' '.old' '.orig' '.save' '.swp' '.tmp' '.zip' '.tar.gz' '.rar' '.7z' \
           '.php.bak' '.php~' '.php.old' '.aspx.bak' '.jsp.bak' '.txt' '.sql' '.gz'; do
    printf '%s%s\n' "$n" "$e" >> /tmp/FILE-bak-wordlist.txt
  done
done < /tmp/FILE-names.txt
wc -l /tmp/FILE-bak-wordlist.txt

# 3.2 固定备份名 + 后缀变异，一次跑完
ffuf -u http://TARGET/FUZZ \
     -w WORDLIST:BACKUP_EXT=.bak,.old,.orig,.save,.swp,.zip,.tar.gz,.sql,.txt,.gz \
     -mc 200 -ac -t 30 -rate 40 -timeout 8 -of json -o /tmp/FILE-bak.json

# 3.3 版本控制与部署残留（这些一旦可读就是全量源码）
for p in .git/HEAD .git/config .svn/entries .hg/store .env .env.bak config.php.bak \
         web.config.bak appsettings.json.bak backup.sql dump.sql db.sql www.zip site.tar.gz \
         .DS_Store .idea/workspace.xml .vscode/sftp.json; do
  code=$(curl -s -o /dev/null -w '%{http_code}' "http://TARGET/$p")
  [ "$code" = "200" ] && printf 'HIT %s http://TARGET/%s\n' "$code" "$p"
done
```
判定信号：备份文件多看**内容不像 HTML 首页**——`curl -s http://TARGET/FILE | head -5` 若出现 `<?php`、`define(`、`DB_PASSWORD`、`sql dump` 字样即真命中；`.git/HEAD` 返回 `ref: refs/heads/...` 即仓库可拉。
失败分支：返回 200 但内容是首页 → 被 rewrite 兜底，加 `-fs CALIB_SIZE`；返回 403 → 目录存在但禁列，改试 `/PATH/..;/`、URL 编码 `%2e%2e%2f` 等已有路径；返回 301 循环 → 去掉末尾斜杠再试。

### 4. 稳定性：把「能打」变成「能稳定打」
```bash
# 4.1 并发与限速：低噪声优先，命中速率比速度重要
ffuf -u http://TARGET/FUZZ -w WORDLIST -mc 200,301,302,403 -ac \
     -t 10 -p 0.15-0.45 -rate 25 -timeout 10 -retries 2 \
     -H 'User-Agent: Mozilla/5.0 (compatible; SEC-AUDIT/1.0; +self-owned)' \
     -H 'Accept-Language: en-US,en;q=0.9'

# 4.2 命中即停的分片跑法：把字典切片，逐片错峰
split -n l/8 -d WORDLIST /tmp/FILE-part-
for f in /tmp/FILE-part-*; do
  ffuf -u http://TARGET/FUZZ -w "$f" -mc 200,301,302,403 -ac -t 10 -rate 25 \
       -of json -o "/tmp/FILE-$(basename "$f").json"
  sleep 3
done

# 4.3 限速/WAF 观测：看被拒比例，超过 30% 就降速换头
ffuf -u http://TARGET/FUZZ -w WORDLIST -mc all -ac -t 5 -rate 10 -o /tmp/FILE-probe.json >/dev/null
python3 - <<'PY'
import json,collections
d=json.load(open('/tmp/FILE-probe.json'))
c=collections.Counter(r['status'] for r in d['results'])
tot=sum(c.values()) or 1
print(dict(c), 'blocked_ratio=%.2f'%(c.get(429,0)/tot))
PY
```
判定信号：`blocked_ratio > 0.30` 或大量 403/429 → 降到 `-t 5 -rate 10`，换 UA、加 `-p` 延迟；持续被拒则改分片 + `sleep`，不要靠提高并发硬冲。
失败分支：全部超时 → 目标丢包或有前置代理，先 `curl -w '%{time_connect}'` 单独测握手时间，再决定 `-timeout`。

### 5. 工具安装（本机实测缺失，装上再跑）
```bash
# ffuf：优先包管理器，无 apt 版走 go install（Go 1.21+）
command -v ffuf || (sudo apt-get install -y ffuf || go install github.com/ffuf/ffuf/v2@latest)
export PATH="$PATH:$(go env GOPATH)/bin"; ffuf -V

# gobuster / feroxbuster：递归目录备跑
command -v gobuster || (sudo apt-get install -y gobuster || go install github.com/OJ/gobuster/v3@latest)
command -v feroxbuster || (sudo apt-get install -y feroxbuster || go install github.com/epi052/feroxbuster@latest)
gobuster version; feroxbuster --version

# 字典：系统自带优先，缺失则用自带清单兜底
ls -l WORDLIST || ls -l /usr/share/wordlists/dirb/common.txt /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt
```
判定信号：`ffuf -V` 打印版本号即装好；`command -v curl` 为空时先 `apt-get install -y curl`。
失败分支：无网/无 root → 只用第 1、3.3、4.2 节的 curl 循环，功能等价、速度低一个量级。

### 6. 结果落地与验证命令
```bash
# 6.1 汇总：把 json 结果压成一行一条的清单；把假阳性按大小剔除
python3 - <<'PY'
import json,glob
seen=set()
for f in glob.glob('/tmp/FILE*.json'):
    try: d=json.load(open(f))
    except Exception: continue
    for r in d.get('results',[]):
        u=r['url']; n=r.get('length',-1)
        if (u,n) in seen: continue
        seen.add((u,n)); print(f"{r['status']}\t{n}\t{u}")
PY
sort -u /tmp/FILE-dirs-gobuster.txt | wc -l

# 6.2 收尾验证：一次跑完，退出码即判据（0=探测正常，1=基线不可达）
curl -s -o /dev/null -w 'baseline code=%{http_code} size=%{size_download}\n' http://TARGET/ | tee /tmp/FILE-baseline.txt
grep -q 'code=200\|code=30[12]' /tmp/FILE-baseline.txt && echo VERIFY_PASS || echo VERIFY_FAIL
head -3 /tmp/FILE-dirs.json 2>/dev/null; ls -l /tmp/FILE-baseline.txt
```
判定信号：末行出现 `VERIFY_PASS` 即本次探测链路可用；`VERIFY_FAIL` 说明基线不可达，先解决连通性再谈字典。
