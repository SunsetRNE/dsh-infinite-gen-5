## 日志取证三件套部署与判据：Plaso 时间线 / Chainsaw EVTX 猎杀 / Zeek 网络日志

本机先探（本会话实测，非推断）：Linux 6.1.141-android14-11 容器内 Ubuntu 工作区，uid=0，Python 3.12.3，`apt-get`/`curl`/`git` 可用，`pip3`、`go`、`cargo` 缺失，网络可达（`curl -sSI https://pypi.org/simple/` → 200，github.com → 200）。`log2timeline.py`、`psort.py`、`chainsaw`、`hayabusa`、`zeek`、`tshark`、`jq` **全部 MISSING** —— 下面是首次安装的完整路径，不是复述官方文档。取证对象为自有镜像与书面授权样本（`EVIDENCE_DIR = /evidence/ARM28`），只读取，不写回证据盘。

三件套分工：Plaso 出全盘超级时间线（回答"什么时候发生了什么"），Chainsaw 出 Windows 事件日志的规则命中（回答"哪条行为可疑"），Zeek 出网络会话日志（回答"和谁通信、传了什么"）。三者独立可跑，也可只装其中一件。

### 一、Plaso —— 超级时间线（装 / 跑 / 判据）

```bash
# ── 装：pip3 缺失，先补 pip，再装 plaso ─────────────────────────────────
apt-get update && apt-get install -y python3-pip jq
python3 -m pip install --upgrade plaso
# 备选（未核）：apt-get install -y python3-plaso  —— 仅部分发行版源内有包
log2timeline.py --version && psort.py --version   # 实测未跑：本机 plaso 未安装

# ── 跑：E01/RAW 镜像 → 存储文件 → 排序时间线（只读挂载，绝不写回证据盘）──
CASE_ID=ARM28; EVIDENCE_DIR=/evidence/${CASE_ID}; OUT=/cases/${CASE_ID}
mkdir -p "$OUT"
log2timeline.py --storage-file "$OUT/plaso.dump" --logfile "$OUT/plaso.log" \
  --hashers md5,sha256 "$EVIDENCE_DIR/disk.E01"
psort.py -o l2tcsv -w "$OUT/timeline.csv" "$OUT/plaso.dump"

# ── 判据：三条同时成立才算取证成功 ────────────────────────────────────
ARTIFACT_SOURCE=evtx                     # 占位：换成案情关注来源（evtx/prefetch/lnk…）
ROWS=$(( $(wc -l < "$OUT/timeline.csv") - 1 ))
SRC=$(grep -c "$ARTIFACT_SOURCE" "$OUT/timeline.csv" || true)
test "$ROWS" -ge 1 && test "$SRC" -ge 1 \
  && echo "PASS  events=$ROWS source=${ARTIFACT_SOURCE}x$SRC" \
  || echo "FAIL  events=$ROWS source=$SRC  → 查 $OUT/plaso.log 的解析错误行"
head -1 "$OUT/timeline.csv"; grep -m3 -i "$ARTIFACT_SOURCE" "$OUT/timeline.csv"
```
判定信号：`PASS` 且 `plaso.log` 无 `Unable to parse` 堆积。`ROWS=0` 说明镜像解析层就没通（先查 E01 段表与文件系统支持），不是分析结论；`SRC=0` 说明来源过滤写错或该来源在镜像里根本不存在。

### 二、Chainsaw —— EVTX + Sigma 规则猎杀（装 / 跑 / 判据）

```bash
# ── 装：本机无 go/cargo，走官方 release 二进制（版本号未知，用占位替换）──
apt-get install -y curl unzip jq
CHAINSAW_VERSION=<CHAINSAW_VERSION>      # 占位：取官方 release 最新 tag，未核
ASSET=chainsaw_x86_64-unknown-linux-gnu.tar.gz   # 推测：附件命名随版本变动，用前核对 release 页
curl -fsSL -o /tmp/chainsaw.tar.gz \
  "https://github.com/WithSecureLabs/chainsaw/releases/download/v${CHAINSAW_VERSION}/${ASSET}"
tar -xzf /tmp/chainsaw.tar.gz -C /opt/ && /opt/chainsaw/chainsaw --version
git clone --depth 1 https://github.com/SigmaHQ/sigma /opt/sigma   # 规则集

# ── 跑：EVTX 目录 → Sigma 匹配 → JSON + CSV ───────────────────────────
chainsaw hunt "${EVIDENCE_DIR}/evtx" \
  --sigma /opt/sigma/rules \
  --mapping /opt/chainsaw/mappings/sigma-event-logs-all.yml \
  --output "$OUT/hunt.json" --csv "$OUT/hunt.csv" --level high

# ── 判据：命中规则数 ≥1，且命中项带得出 RuleID / EventID ──────────────
python3 - "$OUT/hunt.json" <<'PY'
import json, sys
d = json.load(open(sys.argv[1]))
det = [r for r in d if r.get("detections")]
print("rules_hit=", len(det))
for r in det[:5]:
    for h in r["detections"][:1]:
        print("  rule=", r.get("name"), "| count=", h.get("count"),
              "| eventid=", (h.get("events") or [{}])[0].get("Event", {}).get("System", {}).get("EventID"))
print("CRITERION:", "PASS" if det else "FAIL")
PY
```
判定信号：`CRITERION: PASS`。`FAIL` 且 `hunt.json` 为空数组时先确认 EVTX 是否真被解出——`chainsaw dump` 单文件计数（`chainsaw dump FILE.evtx | wc -l`，0 则文件损坏或被复制时截断）；规则全不中不等于没入侵，只等于规则集没覆盖。

### 三、Zeek —— 网络日志取证（装 / 跑 / 判据）

```bash
# ── 装：apt 源或官方 OBS 仓库；容器路线为降级备选 ─────────────────────
apt-get install -y zeek || { echo "apt 源无 zeek → 用官方 OBS 仓库或容器"; }
zeek --version                                     # 实测未跑：本机 zeek 未安装
# 备选（无 root / 源不可用时）：docker run --rm -v "$PWD":/pcap zeek/zeek -r /pcap/capture.pcap local

# ── 跑：pcap → conn/dns/http 等分离日志（JSON 便于下游解析）────────────
mkdir -p "$OUT/zeek" && cd "$OUT/zeek"
zeek -r "${EVIDENCE_DIR}/capture.pcap" LogAscii::use_json=T local
ls -1 *.log | sed 's/^/log:/'

# ── 判据：conn.log 非空 + 定位到目标 IP 的会话 + uid 唯一性可查 ────────
TARGET_IP=203.0.113.7                              # 占位：换成案情关注的对端
python3 - "$OUT/zeek/conn.log" "$TARGET_IP" <<'PY'
import json, sys
rows = [json.loads(l) for l in open(sys.argv[1]) if l.strip()]
hits = [r for r in rows if sys.argv[2] in (r.get("id.orig_h"), r.get("id.resp_h"))]
bytes_out = sum(r.get("orig_bytes", 0) for r in hits)
print(f"conn_rows={len(rows)} uniq_uid={len({r['uid'] for r in rows})} "
      f"target_hits={len(hits)} orig_bytes={bytes_out}")
print("CRITERION:", "PASS" if rows and hits else "FAIL")
PY
```
判定信号：`CRITERION: PASS`。`target_hits=0` 时先查 pcap 是否有丢包/被截断（`zeek` 会在 `reporter.log` 里记 `truncated` / `capture_loss`），再看时间窗是否覆盖案情时段——两者都不是"没通信"的结论。
