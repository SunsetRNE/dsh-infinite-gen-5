## Windows 内存镜像取进程列表：volatility3 安装、版本核验与判定

取证对象为自有或受托分析的资产，流程只做只读提取，不写回镜像。

环境结论（本机实测，非推测）：Ubuntu 24.04.3 LTS / Python 3.12.3；`command -v vol.py`、`command -v volatility3`、`command -v vol` 三条全空，`python3 -c "import volatility3"` 报 `ModuleNotFoundError: No module named 'volatility3'`；系统无 pip3、无 pip 模块、无 pipx；出网正常（pypi.org 与 bootstrap.pypa.io 均返回 200）。所以「装什么」这一步是必须的，不是可选优化。

### 0. 证据固定（先做，顺序不能反）

镜像到手第一件事是哈希与只读，之后所有命令只读镜像、不挂载写。

```bash
sha256sum IMAGE.mem | tee /tmp/IMAGE.sha256     # 证据完整性基线，后续结论都挂在这个哈希上
cp --reflink=auto IMAGE.mem /cases/ro/IMAGE.mem # 分析副本，原件封存；分析只碰副本
ls -l IMAGE.mem; file IMAGE.mem                 # 记录字节数，核对采集工具声明的容量是否一致
```

判据：`sha256sum` 输出的哈希与采集方交付单一致 → 证据链成立；不一致 → 停止分析，先回到采集环节。

### 1. 安装 volatility3（本机验证过的路径）

本机 `python3 -m venv` 生成的虚拟环境里没有 pip，且 `python -m ensurepip` 直接报 `No module named ensurepip`（Ubuntu 的 ensurepip 在 python3-venv 包里）。因此不要走 venv+ensurepip 这条链，用官方 get-pip.py 把 pip 引导进 venv：

```bash
python3 -m venv /opt/vol3env
curl -sSL -o /tmp/get-pip.py https://bootstrap.pypa.io/get-pip.py
/opt/vol3env/bin/python /tmp/get-pip.py                 # 实测落 pip 26.2.1 (python 3.12)
/opt/vol3env/bin/python -m pip install -U volatility3   # 实测退出码 0，生成 bin/vol 与 volshell
ls -l /opt/vol3env/bin/vol /opt/vol3env/bin/volshell
```

可选路线（同一台机上任选其一，不要叠加）：`apt-get install -y pipx && pipx install volatility3`；或 `apt-get install -y python3-pip` 后 `pip3 install --user volatility3`。代价对比：venv 路线不动系统 Python，回收只需 `rm -rf /opt/vol3env`；pipx 路线自动隔离但依赖 apt；--user 安装最省事，但会和系统 site-packages 混在一起。

无出网时的降级：在联网机 `pip download volatility3 -d /tmp/whl` 后离线 `pip install --no-index --find-links /tmp/whl volatility3`；仍不可行则退到已编译的 Volatility 2 standalone 二进制跑 `windows.pslist`（插件名与输出格式不同，判据需另写）。

### 2. 版本核验（本机实测有一条坑）

`volatility3` 模块没有 `__version__` 属性，实测 `python -c "import volatility3; print(volatility3.__version__)"` 抛 `AttributeError: module 'volatility3' has no attribute '__version__'`。所以版本只从下面两处读：

```bash
/opt/vol3env/bin/vol -h 2>&1 | head -1        # 实测首行：Volatility 3 Framework 2.28.2
/opt/vol3env/bin/python -m pip show volatility3 | grep -iE '^Name|^Version'
/opt/vol3env/bin/vol -h 2>&1 | grep -E 'windows\.(pslist|cmdline|psscan)\.'   # 确认插件确实在
```

判据：`vol -h` 首行以 `Volatility 3 Framework` 开头并带版本号 → 可用；`pip show` 的 Version 与首行一致 → 安装无残留旧版。若首行不是 Framework 而是 traceback，多数是 Python 版本与 wheel 不匹配（本机是 3.12，实测可装）。

### 3. 跑什么：取进程列表

Volatility 3 的 `-f` 可省，镜像位置作为位置参数；输出走 `-o` 落盘目录，不污染当前工作目录。

```bash
/opt/vol3env/bin/vol -f /cases/ro/IMAGE.mem -o /cases/out windows.pslist.PsList --output=json
/opt/vol3env/bin/vol -f /cases/ro/IMAGE.mem -o /cases/out windows.cmdline.CmdLine --output=json
/opt/vol3env/bin/vol -f /cases/ro/IMAGE.mem -o /cases/out windows.psscan.PsScan  --output=json
```

`windows.pslist.PsList` 实测 usage 为 `vol windows.pslist.PsList [-h] [--physical] [--pid [PID ...]] [--dump]`，插件自述 "Lists the processes present in a particular windows memory image."。参数取舍：`--pid PID_1` 只看目标进程；不指定 `--dump`，`--dump` 会把进程内存体写到磁盘（体量大、且会把受害者数据落盘，只在确有必要时用）；`--physical` 走物理地址扫描语义，与默认的虚拟地址遍历结果集合不同。

### 4. 判据与异常分支

- 正常：JSON 里每个进程条目含 PID、PPID、ImageFileName、创建时间等字段；条目数在几十到数百量级；`System`、`smss.exe`、`csrss.exe`、`wininit.exe` 等内核/会话进程在列。
- 判据要看的是差异，不是条数：`PsList` 与 `PsScan` 两份 PID 集合做差 —— 只出现在 `PsScan` 里的 PID 说明进程已从活动链表中摘除（常见于退出残留或 DKOM 类隐藏），这是最值得追的一条线索。
- 交叉核对：某 PID 的 `cmdline.CmdLine` 为空或读不出，而 `pslist` 有该进程 → 该进程的 PEB 被清过或镜像对应页缺失，需要结合实际主机情况判读，不能直接判恶意。
- 全空/0 条：多半是镜像不完整、采集时按了休眠，或符号表版本对不上，不是插件坏了。
- `Unsatisfied requirement(s)` / 需要符号表：Volatility 3 首次跑某内核版本会去拉符号包。离线机先在有网机器下好符号包目录，再用 `--symbol-dirs` / 环境变量 `VOLATILITY_SYMBOL_DIRS` 指向本地目录。

```bash
/opt/vol3env/bin/vol -f /cases/ro/IMAGE.mem -o /cases/out --symbol-dirs /cases/symbols windows.pslist.PsList
```

### 5. 验证件：一条命令跑出可核对结果

```bash
/opt/vol3env/bin/vol -f /cases/ro/IMAGE.mem -o /cases/out windows.pslist.PsList --output=json \
  | /opt/vol3env/bin/python -c "import sys,json;d=json.load(sys.stdin);rows=d['rows' if 'rows' in d else 'data'];print('process_count',len(rows));print('first_pid',rows[0])"
```

判据：该行打印出的 `process_count` 与 `-o` 目录里 JSON 的条目数一致，且 `first_pid` 里的 PID 能在 `PsScan` 输出里找到同名 ImageFileName → 提取链路自洽。数量对不上就说明读的不是同一份输出，重跑而不是改结论。
