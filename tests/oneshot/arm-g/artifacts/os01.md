## TARGET 站点目录发现与备份文件探测命令序列（逐条判定信号）

授权范围：自有授权靶场 `http://TARGET/`（内部资产，非互联网目标）；以下命令只在本靶场与本机执行。

已在本会话实测（2026-09-29）：`curl` 位于 /usr/bin/curl 可用；`ffuf` / `gobuster` / `feroxbuster` / `nuclei` / `dirsearch` 在 `command -v` 下全部为空；`/usr/share/wordlists` 目录不存在。

### 0. 环境准备（先让工具真的在）
```bash
# 路线 A：包管理器
apt-get install -y ffuf gobuster curl
# 路线 B：无 seclists 包时自建词表
mkdir -p /root/wl && curl -sLo /root/wl/common.txt \
  https://raw.githubusercontent.com/danielmiessler/SecLists/master/Discovery/Web-Content/common.txt
# 路线 C：无 root / 无网兜底
python3 -m pip install dirsearch
# 验版本（任一为空就停下走兜底，别继续跑探测）
ffuf -V ; gobuster version ; curl --version | head -1
```
判定信号：`ffuf -V` 打印 `ffuf version ...` 为装好；`curl --version` 首行给出协议与版本。三条里任何一条 `command not found` → 换同段兜底路线，**不要**把「工具没装」读成「扫不到东西」。

### 1. 基线与软 404 标定（必须先拿到基线长度）
```bash
TARGET=http://TARGET
curl -s -o /dev/null -w 'code=%{http_code} len=%{size_download} type=%{content_type} time=%{time_total}\n' "$TARGET/"
curl -sI "$TARGET/" | head -20
curl -s "$TARGET/robots.txt" ; curl -s "$TARGET/sitemap.xml" | head -20
curl -s -o /dev/null -w 'baseline404=%{http_code} len=%{size_download}\n' "$TARGET/THIS_PATH_SHOULD_NOT_EXIST_9f3a"
```
判定信号：
- `code=200` 且 `len` 稳定 → 站点活着，把该 `len` 记为**正常页基线**。
- 随机不存在路径返回 200 且 `len` 与首页一致 → 站点使用「200 兜底页」；此后所有 `-mc 200` 都是误报，必须改用长度/相似度过滤（§4）。
- `robots.txt` 输出含 `Disallow:` 行 → 把这些路径直接抄进词表头部（作者自曝的隐藏路径，优先级最高）。
- `Server:` / `X-Powered-By:` / `Set-Cookie:` 给出栈指纹 → 决定 §3 的扩展名矩阵（PHP 栈重 `.php.bak`，Java 栈重 `.war.old`、`WEB-INF/web.xml`）。

### 2. 目录发现（三条路线各给判定信号）
```bash
TARGET=http://TARGET ; WL=/root/wl/common.txt

# 2.1 ffuf：快扫 + 自动校准
ffuf -u "$TARGET/FUZZ" -w "$WL" -mc 200,204,301,302,307,401,403,405 -ac -t 40 -rate 100 -o /tmp/ffuf.json -of json

# 2.2 gobuster：长词表 + 直接带备份扩展名
gobuster dir -u "$TARGET" -w "$WL" -x php,asp,aspx,jsp,bak,old,zip,tar.gz,sql,swp -t 20 -k --timeout 10s -o /tmp/gobuster.txt

# 2.3 feroxbuster：递归下钻
feroxbuster -u "$TARGET" -w "$WL" -x php,bak,zip -d 2 -t 30 --auto-tune --filter-status 404 -o /tmp/ferox.txt
```
判定信号（逐条）：
- `301/302` 且 `Location:` 以 `/` 结尾 → 真目录；跟一次 `curl -sI "$TARGET/<dir>/"` 复核 200/403 后再入递归队列，避免伪跳转。
- `401` → 存在且需认证：记录，并把它列为 §3 重点目录（备份文件常缺 authz 检查）。
- `403` → 存在但被拒：试 `$TARGET/<dir>/`、`$TARGET/<dir>/.git/HEAD`、`$TARGET/<dir>/index.php~`（403 目录下的点文件常单独放行）。
- `200` 且 `len` == §1 基线 → 软 404，丢弃。
- `200` 且 `len` 与基线差异明显（>10%）→ 真命中，人工看内容后再决定是否递归。
- 输出里 `[Status: 200, Size: N, Words: W, Lines: L]` 四列与基线页全不同 → 强命中信号，优先手工验证。
- 连续 `429` 或 403 数量激增 → 判定为限速/WAF 触发，立刻转 §5 降速，不要继续加压。

### 3. 备份文件与源码残留探测（本步核心）
思路：**已知文件名 × 扩展名矩阵** + **目录级残留**，不是盲跑大词表。
```bash
TARGET=http://TARGET
# 3.1 文件名 × 扩展名派生（把 §2 的命中目录名也加进 f 列表）
for f in index config db database backup www web app .env settings; do
  for e in '' .bak .bak1 .bak2 .old .orig .save .swp .swo '~' .zip .tar .tar.gz .tgz .rar .7z .sql .sql.gz .txt .log .copy .tmp; do
    printf '%-58s ' "$TARGET/${f}${e}"
    curl -s -o /tmp/body -w 'code=%{http_code} len=%{size_download} type=%{content_type}\n' --max-time 8 "$TARGET/${f}${e}"
  done
done > /tmp/bak_probe.txt
grep -Ev 'code=404|code=000' /tmp/bak_probe.txt   # 只看有反应的行

# 3.2 目录级残留（版本控制 / 编辑器 / 依赖清单）
for p in .git/HEAD .git/config .svn/entries .hg/store .DS_Store .idea/workspace.xml .vscode/settings.json composer.lock package-lock.json; do
  printf '%-32s ' "$p"; curl -s -o /dev/null -w 'code=%{http_code} len=%{size_download}\n' "$TARGET/$p"
done

# 3.3 长跑等价写法（gobuster 一把梭扩展名）
gobuster dir -u "$TARGET" -w "$WL" -x bak,bak1,old,zip,tar.gz,sql,swp,save,txt -t 15 -b 404
```
判定信号：
- `200` 且 `content_type` 为 `text/plain`、`application/octet-stream`、`application/zip` 而**不是**首页的 `text/html` → 文件被原样吐出，最可能直接可用。
- 首字节定性（防 200 兜底页）：`curl -s "$TARGET/index.php.bak" | head -c 16 | xxd`；出现 `<?php`、`PK`（zip 常量）、`SQLite format 3`、`-- MySQL dump` 属真备份；出现 `<!DOCTYPE html>` 且长度等于基线 → 软 404，丢弃。
- `.git/HEAD` 返回 `ref: refs/heads/...` → 源码可整体取回（转 3.4 验证）；`.svn/entries` 返回版本数字或 `dir` → 老式残留可用。
- `403` 而非 404 → 文件存在但被规则拦：试大小写变体（`Config.BAK`）、URL 编码（`%2e`）、双写扩展（`config.bak.php`）、路径归一化（`/static/../config.php.bak`）；判据只有一条 —— 状态码是否翻成 200 且长度非零。
- 纯 `301` 到带斜杠路径 → 是目录不是文件，不要当备份记。
- `000` / 超时 → 连接层丢弃，不是「不存在」的结论；加 `--max-time 8 --retry 2` 后仍 000 才跳过。

### 3.4 最小验证件（一条命令定性，命中即断言）
```bash
TARGET=http://TARGET ; u="$TARGET/config.php.bak"
code=$(curl -s -o /tmp/v.bin -w '%{http_code}' --max-time 8 "$u")
head -c 16 /tmp/v.bin | xxd | head -1
if [ "$code" = 200 ] && grep -qE '<\?php|PK|MySQL dump|SQLite format' /tmp/v.bin; then
  echo "CONFIRMED $u bytes=$(wc -c < /tmp/v.bin)"; exit 0
else
  echo "NOT-A-BACKUP code=$code"; exit 1
fi
```
判据：退出码 0 且打印 `CONFIRMED` → 拿到真实可读备份；退出码 1 → 该路径是壳页或软 404，换下一个候选，不在同一路径反复重试。
复现命令：`bash /tmp/verify_bak.sh; echo "exit=$?"`（把上面保存为 /tmp/verify_bak.sh 再执行，退出码即判据）。

### 4. 判定信号对照表（照表读输出，别把噪声当真命中）
| 观测 | 判定 | 动作 |
|---|---|---|
| 404 / 410 | 不存在 | 丢弃，不入递归 |
| 200 且 len == 基线 len | 软 404 兜底页 | 丢弃；之后一律加 `-fs <基线len>` 过滤 |
| 200 且 content_type 非 text/html | 真文件/备份 | 落地 + §3.4 验证 |
| 301 / 302 且 Location 带尾斜杠 | 目录 | 跟一次 `curl -I`，再入递归队列 |
| 302 到 `/login?next=` | 受保护资源 | 记录，按授权范围决定是否继续 |
| 401 / 403 | 存在但受限 | 试变体绕过；403 目录下找点文件 |
| 429 或 403 激增 | 触发限速 / WAF | 降速：`-rate 5 -t 5 -p 0.5-2` |
| 000 / 超时 | 连接层丢弃，非结论 | `--retry 2` 后仍 000 则跳过 |
| 5xx 大量出现 | 后端异常或被压崩 | 立即降到 `-t 1`，必要时停手 |

### 5. 稳打与限速（「能打」与「能稳定打」分开）
```bash
TARGET=http://TARGET ; WL=/root/wl/common.txt
ffuf -u "$TARGET/FUZZ" -w "$WL" -mc 200,204,301,302,401,403 \
     -t 5 -rate 20 -p 0.5-2.0 -recursion -recursion-depth 2 \
     -o /tmp/ffuf_slow.json -of json
# 目标做 IP 级封禁时：加 -x http://PROXY:8080（轮换）或 -replay-proxy http://PROXY:8080（只回放命中）
```
判定信号：出现 429 → `-rate` 减半；仍 429 → 上代理池并把抖动调到 `-p 1-3`；「命中数随并发升高而下降」判定为被限速，不是目标没内容。
