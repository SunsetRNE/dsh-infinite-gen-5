## Qwen2.5-7B 自有权重 GGUF 量化交付：转换 / Q4_K_M 量化 / 质量对比

本机实测（本会话 2026-09-29，非推测）：python3 3.12.3、pip3、g++、make 在位；cmake、go、llama.cpp 三件套（llama-quantize / llama-cli / llama-perplexity）、torch 缺失；无 GPU（nvidia-smi 缺失）；8 核 / 22 GB 内存（可用约 5 GB）；出网不可达（`curl -s -o /dev/null -w '%{http_code}' https://pypi.org/simple/` 无响应）。故安装走「离线 release tarball + 本地源码编译」，权重用自有权重目录 MODEL_DIR，全程 CPU 路径。

1. 转换：把自有权重 HF 目录转成 GGUF f16，作为量化基准与 PPL 基线。

```bash
MODEL_DIR=${MODEL_DIR:-./MODEL_DIR}          # 自有权重目录
cmake -B build -DGGML_NATIVE=ON && cmake --build build -j8
# cmake 缺失时降级：make -j8（旧 Makefile 路径），或解压官方 release tarball 到 ./build
python3 convert_hf_to_gguf.py "$MODEL_DIR" --outfile /tmp/FILE.f16.gguf --outtype f16
```

2. 量化：同一 f16 源分别出三档，便于质量-体积取舍；K-quant 参数用类型名指定，不手改 block 尺寸。

```bash
./build/bin/llama-quantize /tmp/FILE.f16.gguf /tmp/FILE.q4_k_m.gguf Q4_K_M
./build/bin/llama-quantize /tmp/FILE.f16.gguf /tmp/FILE.q5_k_m.gguf Q5_K_M
./build/bin/llama-quantize /tmp/FILE.f16.gguf /tmp/FILE.q8_0.gguf  Q8_0
ls -l /tmp/FILE.q4_k_m.gguf /tmp/FILE.q5_k_m.gguf /tmp/FILE.q8_0.gguf   # 体积实测，回填下表
```

| 类型 | 输出文件 | 体积（ls 实测） | 用途 |
|---|---|---|---|
| f16 | /tmp/FILE.f16.gguf | SIZE_F16 | PPL 基线、再量化源 |
| Q4_K_M | /tmp/FILE.q4_k_m.gguf | SIZE_Q4KM | 默认部署档，体积最小 |
| Q5_K_M | /tmp/FILE.q5_k_m.gguf | SIZE_Q5KM | 质量回退档 |
| Q8_0 | /tmp/FILE.q8_0.gguf | SIZE_Q8 | 近似无损对照 |

3. 质量对比：不写「效果差不多」，只用同一语料的 PPL 数值说话；f16 与三档量化跑同一 chunk 数、同一上下文长度。

```bash
./build/bin/llama-perplexity -m /tmp/FILE.f16.gguf   -f /tmp/WIKITEXT_TEST.txt -c 2048 --chunks 64 > /tmp/ppl_f16.log
for Q in q4_k_m q5_k_m q8_0; do
  ./build/bin/llama-perplexity -m /tmp/FILE.$Q.gguf -f /tmp/WIKITEXT_TEST.txt -c 2048 --chunks 64 > /tmp/ppl_$Q.log
done
grep -E 'Final estimate' /tmp/ppl_*.log
```

| 档位 | PPL（llama-perplexity 实测） | 相对 f16 的 PPL 增幅 | 结论 |
|---|---|---|---|
| f16 | PPL_F16 | 0（基线） | 基线 |
| Q8_0 | PPL_Q8 | (PPL_Q8−PPL_F16)/PPL_F16 | 待实测回填 |
| Q5_K_M | PPL_Q5KM | (PPL_Q5KM−PPL_F16)/PPL_F16 | 待实测回填 |
| Q4_K_M | PPL_Q4KM | (PPL_Q4KM−PPL_F16)/PPL_F16 | 待实测回填 |

PPL_* 与 SIZE_* 是回填占位符：本机无 llama.cpp、无权重、出网不可达，本会话未跑出任何真实数值，表内不写编造值。

4. 验证（判据）与冒烟：

```bash
sha256sum /tmp/FILE.q4_k_m.gguf
./build/bin/llama-quantize --help | head -3                 # 工具在位与用法核验
./build/bin/llama-cli -m /tmp/FILE.q4_k_m.gguf -p "SERIAL-1 自检：" -n 64 --seed 1 -ngl 0
```

判据：`llama-perplexity` 日志出现 `Final estimate: PPL = <数值>` 即评估成立；`llama-cli` 在 `-ngl 0`（CPU）下返回非空续写即权重可加载；上表 PPL_* 全部被实测值替换后，质量对比才算交付完成。

5. 降级与失败分支：无 cmake → 解压官方 release tarball 或 `make -j8`；内网无 tarball → 从已装机器拷贝 `build/bin/` 与 `libggml*.so` 同版本目录；内存不足（Q4 7B 常驻加 2048 上下文接近本机可用 5 GB 上限）→ 降 `-c 1024` 或换 3B 级模型；GIL/线程争用 → `-t 6` 留核给 IO。
