## 自有容器 进程-网络-文件三源交叉基线观测（R1）

授权与范围：自有容器 / 授权测试，全部命令为只读观测（ps / ss / ls / cat / sha256sum / awk），不做任何攻击动作，不写目标、不改配置。
环境锚定（本会话实测）：`Linux 6.1.141-android14-11-o-g659d588fa0da #1 SMP PREEMPT Thu Aug 6 07:53:55 UTC 2026 aarch64`；观测时刻 `2026-09-29T06:47:41Z`；`/proc/uptime` = `691614.83 2791582.56`（≈ 8.0 天）。
工具面实测：`ss` = `/usr/bin/ss`（iproute2-6.1.0）可用、`nmap` = 7.94SVN 可用、`python3` = 3.12.3 可用；`netstat` / `nc` / `lsof` / `hydra` / `sshpass` / `medusa` / `ncrack` 全部 MISSING → 归因降级到 `/proc/net/tcp*` 与 `python3 socket`。

### 1. 进程源：本 PID 命名空间只有 7 条进程

```bash
# 全部真跑，rc 逐条记录；--sort=-rss 取内存占用降序
ps -eo pid,ppid,comm,rss --sort=-rss | head -15     # rc=0
ps -e --no-headers | wc -l                          # rc=0 → 7 条

# 兜底（无 ps 时）：直接数 /proc 下的数字目录
ls -d /proc/[0-9]* | wc -l
```

实测输出（截取）：

| PID | PPID | COMM | RSS(KB) |
|---|---|---|---|
| 1872 | 1863 | MainThread | 853512 |
| 2140 | 1872 | MainThread | 533024 |
| 2151 | 1872 | MainThread | 33124 |
| 1863 | 27013 | libproot.so | 4540 |
| 8229 | 8224 | ps | 3208 |

合计 **7 条**进程，RSS 合计 ≈ 1.43 GB（853512+533024+33124+4540+3004+3208+800）。可见进程名只有 `MainThread` / `libproot.so` / 本次命令自身三类；`libproot.so` 是 proot 载体（PPID 27013 在本 ns 外），说明谱系根部挂在宿主。

### 2. 网络源：14 条监听、122 条 established，只有 2 条监听能被进程归因

```bash
ss -ltnp                                 # rc=0 → 14 条 LISTEN
ss -tan state established                # rc=0 → 122 条 established
ss -ltn | tail -n +2 | wc -l             # 14
ss -ltnp | grep -c 'users:'              # 2（仅 2 条带进程归因）
ss -tan state established | tail -n +2 | grep -c '127.0.0.1'   # 62 条环回
ss -tan state established | tail -n +2 | grep -vc '127.0.0.1'  # 60 条非环回

# ss 缺失时的降级路径（本环境 ss 在，仅作备用口径）
awk 'NR>1 && $4=="0A"{n++} END{print "tcp4 LISTEN:", n+0}' /proc/net/tcp   # 常量 0A = TCP_LISTEN
awk 'NR>1 && $4=="0A"{n++} END{print "tcp6 LISTEN:", n+0}' /proc/net/tcp6
python3 -c "import socket;s=socket.socket();s.settimeout(1);print(s.connect_ex(('127.0.0.1',3080)))"  # 0 = 端口开
```

实测关键读数：

- LISTEN **14 条**：`127.0.0.1:43795`、`127.0.0.1:10156`、`127.0.0.1:10157`、`172.19.0.1:40379`、`0.0.0.0:12479`、`127.0.0.1:3080`、`0.0.0.0:16094`、`[::1]:3090`、`*:7890`、`*:10150`、`*:10152`、`*:10162`、`*:46888`、`[::ffff:127.0.0.1]:3090`
  - 其中 `[::1]:3090` 与 `[::ffff:127.0.0.1]:3090` 是同一条双栈 socket 的两种显示形态，端口面实际是 13 个不同端口号。
- 仅 **2 条**带 `users:` 归因：`pid=2140 fd=20` → `127.0.0.1:43795`；`pid=1872 fd=19` → `127.0.0.1:3080`。其余 **12 条无进程归因**。
- established **122 条**：环回 62 条、非环回 60 条。非环回读数（出口连接语境，非靶标）：`10.202.11.230 → ×:443`、`172.19.0.1 → 157.255.5.249:80`、`172.19.0.1:40379 ↔ 172.19.0.2:30413` 等；`127.0.0.1:3080 ↔ 127.0.0.1:59980` 是 Web GUI 自连接。
- `/proc/net/tcp` 311 行 + `/proc/net/tcp6` 143 行 = 454 行（全状态），`/proc/net/tcp` 单文件 47550 字节。

### 4. 三源交叉：对得上 4 处，对不上 3 处

| # | 结论 | 依据（均为本会话实测） |
|---|---|---|
| ✅1 | LISTEN 面完全一致：`ss` 14 条 = `/proc/net/tcp` 7 + `/proc/net/tcp6` 7 | 两路独立口径同值 14 |
| ✅2 | 进程名/端口归因一致：`ss` 报 `pid=1872`/`pid=2140`，`ps` 中同 PID 同名 `MainThread` | PID 与 comm 双字段吻合 |
| ✅3 | 环回自连接成对出现：`127.0.0.1:3080 ↔ 127.0.0.1:59980` 在两列同时存在 | ss 输出双向配对 |
| ✅4 | established 量级一致：`ss` 122 vs `/proc/net/tcp*` 常量 01 合计 74+45=119 | 差 3 条属两次快照间的抖动 |
| ❌1 | 归因缺口：14 条监听里 12 条无 `users:`；`/proc/1/fd` 下 socket fd 计数 = 0 | 本 ns 无法看见持有者 |
| ❌2 | 身份口径冲突：`id` 返回 `uid=0(root)`，而环境探明记载 uid=10527；groups 里同时存在 `aid_10527`、`aid_50527`、`3003(inet)` | proot 身份映射，两源对同一事实给出不同值 |
| ❌3 | 命名空间无法比对：`/proc/self/ns/net` = `net:[4026531840]`，`/proc/1/ns/net` 不存在（无真 PID 1） | 无法用 nsid 判定是否与宿主共享 netns |

### 5. 本轮未闭合的未知（轮 2 / 轮 3 的闭合目标）

1. **12 条无归因监听的持有者是谁** —— 端口 `12479`、`16094`、`10150`、`10152`、`10156`、`10157`、`10162`、`40379`、`46888`、`7890`、`3090` 的 PID/UID 全未知；本 ns 只有 7 条进程且 uid 无 CAP_NET_ADMIN，需换 `/proc/*/fd` 全扫或宿主侧视图。
2. **60 条非环回 established 由谁发起** —— 本 ns 的 7 条进程解释不了 60 条外连；需判定它们是宿主进程经共享 netns 暴露的，还是 proot 内某个未显示进程的。
3. **`172.19.0.1:40379 ↔ 172.19.0.2:*` 的成对连接性质** —— 跨容器 / 端口转发 / unix 代理未定；缺 `lsof`/`netstat`，暂无归因手段。
4. **`7890` 的双向自反连接群** —— `127.0.0.1:*↔127.0.0.1:7890` 出现 30 余对，是本地代理（出口代理）还是回环转发，未取进程证据。
5. **`/etc/hosts` 为 0 字节但名称解析仍可用** —— 实际走 `nsswitch.conf` 的哪条分支（resolve/dns）未验，轮 2 需以 `getent hosts` + 抓取 stub-resolv 链判定。
6. **`/proc/net/tcp` 不可作为稳定基线锚点** —— 同一文件两次读数哈希必变（连接表在动），只能作为窗口快照，不能作为回归基准。

### 6. 判据与复现

判据：`ss -ltn | tail -n +2 | wc -l` 输出 `14`，且 `/proc/net/tcp` 与 `/proc/net/tcp6` 中状态常量 `0A`（TCP_LISTEN）的行数之和同为 `14` —— 两路独立口径同值即三源基线的 LISTEN 面成立；任一路偏离即本轮基线作废、需重取快照。

```bash
# 一条命令重放本轮基线（只读）：期望 14 / 14 / 7 / 2
printf 'ss=%s proc=%s ps=%s attr=%s\n' \
  "$(ss -ltn | tail -n +2 | wc -l)" \
  "$(awk 'FNR>1 && $4=="0A"' /proc/net/tcp /proc/net/tcp6 | wc -l)" \
  "$(ps -e --no-headers | wc -l)" \
  "$(ss -ltnp | grep -c 'users:')"

# 缺失工具的补齐（本环境 netstat/nc/lsof 均 MISSING，择一即可，只读观测用 net-tools 足够）
apt-get install -y --no-install-recommends net-tools iproute2 procps 2>/dev/null || \
  echo "no-root-or-no-net: 保持 /proc/net/tcp 降级口径"

# 归因降级件：ss 无 users: 时用 python3 逐个探端口是否真的在听（不发送任何载荷）
python3 - <<'PY'
import socket
for p in (3080, 7890, 3090, 12479, 16094, 10150):
    s = socket.socket(); s.settimeout(0.5)
    print(p, "connect_ex=", s.connect_ex(("127.0.0.1", p)))   # 0 = 在听，111 = 拒
    s.close()
PY
```
