# 可执行文件逆向 (Executable Reversing)

## 概述

可执行文件逆向针对特定操作系统下的可执行文件格式进行分析。每种文件格式都有其独特的结构——文件头、区段表、导入/导出表、资源、重定位信息等——理解这些结构是逆向分析的第一步，也是最基础的一步。

可执行文件格式反映了一个操作系统平台的软件架构和运行时设计哲学。从古老的 DOS 到现代的 Linux ELF、Windows PE、macOS Mach-O 和 Android APK，每种格式都有其独特的逆向挑战。

---

## 常见分析手法

### 1. DOS 文件逆向 (COM / EXE)
DOS 是最早的 PC 操作系统之一，其可执行文件格式较为简单。

**COM 文件**:
- 纯二进制映像，无文件头，加载到 0x100 偏移处（PSP 之后）。
- 最大 64KB（实模式段限制）。
- 入口点固定为第一条指令（ORG 100h）。
- 常使用 `INT 21h` 进行 DOS 系统调用。

**EXE 文件 (MZ 格式)**:
- 以 `MZ` 魔数开头（4D 5A）。
- **MZ Header**: 包含 `e_cblp`（最后扇区字节数）、`e_cp`（文件扇区数）、`e_cs`（CS 寄存器）、`e_ip`（IP 寄存器）等。
- 重定位表: 程序加载时需要根据基址调整的地址列表。
- **DOS Stub**: 在 Win32 PE 中，MZ header 后有一段简单的 DOS stub（通常输出 "This program cannot be run in DOS mode"）。

**逆向要点**:
- DOSBox / 86Box 可模拟运行 DOS 程序。
- IDA 支持 MZ/NE/LE 格式分析。
- 16 位段式内存模型（Segment:Offset）需要额外注意。

### 2. PE 文件逆向 (Windows)
PE (Portable Executable) 是 Windows 平台的可执行文件格式（EXE、DLL、SYS、OCX 等）。

**结构组成**:
```
+------------------+
| MZ Header        | ("MZ" magic)
+------------------+
| DOS Stub         | (DOS 兼容 stub)
+------------------+
| PE Signature     | ("PE\0\0")
+------------------+
| IMAGE_FILE_HEADER| (CPU 类型、区段数、时间戳等)
+------------------+
| IMAGE_OPTIONAL_HEADER | (入口点、镜像基址、区段对齐等)
+------------------+
| Data Directory   | (导入表、导出表、资源、重定位等)
+------------------+
| Section Table    | (.text .data .rdata .rsrc 等)
+------------------+
| Section Data     |
+------------------+
```

**关键数据结构**:
- **导入表 (Import Table)**: 列出程序调用的外部 DLL 函数。IDA 可解析显示。
- **导出表 (Export Table)**: DLL 导出的函数列表。通过 `GetProcAddress` 动态获取函数地址。
- **资源 (Resource Section)**: 存储图标、对话框、字符串表、版本信息等。可使用 Resource Hacker 查看。
- **重定位表 (Base Relocation Table)**: 当 DLL 无法加载到首选基址时用于修复地址。
- **TLS (Thread Local Storage) 表**: 包含 TLS 回调函数，在入口点执行前被执行（反调试常用）。
- **Exception Table (PData)**: x64 结构化异常处理信息。

**逆向要点**:
- **区段识别**: `.text`（代码）、`.rdata`（只读数据）、`.data`（读写数据）、`.rsrc`（资源）、`.reloc`（重定位）。
- **延后加载 (Delay-Load Import)**: 某些 DLL 导入在首次调用时才解析。
- **绑定导入 (Bound Import)**: 编译时已绑定好 DLL 中的函数地址（无法被重定向）。
- **ASLR**: PE 文件可以通过 `/DYNAMICBASE` 链接选项支持地址随机化。
- **DEP (NX)**: 通过 `/NXCOMPAT` 启用数据执行保护。

**常用工具**: PE-Bear、CFF Explorer、LordPE、PEview。

### 3. ELF 文件逆向 (Linux)
ELF (Executable and Linkable Format) 是 Linux/Unix 平台的主要可执行文件格式。

**结构组成**:
```
+----------------------+
| ELF Header           | (Elf64_Ehdr)
+----------------------+
| Program Header Table | (Elf64_Phdr) - 用于加载
+----------------------+
| Section Header Table | (Elf64_Shdr) - 用于链接/反汇编
+----------------------+
| Sections             | (.text .data .bss .rodata .got .plt 等)
+----------------------+
```

**关键数据结构**:
- **ELF Header**: `e_ident`（魔数 `\x7fELF`、架构、字节序）、`e_type`（ET_REL/ET_EXEC/ET_DYN）、`e_machine`、`e_entry`（入口点）。
- **Program Header (PHDR)**: 描述如何将文件映射到内存（`PT_LOAD` 装载段、`PT_DYNAMIC` 动态信息、`PT_GNU_STACK` 栈权限、`PT_GNU_RELRO` 只读重定位、`PT_GNU_EH_FRAME` 异常处理信息）。
- **Section Header (SHDR)**: 描述文件的各个区段。
- **动态段 (.dynamic)**: 列出程序依赖的共享库、符号表位置、重定位表等。
- **GOT (Global Offset Table) + PLT (Procedure Linkage Table)**: 动态链接的核心结构。
- **重定位表 (.rel.dyn / .rel.plt)**: 记录运行时需要修正的地址。

**逆向要点**:
- **PIE (Position Independent Executable)**: ELF 可编译为位置无关代码（`-pie`），需要泄露基址。
- **RELRO**: Partial RELRO 下 GOT 可写；Full RELRO 下 `.got.plt` 被映射为只读。
- **SSP (Stack Smashing Protection)**: 通过 `__stack_chk_fail` 检测栈溢出。
- **`.interp` 段**: 指定动态链接器路径（通常为 `/lib64/ld-linux-x86-64.so.2`）。
- **`.init_array` / `.fini_array`**: 存储构造函数和析构函数指针，在 `main` 之前/后执行。
- **`readelf` / `objdump`**: 查看 ELF 结构信息的标准工具。

### 4. APK 逆向 (Android)
APK (Android Package Kit) 是 Android 应用的安装包格式，本质是一个 ZIP 压缩包。

**结构组成**:
```
+--------------------+
| AndroidManifest.xml| (二进制 XML 格式)
+--------------------+
| classes.dex        | (DEX 字节码)
+--------------------+
| classes2.dex ...   | (多 DEX)
+--------------------+
| lib/               | (Native .so 库: armeabi-v7a, arm64-v8a, x86 等)
|   |- libnative.so  |
+--------------------+
| res/               | (资源文件: 布局、图片、字符串等)
+--------------------+
| META-INF/          | (签名信息: MANIFEST.MF, CERT.RSA, CERT.SF)
+--------------------+
| resources.arsc     | (编译后的资源索引表)
+--------------------+
```

**逆向要点**:
- **JADX**: 将 DEX 反编译为 Java 源码，是目前最常用的 APK 逆向工具。
- **JEB**: 商业 APK 逆向工具，支持 DEX/Native 混合分析。
- **apktool**: 解包/重打包 APK，将二进制 XML 转为可读格式。
- **AndroidManifest.xml** 中关注: `<activity>` / `<service>` / `<receiver>` / `<provider>` 组件、权限声明、`android:debuggable` 属性。
- Native 层（.so 文件）通过 JNI 调用，使用 IDA/Ghidra 分析。
- Root 检测、模拟器检测、完整性校验通常在 Native 层实现。

**常用工具**: JADX、apktool、jeb、IDA Pro（分析 .so）、Frida（动态 Hook）、objection。

### 5. 其他可执行文件逆向
- **Mach-O (macOS/iOS)**: macOS/iOS 的可执行格式。`otool` 查看结构，`class-dump` 导出 Objective-C 类信息。结构包括 Mach Header、Load Commands、Segments/Sections。使用 Hopper / IDA 分析。
- **NE / LE (Windows 3.x / OS/2)**: 16 位 Windows 的 New Executable 和 OS/2 的 Linear Executable 格式。
- **Universal Binary (macOS)**: 包含多架构（如 x64 + arm64）的单一二进制文件，头部包含 Fat Header。
- **WebAssembly (.wasm)**: 浏览器端的二进制格式，使用 `wasm2wat` 或 `wasm-decompile` 查看。
- **COFF (Common Object File Format)**: Windows 的静态库格式（.lib），也是 ELF 之外的一种通用目标文件格式。

## 防御/对抗建议

- **加壳保护**: 使用 UPX / ASPack / Themida / VMProtect 保护 PE 文件；使用 UPX / gzexe 保护 ELF 文件；使用 360 / Bangcle / Tencent Legu 保护 APK。
- **签名校验**: 对关键代码区段进行哈希/数字签名校验（如 APK 签名、PE Authenticode）。
- **资源加密**: 将字符串和资源文件加密存储，运行解密。
- **多格式嵌套**: PE 文件中藏 ELF、APK 中使用加密的 DEX 等，增加逆向难度。
- **反虚拟化**: 检测是否运行在虚拟机/模拟器环境中。
