# 逆向分析基础 (Basic Analysis)

## 概述

逆向分析基础是 REVERSE 领域的入门技能，涵盖使用各类工具对二进制程序进行静态分析与动态调试的基本方法。无论面对何种平台、何种语言编译的程序，熟练掌握基础分析工具和技巧都是成功逆向的前提。

逆向分析的目标可以包括: 还原程序的逻辑结构、寻找特定算法、获取隐藏数据（flag）、破解许可验证、理解恶意软件行为、发现安全漏洞等。

---

## 常见分析手法

### 1. 工具使用
**反汇编器 (Disassembler)**
- **IDA Pro**: 最强大的商业反汇编/反编译工具，支持多架构、插件丰富（Hex-Rays Decompiler、FindCrypt、SigMaker 等）。常用快捷键: `G`（跳转到地址）、`N`（重命名）、`Y`（修改类型）、`X`（交叉引用）、`F5`（反编译）。
- **Ghidra**: NASA 开发的开源反编译框架，支持插件扩展和脚本化（Python/Java）。与 IDA 相比免费开源，在大型项目分析上有独特优势。
- **Radare2 / Cutter**: 命令行反汇编框架，支持多架构，r2pipe 可与其他工具集成。Cutter 是其图形界面版本。
- **Binary Ninja**: 商业反汇编工具，中间表示（MLIL）设计优秀，API 友好。

**调试器 (Debugger)**
- **GDB**: Linux 平台标准调试器，配合 pwndbg/GEF/PEDA 插件可大幅提升使用体验。
- **x64dbg**: Windows 平台 64 位开源调试器，继承 OllyDbg 设计理念。
- **OllyDbg**: Windows 32 位经典调试器，适合分析加壳/反调试程序。
- **WinDbg**: Windows 内核/用户态调试器，主要用于内核分析。

**十六进制编辑器**
- **010 Editor**: 支持模板（Binary Templates），可解析 PE/ELF/Mach-O 等文件结构。
- **HxD**: 轻量免费的十六进制编辑工具。
- **ImHex**: 开源高级十六进制编辑器，支持模式和数据分析。

**其他辅助工具**
- **Detect it Easy (DiE)**: 查壳工具，支持大量壳和编译器的特征识别。
- **ExeInfo PE**: 查壳和信息检测。
- **Process Monitor / Process Explorer**: Windows 进程/文件/注册表监控。
- **dnSpy**: .NET 程序反编译调试器。
- **PE-Bear / CFF Explorer**: PE 文件结构查看编辑工具。

### 2. 静态分析
静态分析指在不运行程序的情况下，通过分析二进制文件的内容来理解其逻辑。

**文件格式分析**:
- 识别文件类型（PE/ELF/Mach-O/APK/DOS）。
- 查看文件头部信息、区段（Section）分布、导入/导出表。
- 对于 PE: `IMAGE_NT_HEADERS`、`IMAGE_SECTION_HEADER`、`Import Table`、`Export Table`、`Resource Section`、`TLS Callbacks`。
- 对于 ELF: `Elf64_Ehdr`、`Program Header`、`Section Header`、`.got.plt`、`.dynamic` 段。

**反汇编分析**:
- 从入口点开始跟踪函数的执行路径。
- 识别标准库函数（通过 Signature / FLIRT 或手动识别）。
- 定位关键逻辑（字符串引用、加密/解密循环、系统调用）。
- 使用交叉引用（Xrefs）追踪数据流和控制流。

**字符串分析**:
- 搜索可打印字符串（`strings` 命令或 IDA View）。
- 关注 `flag`、`password`、`key`、`wrong`、`correct`、`error` 等关键词。
- 硬编码的密钥、IV、魔术数字等也是重点关注对象。

**图形视图分析**:
- 使用函数流程图（Flow Chart）理解分支结构。
- 识别混淆模式: 不透明谓词（Opaque Predicate）、控制流平坦化（Control Flow Flattening）。
- 合并被故意分割的基本块。

### 3. 动态调试
动态分析在程序运行时观察其行为和状态变化。

**断点设置**:
- **硬件断点**: 基于 CPU 调试寄存器，不修改代码，难以被检测。
- **软件断点**: 替换指令为 `INT3`（0xCC），易于被反调试检测。
- **内存断点**: 在指定内存区域读写时触发。
- **条件断点**: 在满足特定条件时暂停执行（如寄存器等于某值）。

**运行时监控**:
- 查看寄存器值（RAX/RBX/RCX 等）和栈布局。
- 跟踪内存分配与修改（Call Stack + Memory Window）。
- 监视 API 调用（通过断点或 API Monitor 工具）。
- 记录程序执行轨迹（以了解复杂分支的执行路径）。

**补丁 (Patching)**:
- 修改程序二进制代码以改变其行为，常用于绕过验证或简化分析。
- **常见补丁操作**:
  - 将条件跳转替换为无条件跳转（如 `jz` -> `jmp`）。
  - NOP 掉（填充 0x90）关键检查指令。
  - 修改函数返回值（如将 `xor eax, eax; ret` 替换为 `mov eax, 1; ret`）。
  - 修改指令助记符（`jb` -> `jnb`）。
- **工具**: IDA（Edit > Patch Program）、010 Editor、x64dbg（Assemble 功能）。

### 4. 程序补丁 (Patching)
除了动态调试中的临时补丁，静态补丁也是一种重要的分析辅助手段:
- **静态补丁**: 直接在二进制文件中修改字节，保存为新的可执行文件。
- **动态补丁**: 在调试器中修改内存中的指令，运行结束后恢复原状。
- **SMC (Self-Modifying Code)**: 对于自修改代码，需要在动态执行后才能看到真实的代码逻辑。
- **补丁 + Dump**: 脱壳时常在 OEP 处补丁 `INT3`，在断点命中后 dump 内存到文件。

### 5. 其他逆向分析基础
- **内存搜索**: 在程序运行时搜索特定值（连续数据、字符串、ASCII 码等），定位关键数据的位置。
- **日志记录**: Hook 关键函数并通过日志输出调用参数和返回值，常用于分析协议或加密算法。
- **符号恢复**: 对于 Strip 掉符号的二进制文件，通过签名匹配、调试信息残留、函数特征推断等方式恢复函数名。
- **时间线分析**: 在分析恶意软件时，通过时间戳、编译信息、版本号等构建分析时间线。
- **交叉引用 (Xrefs)**: 在 IDA/Ghidra 中追踪数据引用和代码引用，是理解程序结构最重要的手段之一。

## 防御/对抗建议

- **代码混淆**: 使用花指令、控制流平坦化、不透明谓词增加静态分析难度。
- **反调试**: 使用 TLS 回调、定时器检测、断点扫描、调试器检测等反调试技术。
- **加壳**: 使用 UPX/ASPack/Themida/VMP 等壳保护原始代码。
- **完整性校验**: 校验代码段的 CRC/哈希，防止被补丁修改。
- **反分析提示**: 隐藏字符串、使用动态 API 解析、加密常量数据。

## 示例/思路

### 基础逆向流程示例
```
1. DiE (Detect it Easy) 查壳 -> 确认无壳，Visual C++ 编译
2. IDA 打开文件，分析入口点 -> 找到 main/WinMain 函数
3. 搜索字符串（Shift+F12） -> 找到 "Correct!" / "Wrong!" 字符串
4. 追踪字符串引用 -> 定位到关键验证函数
5. 分析验证函数逻辑 -> 发现 XOR 加密 + 字符串比较
6. 提取密钥和密文 -> 编写解密脚本还原 flag
```

### 补丁绕过示例
```asm
; 原始代码: 关键验证
00401000: cmp eax, 0x12345678
00401005: jnz short loc_401010   ; 如果不等则跳转到失败路径
00401007: mov eax, 1             ; 成功
0040100C: jmp short loc_401015

; 补丁: 将 jnz 改为 jmp（无条件跳转到成功路径）
00401005: EB 00                  ; jmp short $+2 (空跳)
; 或直接改为:
00401005: 90 90                  ; NOP NOP
```
