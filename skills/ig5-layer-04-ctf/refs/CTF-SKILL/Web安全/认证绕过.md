# 认证绕过

## 概述

认证绕过（Authentication Bypass）指绕过应用的身份验证机制获取未授权访问的技术。CTF 中常见的认证绕过考点包括 JWT 伪造、HTTP 基础验证绕过、Cookie 篡改、Session 固定/伪造、OAuth 缺陷等。这些漏洞通常源于开发人员对认证机制的错误实现或配置不当。

## 常见攻击手法

### 1. JWT 绕过

JWT（JSON Web Token）是当前最流行的认证令牌格式之一，由 Header、Payload、Signature 三部分组成。

- **算法混淆攻击**：
  - 将 Header 中的 `alg` 从 `RS256`（非对称）改为 `HS256`（对称），使用服务端公钥作为 HMAC 密钥签名
  - 利用库的自动算法协商特性，服务端可能使用攻击者指定的算法验证
  - 工具：`jwt_tool` 的 `-X a` 参数

- **none 算法攻击**：
  - 将 `alg` 改为 `none`，部分 JWT 库在验证时跳过签名检查
  - Payload：`{"alg":"none"}` + 任意 payload + 空签名
  - 注意：现代 JWT 库大多已禁用 `none` 算法

- **暴力破解密钥**：
  - 弱 HMAC 密钥（如 `secret`、`password`、`123456`）
  - 使用 `hashcat`（`-m 16500` for HMAC-SHA256）或 `john` 爆破
  - 在线破解：使用 `jwt_cracker` 或 `pyjwt` 工具

- **JWK 注入 (CVE-2018-0114)**：
  - 在 JWT Header 中注入自定义的 `jwk`（JSON Web Key），服务端可能使用攻击者提供的公钥验证签名
  - 利用 `jwk`、`jku`（JWK Set URL）、`kid`（Key ID）等参数

- **kid 注入**：
  - `kid` 参数用于指定密钥，若其值被直接拼接到文件路径或 SQL 查询中可导致注入
  - 文件读取：`"kid": "/dev/null"` 或 `"kid": "../../etc/passwd"`
  - SQL 注入：`"kid": "key' UNION SELECT ..."`

- **信息泄露**：
  - JWT 的 Payload 仅 Base64 编码，未加密，可解码直接查看
  - 敏感信息（如密码）不应放在 JWT Payload 中

- **过期 Token 未验证**：
  - 服务端未检查 `exp`（过期时间）声明
  - 或使用过期的 Token 仍然可以通过认证

- **KID 路径遍历**：
  - `"kid": "../../../etc/passwd"` 读取服务器任意文件（如果密钥加载逻辑基于 KID 读取文件）

### 2. HTTP 基础验证绕过

HTTP Basic Authentication（HTTP 基础验证）是一种简单的认证方式。

- **弱密码爆破**：
  - 使用常见密码字典对 Basic Auth 进行爆破
  - `Authorization: Basic base64(username:password)`

- **认证头未正确实现**：
  - 删除 `Authorization` 头查看是否跳过认证
  - 修改 `Authorization` 为错误格式查看响应差异

- **密码编码问题**：
  - 密码中的特殊字符可能导致验证失败（Unexpected behavior）
  - 双重 Base64 编码

- **HTTP Digest Auth 绕过**：
  - 重放攻击：捕获一次认证包后重放
  - 使用已知的 QoS 值

- **条件竞争**：在认证建立前发送大量请求

### 3. Cookie 绕过

- **Cookie 篡改**：
  - 修改 Cookie 中的用户标识：`user=guest` → `user=admin`
  - 修改权限标识：`role=0` → `role=1` 或 `role=user` → `role=admin`
  - 添加未设置的 Cookie 字段

- **Cookie 序列化反序列化**：
  - 某些框架将 Cookie 值序列化存储（如 PHP 的 `session` 序列化）
  - 篡改序列化后的值可导致认证绕过

- **Cookie 加密绕过**：
  - 部分应用对 Cookie 进行加密存储，若加密密钥泄露可伪造
  - 某些密钥可猜测（如 `secret`、`key`、应用名称）

- **Session 固定攻击 (Session Fixation)**：
  - 在用户登录前设置已知的 Session ID，用户登录后该 Session 被认证
  - 利用：提前设置 Session ID（通过 URL 或 Cookie），然后诱导用户使用该 Session 登录

- **Session 劫持**：
  - 通过 XSS 窃取 Session Cookie
  - 通过中间人攻击捕获 Session ID
  - Session ID 在 URL 中泄露

- **记住我功能绕过 (Remember Me)**：
  - Shiro RememberMe 密钥爆破（已知漏洞）
  - Spring Security RememberMe 的 Token 预测
  - 持久化 Cookie 的加密密钥泄露

### 4. OAuth/OIDC 绕过

- **重定向 URI 绕过**：
  - 使用路径遍历：`https://app.com/oauth/callback%2F..%2Fattacker.com`
  - 使用子域名：`https://attacker.app.com/`
  - URI 模式混淆：`https://app.com.evil.com/`
  - state 参数缺失或可预测

- **CSRF in OAuth**：
  - 缺少 state 参数时，可将用户的认证码绑定到攻击者的账号
  - 攻击者用自己的账号获取 code，然后诱使用户点击绑定链接

- **Token 劫持**：
  - 通过 Referer 头泄露 Authorization Code 或 Token
  - 通过中间人攻击截获 Token（未使用 HTTPS）

- **Scope 越权**：
  - 修改 OAuth Scope 参数获取更高权限
  - 使用已撤销的 Token

### 5. 多因素认证绕过 (MFA/2FA)

- **暴力破解验证码**：6 位数字验证码（100 万种组合）若未限制可被爆破
- **MFA 疲劳攻击**：持续推送 MFA 通知直到用户误点确认
- **备份码泄漏**：初始设置的备份码未妥善保管
- **绕过 MFA 直接访问 API**：某些 API 端点未强制 MFA 校验

### 6. 密码重置绕过

- **Token 在 URL 中泄露**：Referer 头泄露
- **Token 可预测**：基于时间戳、用户 ID、序列号
- **Token 未绑定 session**：可在不同设备上使用
- **密码重置链接不过期**
- **重置后修改目标邮箱**

## 防御建议

- JWT：验证 `alg` 白名单，禁用 `none` 算法，使用强密钥
- Cookie：设置 HttpOnly、Secure、SameSite 属性
- OAuth：正确实现 state 参数防止 CSRF，验证 redirect_uri 白名单
- 基础认证：配合 HTTPS 使用，避免明文传输
- 多因素认证：限制验证码尝试次数

## CTF 中的常见考点

- JWT `alg: none` 绕过签名验证
- JWT 弱 HMAC 密钥爆破后伪造 Token
- 修改 Cookie 中的 role 或 username 提升权限
- OAuth redirect_uri 白名单绕过
- 密码重置 Token 爆破或预测
