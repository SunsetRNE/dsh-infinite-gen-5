# 逻辑漏洞

## 概述

逻辑漏洞（Business Logic Vulnerability）指利用应用业务流程设计的缺陷而非技术实现漏洞进行攻击。这类漏洞通常没有固定的模式和安全补丁，依赖于对业务逻辑的深入理解。CTF 中的逻辑漏洞包括权限控制绕过、数据校验绕过、流程篡改、竞争条件等。

## 常见攻击手法

### 1. 权限控制绕过

- **水平越权**：
  - 修改请求中的用户标识（如 `user_id`、`uid`、`account`）访问其他用户的数据
  - 遍历 ID：`/api/user/1`、`/api/user/2`、`/api/user/3`
  - 修改 POST 参数：`{"username":"admin"}` → `{"username":"other_user"}`

- **垂直越权**：
  - 普通用户访问管理员接口：`/admin`、`/manage`、`/api/admin/users`
  - 修改用户角色参数：`{"role":"user"}` → `{"role":"admin"}`
  - 添加隐藏参数：`is_admin=1`、`admin=true`、`level=0`
  - Cookie 中的权限标识：修改 Cookie 中的 `role=admin`

- **未授权访问**：
  - 直接访问需要认证的接口
  - 删除请求中的认证参数，看是否仍可正常访问
  - 使用 HTTP 方法绕过（将 POST 改为 GET 或 PUT）

### 2. 数据校验绕过

- **参数篡改**：
  - 修改订单金额：`{"price":100}` → `{"price":0}` 或 `{"price":-100}`
  - 修改商品数量为负数（减少支付金额或增加积分）
  - 修改优惠券/折扣力度
  - 整数溢出：将数量设置为极大值导致溢出反转

- **类型混淆**：
  - 将数字 ID 改为字符串/数组：`id[]=1&id[]=2`
  - 修改参数类型使后端校验失效
  - 利用 JSON/XML 解析差异

- **删除/绕过必填参数**：
  - 删除最终价格参数，系统可能使用初始默认值
  - 删除验证码参数使校验跳过

- **边界条件错误**：
  - 负数绕过：`quantity=-1`（增加库存）
  - 零值绕过：`price=0`
  - 极大值绕过：`price=9999999999999999999`（整数溢出）

### 3. 业务逻辑漏洞

- **支付逻辑漏洞**：
  - 订单金额篡改：拦截支付请求修改金额
  - 重复支付：使用同一订单多次支付
  - 支付与订单分离：使用小笔金额的支付流水关联大笔金额的订单
  - 负值支付：数量为负数时支付金额为负（倒赚钱）
  - 越权支付：使用他人的支付凭证
  - 重放攻击：重新发送支付成功的请求包

- **优惠券/促销逻辑漏洞**：
  - 同一优惠券多次使用
  - 优惠券叠加使用超出预期折扣
  - 修改优惠券金额或适用范围
  - 利用时间漏洞（在促销开始前或在结束后使用优惠券）

- **用户注册/认证逻辑**：
  - 批量注册（无验证码或 IP 限制）
  - 邮箱/手机验证跳过
  - 用户名枚举（注册时检查用户名是否存在泄露信息）
  - 密码重置 Token 可预测
  - 注册后自动登录（可能有未校验的角色）

- **密码重置逻辑**：
  - Token 在 URL 中泄露（通过 Referer）
  - Token 可爆破（时间戳/序列号）
  - 修改接收邮箱/手机号
  - 跳过验证直接修改密码的步骤
  - 链接不过期，可被攻击者复用

- **积分/奖励系统**：
  - 签到奖励篡改
  - 推荐奖励：创建大量虚假账号获取奖励
  - 任务完成条件绕过

### 4. 并发与竞争条件

- **优惠券抢购**：同时发送多个请求领取同一张优惠券
- **提现竞争**：同一笔余额多次提现（先查询余额再扣减，两笔同时操作）
- **并发利用脚本**：
  - Python + 多线程/异步
  - Burp Turbo Intruder

### 5. 流程绕过

- **跳过多步流程中的步骤**：
  - 直接跳到最后一步提交
  - 修改流程状态参数
- **重放攻击**：
  - 重放成功的请求（如重复提交订单）
  - 重放签名后的请求包
- **不当的 HTTP 方法**：
  - DELETE 方法删除数据
  - PUT 方法修改数据

### 6. 信息泄露

- **错误信息泄露**：详细的错误堆栈暴露 SQL 语句、文件路径、版本信息
- **接口返回多余数据**：API 返回了不需要的敏感字段（如密码 Hash、身份证号）
- **接口遍历**：未限制频率的接口可被枚举遍历

## 相关工具

| 工具 | 用途 |
|------|------|
| Burp Suite | 拦截修改请求、分析逻辑 |
| Turbo Intruder | HTTP 并发请求（竞争条件） |
| custom Python script | 自动化逻辑验证 |

## 防御建议

- 服务端对所有业务参数做完整性校验，不接受客户端传来的价格等敏感参数
- 对用户身份进行全程校验（不只在登录时验证）
- 关键操作使用幂等性 Token 防止重放
- 多步骤流程在服务端维护状态，防止跳过
- 使用事务和锁机制防止并发竞争

## CTF 中的常见考点

- 修改请求中的 `price` 或 `quantity` 参数为非预期值
- 水平越权访问其他用户的文件或数据
- 密码重置 Token 爆破或逻辑跳过
- 并发请求领取多次奖励或完成多次提现
