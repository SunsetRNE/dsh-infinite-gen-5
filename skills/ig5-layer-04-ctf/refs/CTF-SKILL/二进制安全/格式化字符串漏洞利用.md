# 格式化字符串漏洞 (Format String)

## 概述

格式化字符串漏洞（Format String Vulnerability）是 C 语言中 `printf` 系列函数（`printf`/`sprintf`/`fprintf`/`snprintf` 等）使用不当导致的安全问题。当程序将用户可控的字符串直接作为格式化字符串的第一个参数传递给 `printf` 时，攻击者可以:
- **读取栈内存**: 通过 `%p`/`%x`/`%s` 等格式符泄露栈上的数据（包括地址、Canary、密钥等）。
- **写入任意内存**: 通过 `%n` 格式符向指定地址写入已打印的字符数。

格式化字符串漏洞是 CTF PWN 中极为重要的信息泄露手段，也常被用作唯一的任意写原语。其利用灵活、效果强大，几乎是每位 PWN 选手的必备技能。

## 常见攻击/分析手法

### 1. 格式化字符串基础
- `%d` / `%i`: 以十进制输出整数
- `%x` / `%X`: 以十六进制输出无符号整数
- `%p`: 输出指针地址
- `%s`: 输出字符串（从栈上的指针读取）
- `%n`: 将已输出的字符数写入栈上的指针所指向的位置
- `%hn`: 写入 2 字节（short）
- `%hhn`: 写入 1 字节（char）
- `%ln`: 写入 8 字节（long，x64 上）
- `%<num>c`: 输出 num 个字符，用于填充控制 %n 写入的值
- `%<offset>$p`: 直接访问第 offset 个参数（Posix 扩展）

### 2. 32 位格式化字符串利用
- **参数传递方式**: 函数调用时所有参数都在栈上。
- **偏移量计算**: 格式化字符串本身的地址也在栈上，通过 %n\$p 可以枚举找到。
- **利用特点**:
  - 字符串地址直接可以通过栈上偏移引用，不需要额外 gadget。
  - 通常需要在栈上布置目标地址（如 GOT 表项），然后通过 %n 写入覆盖值。
  - 写入操作可以一次性完成，也可以分多次（每次 %hhn 写 1 字节）。
- **典型流程**:
  1. 确定格式化字符串在栈上的偏移（假设为 k）。
  2. 将目标地址（如 puts@GOT）放在字符串的起始位置。
  3. 使用 `%<value>c%<k>$hn` 向目标地址写入指定的值。

### 3. 64 位格式化字符串利用
- **参数传递方式**: 前 6 个参数在寄存器（rdi/rsi/rdx/rcx/r8/r9）中，从第 7 个参数开始在栈上。但格式化字符串函数内部处理时，`printf` 将其所有参数（包括寄存器中的）作为一个连续数组处理，第 1 个 `%p` 对应 rsi（fmt 后的第一个参数）。
- **偏移量计算**:
  - `%1$p` = rsi, `%2$p` = rdx, `%3$p` = rcx, `%4$p` = r8, `%5$p` = r9
  - `%6$p` 开始对应栈上的参数。
  - 需要测试确定格式化字符串本身在栈上的偏移（通常较大，如 6\~10+）。
- **利用特点**:
  - 地址中通常包含空字节（高位为 0x7f/0x00），需要将地址放在字符串末尾。
  - 无法通过直接的 %k$n 向地址写入，因为地址含空字节会截断字符串。
  - **常用技巧**: 使用 `%<k>$n` + 地址预置，或将地址放在格式字符串结尾。
  - 每字节写入需要独立的 %hhn 操作，且在栈上布置多个目标地址。
- **PAYLOAD 构造要点**:
  ```python
  # 目标地址放在格式化字符串末尾（避开空字节问题）
  payload = b"%<val>c%<offset>$hhn"     # 写 1 字节
  payload += b"\x00" * padding           # 填充对齐
  payload += p64(target_addr)            # 目标地址
  ```

### 4. 栈上利用 (On-stack Format String)
- **原理**: 格式化字符串本身位于栈上，攻击者可以在字符串中嵌入目标地址，然后利用 `%k$n` 直接引用这些地址进行写操作。
- **优点**: 不需要额外的任意地址写原语来布置目标地址。
- **缺点**: 需要在一次 printf 中完成所有数据的布置和写入，payload 长度可能受限。
- **典型场景**: 一次 printf 调用中完成信息泄露 + 任意地址写。

### 5. 非栈上利用 (Off-stack Format String)
- **原理**: 格式化字符串不在栈上（位于 .data/.bss/堆/其他全局区域），此时无法直接在格式字符串中嵌入目标地址并通过栈偏移引用。需要先将目标地址写入栈上的某个位置，然后通过 %n 写入。
- **常用技术**:
  - **Stack Migration**: 先通过格式化字符串泄露栈地址，然后利用 %n 修改栈上的返回地址，使其指向堆上的 ROP 链。
  - **双重利用**: 第一次格式化字符串泄露 libc 地址，第二次格式化字符串通过修改 __malloc_hook/__free_hook 等实现控制。
  - **递归利用**: 利用格式化字符串的 %n 写操作，逐步构建完整的利用链。
- **场景**: 题目将用户输入读入堆内存或全局缓冲区，然后对该缓冲区执行 printf。

### 6. 内存信息泄露 (Memory Leak via Format String)
- **核心技巧**: 利用 `%p`、`%s`、`%x` 格式符从栈或内存中读取敏感数据。
- **泄露目标**:
  - **Canary**: 栈上的 Canary 值，通过枚举偏移找到。
  - **libc 地址**: 栈上的 libc 函数返回地址（如 `__libc_start_main+XX`）。
  - **栈地址**: 栈上保存的 EBP/RBP 值。
  - **堆地址**: 堆上的指针或数据。
  - **PIE 基址**: 栈上保存的代码段返回地址。
  - **任意地址内容**: 使用 `%s` 配合栈上已有的指向目标地址的指针。
- **任意地址读**: 如果能在栈上布置目标地址，通过 `%k$s` 可以读取该地址处的字符串内容（直到遇到 `\0`）。

## 防御/对抗建议

- **使用正确的格式**: 永远使用 `printf("%s", user_input)` 而非 `printf(user_input)`。
- **编译器警告**: GCC/Clang 默认会对 `printf(user_input)` 这种写法发出 `-Wformat-security` 警告。
- **FORTIFY_SOURCE**: 启用 `-D_FORTIFY_SOURCE=2` 后，`printf` 会被替换为 `__printf_chk`，后者会在运行时检查格式字符串是否来自非常量字符串。
- **RELRO 保护**: Full RELRO 将 GOT 设为只读，防止通过格式化字符串修改 GOT 条目。
- **格式字符串过滤**: 在嵌入式中可禁用 `%n` 格式符（通过 `_FORTIFY_SOURCE` 或自定义 printf 实现）。
- **减少信息泄露**: 不要在栈上保存过多的敏感指针；使用 ASLR 增加地址熵。

### 安全编码示例
```c
// 不安全的写法
printf(user_input);   // 危险：用户输入作为格式化字符串

// 安全的写法
printf("%s", user_input);  // 安全：用户输入作为参数
fputs(user_input, stdout); // 更安全：不需要格式化
```
