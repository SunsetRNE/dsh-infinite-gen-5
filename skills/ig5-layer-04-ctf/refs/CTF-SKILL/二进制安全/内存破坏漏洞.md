# 内存破坏漏洞 (Memory Corruption)

## 概述

内存破坏漏洞是 PWN 领域最基础、最核心的漏洞类型。此类漏洞的根本原因在于程序对内存操作（读、写、分配、释放）的边界或生命周期管理不当，导致攻击者能够突破正常的内存访问限制，实现任意地址读写、控制流劫持等目的。

在 CTF 比赛中，内存破坏漏洞几乎涵盖所有二进制题目的基础阶段，也是构建更复杂利用链的起点。

---

## 常见攻击/分析手法

### 1. 内存未初始化 (Uninitialized Memory)
- **原理**: 栈或堆上的变量在使用前未被正确初始化，残留的上次调用的数据可能包含敏感信息（如 libc 地址、堆地址、函数指针等）。
- **利用手法**: 通过构造调用序列使未初始化的内存区域保留有利数据，进而泄露地址或直接控制执行流。
- **识别**: 关注未赋值的局部变量、realloc 未清零的内存、kmalloc 未清零的内核内存。

### 2. 内存溢出 (Buffer Overflow)
- **栈溢出**: 写入数据超过栈缓冲区大小，覆盖返回地址、EBP/RBP、局部变量等。详见 [栈溢出利用](栈漏洞利用.md)。
- **堆溢出**: 写入数据超过堆块大小，覆盖下一个堆块的元数据（size/prev_size/fd/bk 等）。详见 [堆漏洞利用](堆漏洞利用.md)。
- **检测**: 寻找不安全的拷贝函数（strcpy/memcpy/sprintf/read 等）及缺乏边界检查的循环。

### 3. Off-by-One / Off-by-Null
- **原理**: 循环或拷贝操作结束时多写入或少写入一个字节。
  - Off-by-One: 多写一个字节，可能覆盖相邻数据的低位字节。
  - Off-by-Null: 在字符串末尾多写入一个 `\0`，可能破坏相邻堆块的 size 字段低位。
- **利用手法**:
  - 栈 Off-by-One: 覆盖 EBP 最低字节，实现栈帧移位。
  - 堆 Off-by-One/Null: 篡改相邻堆块 size 的 PREV_IN_USE 位，触发 unlink 或堆块合并，构造重叠块。
- **典型场景**: `for(i = 0; i <= n; i++)` 而非 `i < n`；`read(fd, buf, size)` 后未正确处理空终止字符。

### 4. 内存越界读写 (OOB Read/Write)
- **原理**: 索引或指针计算超出数组/缓冲区的合法边界，允许读取或写入越界内存。
- **利用手法**:
  - 越界读: 泄露相邻内存中的地址、密钥、标志位等。
  - 越界写: 修改相邻对象的数据、函数指针、虚表指针等。
- **常见触发点**: 数组索引未检查、指针算术错误、错误的类型转换导致访问范围扩大。

### 5. 内存泄露 (Memory Leak / Info Leak)
- **原理**: 程序将内存中的敏感数据（未初始化的数据、残留指针等）输出给用户，帮助攻击者绕过 ASLR 等地址随机化保护。
- **泄露目标**: libc 地址（泄露 GOT 或 __libc_start_main 返回地址）、堆地址、栈地址、Canary 值、PIE 基址。
- **泄露手段**: 格式化字符串、越界读、未初始化变量使用、`puts/printf` 输出未以 `\0` 结尾的缓冲区。

### 6. Use-After-Free (UAF)
- **原理**: 内存块被释放后，程序仍持有指向该内存块的指针并继续使用该指针进行读/写/释放操作。
- **利用手法**:
  - UAF 读: 释放后重新分配覆盖该区域，通过原指针泄露敏感数据。
  - UAF 写: 释放后伪造堆块内容，劫持函数指针或修改堆元数据。
  - UAF 释放: 对同一块内存重复释放（Double Free）。
- **关键**: 利用释放后重新分配时的类型混淆（Type Confusion）或堆布局控制。

### 7. Double Free
- **原理**: 对同一块内存调用两次 free，破坏堆管理器的链表结构。
- **利用手法**:
  - Tcache Double Free: 在 tcache 中实现任意地址分配（tcache poisoning）。
  - Fastbin Double Free: 利用 fastbin 的循环检测绕过，实现任意地址写。
  - Unsorted Bin Double Free: 触发异常堆状态转化为地址泄露。
- **绕过**: 现代 glibc 加入了 key 字段检测 tcache double free，但仍可通过欺骗 key 或利用中间释放来绕过。

### 8. 整数溢出 (Integer Overflow)
- **原理**: 整数运算结果超出数据类型的表示范围，产生回绕（wrap-around），导致分配大小异常、循环计数错误或索引越界。
- **类型**:
  - 上溢: 正数相加超过最大值，回绕为负数或小值。
  - 下溢: 无符号数减至负数以下，回绕为极大值。
- **利用手法**:
  - 通过整数溢出使 `malloc(size)` 分配过小的堆块，后续拷贝大量数据造成堆溢出。
  - 使循环计数器回绕，实现越界读写。
- **检测**: 关注涉及 `malloc(n)`、循环条件、索引计算中的算术运算，尤其是无符号类型参与的计算。

## 防御/对抗建议

- **编译器保护**: 现代编译器提供多种保护机制（Stack Canary、FORTIFY_SOURCE、PIE、RELRO），开启后可大幅提高利用难度。
- **操作系统保护**: ASLR（地址随机化）、NX（数据不可执行）、SMAP/SMEP（内核态用户态隔离）。
- **使用安全函数**: 优先使用 `strncpy`/`snprintf`/`memmove` 等边界检查函数，避免 `gets`/`strcpy`/`sprintf`。
- **整数安全**: 在敏感运算前进行溢出检测，使用 `__builtin_add_overflow` 等编译器内置检查函数。
- **内存安全语言**: 在关键组件中使用 Rust 等内存安全语言替代 C/C++。

## 示例/思路

### 典型利用链示例（堆溢出 + UAF）
```
1. 通过堆溢出篡改相邻堆块的 size 位
2. 触发堆块合并/Unlink 获得重叠块 (Overlapping Chunk)
3. 重叠块中伪造目标结构，修改函数指针
4. 触发函数调用，劫持控制流到 one-gadget 或 system("/bin/sh")
```

### 常见绕过思路
- **Canary**: 泄露 + 保留原值；子线程/子进程 fork 后共享 Canary；覆盖 TLS 中的 Canary 值。
- **PIE**: 通过泄露任意地址获取基址；部分覆盖（Partial Overwrite）利用低 12 位的固定偏移。
- **ASLR**: 多次泄露 + 爆破（Brute Force）低 12 位或堆地址随机化范围。
