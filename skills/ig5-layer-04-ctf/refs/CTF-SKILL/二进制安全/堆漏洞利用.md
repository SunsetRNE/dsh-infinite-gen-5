# 堆漏洞利用 (Heap Exploit)

## 概述

堆（Heap）是程序运行时用于动态内存分配的内存区域。glibc 使用的 ptmalloc2 分配器维护着复杂的数据结构来管理堆块（chunk）的分配与释放，包括 tcache、fastbin、unsorted bin、small bin、large bin 等容器。堆漏洞利用指利用堆管理逻辑中的缺陷（溢出、UAF、Double Free 等）来篡改堆元数据或堆块内容，最终实现任意地址读写或控制流劫持。

与栈溢出利用相比，堆利用更加复杂多变——堆的状态受分配/释放操作的顺序影响极大，需要攻击者对堆管理器内部机制有深入理解，并能够精确控制堆的布局。

## 常见攻击/分析手法

### 1. Unlink 攻击
- **原理**: 利用 glibc 在 unlink（从双向链表中移除空闲块）操作中对指针的有限验证绕过，实现任意地址写。通过伪造堆块中的 `fd` 和 `bk` 指针，在 unlink 时向目标地址写入预先计算的值。
- **glibc 保护**: 现代 glibc 中 unlink 会检查 `fd->bk == p && bk->fd == p`，使传统 unlink 攻击几乎失效。
- **绕过思路**: 在已知堆地址的情况下，构造满足检查条件的伪指针。某些场景下可以使用 **Safe Unlink**（在 small bin 中操作）。

### 2. Fastbin Attack
- **原理**: fastbin 是单链表（LIFO），对大小小于 `global_max_fast`（默认 0x80）的释放块进行管理。Fastbin Attack 包括：
  - **Fastbin Double Free**: 对同一 fastbin 块连续释放两次，使该块出现在链表中两次，实现任意地址分配。
  - **Fastbin 伪造**: 释放后修改 fd 指针指向目标地址（如 `__malloc_hook` 附近的地址），后续两次 malloc 将分配到目标区域。
- **绕过检测**: glibc 2.26+ 加入 tcache 后，fastbin double free 需要绕过 tcache（先填满 tcache 使块进入 fastbin）。

### 3. Unsorted Bin Attack
- **原理**: 当一个堆块被释放且不属于 fastbin/tcache 范围时，它会进入 unsorted bin。Unsorted Bin Attack 利用 unlink 操作向目标地址写入 `main_arena+88`（即 unsorted bin 链表的头部地址）。
- **局限性**: 新版 glibc 中 unsorted bin attack 的写入值变得难以预测（改为写入 `&main_arena.bins[0]`），且通常只能写入一个已知堆地址而非期望的值。
- **用途**: 在旧版 glibc 中可以用于修改 `_IO_list_all`、`global_max_fast` 等关键全局变量。
- **现代替代**: 通常结合其他漏洞（如 House of Orange）使用。

### 4. Large Bin Attack
- **原理**: 当 large bin 中的堆块被重新分配或移入时，glibc 会更新 `main_arena` 中的相关指针。Large Bin Attack 通过伪造 large bin 堆块中的 `bk_nextsize` 或 `fd_nextsize` 指针，在特定条件下实现任意地址写。
- **利用场景**: 常配合堆溢出或 UAF 使用，向目标地址写入堆地址。
- **特点**: 对 glibc 版本敏感，较新版本中 large bin 的处理逻辑有所变化。

### 5. Tcache Attack
- **原理**: tcache（Thread Local Cache）是 glibc 2.26 引入的每线程私有缓存，用于加速小内存分配。Tcache 的结构比 fastbin 更简单（无循环链表检查），因此更容易被利用。
- **常见手法**:
  - **Tcache Poisoning**: 释放后篡改 `tcache->next` 指针指向目标地址，下次分配获取该地址。
  - **Tcache Double Free**: 对同一 tcache 块连续释放两次（绕过 `key` 字段检测后可实现）。
  - **Tcache Perthread Structure 攻击**: 修改 tcache_perthread_struct 本身（位于堆起始处），实现任意地址分配。
  - **Tcache Stashing Unlink**: 详见下文。
  - **Count 域篡改**: 修改 tcache 的 counts 数组绕过 tcache 数量限制。
- **Tcache key 绕过**: glibc 2.29+ 在 tcache_entry 中加入 `key` 字段检测 double free，可通过释放到不同大小 bin 再重新申请回 tcache 来绕过，或利用堆溢出直接修改 key。

### 6. Tcache Stashing Unlink Attack
- **原理**: 在 `malloc` 从 small bin 向 tcache 转移堆块时（称为 Stashing），会对 next 指针进行有限度的写入操作。通过伪造 small bin 链表的 `bk` 指针，可以向目标地址写入一个堆地址或 libc 地址。
- **条件**: 需要能够控制 small bin 中某个堆块的 bk 指针。
- **效果**: 可以实现将目标地址添加到 tcache 链中，从而在后续的 malloc 中获得该地址对应的"堆块"。

### 7. House of 系列
House of 系列是由安全社区总结的一系列针对 glibc 的特定利用技术，每种技术针对特定的漏洞场景和 glibc 版本。

- **House of Force** (glibc < 2.29): 通过溢出修改 top chunk 的 size 为极大值，使后续 `malloc` 返回任意地址。已经被现代 glibc 中的 size 检查所禁止。
- **House of Spirit**: 在栈上构造伪造的堆块头，通过 free 将该区域释放到 bin 中，后续 malloc 获得栈内存，实现栈上任意地址写。
- **House of Einherjar**: 利用 off-by-null 漏洞修改堆块的 `PREV_IN_USE` 位，实现向前合并（backward consolidation）到任意地址。
- **House of Orange** (glibc < 2.24): 通过修改 top chunk 的 size 并触发 `sysmalloc`，获得一个伪造的 FILE 结构体（通过 FSOP 利用）。新版本中引入 vtable 合法性验证后难以直接使用。
- **House of Storm**: 结合 unsorted bin attack 和 large bin attack，在特定版本上实现稳定且强大的任意地址分配。
- **House of Lore**: 利用 small bin 的 bk 指针篡改，实现从 small bin 获得任意地址分配。
- **House of Rabbit**: 利用 heap overflow 或 off-by-one 实现堆块的向前/向后合并。
- **House of Cat**: 通过 `_IO_wfile_overflow` + large bin attack 实现控制流劫持（glibc 2.24+）。
- **House of Pig**: 结合 large bin attack 与 IO_FILE 利用，适用于 glibc 2.31-2.34。
- **House of Apple**: 现代 glibc（2.35+）中通过 `_IO_wfile_overflow` 或 `_IO_wdefault_xsputn` 等函数绕过 `IO_validate_vtable` 限制。

### 8. Musl-PWN (musl 堆管理器)
- **原理**: musl libc 使用不同于 glibc 的堆管理器（mallocng），结构更加简洁、安全性更高。Musl 堆基于 **group** 和 **slot** 的概念。
- **特点**:
  - 元数据和用户数据分离存储（meta 区 + 数据区）。
  - 没有 free list（无 fastbin/unsorted bin/large bin 概念）。
  - 使用 bitmap 管理空闲块分配。
- **常见攻击手法**:
  - 利用 UAF 泄漏 meta 结构中的指针。
  - 伪造 meta 结构实现任意地址分配。
  - 利用 size 回绕（wrap）绕过边界检查。
- **挑战**: Musl 堆的随机化程度更高，安全设计更精简，可利用原语通常弱于 glibc。

### 9. 其他堆管理器
- **jemalloc**（FreeBSD、Firefox、Android）：采用 extent 管理，多 arena 设计。利用需要理解 rtree、bin、extent 等结构。
- **tcmalloc**（Google、Chrome）：Thread Caching + Central Free List。每个线程有本地缓存。
- **Windows Heap (NT Heap)**: 基于 _HEAP 结构、LFH（Low Fragmentation Heap）、Segment Heap。利用方式与 Linux 堆有显著差异。
- **内核堆 (slab/slub)**: 详见 [内核漏洞利用](Linux内核漏洞利用.md)。

## 防御/对抗建议

- **glibc 持续加固**: 新版本 glibc 不断引入更强的堆保护（tcache key、size 检查、safe unlinking、指针加密等）。建议使用最新版本进行编译。
- **堆元数据只读**: 某些加固方案将堆元数据存放在单独的只读区域。
- **指针加密 (Pointer Guard)**: glibc 2.32+ 对 `tcache->next`、`fastbin->fd` 等关键指针进行了异或加密（PTR_MANGLE/PTR_DEMANGLE）。
- **使用内存安全语言**: 对于关键组件使用 Rust 或 Go 等有 GC 或所有权系统的语言。
- **最小化堆操作**: 严格验证输入长度；避免在堆内存上执行复杂的数据操作。
- **日志与监控**: 监控异常的堆操作模式（如频繁的 malloc/free、异常的堆块大小）。

## 示例/思路

### Tcache Poisoning 示例（glibc 2.26 - 2.28）
```
1. free(chunk_A)  # chunk_A -> tcache
2. free(chunk_B)  # chunk_B -> tcache (chunk_A in chunk_B->next)
3. 利用 UAF 修改 chunk_B->next = target_addr
4. malloc(size)   # 返回 chunk_B
5. malloc(size)   # 返回 target_addr
6. 向 target_addr 写入恶意数据（如 __free_hook = system）
```

### House of Apple 2 思路（glibc 2.35+）
```
1. 通过 large bin attack 向 _IO_list_all 写入堆地址
2. 伪造 IO_FILE 结构，在堆上构造包含 vtable 指向 _IO_wfile_jumps 的文件对象
3. 设置 _wide_data->_IO_write_base < _IO_write_ptr
4. 触发 exit() / 流刷新，调用 __overflow(__fp, EOF)
5. 控制参数寄存器和指令流，跳转到 one_gadget
```
