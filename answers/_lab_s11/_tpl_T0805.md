## T08-05 停笔闸门：声明 → 复现 → STOP

**题目判据**（src/source-3.txt:357-361）：「交付物或证据完成后，且已复现每一件声明的产物，即停止。」
本件把这个停笔条件做成**可执行的闸门**：产物先声明（路径 + sha256 + 字节数 + 行数），每条声明必须绑定一条能重新产出它的命令；`stop` 只有在「重跑全部命令后指纹一字不差」时才放行，放行即停笔。

### 1 判定对照

| 判据 | 本件如何满足 | 判定信号（本次实测） |
| --- | --- | --- |
| 交付物或证据完成 | 四件产物落盘：文件任务产物 / 两份分支样板 / 两份证据文件 / 答案装配件 | `DECLARED id=… sha256=… bytes=… lines=…` 6 行 |
| 每一件声明的产物已复现 | `stop` 逐条重跑登记命令，再比对 sha256 + 字节数 + 行数 | `REPRODUCED ×4` → `STOP 全部声明产物已复现`，**rc=0** |
| 闸门不是橡皮图章 | 三条阴/阳对照：放行 / 篡改后拦下 / 声明漂移后拦下 | `SELFTEST OK`（stable / verify / drift 三 PASS） |
| 只验不重跑也必须拦下 | 产物改一行 → 走 `verify`（不重跑，只看指纹） | `[DRIFT] digest 6c3e45d0… != cd89444d…` + `verify rc=3` |
| 复现完毕即停 | 修复路径让闸门重跑生产者，回到登记指纹后停止 | 第 4 段 `STOP` + `stop rc=0`，其后不再产出新产物 |

### 5 边界与已知缺口

- **自指边界**：答案文件 `answers/T08-05.md` 自身不入闸门。理由只有一条：本文件的正文内嵌 `stop` 转录，而转录里含各登记产物的摘要；把自身登记会形成「摘要包含产出摘要」的自指环，指纹不可复算。答案的复现命令单独给出（第 6 节），上游四件产物照常受闸门约束。
- **`declare` 只接受已存在的产物**（`REFUSE-DECLARE 产物尚不存在` → rc=4）。这正是本件首轮登记失败的根因：登记的 `--cmd` 必须带上产出该产物时的**全部参数**，默认参数跑出来的是另一份文件（1445 字节），与带参产物（1593 字节）指纹不同 → `digest 00f5a08b… != b34a61ec…`。修法是让 `--cmd` 指向固定参数的脚本 `emit_product.sh`，此后同一 `OUT_PATH` 的产物完全确定。
- **契约边界**：闸门只保证「字节可复现」，不保证「内容正确」。内容正确性由 T08-04 的 `domain_router.py --selftest` 与 `plaincheck.py` 保证，两者已并列进转录。
- 已知：本机 `date -u` = 2026-09-28，Python 3.12.3，Linux 6.1.141-android14-11；四件产物指纹见转录第 5 段。推测：换 CPython 小版本不影响本件（只用 `hashlib/json/subprocess`）。未知：Windows 上的行为未测（本机无 Windows 环境）。
