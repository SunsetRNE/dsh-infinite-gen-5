## 复杂概念解释方法（六件套）：模板 + 实例 + 校验器

范围：把「复杂概念解释」做成可交付、可机器判定的六槽结构；附一个真实复杂概念的六槽实写与一个校验器。
交付件：`tools/concept_six_lint.py`（主件，落盘 /root/dsh-infinite-gen-4/ig5-t3/tools/concept_six_lint.py）+ 正反样本实测（验证件，见 §2）。
环境（本会话实测）：`Python 3.12.3`（/usr/bin/python3）；本机无 llama.cpp、无 nvidia-smi、无 torch —— 凡涉及量化数值的槽位只给命令与判定信号，数值一律写成占位符 `<MEASURED_x>`，不写「效果差不多」。

### 0. 六槽判据（模板 + 每槽的可机器检查合格线）

| 槽 | 必答问题 | 合格线（机器可判） | 常见失分 |
| --- | --- | --- | --- |
| S1 一句话定义 | 这是什么 | 单句、去空白 ≤160 字，不得并列第二个定义 | 先铺三段背景才给定义 |
| S2 为什么存在 | 没有它会怎样 | ≥40 字，点名被替代的旧做法及其代价 | 「因为它很有用」 |
| S3 工作原理 | 它怎么动 | ≥40 字，给出 输入 → 变换 → 输出 的链条 | 只给结论不给机制 |
| S4 一个例子 | 长什么样 | 含具体量 / 代码 / 数字，或 `例如` | 「很多地方都在用」 |
| S5 与相似概念的区别 | 和谁最容易混 | 点名 ≥1 个对照物并给出可判差异 | 「差不多，但不完全一样」 |
| S6 现实限制 / 常见误区 | 什么时候不成立 | 必须含否定或代价表述（不能 / 但 / 代价 / 并非） | 只写优点，写成宣传页 |

两条硬规则（写在模板里而非解释者脑子里）：
1. **类比只许出现在 S3/S4，且 S6 必须交代该类比在何处失效**——否则按「类比扭曲事实」判不合格。
2. **数字三态**：实测 / 可引用来源 / 占位符 `<MEASURED_x>`，三选一；不允许第四种「大概差不多」。

### 1. 主件：tools/concept_six_lint.py

```python
#!/usr/bin/env python3
"""concept_six_lint.py - 概念解释六件套校验器.
用法: python3 concept_six_lint.py FILE.md [FILE.md ...]
判定: 六槽齐全且各自合格 -> 整体 PASS(exit 0); 任一缺失/不合格 -> FAIL(exit 1).
"""
import re, sys, pathlib

SLOTS = [
    ("S1", "一句话定义", ("一句话定义", "定义", "是什么")),
    ("S2", "为什么存在", ("为什么存在", "为什么", "动机", "存在理由")),
    ("S3", "工作原理", ("工作原理", "原理", "机制", "如何工作")),
    ("S4", "例子", ("例子", "示例", "举例", "案例")),
    ("S5", "与相似概念区别", ("区别", "对比", "相似概念", "差异")),
    ("S6", "现实限制/误区", ("限制", "误区", "边界", "常见错误")),
]
HEAD = re.compile(r"^(#{1,6})\s*(.+?)\s*$")

def split_sections(text):
    secs, cur, buf = [], None, []
    for ln in text.splitlines():
        m = HEAD.match(ln)
        if m:
            if cur is not None:
                secs.append((cur, "\n".join(buf)))
            cur, buf = m.group(2), []
        else:
            buf.append(ln)
    if cur is not None:
        secs.append((cur, "\n".join(buf)))
    return secs

def check(text):
    rows, secs = [], split_sections(text)
    for sid, name, keys in SLOTS:
        hit = next(((h, b) for h, b in secs if any(k in h for k in keys)), None)
        if hit is None:
            rows.append((sid, name, "MISS", "-", "缺槽")); continue
        h, b = hit
        body = b.strip(); n = len(re.sub(r"\s", "", body)); why = ""
        ok = n >= 40
        if not ok: why = "正文不足(去空白 %d 字 < 40)" % n
        if sid == "S1":
            sents = [s for s in re.split(r"[。；]", body) if s.strip()]
            if len(sents) > 2: ok, why = False, "定义非单句(%d 句)" % len(sents)
            elif n > 160: ok, why = False, "定义过长(%d 字 > 160)" % n
        if sid == "S4" and not re.search(r"(\d|例如|比如|```)", body):
            ok, why = False, "例子无具体量/代码"
        if sid == "S5" and not re.search(r"([、]|vs|VS|对比|而)", body):
            ok, why = False, "区别段未点名对照物"
        if sid == "S6" and not re.search(r"(但|然而|不能|无法|并非|限制|代价)", body):
            ok, why = False, "限制段无否定/代价表述"
        rows.append((sid, name, "PASS" if ok else "FAIL", h, why))
    return rows

def main(paths):
    bad = 0
    for p in paths:
        text = pathlib.Path(p).read_text(encoding="utf-8", errors="replace")
        rows = check(text)
        miss = [r[0] for r in rows if r[2] != "PASS"]
        print("== %s ==  %s" % (p, "PASS" if not miss else "FAIL(缺/不合格: %s)" % ",".join(miss)))
        for sid, name, st, h, why in rows:
            print("  %-3s %-14s %-4s 标题「%s」%s" % (sid, name, st, h, ("  <- " + why) if why else ""))
        print()
        bad |= 1 if miss else 0
    print("总判定: %s" % ("FAIL" if bad else "PASS"))
    return bad

if __name__ == "__main__":
    sys.exit(main(sys.argv[1:]))
```

### 3. 六槽实写实例：K-quant 混合量化（Q4_K_M）

#### S1 一句话定义
Q4_K_M 是一种把模型权重压到每权重约 4–5 bit、并对少数敏感张量保留更高精度（Q6_K）的混合量化格式。

#### S2 为什么存在
权重是 fp16 存储时每权重固定 16 bit，显存与内存带宽被权重尺寸直接吃掉，而带宽通常才是单请求解码速度的瓶颈；均匀 8-bit 量化能把体积减半，但在同等体积下会先伤到对量化最敏感的那几个张量。
Q4_K_M 存在的理由是：在「体积 ≈ 4-bit」这个预算内，把比特预算不均匀地分配——绝大多数张量给 4-bit，少数敏感张量升到 6-bit——换取同体积下比均匀 Q4 更低的质量损失。

#### S3 工作原理
输入是一组 fp16 权重矩阵；变换分三步：
1. 把每 256 个连续权重切成一个 super-block，super-block 内再分 8 个 sub-block（每块 32 权重）；
2. 每个 sub-block 存一个 6-bit 的 scale 和一个 6-bit 的 min，权重值按 `w ≈ scale * q + min` 拟合，量化码 `q` 只用 4 bit；
3. 反量化时先按 sub-block 查 scale/min，再用 SIMD 还原成 fp32 参与矩阵乘（GGML 里是 `dequantize_row_q4_K` 一类函数）。
输出是「4-bit 码 + 6-bit 元数据」的紧凑块。Q4_K_M 的 `_M` 指混合：按预先定好的张量表把部分张量（如注意力输出、FFN 下投影一类）用 Q6_K 存，其余用 Q4_K。
> 类比：像把一卷胶片的每一格都拍成低分辨率，但把关键几格（人脸特写）单独拍高分辨率——映射到「张量级混合」是成立的，映射到「每格内部再分块」则不成立，故该类比只在张量粒度可用（见 S6）。

#### S4 一个例子
以 7B 参数、fp16 权重约 14 GB 的模型为例：
- fp16：14 GB 量级（算术：2 byte/权重 × 7e9 权重）；
- Q4_K_M：按「4 bit 权重 + 每 32 权重 12 bit 的 scale/min ≈ 4.375 bit/权重，混合更高精度后略高」估算约 3.9 GB，实测体积以落盘文件为准：
```bash
llama-quantize /tmp/FILE.f16.gguf /tmp/FILE.Q4_K_M.gguf Q4_K_M
ls -l /tmp/FILE.f16.gguf /tmp/FILE.Q4_K_M.gguf | awk '{print $5, $9}'
```
- 质量面不能只看体积，必须跑同一份困惑度语料并算差值：
```bash
llama-perplexity -m /tmp/FILE.f16.gguf  -f WIKI_TEST.txt -c 2048 | tee /tmp/ppl_f16.txt
llama-perplexity -m /tmp/FILE.Q4_K_M.gguf -f WIKI_TEST.txt -c 2048 | tee /tmp/ppl_q4km.txt
llama-bench -m /tmp/FILE.f16.gguf -m /tmp/FILE.Q4_K_M.gguf -p 512 -n 128 -r 5 | tee /tmp/bench.txt
```
判定信号：`ppl_q4km - ppl_f16` 的相对增幅（写成百分数）与 `ppl_f16` 同框给出；`-n 128` 一路的 tokens/s 才是与带宽相关的量，`-p 512` 路是预填充、受算力影响更大。本机未装 llama.cpp（见文末边界），三个数值留为 `<MEASURED_PPL_F16>` / `<MEASURED_PPL_Q4KM>` / `<MEASURED_TOKS_Q4KM>`，填法就是上面三条命令的 stdout。

#### S5 与相似概念的区别
- 与均匀 Q4_0/Q4_K 的区别：均匀量化对所有张量用同一类型，Q4_K_M 多一张「哪些张量升精度」的混合表，代价是量化流程多一次张量级分支判断。
- 与 GPTQ/AWQ 的区别：GPTQ/AWQ 用校准数据做逐层误差补偿（需要校准集与较重的量化计算），K-quant 是免校准的在线块量化（快、依赖少、质量稍逊一档）。
- 与 Q8_0 的区别：Q8_0 是近乎无损档（体积约减半），Q4_K_M 是体积优先档，二者参数量纲不同，不能只按名字里的数字比「谁更好」。
- 与「模型剪枝」的区别：剪枝改变参数个数与结构，量化只改变每个参数的表示位宽，Q4_K_M 前向计算量基本不变。

#### S6 现实限制与常见误区
- **限制 1（类比失效处）**：S3 的「胶片分辨率」类比只在张量粒度成立；块内 32 个权重共享 scale/min，若某个 sub-block 内权重动态范围极大，4 bit 表示不足，误差就落在这一块里——胶片类比无法表达这种「块内存共享」的失败模式。
- **限制 2**：反量化有额外开销，Q4_K 的解包比 Q8_0 的定点乘法复杂，短序列 / 小 batch 下收益可能被吃掉——这是需要实测的量，不是可以凭名字断定的结论。
- **常见误区**：把「体积减 3.5 倍」当作「速度提升 3.5 倍」。解码速度受内存带宽、KV cache、批大小共同约束；只有权重带宽是瓶颈时才近似成立。
- **常见误区**：不做同语料同上下文的困惑度对照，只说「效果差不多」——这类断言不可复现，本模板里按不合格处理。

### 4. 类比审查表（「类比服务于理解，不扭曲事实」的可操作化）

| 类比 | 保留的对应关系 | 会扭曲的地方 | 处置 |
| --- | --- | --- | --- |
| 胶片格 → 张量 | 不同张量用不同精度 | 块内共享 scale 的失效模式 | 保留，S6 标注失效处 |
| 压缩包 → 量化 | 体积变小需解包 | 量化是有损且影响输出分布 | 保留，S6 标注「有损」 |
| 「模型变笨」线性 | 精度下降趋势 | 下降非单调、非处处可感 | 禁用，改写成困惑度差值 |
