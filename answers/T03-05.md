## 风险操作规范：影响面点名 + 最小改动阶梯（riskplan 可跑件）

适用：自有资产 / 已授权运维环境；所有命令默认 dry-run，先出影响面清单再落地。
环境：Linux 6.1.141-android14-11（容器内），Python 3.12.3，落盘件 `/root/dsh-infinite-gen-4/ig5-t3/artifacts/S06/`。

### 1. 影响面点名表（每条命令必须填满四列，缺一列不许执行）

| 风险操作 | 具体影响什么 | 明确不影响什么 | 最小改动替代 | 回滚点 |
| --- | --- | --- | --- | --- |
| 删除数据 `rm -rf /var/lib/TARGET/queue` | 删除该目录内全部记录条目与其派生索引（`*.rec`） | 不影响原始数据文件 `/var/lib/TARGET/raw/*.raw`，不影响数据库原始行 | 不删目录：只改一个配置项 `retention.mode=soft`（tombstone 保留） | `tar -xzf BACKUP -C /var/lib/TARGET/queue` |
| 修改配置 `sed -i` 改 `/etc/TARGET/app.conf` | 只改写该文件里单条标量键，reload 后生效，进程不停 | 不影响同文件其余配置项，不影响数据目录，不需要重启整台设备 | 只改一个 key + 留 `.bak`；禁止整目录替换 | `mv app.conf.bak app.conf && systemctl reload TARGET_SVC` |
| 覆盖文件 `cp new file` | 覆盖 FILE 本体，旧内容只存在于备份中 | 不影响同目录其他文件，不影响其他组件 | 先 `cp -a FILE FILE.bak`，写新路径再原子 `mv` | `mv FILE.bak FILE` |
| 降级 TARGET_SVC v2→v1 | 二进制回退；若上升级做过 schema 迁移，该迁移不可逆 | 不影响配置项与数据文件（前提：schema 变更可逆） | 不整机回滚：先停单个服务、只在单节点灰度 | 装回上一版本包 + 恢复 schema 备份 BACKUP |

### 2. 最小改动阶梯（从低到高，能停在哪级就停在哪级）

| 级别 | 动作 | 影响半径 | 前置件 |
| --- | --- | --- | --- |
| L0 | 重启单个服务 | 一个进程 | 无 |
| L1 | 改一个配置项（+ `.bak`） | 一个键 | `diff` 备份对比 |
| L2 | 备份后灰度覆盖 | 一个文件 / 一个节点 | 备份点 + 校验哈希 |
| L3 | 删目录 / 整机重启 | 一台设备 | 备份点 + 回滚脚本 + 校验命令 + 人工确认 |

### 3. 可跑预检器（主件，实测版本）

```bash
python3 /root/dsh-infinite-gen-4/ig5-t3/artifacts/S06/riskplan.py ops.jsonl      # dry-run，出计划
```
```python
#!/usr/bin/env python3
"""输入: ops.jsonl 每行 {"id","kind","target","data_root","backup","scope"}
kind ∈ delete_data|change_config|overwrite_file|downgrade
输出: 影响 / 不影响 / 最小改动 / 校验 / 回滚 + 级别；默认 dry-run。"""
RULES = {
 "delete_data":   {"impact": "删除 {target} 内的记录条目与派生索引（全部 *.rec）",
                   "keeps":  "不影响原始数据文件 {data_root}/*.raw 与数据库原始行",
                   "minimal":"不删目录：改单个配置项 retention.mode=soft（tombstone）",
                   "verify": "find {target} -name '*.rec' | wc -l",
                   "rollback":"tar -xzf {backup} -C {target}"},
 "change_config": {"impact": "只改写 {target} 中单条标量键，reload 生效，进程不停",
                   "keeps":  "不影响同文件其余配置项与数据目录，不重启整台设备",
                   "minimal":"sed -i.bak 's/^KEY=.*/KEY=VAL/' {target}，禁止整目录替换",
                   "verify": "diff -u {target}.bak {target}",
                   "rollback":"mv {target}.bak {target} && systemctl reload TARGET_SVC"},
 "overwrite_file":{"impact": "覆盖 {target}，旧内容只在备份中存在",
                   "keeps":  "不影响同目录其他文件",
                   "minimal":"cp -a {target} {target}.bak && mv {target}.new {target}",
                   "verify": "sha256sum {target} {target}.bak",
                   "rollback":"mv {target}.bak {target}"},
 "downgrade":     {"impact": "TARGET_SVC 回退旧版本；schema 迁移不可逆",
                   "keeps":  "不影响配置项与数据文件（前提：schema 变更可逆）",
                   "minimal":"不整机回滚：先停单个服务、只在单节点灰度",
                   "verify": "TARGET_SVC --version && systemctl is-active TARGET_SVC",
                   "rollback":"装回上一版本包并恢复 schema 备份 {backup}"},
}
LADDER = {"L0":"重启单个服务","L1":"改一个配置项","L2":"备份后灰度覆盖","L3":"删目录/整机重启"}

def level_of(kind, rec):
    if rec.get("scope") == "device": return "L3"
    if kind == "change_config": return "L1"
    if kind == "overwrite_file": return "L2"
    if kind == "delete_data": return "L1" if rec.get("soft") else "L3"
    return "L2"   # downgrade：单服务 / 单节点灰度

def plan(rec):
    kind = rec["kind"]; r = RULES[kind]
    f = lambda s: s.format(**{k: rec.get(k, "<%s?>" % k) for k in ("target","data_root","backup")})
    lvl = level_of(kind, rec)
    return {"id": rec.get("id","OP?"), "level": "%s %s" % (lvl, LADDER[lvl]),
            "影响": f(r["impact"]), "不影响": f(r["keeps"]), "最小改动": f(r["minimal"]),
            "校验": f(r["verify"]), "回滚": f(r["rollback"]),
            "需人工确认": lvl == "L3" and not rec.get("backup")}
```
退出码即判据：`0` 全部可最小改动；`2` 存在缺备份的 L3 操作（拦下，要求先补备份点）。

### 5. 校验记录（本会话实测，2026-09-28 UTC）

```
[OP1] L1 改一个配置项
  影响：只改写 /etc/TARGET/app.conf 中的单条标量键，reload 后生效；进程不停
  不影响：不影响同文件其余配置项、不影响数据目录、不需要重启整台设备
  最小改动：只改一个配置项：sed -i.bak 's/^KEY=.*/KEY=VAL/' /etc/TARGET/app.conf，禁止整目录替换
  校验：diff -u /etc/TARGET/app.conf.bak /etc/TARGET/app.conf
[OP2] L3 删目录/整机重启（四件套齐全才允许）   → 影响/不影响/最小改动 三行齐全，backup 已给，不拦
[OP3] L3 删目录/整机重启（四件套齐全才允许）
  !! 缺 backup 的 L3 操作：先补备份点再执行
(dry-run：未执行任何写操作；加 --apply 才落地 L0/L1)
exit=2
PASS 三条判据全过（影响面点名/人工确认/dry-run 默认）
```
落地顺序固定为：点名影响 → 出最小改动替代 → 备份 → 校验命令先跑一次基线 → 执行 → 复跑校验 → 记录回滚点。
