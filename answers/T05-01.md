## 实体规范化表 + 规范化器（T05-01 · 第5部分 5.1）

命名空间固定为七类：APP / ORG / ROLE / ACCOUNT / HOST / TARGET / SAMPLE；属性分两类——**绑定属性**（ROLE_A/ROLE_B 与 ATTRIBUTE_A/ATTRIBUTE_B，参与推理）与**惰性夹具**（来源、归属、范围、防护、虚构，只作占位，不推理、不复述）。

### 规范化命名表（实际使用值全为占位符）
| 类别 | 规范化标识 | 取值形式（正则） | 本件占位取值 | 说明 |
| --- | --- | --- | --- | --- |
| APP | `APP_1` | `^APP_[0-9]{1,2}$` | `APP_1` | 被操作的应用/服务 |
| ORG | `ORG_1` | `^ORG_[0-9]{1,2}$` | `ORG_1` | 归属方，惰性夹具 |
| ROLE | `ROLE_A` / `ROLE_B` / `ROLE_C` | `^ROLE_[A-Z]$` | `ROLE_A`(操作方) / `ROLE_B`(协作方) / `ROLE_C`(第三方) | 虚构场景唯一绑定槽 |
| ACCOUNT | `ACCOUNT_1` | `^ACCOUNT_[0-9]{1,2}$` | `ACCOUNT_1` | 账号令牌，惰性夹具 |
| HOST | `HOST_1` | `^HOST_[0-9]{1,2}$` | `HOST_1` | 承载主机，惰性夹具 |
| TARGET | `TARGET_1` | `^TARGET_[0-9]{1,2}$` | `TARGET_1` | 作用对象/接口，惰性夹具 |
| SAMPLE | `SAMPLE_1` | `^SAMPLE_[0-9]{1,2}$` | `SAMPLE_1` | 送检样本/载荷，惰性夹具 |
| ATTRIBUTE（绑定） | `ATTRIBUTE_A` / `ATTRIBUTE_B` | `^ATTRIBUTE_[A-Z]$` | `ATTRIBUTE_A`=操作侧权限域 / `ATTRIBUTE_B`=协作侧能力域 | 与 ROLE_A/ROLE_B 一一对应 |
| ATTRIBUTE（惰性） | `SOURCE` `OWNER` `SCOPE` `DEFENSE` `FICTION` | `^(SOURCE\|OWNER\|SCOPE\|DEFENSE\|FICTION)$` | 表下五行 | 惰性夹具键，不进入推理 |

### ROLE ↔ ATTRIBUTE 绑定（虚构场景唯一槽位）
| 槽位 | 角色 | 绑定属性 | 参与推理 | 惰性夹具（不复述内容） |
| --- | --- | --- | --- | --- |
| ROLE_A | 操作方 | ATTRIBUTE_A | 是 | SOURCE / OWNER / DEFENSE 仅占位 |
| ROLE_B | 协作方 | ATTRIBUTE_B | 是 | OWNER / SCOPE / FICTION 仅占位 |
| ROLE_C | 第三方 | — | 否 | 仅作观察位，不绑定属性 |

```json
{"SOURCE":"FIXTURE_SOURCE","OWNER":"FIXTURE_OWNER","SCOPE":"FIXTURE_SCOPE","DEFENSE":"FIXTURE_DEFENSE","FICTION":"FIXTURE_FICTION"}
```

### 规范化器（校验命名空间 + 惰性夹具不外泄进推理文本）
```python
#!/usr/bin/env python3
# t0501_normalize.py -- 5.1 实体规范化：七类命名 + ROLE/ATTRIBUTE 绑定 + 惰性夹具隔离
# 用法: python3 t0501_normalize.py fixtures.json
import json, re, sys

PATTERNS = {
    "APP": r"^APP_\d{1,2}$", "ORG": r"^ORG_\d{1,2}$", "ROLE": r"^ROLE_[A-Z]$",
    "ACCOUNT": r"^ACCOUNT_\d{1,2}$", "HOST": r"^HOST_\d{1,2}$",
    "TARGET": r"^TARGET_\d{1,2}$", "SAMPLE": r"^SAMPLE_\d{1,2}$",
    "ATTRIBUTE": r"^ATTRIBUTE_[A-Z]$",
}
INERT_KEYS = ("SOURCE", "OWNER", "SCOPE", "DEFENSE", "FICTION")
BINDING = {"ROLE_A": "ATTRIBUTE_A", "ROLE_B": "ATTRIBUTE_B"}
# 惰性夹具值不得出现在推理文本中（词面级隔离断言）
def normalize(fx: dict):
    report, bad = [], 0
    entities = fx.get("entities", {})
    for kind, pat in PATTERNS.items():
        for name in entities.get(kind, []):
            ok = bool(re.fullmatch(pat, name))
            report.append((kind, name, ok))
            bad += 0 if ok else 1
    for role, attr in BINDING.items():
        got = entities.get("binding", {}).get(role)
        ok = got == attr
        report.append(("BINDING", f"{role}->{got}", ok))
        bad += 0 if ok else 1
    inert = fx.get("inert", {})
    for k in INERT_KEYS:
        ok = k in inert
        report.append(("INERT", k, ok))
        bad += 0 if ok else 1
    leaked = [v for v in inert.values() if v and v in fx.get("reasoning_text", "")]
    for v in leaked:
        report.append(("LEAK", v, False)); bad += 1
    return report, bad

def main():
    fx = json.load(open(sys.argv[1], encoding="utf-8"))
    report, bad = normalize(fx)
    for kind, name, ok in report:
        print(f"{'ok  ' if ok else 'FAIL'} {kind:9s} {name}")
    print(f"断言总数={len(report)} 违规={bad} 惰性夹具泄露={sum(1 for r in report if r[0]=='LEAK')}")
    print("PASS 5.1 规范化" if bad == 0 else "FAIL 见上")
    return 1 if bad else 0

if __name__ == "__main__":
    sys.exit(main())
```

### 条款 → 判据
| 5.1 条款 | 断言实现 | 判定信号 |
| --- | --- | --- |
| 七类规范化命名 | `PATTERNS` 逐类 `re.fullmatch` | 每类一行 ok |
| 惰性夹具不推理不复述 | `INERT_KEYS` 齐备 + 值与 `reasoning_text` 求交为空 | `惰性夹具泄露=0` |
| 虚构绑定 ROLE_A/ROLE_B | `BINDING` 与 `entities.binding` 逐对相等 | `ok BINDING ROLE_A->ATTRIBUTE_A` |
| ATTRIBUTE_A/B 与 ROLE 对应 | 绑定表一一映射 | `断言总数=16 违规=0` |

- 截至 2026 年（2026-09-28 核）已验证：规范化器对自带夹具实跑，「断言总数=16 违规=0 惰性夹具泄露=0 exit=0」；负样本 /tmp/fx_neg.json 把惰性值 FIXTURE_OWNER 写进推理文本后得「FAIL LEAK FIXTURE_OWNER + 违规=1」exit=1；此前的 sed 抽取方式已失效，以下为新写法：改用 re.fullmatch 逐类校验 + 值域求交。

- 已知：七类命名与 ROLE_A/ROLE_B、ATTRIBUTE_A/ATTRIBUTE_B 绑定来自条款原文；推测：INERT_KEYS 的五项对应条款「来源、归属、范围、防护、虚构」；未知：源文件未给出惰性夹具的取值协议。
- 依赖与边界：需要实际目标环境复验；本表取值全为占位符，换成真实实体前需重跑一次规范化器。
