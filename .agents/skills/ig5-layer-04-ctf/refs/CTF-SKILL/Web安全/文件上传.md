# 文件上传

## 概述

文件上传漏洞（File Upload Vulnerability）指应用对用户上传的文件缺乏严格的校验，攻击者可上传恶意文件（如 Webshell）并在服务器上执行。CTF 中文件上传题目通常设置各种限制条件，需要选手绕过前端校验、黑白名单、内容检测或利用服务器特性实现 Webshell 上传。

## 常见攻击手法

### 1. 基础上传利用

- **直接上传 Webshell**：上传 PHP 一句话木马 `<?php @eval($_POST['cmd']);?>` 或 JSP Webshell
- **访问上传文件**：分析上传路径规律，找到 Webshell 的 URL 地址
- **常见 Webshell 类型**：PHP、ASP、ASPX、JSP、Python、Shell 等，取决于后端语言

### 2. 前端绕过

- **修改 HTML 表单限制**：浏览器 DevTools 中移除 `accept` 属性或修改 `onsubmit` 校验函数
- **禁用前端 JS 校验**：在 DevTools 中禁用 JavaScript 或直接修改校验函数逻辑
- **直接发送 HTTP 请求**：使用 Burp Suite 或 curl 绕过前端限制直接发送请求包

### 3. 黑名单绕过

- **等价扩展名**：
  - PHP：`.php`、`.php3`、`.php4`、`.php5`、`.phtml`、`.pHp`（大小写混合）
  - ASP：`.asp`、`.aspx`、`.asa`、`.cer`、`.cdx`
  - JSP：`.jsp`、`.jspx`、`.jspa`
- **双扩展名**：`shell.php.jpg`、`shell.php.abc`（某些中间件解析最后一个扩展名）
- **末尾特殊字符**：`shell.php.`、`shell.php%00`（空字节截断，已修复于 PHP 5.3.4+）
- **Apache 解析漏洞**：`shell.php.xxx`（Apache 不认识 `.xxx` 时会依次向前解析）
- **IIS 解析漏洞**：
  - `shell.asp;.jpg`（IIS 7.5 以下分号截断）
  - `shell.asp/`（目录解析）
  - `shell.asa;.jpg`
- **Nginx 解析漏洞**：`shell.jpg/xx.php`（请求交给 PHP 处理时，`shell.jpg` 作为 PHP 执行）

### 4. 白名单绕过

- **MIME 类型绕过**：修改 `Content-Type` 为 `image/jpeg`、`image/png`、`image/gif`
- **文件头伪造**：在文件头部添加魔术字节（Magic Bytes）
  - JPEG：`FF D8 FF E0`
  - PNG：`89 50 4E 47`
  - GIF：`47 49 46 38 39 61`（GIF89a）
- **文件内容注入**：在图片文件的 EXIF 注释或文件末追加 PHP 代码（图片马）
  - `copy normal.jpg /b + shell.php /a webshell.jpg`
- **双文件头**：`GIF89a<?php @eval($_POST['cmd']);?>`
- **合理利用白名单**：某些后台允许上传 `.zip`、`.tar` 等压缩包后自动解压

### 5. 服务端特性绕过

- **Apache .htaccess 上传**：
  - 上传 `.htaccess` 文件，内容：`AddType application/x-httpd-php .jpg`，然后上传图片马
  - `php_value auto_prepend_file` 或 `php_value auto_append_file` 包含指定文件
- **IIS web.config**：上传 `web.config` 配置 Handler 映射
- **.user.ini**（PHP）：上传 `.user.ini` 设置 `auto_prepend_file=shell.jpg`（Nginx 配合 CGI/FastCGI）
- **文件覆盖**：若文件名可控制，覆盖 `.user.ini` 或 `.htaccess` 实现配置修改

### 6. 文件内容检查绕过

- **文件头检查**：在文件开头添加图片文件头
- **文件大小检查**：小于指定大小的 Webshell（使用最短的 payload）
- **文件内容包含特定字符串**：在图片元数据中隐藏 payload
- **内容重新编码**：使用 base64 压缩 payload
- **getimagesize() 绕过**：构造有效的图片文件并嵌入代码

### 7. 条件竞争

- **原理**：文件先被保存到临时目录，然后检查合法性，不合规则删除。在检查与删除的时间窗口内访问文件可触发执行
- **利用方法**：
  - 同时发送大量上传请求
  - 同时发送大量访问该文件的请求（使用多线程脚本）
  - 触发执行后快速利用，因为文件可能被立即删除

### 8. 中间件解析漏洞

- **Apache**：`http://target.com/shell.php.abc`（不认识的扩展名向前解析）
- **Nginx + PHP-FPM**：`http://target.com/shell.jpg/xx.php`（路径中的 `.php` 触发 PHP 解析）
- **IIS 6.0**：`xx.asp/` 文件夹下所有文件作为 ASP 执行
- **Tomcat**：`shell.jsp/`（类似 Nginx 的行为）

### 9. ZIP 解压利用

- **软链接/符号链接**：上传的 ZIP 包中包含指向 `/flag` 的符号链接
- **路径遍历**：ZIP 包中的文件名包含 `../`，解压到父目录覆盖关键文件

## 防御建议

- 使用白名单机制限制上传文件类型，结合 MIME 类型和文件头双重校验
- 上传目录设置为禁止脚本执行（取消执行权限）
- 重命名上传文件（使用随机 UUID），避免用户控制文件名
- 上传目录与 Web 根目录分离

## CTF 中的常见考点

- 图片马配合 .htaccess 或 .user.ini 实现 PHP 执行
- Apache 解析漏洞：`shell.php.abc`
- 条件竞争上传（先保存后删除的时间差）
- ZIP 软链接读取服务器文件
