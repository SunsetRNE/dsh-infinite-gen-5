# 数据编码转换（Data Encoding）

## 概述

CTF 竞赛中经常出现各种编码的混合使用，选手需要能够快速识别和解码各种编码格式。数据编码转换涵盖从简单的 ASCII 到复杂的自定义编码。熟悉各种编码的特征和转换方法是 MISC 和 CRYPTO 类题目的基础技能。

## 常见编码类型

### ASCII / Unicode 编码
- ASCII（7 位）：0-127 的标准字符编码
- 十六进制 ASCII：将字符转换为十六进制数值
- 二进制 ASCII：将字符转换为二进制数值
- URL 编码：`%20` 形式的百分比编码
- Unicode 编码：`\uXXXX`（Python/Java）、UTF-8、UTF-16LE/BE

### Base 系列编码
- **Base16**：即十六进制
- **Base32**：字符集 A-Z 2-7，末尾 `=` 填充
- **Base64**：字符集 A-Z a-z 0-9 + /，末尾 `=` 填充
- **Base58**：去除了 0/O/l/I 等易混淆字符
- **Base85 / Ascii85**：Adobe 或 RFC 1924 版本
- **Base36**：0-9 A-Z
- **Base62**：0-9 A-Z a-z

### 其他编码
- **UUencode**：Unix-to-Unix 编码
- **XXencode**：类似 Base64 的变种
- **Quoted-Printable**：MIME 编码，`=` 后跟十六进制
- **汉字编码**：汉字 Unicode 编码、五笔编码、拼音编码
- **国旗编码**：用旗帜符号表示信息

## 常见攻击手法

### 编码识别
- 观察字符集：Base32（A-Z2-7=）、Base64（A-Za-z0-9+/=）
- 观察特殊字符：`=` 填充通常是 Base 系列
- 观察格式：`%` 开头是 URL 编码，`\u` 开头是 Unicode
- 使用自动检测工具

### 多层解码
密文经过多层编码叠加，需逐层剥离：
```
密文: JTJGU1RfTk9URVM=
→ Base64 解码: /FST_NOTES
→ URL 解码: /FST_NOTES
→ 观察结果是否为 Flag 格式
```

### 编码混淆
- 自定义字符表（改 Base64 的字符映射）
- 编码混合使用（如 Base64 后再 Hex）
- 自定义编码（根据题目提示反向推导）

## 防御建议

编码不是加密，不能用于保护敏感信息。编码只是数据格式的转换，不应依赖编码实现安全性。

## 示例思路

```python
import base64
import urllib.parse

# 常见编码转换链
encoded = "JTJGU1RfTk9URVM="
step1 = base64.b64decode(encoded).decode()  # "/FST_NOTES"
step2 = urllib.parse.unquote(step1)  # "/FST_NOTES"
print(step2)

# 自定义 Base64 字符集
import string
STANDARD_ALPHABET = 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/'
CUSTOM_ALPHABET = '...'  # 自定义字符集

def custom_b64decode(data, custom_alphabet):
    trans = str.maketrans(custom_alphabet, STANDARD_ALPHABET)
    return base64.b64decode(data.translate(trans))
```
