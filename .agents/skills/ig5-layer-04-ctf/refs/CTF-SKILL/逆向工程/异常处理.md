# 异常处理 (Exception Handling)

## 概述

异常处理是操作系统和编程语言提供的一种机制，用于处理程序运行时发生的错误或特殊情况。在 Windows 平台上，异常处理机制错综复杂，包括结构化异常处理（SEH）、向量化异常处理（VEH）、未处理异常过滤器（UEF）以及 C++ 异常处理等。

在逆向工程与漏洞利用中，异常处理不仅是理解程序行为的重要方面，也是实现反调试、控制流劫持以及代码执行的重要途径。恶意软件常利用异常处理来隐蔽执行代码——通过"抛出异常 — 异常处理程序执行 — 程序继续运行"的模式绕过常规的代码追踪。

---

## 常见异常处理机制

### 1. SEH (Structured Exception Handling / 结构化异常处理)
SEH 是 Windows 操作系统提供的基础异常处理机制，以链表形式组织异常处理函数。

**SEH 链结构**:
```c
typedef struct _EXCEPTION_REGISTRATION_RECORD {
    struct _EXCEPTION_REGISTRATION_RECORD *Next;  // 下一个处理节点
    PEXCEPTION_ROUTINE Handler;                    // 异常处理函数指针
} EXCEPTION_REGISTRATION_RECORD;
```

**工作原理**:
- SEH 链表存储在 TEB（线程环境块）的 `NtTib.ExceptionList`（fs:[0]）。
- 当异常发生时，操作系统从链表头部开始遍历，依次调用每个 Handler。
- 如果某个 Handler 返回 `ExceptionContinueExecution`（恢复执行）或 `ExceptionContinueSearch`（继续搜索）。
- 最后一个 Handler 是系统默认的 `__except_handler3`。

**SEH 在 VC++ 中的实现**:
- `__try / __except` 结构中，编译器生成 `_except_handler3` 或 `_except_handler4` 作为 SEH Handler。
- `_except_handler4` 加入了 Cookie 安全检查（GS 保护），防止 SEH 覆盖攻击。

**SEH 链逆向识别**:
- 函数序言中 `push handler_func / push fs:[0] / mov fs:[0], esp` 的指令序列。
- IDA 可自动识别 `__try` / `__except` 结构并显示伪代码。

**SEH 覆盖攻击 (SEH Overwrite)**:
- 经典的栈溢出利用技术——通过溢出覆盖 SEH Handler 指针和 Next 指针。
- 触发异常后，SEH Handler 指向的恶意代码被执行。
- 在 SafeSEH 和 SEHOP 保护机制出现后，传统 SEH 覆盖受到限制。

### 2. VEH (Vectored Exception Handling / 向量化异常处理)
VEH 是 Windows XP 之后引入的异常处理机制，与 SEH 不同，VEH 处理程序不是以链表形式链接在栈上，而是注册在进程的全局链表中。

**关键 API**:
- `AddVectoredExceptionHandler` / `RemoveVectoredExceptionHandler`: 注册/移除 VEH 处理程序。
- `AddVectoredContinueHandler`: 注册"继续处理"处理程序（在 VEH 之后、SEH 之前执行）。

**VEH vs SEH 执行顺序**:
1. 调试器首次处理（如果有）。
2. **VEH 链表**（优先于 SEH 执行）。
3. **VEH Continue Handler**。
4. **SEH 链表**（基于栈）。
5. 调试器最后一次处理。
6. 未处理异常过滤器（UEF）。

**逆向要点**:
- VEH 处理程序在全局地址空间中，注册后对所有线程有效。
- 恶意代码利用 VEH 实现反调试（设置异常处理函数拦截 INT3 等）。
- VEH 处理程序通常通过 `call [ebp + param]` 等方式间接跳转到恢复执行。

### 3. UEF (Unhandled Exception Filter / 未处理异常过滤器)
当所有 SEH 和 VEH 处理程序都不处理异常时，最终由 UEF 处理。

**关键 API**:
- `SetUnhandledExceptionFilter`: 设置进程级别的未处理异常过滤器。
- 默认行为: 调用 `__except_handler3`（最终版本）或 `kernel32!UnhandledExceptionFilter`，显示错误对话框并终止进程。

**逆向要点**:
- UEF 是程序最后的"保护屏障"，常被用来在崩溃前执行清理/日志操作。
- 也被用作防止调试的最后一环——检测到异常来源可疑时直接终止进程或触发错误报告（WER）。
- 修改 UEF 的行为也可以用于绕过程序的崩溃保护。

### 4. VCH (Vectored Exception Handler Chaining / 向量化异常处理链)
VCH 不是微软官方的术语，而是指 VEH 处理程序链的管理和调度过程。

**关键规则**:
- VEH 处理程序在注册时指定 `first` 参数（是否插入链表头部）。
- 从链表头到尾遍历，一旦某个处理程序返回 `EXCEPTION_CONTINUE_EXECUTION` 即停止。
- 所有 VEH 处理程序都在进程的同一地址空间内。

### 5. 其他异常处理机制

**C++ 异常处理 (C++ EH / Windows x64)**:
- x64 平台使用基于表的异常处理（`IMAGE_DIRECTORY_ENTRY_EXCEPTION` 指向的 Function Table）。
- 异常处理信息存储在 `.pdata`（函数表）和 `.xdata`（异常处理数据）段中。
- 反编译后表现为 `try / catch / throw` 结构。
- `__CxxFrameHandler3` / `__CxxFrameHandler4` 是 C++ EH 的核心函数。

**SEHOP (Structured Exception Handling Overwrite Protection)**:
- Windows 安全机制，维护 SEH 链的完整性。
- 在异常分发前验证 SEH 链的最后一个节点是否指向 `ntdll!FinalExceptionHandler`。
- SEHOP 的绕过需要控制 SEH 链的尾部指针使其指向合法的结束节点。

**SafeSEH**:
- 编译时选项（`/SAFESEH`），生成合法的 SEH Handler 地址列表。
- 异常分发时检查 Handler 地址是否在合法列表内。
- 绕过: 跳转到非 PE 模块中的地址（如堆上的代码）。

**VectoredExceptionHandler vs VectoredContinueHandler**:
- VEH: 在异常处理分发的早期阶段调用，可以拦截并处理异常。
- ContinueHandler: 在 VEH 之后、SEH 之前调用，主要用于记录和监控。

## 异常处理在逆向中的价值

**反调试中的应用**:
- SEH/VEH 拦截 `INT3` 异常（`EXCEPTION_BREAKPOINT`），如果在调试器中则被调试器处理，否则触发自定义处理函数。
- 通过 `RaiseException` 或 `int 3` 构造异常，在异常处理函数中执行关键逻辑（"执行流隐藏在异常处理中"）。
- **典型模式**:
  ```cpp
  __try {
      RaiseException(0xE0000001, 0, 0, NULL);  // 主动触发异常
  } __except(EXCEPTION_EXECUTE_HANDLER) {
      // 关键逻辑放在异常处理块中
      // 调试器若设置断点在异常处理块则会被绕过
  }
  ```

**漏洞利用中的应用**:
- **SEH Overwrite**: 控制 `EXCEPTION_REGISTRATION_RECORD` 的 Handler 指针实现代码执行。
- **VEH 利用**: 在漏洞利用链中通过注册 VEH 来接管某些异常的处理。
- **异常处理函数地址泄露**: 从栈上残留的 SEH 链地址推断进程状态。

**逆向分析辅助**:
- 通过理解异常处理结构，在 IDA 中正确还原 `__try/__except` 伪代码。
- 通过 VEH/SEH 反调试的绕过（禁用异常处理拦截或手动操作异常）。

## 防御/对抗建议

- **SafeSEH**: 编译时启用 `/SAFESEH` 限制合法的 SEH Handler 地址。
- **SEHOP**: 系统级别的 SEH 链完整性检查。
- **SEH 混淆**: 手动构建非标准的 SEH 链或修改 VEH 处理逻辑来增加分析难度。
- **异常执行路径**: 将关键解密/校验逻辑隐藏在异常处理路径中，增加逆向复杂度。
- **Hook 检测**: 定期扫描 VEH 链表，检查是否有未知的处理程序。
