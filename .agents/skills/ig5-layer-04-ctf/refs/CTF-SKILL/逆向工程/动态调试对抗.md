# 动态调试对抗 (Anti-Debugging)

## 概述

动态调试对抗（反调试）是软件保护体系中针对动态分析（调试器）的防御技术。反调试技术的核心目标是检测程序是否正在被调试，并在检测到调试环境时改变行为——终止运行、执行误导路径或触发自我破坏。

在 CTF 逆向中，掌握各种反调试技术的原理与绕过方法，是成功调试和分析受保护程序的必要条件。反调试与反调试绕过之间的"猫鼠游戏"既是安全研究的核心内容，也是 CTF 题目中常见的考察点。

## 常见对抗手法

### 1. 基于内存标志的检测
**PEB (Process Environment Block) 检测 (Windows)**:
- Windows 进程的 PEB 结构中包含 `BeingDebugged` 标志。
- 通过 `mov eax, fs:[30h]`（PEB 地址在 fs:0x30）-> `movzx eax, byte ptr [eax+2]` 检测。
- 检测到 `BeingDebugged = 1` 即认为被调试。

**绕过**: 在调试器中将 `BeingDebugged` 标志改为 0；或使用 ScyllaHide 等反反调试工具自动处理。

**NtGlobalFlag 检测 (Windows)**:
- PEB 偏移 0x68 处的 `NtGlobalFlag` 字段，正常值为 0，调试时被设为 `FLG_HEAP_ENABLE_TAIL_CHECK (0x10)` | `FLG_HEAP_ENABLE_FREE_CHECK (0x20)` | `FLG_HEAP_VALIDATE_PARAMETERS (0x40)` = 0x70。

**TEB (Thread Environment Block) 检测**:
- TEB 的 `ProcessEnvironmentBlock`、`TlsSlots` 等字段可间接反映调试状态。

### 2. 基于 API 的检测
**Windows 常见 API 检测**:
- `IsDebuggerPresent()`: 检测 PEB.BeingDebugged 标志。
- `CheckRemoteDebuggerPresent()`: 检测远程调试器的存在。
- `NtQueryInformationProcess()`: 查询 `ProcessDebugPort` (0x7)、`ProcessDebugFlags` (0x1F)、`ProcessDebugObjectHandle` (0x1E)。
- `FindWindow()` / `EnumWindows()`: 搜索调试器窗口（如 "OllyDbg"、"x64dbg"、"WinDbg" 等）。
- `OutputDebugString()`: 使用 `GetLastError()` 检测调试器是否处理了调试字符串。

**Linux 常见 API 检测**:
- `ptrace(PTRACE_TRACEME, ...)`: 如果返回 -1，说明已处于被跟踪状态（一个进程只能被一个 ptracer 跟踪）。
- `/proc/self/status`: 检查 `TracerPid` 字段，非 0 表示被调试。
- `/proc/self/cmdline`: 检查是否有调试器相关的命令行参数。
- `getppid()`: 父进程是调试器时可能为特定进程名。

**绕过方法**: Hook 这些 API 函数，使其返回正常值；使用 ScyllaHide / TitanHide 等内核级反反调试驱动。

### 3. 基于进程跟踪的检测
**Windows**:
- `NtSetInformationThread(ThreadHideFromDebugger)`: 使指定线程对调试器不可见。
- `ZwQueryInformationThread(ThreadHideFromDebugger)`: 检查当前线程是否被隐藏。
- `NtCreateDebugObject`: 创建调试对象，可与其他检测组合使用。

**Linux**:
- `prctl(PR_GET_TRACER, ...)`: 获取当前进程的 tracer PID。
- 检查 `/proc/self/status` 的 `TracerPid` 域。
- `/proc/self/stat` 中的进程状态标志位包含调试信息。

**绕过**: 使用内核级别的调试（如 WinDbg 内核调试），绕过用户态的进程跟踪检测。

### 4. 基于 TLS (Thread Local Storage) 的检测
- Windows PE 文件中的 TLS 回调函数在程序入口点之前执行。
- 恶意代码可以在 TLS 回调中执行反调试检测和代码解密。
- 当调试器在主入口点设置断点时，TLS 回调已经执行完毕。
- 某些 TLS 回调还会持续监控调试状态（通过定时器或额外线程）。

**绕过**: 在 TLS 回调函数入口处设置断点；使用 IDA 的 TLS 解析功能提前查看回调地址。

### 5. 基于时间差的检测
- 程序在执行前后记录时间戳，如果差值过大则说明被调试器单步跟踪。
- **常用 API**:
  - `rdtsc` (Read Time-Stamp Counter): x86/x64 指令，读取 CPU 自启动以来的时钟周期数。
  - `QueryPerformanceCounter()` (Windows): 高精度性能计数器。
  - `GetTickCount()` / `timeGetTime()` (Windows): 系统启动以来的毫秒数。
  - `clock()` / `gettimeofday()` / `clock_gettime()` (Linux): 时间测量。
- **检测逻辑**: 获取时间 -> 执行一段代码 -> 再次获取时间 -> 如果差值超出阈值说明有调试开销。

**绕过**:
- 不使用单步步过（Step Over），直接使用运行到断点（Run to Cursor）减少时间开销。
- Patch 时间函数使其直接返回固定值。
- 在 `rdtsc` 处设置断点，手动控制返回值。

### 6. 基于调试器特征的检测
**进程特征检测**:
- 遍历进程列表，查找已知调试器的进程名（`ollydbg.exe`、`x64dbg.exe`、`windbg.exe`、`ida.exe` 等）。
- 通过 `CreateToolhelp32Snapshot` + `Process32First/Next` 枚举进程。

**窗口特征检测**:
- `FindWindow(NULL, "x64dbg")` 等搜寻调试器窗口标题。
- `EnumWindows` 遍历所有顶级窗口，检查类名/窗口名。

**模块特征检测**:
- 检查加载的模块中是否包含调试器相关的 DLL。

**绕过**: 使用进程重命名、窗口隐藏插件（ScyllaHide 的 HideWindow 功能）、或直接修改调试器的名称。

### 7. 基于异常的检测
**Windows VEH/SEH 反调试**:
- 利用结构化异常处理（SEH）或向量化异常处理（VEH）拦截调试器触发的异常。
- 设置异常处理函数，如果 `EXCEPTION_BREAKPOINT (0x80000003)` 没有被调试器处理而落入异常处理器，说明无调试器。
- "**Debugger Detection via INT3**": 在代码中插入 `INT3`，如果被调试器处理则继续运行（单步绕过），否则触发 SEH 执行其他逻辑。

**Linux 信号检测**:
- 利用 `signal()` 设置信号处理器，发送 `SIGTRAP` 等信号，观察是否被调试器拦截。

**绕过**: 理解异常处理流程，在合适的时机屏蔽或模拟异常；手动跟踪异常处理路径。

### 8. 基于断点的检测
**软件断点扫描**:
- 扫描代码段中的 `0xCC`（INT3 指令），检测是否被调试器下了软件断点。
- 计算关键函数的 CRC32/MD5 哈希，与原始值比较。
- `memcmp` 比较代码段的校验和。

**硬件断点检测**:
- 通过 `GetThreadContext` / `NtGetContextThread` 读取线程上下文中的 DR0-DR3（调试寄存器）。
- 如果调试寄存器非零，说明有硬件断点。

**绕过**:
- 软件断点: 不要直接在函数入口下断点；使用一次性断点；在检测代码运行后设置断点。
- 硬件断点: Patch 掉检测代码；Hook 检测函数使其返回假。
- 使用内存断点（基于页属性）替代硬件断点。

### 9. 基于沙箱的检测
沙箱（Sandbox）检测常用于恶意软件分析场景，CTF 中较少但仍有出现。

**常见检测方法**:
- 检测常见虚拟机环境: VMware、VirtualBox、QEMU 的特征（硬件设备、MAC 地址前缀、特定 I/O 端口）。
- 检测用户交互: 如果鼠标从未移动、窗口外置少见等。
- 检测系统属性: 少量的 RAM、小的磁盘空间、特定的用户名等。
- 检测特定进程/驱动: `vmtoolsd.exe`、`VBoxService.exe`。

**绕过**: 修改虚拟机配置去除特征；使用真实硬件环境；Patch 检测函数。

## 对抗建议（防御方视角）

- **多重检测**: 组合使用多种反调试技术，增加绕过难度。
- **隐蔽检测**: 不要在明显的检测点使用标准 API，而是使用不常见的方法（如直接解析 PEB）。
- **异步检测**: 通过单独的线程或定时器不断进行反调试检查。
- **诱饵检测**: 设置假的"反调试"代码路径，诱导逆向工程师耗费时间。
- **动态响应**: 不要立即终止程序，而是在检测后正常运行但在关键操作中植入错误。
