# 低级语言分析 (Low-Level Language Analysis)

## 概述

低级语言分析是逆向工程的核心技能，指对直接面向处理器或虚拟机的指令级代码进行分析。与高级语言逆向不同，低级语言分析要求逆向工程师深入理解目标架构的指令集、寄存器模型、内存模型和调用约定。

无论程序使用何种高级语言编写，最终都会被编译为目标架构的低级指令。因此，掌握低级语言分析是理解任何二进制程序的基础。

---

## 常见分析手法

### 1. Intel 汇编语言分析（x86 / x64）
Intel 汇编是 CTF 中最常见的汇编语言，分为 32 位 (x86) 和 64 位 (x64/AMD64) 两种模式。

**x86 基础**:
- 8 个通用寄存器: EAX/EBX/ECX/EDX/ESI/EDI/ESP/EBP。
- 参数传递: __cdecl（栈传递）、__stdcall（栈传递、被调用者清理）、__fastcall（ECX+EDX+栈）。
- 关键指令: `CALL/RET`、`JMP/Jcc`、`PUSH/POP`、`MOV/LEA`、`ADD/SUB/XOR`、`CMP/TEST`。
- 寻址模式: `[base + index*scale + displacement]`。

**x64 新增特性**:
- 16 个通用寄存器: RAX 到 R15，扩展为 64 位。
- **参数传递**: 前 4 个参数在 RCX/RDX/R8/R9（Windows）或 RDI/RSI/RDX/RCX/R8/R9（System V）。
- RIP 相对寻址: `LEA RAX, [RIP + offset]`，实现位置无关代码。
- REX 前缀: 用于扩展寄存器访问和 64 位操作数大小。
- 调用约定: Windows x64 使用单一调用约定，Linux x64 使用 System V AMD64 ABI。

**常见逆向模式**:
- **函数序言**: `push ebp; mov ebp, esp`（x86）或 sub rsp, XXX（x64）。
- **虚函数调用**: `call [rax + offset]` 或 `call [rdx + vtable_offset]`。
- **switch 语句**: 跳转表（Jump Table）`jmp [table + index*4]`。
- **循环结构**: cmp/jcc + jmp 构成的循环体。

### 2. ARM 汇编语言分析
ARM 是嵌入式领域的主导架构，有 ARM（32 位）和 Thumb（16 位）两种指令集模式。

**ARM 模式**:
- 16 个寄存器: R0-R15（R13=SP、R14=LR、R15=PC）。
- 大多数字令可以条件执行（根据 CPSR 标志位）——这是 ARM 的独特优势。
- 参数传递: R0-R3，返回值 R0。
- 典型函数序言: `push {r4-r7, lr}` / `pop {r4-r7, pc}`。
- **加载/存储架构**: `LDR/STR` 访问内存，数据处理指令只操作寄存器。
- 多种寻址模式: `[base, #offset]`、`[base, reg, LSL #n]`、`[base], #offset`（后变址）。

**Thumb 模式**:
- 指令长度 16 位（Thumb）/ 32 位（Thumb-2）。
- 条件执行受限（大部分指令无条件执行）。
- 函数调用通过 `BL` 指令，返回通过 `BX LR`。
- 在 IDA/Ghidra 中需要注意函数地址最低位: 0 表示 ARM 模式，1 表示 Thumb 模式。

**AArch64 模式**:
- 31 个 64 位通用寄存器 X0-X30（X30=LR）。
- 参数传递: X0-X7，返回值 X0。
- 固定 4 字节指令长度（无 Thumb）。
- 典型 RET: `ret` 指令（隐式跳转到 X30）。
- 新增 `LDP/STP` 成对加载/存储指令，常用于栈操作。

### 3. MIPS 汇编语言分析
MIPS 是经典 RISC 架构，在路由器、嵌入式设备和龙芯处理器中使用。

**基本特点**:
- 32 个寄存器: `$zero`（恒为 0）、`$at`（汇编临时）、`$v0-$v1`（返回值）、`$a0-$a3`（参数）、`$t0-$t9`（临时）、`$s0-$s7`（保存）、`$k0-$k1`（内核）、`$gp`（全局指针）、`$sp`（栈指针）、`$fp`（帧指针）、`$ra`（返回地址）。
- **延迟槽 (Delay Slot)**: 分支指令后的指令在跳转之前一定会执行——这是逆向时必须注意的特性。
- 指令固定 4 字节长度，所有指令对齐到 4 字节边界。
- 调用约定: 参数通过 `$a0-$a3` 传递，返回值通过 `$v0`。
- 函数返回: `jr $ra`，通常跟在 `lw` 恢复寄存器后。
- 加载/存储架构: `LW/SW` + `LB/SB` + `LH/SH`。

**常见逆向注意点**:
- 延迟槽导致分支目标的地址需要 +4 偏移。
- MIPS 的 `NOP` 编码是 `sll $zero, $zero, 0`（0x00000000）。
- `jalr`（通过寄存器间接跳转并链接）在逆向中被广泛用于动态调用场景。

### 4. SMALI 语言分析
SMALI 是 Android DEX 字节码的可读文本表示，由 `baksmali` 工具生成。

**基本特点**:
- 面向寄存器（寄存器数量不固定，由方法决定）。
- `v0-vn`: 局部寄存器；`p0-pn`: 参数寄存器（`p0 = this` 实例方法）。
- 指令格式: `.class` / `.method` / `.field` / `invoke-*` / `iget/iput` 等。
- 方法定义: `.method public/private <name>(<params>)<return_type>`。
- **常用指令**:
  - `invoke-virtual`/`invoke-direct`/`invoke-static`/`invoke-interface`。
  - `const`/`const-wide`/`const-string` 加载常量。
  - `if-eq`/`if-ne`/`if-gt` 等条件跳转。
  - `sget`/`sput` 静态字段读写; `iget`/`iput` 实例字段读写。

**逆向注意点**:
- 字符串池（String Pool）中通常包含关键常量。
- Android 框架的 Intent/Cookie/签名验证逻辑常出现在 SMALI 层。
- Native 函数通过 `invoke-static {...}, Ldalvik/system/NativeStart;->run()V` 调用。

### 5. MSIL 语言分析（.NET IL）
MSIL（Microsoft Intermediate Language）是 .NET 平台的中间语言，被 JIT 编译器在运行时转为机器码。

**基本特点**:
- 基于栈的虚拟机指令集。
- `.method` / `.field` / `.class` 定义结构。
- `ldarg/ldloc/stloc` 加载/存储参数和局部变量。
- `call/callvirt` 调用静态/虚方法。
- `box/unbox` 值类型与引用类型转换。
- `ldstr`、`ldc.i4`、`ldc.r8` 等加载常量。
- 异常处理: `.try` / `.catch` / `.finally`。

**逆向注意点**:
- .NET 程序通常有丰富的元数据（Metadata），反编译后接近原始代码。
- **dnSpy** / **ILSpy** / **dotPeek** 可将 MSIL 反编译为 C# 代码。
- 混淆工具（ConfuserEx、SmartAssembly、Dotfuscator）会重命名符号、控制流平坦化，增加逆向难度。
- 资源文件（Resources）中可能包含嵌入式可执行文件或加密数据。

### 6. Python 字节码分析
Python 源代码被编译为 `.pyc` 文件，内含 Python 字节码（由 CPython 虚拟机执行）。

**常用指令**（Python 3.x）:
- `LOAD_CONST` 加载常量
- `LOAD_FAST`/`STORE_FAST` 快速局部变量存取
- `LOAD_GLOBAL`/`STORE_GLOBAL` 全局变量存取
- `CALL_FUNCTION`/`CALL_METHOD` 函数调用
- `COMPARE_OP` 比较操作
- `JUMP_FORWARD`/`POP_JUMP_IF_FALSE` 控制流
- `BINARY_ADD`/`BINARY_XOR` 等算术/位运算

**分析工具**: `dis` 模块（Python 内置）、`uncompyle6`/`decompyle3`/`pycdc`、`pycdump`。

**逆向注意点**:
- Python 字节码不包含类型信息，逆向时需要根据操作推断数据类型。
- 混淆后的 Python 代码可能动态构造 code object 或使用 `marshal` 序列化。
- 使用 Cython/Nuitka 编译的 Python 代码会转译为 C 原生的机器码，逆向难度大幅上升。

### 7. 其他低级语言
- **LLVM IR**: 中间表示，在 OLLVM 混淆分析中常见。三地址码格式（`%result = add i32 %a, %b`）。
- **WebAssembly (WASM)**: 浏览器端二进制格式，基于栈的虚拟机。可以使用 wasm-decompile 还原为可读格式。
- **Dalvik 字节码**: Android 4.4 之前的虚拟机字节码（已被 ART 替代，但在遗留 APK 中仍可见）。
- **Java 字节码**: JVM 指令集，.class 文件格式。使用 `javap` 或 `CFR`/`Procyon` 反编译。
- **P-Code**: IDA 的中间表示，介于汇编和反编译 C 代码之间，是 IDA 插件的常用操作对象。

## 防御/对抗建议

- **架构多样化**: 使用不同架构编译可增加逆向难度（如使用 MIPS 编译关键校验逻辑）。
- **多架构混淆混合**: 在同一程序中混合使用 ARM/Thumb 模式切换。
- **动态代码生成**: LLVM JIT 等方式在运行时生成代码，绕过静态分析。
- **二进制翻译**: 使用 QEMU user-mode 等透明翻译技术，增加溯源难度。
