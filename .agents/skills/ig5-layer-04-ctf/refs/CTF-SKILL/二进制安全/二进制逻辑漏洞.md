# 逻辑漏洞 (Logic Vulnerability)

## 概述

逻辑漏洞（Logic Vulnerability）是指由于程序在业务流程、状态管理、权限判定等方面存在设计缺陷，导致攻击者能够绕过预期的安全限制、执行未授权操作或获取敏感信息的一类漏洞。与内存破坏漏洞不同，逻辑漏洞通常不涉及直接的缓冲区溢出或内存管理错误，因此传统的内存安全防护机制（如 ASLR、Canary、NX）无法对其进行有效防御。

在 CTF 的 PWN 题目中，逻辑漏洞往往与内存破坏漏洞组合出现，或是作为获取初始信息泄露、突破额外限制的辅助手段。随着安全防护技术的进步，纯内存破坏类题目的难度日益提高，逻辑漏洞在现代 CTF 题目中的比重逐渐增加。

## 常见攻击/分析手法

### 1. 条件竞争 (Race Condition)
- **原理**: 多线程或多进程环境下，程序对共享资源的访问缺乏适当的同步机制，导致操作时序上存在可利用的窗口。
- **常见类型**:
  - TOCTOU (Time-of-Check Time-of-Use): 检查与使用之间存在时间差，攻击者在检查后修改条件。
  - 信号量/锁滥用: 不正确的加锁粒度或遗漏解锁。
  - Dirty COW (经典内核条件竞争): 多线程同时访问写时复制的内存页。
  - 文件操作竞争: `access()` + `open()` 之间替换文件为符号链接。
  - Setuid 程序竞争: 在多线程中对 uid 的操作存在竞争窗口。
- **利用手法**:
  - 使用 `pthread_create` 创建大量线程同时发起操作。
  - 利用 BROP 等手法爆破竞争窗口。
  - 使用 ptrace 暂停线程以精确控制执行时序。
- **检测**: 关注全局变量/共享资源的多线程并发访问、信号处理函数中的非重入函数调用。

### 2. 类型混淆 (Type Confusion)
- **原理**: 程序将某个对象当作不兼容的类型使用，通常发生在 C++ 的向下转型（Downcasting）、联合体（Union）的错误解释、强制类型转换不当等场景。
- **利用手法**:
  - 伪造虚表指针（Vtable Pointer），将对象虚函数调用劫持到攻击者控制的地址。
  - 将小对象当作大对象使原本不重叠的字段重叠，实现任意读写原语。
  - 利用 JavaScript/Flash 等引擎中的类型混淆实现远程代码执行。
- **典型场景**: C++ 中 `dynamic_cast` 缺失检查；联合体未正确记录当前活跃成员；`reinterpret_cast` 滥用；JSON 解析中的类型判断错误。
- **浏览器/JS 引擎高频漏洞**: V8 TurboFan JIT 优化导致的类型推断错误（Deoptimization 问题），是近年来 Pwn2Own 和 CTF 的热点。

### 3. 鉴权绕过 (Authentication Bypass)
- **原理**: 程序在对用户身份或权限进行验证时存在逻辑缺陷，攻击者可绕过验证获得未授权的访问权限。
- **常见手法**:
  - 索引/ID 未验证: 仅依赖客户端传入的 ID 进行权限判定，可篡改 ID 访问其他用户数据（IDOR）。
  - 状态覆盖: 在认证流程中对特定状态位进行篡改。
  - Cookie/Token 伪造: 弱随机数种子、JWT none 算法、签名验证缺失。
  - 竞争条件绕过鉴权: 在鉴权完成与状态设置之间利用窗口期。
  - 修改返回地址跳过鉴权检查（配合其他漏洞）。

### 4. 命令注入 (Command Injection)
- **原理**: 用户输入被用于构建系统命令或执行代码，且输入未经过充分的过滤或转义。
- **PWN 场景**:
  - 调用 `system()`/`exec()`/`popen()` 等函数执行动态构造的命令。
  - `dlopen()`/`dlsym()` 加载用户控制的库或符号。
  - 内核模块中用户输入的路径/参数直接传递给系统调用。
  - 沙箱环境中通过特定系统调用组合构建执行原语。
- **利用**: 管道符 `| ; && ||` 拼接命令；`$()` 反引号命令替换；换行符绕过单行限制。
- **注意**: 在现代 CTF 中，命令注入通常作为取得初步 shell 后的二次利用手段。

### 5. 信息泄露 (Information Leakage)
- **原理**: 程序在正常功能中无意暴露了敏感信息，为后续攻击提供情报支撑。
- **PWN 中常见泄露对象**:
  - **地址泄露**: libc 基址、堆基址、栈地址、PIE 基址、Canary 值。
  - **数据泄露**: 标志位（flag）、密钥材料、其他用户的数据。
  - **配置泄露**: 程序路径、环境变量、内存映射信息。
- **泄露途径**:
  - 格式化字符串漏洞（详见 [格式化字符串漏洞](格式化字符串漏洞利用.md)）
  - 错误信息中过度暴露（路径、SQL 错误、栈回溯等）
  - 内存未初始化泄露
  - 侧信道泄露（时间差、功耗、缓存命中率等）

## 防御/对抗建议

- **条件竞争**: 正确使用锁/信号量/原子操作；遵循最小权限原则；使用 `O_CREAT | O_EXCL` 原子创建文件；避免在临时文件目录中作安全检查。
- **类型混淆**: 严格遵循类型安全的向下转型（使用 `dynamic_cast`）；避免将原始内存数据直接解释为复杂对象；使用内存安全语言。
- **鉴权**: 每次请求独立验证权限；服务端不应信任客户端传来的权限字段；建立统一鉴权网关。
- **命令注入**: 优先使用库 API 而非 shell 调用；严格过滤输入的白名单策略；转义 shell 特殊字符；极小化系统命令的权限。
- **信息泄露**: 移除调试输出；统一错误信息格式；使用 RELRO 保护 GOT 只读；谨慎管理堆内存的零化。

## 示例/思路

### 条件竞争 TOCTOU 示例
```
伪代码:
if (access("config.txt", R_OK) == 0) {    // 检查权限
    fd = open("config.txt", O_RDONLY);     // 打开文件
    read(fd, buf, size);                   // 读取内容
}
攻击: 在 access() 返回后，open() 执行前，
将 config.txt 替换为指向 /etc/shadow 的软链接。
```

### 类型混淆利用思路（C++ 虚表劫持）
```
1. 找到两个大小相同但类型不同的对象（对象 A 含危险虚函数，对象 B 含可控数据）
2. 利用堆布局控制使对象 B 的内存覆盖对象 A
3. 通过对象 A 调用虚函数时，实际执行的是对象 B 伪造的"虚表"中的地址
4. 控制参数寄存器（如 RDI）指向可控数据，实现 getshell
```
